# 명령어 안의 사건과 시간선

상위 표현 원칙은 [애니메이션 설계](animation.md), 속도 조작은 [UI 설계](ui.md)를 따릅니다. 이 문서는 사건별 수치와 표시 시점의 세부 명세입니다.

2026-11-10. 명령어는 `a+b`와 같은 중간언어 작업 단위, 사건은 그 안의 개별 값 전달 과정이다. 기존 스키마의 `trace.events`·`eventId`는 명령어 실행 기록을 가리키는 내부 이름으로 유지한다. 애니메이션 사건 때문에 중간언어를 추가·분할·재정렬하지 않는다.

## 사건이 늘면 명령어 시간도 늘어난다

명령어의 고정된 시간을 여러 사건이 나눠 쓰지 않는다. 사건마다 1× 기준으로 아래 시간을 확보하고 합계로 명령어 길이를 정한다. 설정은 `src/animation/timing.js`의 `incidentTiming`에 모은다.

| 과정 | 1× 기준 |
| --- | ---: |
| 명령어 준비 | 250ms |
| 사건 하나의 전달선 강조 | 350ms |
| 값 이동 | 900ms |
| 도착한 값 확인 | 550ms |
| 모든 피연산자가 모인 상태 확인 | 650ms |
| 계산 | 650ms |
| 목적지에 반영 | 250ms |
| 결과 확인 | 900ms |
| 경로 공통 소멸 | 350ms |

전달 사건 하나는 1,800ms다. 사건이 하나 추가되면 명령어 길이도 1,800ms 늘어나며 기존 사건 시간을 줄이지 않는다. `a+b`의 두 입력 CALC는 6,400ms, 결과를 저장하는 한 사건의 WRITE는 3,550ms다. 상수에는 가상의 출발 상자나 이동을 만들지 않는다. 전달이 없는 기본 SPACE·READ·FLOW의 시간은 유지한다.

## 값 표시 시점

- 전체 화살표는 유지하고 현재 사건만 강조한다. 이동 중에는 숫자가 경로를 따라 움직이며, 도착하면 알루에 남는다. 다음 사건의 강조·이동은 앞 사건의 도착 확인 뒤에 시작한다.
- 모든 피연산자가 모인 상태를 먼저 확인한 뒤 계산 단계를 진행한다. 기록된 결과는 계산 단계 종료 후 표시하고 별도의 결과 확인 시간을 둔다. C 연산을 다시 실행하지 않는다.
- 도착 여부 `delivered`와 목적지 숫자 갱신 시점 `valueReady`를 구분한다. 목적지 상자는 전달 뒤 반영 단계가 끝나야 갱신한다. 반환구·출력·범위 쓰기·재할당 보존 값과 포인터 선의 전후 상태도 같은 시간선을 사용한다.
- 앞선 CALC의 결과를 소비하는 FLOW·WRITE에서 같은 계산이나 피연산자 전달을 다시 재생하지 않는다. 결과 확인 뒤 전체 전달선을 함께 흐리게 한다.
- 정지와 속도 변경은 현재 사건의 위치를 유지한다. 0.25×~10× 슬라이더는 사건별 시간선 전체를 같은 비율로 조절한다. 사건이 많은 명령어를 시간 상한에 맞추어 자동 압축하지 않는다.
- 실제 재생 상태는 기존처럼 명령어 경계에서만 커밋한다. 명령어 클릭 미리보기는 실행 상태를 바꾸지 않는다. ‘한 명령어’와 진행 슬라이더는 기존 중간언어 경계를 사용한다.

`instructionTiming`은 기록·명령어별 시간선을 캐시한다. 재생기의 duration, 화살표 이동과 피연산자 도착, 알루 결과, 상자 쓰기, 반환 필드 정리, 도구 소멸이 이 시간선을 함께 사용한다.

명령 완료 경계에서는 속도 환산의 소수점 오차를 허용해 progress가 1인데 완료되지 않는 정지를 방지한다. 재생 중 이미 완료된 경계는 0ms에서도 한 번 커밋할 수 있지만 일시정지와 남은 연출 시간은 보존한다. [정지 원인과 관련 검증](../validation/playback-boundary-stall.md)을 참고한다.

## 확인

관련 검사 52개와 빌드가 통과했다. 전달 사건 1/2/8/16/32개에서도 강조·이동·도착 대기 시간이 동일한지, 모인 값 확인→계산→결과 확인의 분리, 숫자 갱신 전후, 정지·속도 변경, 기록과 이전 상태 불변을 검사했다. 산술·논리·인자·반환·복사·입출력·재할당을 공통 재생기로 확인했고 전체 과거 C 예제 모음은 재실행하지 않았다.

브라우저 1× 재생에서도 첫 피연산자 도착 확인, 두 피연산자 확인, 계산, 결과 확인을 차례로 확인했다. 저장 명령어에서는 화살표 도착 확인 중에는 목적지 c가 미초기화로 남고, 다음 반영 단계 뒤에 30으로 바뀌는 것을 확인했다.
