# BST 의미 판별과 복합 키

2026-11-11. 확정된 중간언어와 기존 트리 후보를 읽는 선택적 추론 계층입니다. C 코드·실행 사건·배치·애니메이션은 변경하지 않습니다.

## 근거와 경계

`bst-views.mjs`는 다음 관측 근거를 연결합니다. 저장 관계는 `structure-relations.mjs`의 공통 표현으로 투영하고, 순서 검사는 `structure-conditions.mjs`의 `checkBSTOrder`로 분리했습니다. [조합 계약](structure-composition.md)에 따라 같은 관계에서 BST·AVL·레드-블랙 조건을 조합할 수 있으며, 색 역할의 자동 추론까지 구현한 것은 아닙니다.

1. 실제 CALC 비교와 피연산자 READ의 저장 위치. 값이 비슷하다는 이유로 출처를 연결하지 않습니다.
2. 비교를 소비한 FLOW 분기와 그 분기에 의해 실행된 자식 링크 접근.
3. 같은 커서 슬롯으로의 대입, 호출 인자에서 다음 노드 키 접근까지의 전달, 또는 비교 대상 노드를 가리키는 자식 링크 삽입.

포인터를 출력 함수에 넘기는 것만으로 탐색 근거를 만들지 않습니다. 재귀 호출은 실제 매개변수가 다음 노드의 키 주소에 쓰였는지 확인하며 그 READ 시점부터 근거로 사용합니다. 별도 호출 프레임이나 동일 숫자의 다른 변수를 혼동하지 않습니다.

키 역할은 구조체 내 바이트 위치 또는 확인된 공동 인덱스 배열의 저장 위치입니다. 변수·함수·필드 이름과 예제 번호를 사용하지 않습니다. 포인터 구조체, 구조체의 정수 연결 인덱스, 값/연결 분리 배열을 같은 비교 규칙으로 처리합니다. 실제 저장소와 원래 간선은 유지합니다.

현재 지원 범위는 정수 키의 비교입니다. 비교 결과의 산술·논리 조합과 값 전달을 따라가므로 `(a<b)-(a>b)` 같은 역순 비교 보조 함수도 처리할 수 있습니다. 임의의 사용자 함수를 다시 호출하거나 C를 별도로 실행하지 않습니다. 키 자체에 산술 변환을 적용한 복잡한 비교, 손실·순서 변경 가능성이 있는 정수 변환, 불투명한 비교자는 근거가 불충분하면 판정하지 않습니다.

## 순서 조건

두 연결 역할의 방향이 실제 동작으로 확인돼야 완전한 순서 후보가 됩니다. 필드 이름이 left/right라고 가정하지 않고, 각 역할에 `less` 또는 `greater`를 연결합니다.

- 조상의 모든 상한·하한을 내려 보내므로, 부모와는 맞지만 더 위 조상과 어긋나는 키도 찾습니다.
- 실제 동등 키 삽입은 해당 방향의 중복 허용 근거입니다. 조상에서 동등 키를 만나 이동한 뒤 아래에 삽입하는 경우도 같은 질의 저장소·값 전달을 확인하여 연결합니다. 이 근거는 나중의 삽입 시점부터 유효합니다.
- 삽입 경로의 조건이 동등 값을 허용하면 `allowed-by-insertion-rule`, 실제 동등 삽입까지 확인되면 `observed-allowed`입니다. 엄격 비교로 배제된 방향은 `excluded-by-insertion-rule`로 기록합니다. 한 분기 경로가 엄격하다는 이유만으로 같은 방향의 다른 동등 허용 경로를 무시하지 않습니다.
- 중복 정책을 모르는 상태에서 동등 키가 있으면 `incomplete`로 남깁니다.
- 값은 기록된 바이트로 복원하고 BigInt로 비교합니다. 큰 unsigned 키를 JavaScript Number로 반올림하지 않습니다.
- 키·링크·루트·수명이 바뀌면 시점별로 갱신합니다. 위반 후 복구도 기록하며, 일시적인 순환·공유 자식·불완전 관계에서는 완성된 BST 조건을 주장하지 않습니다.
- 구조 위반은 추론 경고입니다. C 런타임 ERROR를 만들지 않습니다.

## 출력 계약

`ordered-tree-candidate`는 `sourceStructureId`, `root`, 키 저장 위치, 실행 근거 `proofs`, 시점별 `states`를 가집니다. 새로운 메모리 객체나 물리 간선을 생성하지 않습니다.

`composition`은 적용 조건을, 상태별 `relation`은 원본 관계·역할·근거 시점을 연결합니다. `queryBSTOrder`의 선택적 `candidateId`는 특정 키 해석 후보에 질의를 고정합니다. 추천 표현의 조건 조회는 `queryStructureConditions`를 사용하여 선택된 후보에 한정합니다.

상태의 주요 값:

| 상태 | 뜻 |
|---|---|
| `satisfied-observed` | 확인된 구성원·규칙·키 값에서 순서 조건 성립 |
| `violated` | 조상 범위 위반 확인; 해당 노드·조상·역할·키 쓰기와 경로 기록 |
| `incomplete` | 방향·키·중복 정책·위상 또는 기록 범위가 부족 |
| `not-checkable` | 충돌·모호한 비교 규칙, 우선순위 근거 부족 또는 지원 범위 밖 |
| `ended` | 원래 루트/저장소 수명 종료 |

기본 한도는 후보별 상태 2,048개·근거 4,096개입니다. 생략 수와 한도를 기록하며, 한도 뒤에서 마지막 성공 상태를 현재 성공 상태로 재사용하지 않습니다.

## 복합 키

`bst-composite.mjs`는 값의 생산 경로와 그 값을 결정한 분기를 함께 읽습니다. 예를 들어 첫 성분이 작으면 `-1`, 크면 `1`을 반환하고 같은 경우에만 두 번째 성분을 비교하는 함수에서, 상수 반환도 앞 성분의 비교 근거를 보존합니다.

1. 각 비교 피연산자의 실제 READ를 구조체 필드 범위 또는 공동 인덱스 배열 범위에 연결합니다. 성분마다 자료형·크기·부호를 유지합니다.
2. 링크 이동/삽입을 지배한 분기와 비교 반환값의 제어 의존성을 합쳐, 성분별 `< / = / >`에 대한 경로 조건을 만듭니다.
3. 논리식의 AST와 실제 CALC 내부 관측을 연결합니다. 단락 평가에서 읽지 않은 항은 미관측 상태로 유지합니다. LLVM의 선택된 임시 상수를 모든 가상 비교 결과에 일반화하지 않습니다. 원본 C 텍스트를 다시 파싱하지 않습니다.
4. 관측 경로들이 하나의 사전식 비교 순서와 맞는지 확인합니다. 앞 성분이 다른 경우 뒤 성분에 무관하게 방향이 정해지고, 같은 경우 다음 성분으로 넘어간다는 근거가 필요합니다. 선언 순서·필드명·수치의 유사성으로 우선순위를 정하지 않습니다.
5. 성분별 오름차순/내림차순과 전체 동등 조건으로 모든 조상 경계를 검사합니다. 전체 키가 같아야 중복 키입니다. 캐시 등 비교에 참여하지 않은 필드는 키에 추가하지 않습니다.

`if`/조기 반환, 중첩 `if`, 삼항식, 단락 논리식, 비교 보조 함수의 인자·반환 전달을 같은 규칙으로 처리합니다. 두 성분에 고정하지 않으며, 분리 배열과 구조체 저장소도 같은 키 성분 표현을 사용합니다.

복합 후보의 `key.kind`는 `composite`, `key.components`는 각 성분의 저장 위치·자료형 목록입니다. **목록의 저장 순서가 비교 우선순위는 아닙니다.** 시점별 `state.keyOrder`의 `{index, direction}`이 우선순위와 방향을 나타냅니다. `direction`은 `1` 또는 `-1`입니다. 노드의 `components`는 각 값·범위·관측 사건을, 위반의 `componentIndex`는 결론을 결정한 성분을 가리킵니다. 완전히 같은 키의 엄격 경계 위반에서는 `componentIndex:null`입니다.

비교 증명에는 `componentReads`, `guardExecutionIds`, 기호 경로 조건 `predicate`를 기록합니다. 새로운 READ/CALC 사건이나 사용자 비교 함수 실행은 만들지 않습니다. 기존 트리의 구성원·간선·수명을 그대로 사용하며 값 또는 연결 변경 시 경계를 다시 검사합니다. 비교 근거가 바뀌지 않은 값 갱신에서는 우선순위 분석 결과를 재사용합니다.

`bst-key-order.mjs`는 축약된 3분기 결정 그래프를 사용합니다. 성분 N개에 대한 `3^N` 표를 펼치지 않으며, 기본 그래프 한도 8,192개를 넘으면 판정 불가로 남깁니다. 성분 간 우선순위가 유일하지 않거나 서로 독립적인 조건을 단순 AND한 경우도 BST로 강제하지 않습니다. 같은 앞 성분끼리만 비교한 실행은 그 앞 성분의 방향을 입증하지 못할 수 있습니다. 미래 실행의 비교를 과거 시점의 근거로 사용하지 않습니다.

`bst-contract.mjs`는 원본 트리와 구성원·간선이 같은지, READ/분기/전달 근거의 순서와 저장 위치, 위반 경로와 비교 값이 일치하는지 독립 검사합니다. 추론 실패는 생성 모델의 결과를 수정하지 않습니다.

## 추천·사용자 지정

완성된 현재 조건이 성립할 때 상위 5개 추천에 BST를 제안합니다. 현재 위반이 확인되면 자동 BST 추천은 제외하지만 원래 트리 보기와 후보의 위반 이력을 유지합니다.

```js
const check = queryBSTOrder(trace, {target, afterExecutionId});
// assessment: satisfied-observed | contradicted | incomplete | not-checkable
// candidates: 검사한 키/후보/상태, warnings: 구조 조건 위반
```

대상 객체·저장 범위 또는 기존 트리의 structureId로 조회할 수 있습니다. 정확한 루트의 후보가 있으면 다른 부분 트리 후보의 검사를 대신 사용하지 않습니다.

추천도 같은 선택 범위를 사용합니다. 전체 루트가 위반인데 일부 정상인 자식 트리만 골라 전체 대상의 BST 추천으로 대신하지 않습니다. 그 자식 루트를 직접 선택하면 해당 부분 트리를 따로 검사할 수 있습니다.

사용자가 BST를 지정하면 기본 기대 조건은 `bst-order`이며, `resolveStructurePresentation`의 `expectationCheck`로 결과를 받습니다. 위반이 발생해도 사용자 지정은 유지합니다. 일반 트리로 지정하면 BST 조건을 상속하지 않으며 `expected:null`로 검사를 끌 수 있습니다. UI는 구현하지 않았습니다.

## 미지원 범위

부동소수점·문자열의 정렬 의미, 키 자체의 임의 산술 변환, 불투명한 사용자 비교자 및 순서 변경 형변환은 별도 보강 대상입니다. 정수 복합 키라도 비교 경로 또는 실제 저장소 연결의 근거가 부족하면 판정하지 않습니다. 관측된 BST 조건은 사용자의 의도나 모든 가능한 입력에 대한 증명이 아닙니다.

기본 구현 이력은 [기본 검사 기록](../validation/bst-basic-inference-2026-11-11.md), 복합 키의 최신 결과는 [복합 키 검사 기록](../validation/bst-composite-inference-2026-11-11.md)을 참고하십시오.
