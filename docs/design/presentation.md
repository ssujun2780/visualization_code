## 기록 상태

제품 변경 전에는 [프로젝트 작업 규칙](../../AGENTS.md)에 따라 관련 설계를 읽고 적용 조항을 확인합니다. 구현 후에는 [설계 대응표](../validation/design-implementation-template.md)로 조항·변경 위치·검증 근거를 연결합니다. 절차 문서이며 자동 준수 검사를 구현한 것은 아닙니다.

- **구현:** 현재 시제품에 연결한 기능입니다. 모든 C 코드의 완전한 지원을 뜻하지 않습니다.
- **설계 확정·미구현:** 대화에서 합의했지만 아직 화면에 적용하지 않은 내용입니다.
- **후속 검토:** 구체적인 연출·조작을 아직 확정하지 않은 항목입니다.

접힌 함수 설계도 목록, 설계도 작성·연결 과정의 컴파일·링크 오류 연출은 설계 확정·미구현입니다. 2026-11-11에 실행 전 빌드 오류 안내와, 런타임 ERROR에서 메시지·코드 강조 후 정지하는 임시 공통 처리를 연결했습니다. 종류별 오류 연출과 전체 통합 확인은 남아 있습니다.

실행 관계 추론기는 독립 API·Worker·CLI와 현재 작업 조회를 제공합니다. 2026-11-12에는 기존 컴파일 근거·구조 대응의 자동 연결과 [현재 작업 연결 보기](work-context-view.md)를 추가했습니다. 원본 공간을 유지하며 현재 접근 구간·원소·연산을 함께 표시합니다. 알고리즘 의도/정확성 판정·일반 자동 배치는 미구현입니다. [초기 공통 규칙](../validation/execution-relations-rules.md), [v2](execution-relations-v2.md), [화면 연결 검증](../validation/work-context-view.md)의 범위를 구분해 확인합니다.

오류 처리 대상은 컴파일·링크·런타임 오류 세 가지입니다. 컴파일·링크는 실제 빌드 실패, 런타임은 실제 실행의 치명적 강제 중단을 기준으로 합니다. 빌드가 성공한 경고·정상 실패 반환·논리 오류를 이 오류 연출에 넣지 않습니다. 논리 오류는 사용자가 기존 실행 시각화로 찾아내는 관찰 대상입니다.

런타임 오류 연출은 실제 프로그램 실행이 치명적인 오류로 강제 중단된 경우에 한정합니다. 경고·정상 실패 반환·중단되지 않은 정의되지 않은 동작을 이 대상으로 자동 승격하지 않습니다.

## 모델·추론과의 경계

실제 실행 정책·명령 정의·관찰·반환 수신 계약은 [실행 관찰과 중간언어 연결](execution-visualization.md), [공통 C 모델](c-model.md), [평가 순서](evaluation-order.md), [반환 계약](return-sequence.md)이 담당합니다. 자료구조 후보·사용자 지정 API는 [자료구조 표현 정책](structure-presentation-policy.md)이 담당합니다.

화면은 이 정보의 소비자입니다. 화면 규칙을 맞추기 위해 C를 추가 실행하거나, 값을 추측하거나, 명령을 새로 만들고 재정렬하지 않습니다. 필요한 근거가 없으면 부족한 정보를 모델 측 보완 사항으로 남깁니다. 이 문서 분리 작업은 실행 코드·중간언어 생성 모델·추론기를 변경하지 않습니다.
