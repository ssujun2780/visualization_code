# 연관 조회와 해시 후보

추론 전용 계약입니다. 중간언어 사건·값·수명은 변경하지 않습니다. 구조 조합 RC-01~03과 사용자 지정 우선·추천 최대 5개 정책을 따릅니다.

| 조항 | 공통 규칙 |
| --- | --- |
| HASH-01 | 실제 검색 키의 값 전달 → 버킷 주소 의존 → 저장 키 동등 비교를 연결합니다. 이름, `%` 유무, 같은 숫자만으로 해시라고 결정하지 않습니다. 사용자 해시 함수의 반환과 비트 마스크도 값 전달로 확인합니다. |
| HASH-02 | 같은 항목의 반환/삽입 값 역할을 연결합니다. 버킷 머리를 복사한 연결 필드는 값 역할에서 제외합니다. 결과는 `associative-lookup-candidate`, 의도는 `unconfirmed`입니다. |
| HASH-03 | 실제 키 비교를 허용하는 상태, 검색 종료 상태, 건너뛰는 상태와 재사용을 분리합니다. 점유했던 슬롯에서 상태가 바뀌고 탐사를 계속한 관측은 삭제 슬롯 후보입니다. 숫자 0/1/2에 의미를 고정하지 않습니다. |
| HASH-04 | 정수 연결의 실제 순회로 필드 역할을 배운 뒤, 동일 필드의 기록된 쓰기와 실제 구성원 접근으로 연결을 보충합니다. 다른 버킷 루트도 기록 인덱스와 루트 쓰기의 동일 출처가 있어야 합니다. 예약 용량 전체는 구성원이 아닙니다. |
| HASH-05 | 종료 표지는 해당 인덱스의 실제 순회를 제어하는 비교에서 얻습니다. `p != sentinel`의 참 분기 아래 인덱스 접근이 관측되면 반대 조건을 종료 경계로 사용할 수 있습니다. 관측되지 않은 경로를 실행한 것으로 기록하지 않습니다. |
| HASH-06 | 분리 배열은 검색 키 비교·같은 인덱스 삽입·반환과 상태 조건으로 역할을 결합합니다. 이전 키/값 READ가 호출을 통해 새 WRITE에 전달될 때만 항목 이동을 연결합니다. 같은 값이라는 이유로 합치지 않습니다. |
| HASH-07 | 발견 시점 이후만 추천합니다. `queryAssociativeLookup`은 해당 시점까지의 상태·조회·탐사·충돌·전달만 반환합니다. 종료된 저장소를 활성 후보로 추천하지 않습니다. |

구현: `scripts/inference/associative-views.mjs`, 별도 근거 검사 `associative-contract.mjs`. 기존 연결/배열 후보는 유지하며 연관 조회 의미를 추가합니다. `hash-table` 추천은 부분 근거 후보로 표시하고 사용자 지정을 덮어쓰지 않습니다.

2026-11-12: 상태 한도에서 앞부분과 최신 상태를 보관하며 생략 구간은 RC-07의 공통 이력 계약을 사용합니다. `queryAssociativeLookup`은 복사된 결과와 `historyGap`을 반환합니다. 생략된 중간 구간에서는 이전 상태를 `incomplete`로 표시하고 해시 추천 근거로 사용하지 않습니다. 보관된 최신 상태는 기존 생략 때문에 무조건 불완전해지지 않습니다. 실제 시점이 확인된 조회·탐사·전달 근거는 별도 시간 필터를 그대로 사용합니다.

한계: 현재 키 발견은 관측된 정수 동등 비교 중심입니다. 문자열/복합 키의 사용자 비교기, 검색이 한 번도 실행되지 않은 구조, 삭제 후 모든 상태 전이, 임의의 여러 프레임에 분산된 삽입은 완전 지원으로 주장하지 않습니다. 탐사 기록과 항목 전달은 실제 관측이고, 해시 함수의 품질·사용자 의도·재해시라는 알고리즘 이름은 확정하지 않습니다.
