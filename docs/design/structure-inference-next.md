# 자료구조 추론: 저장 형태 비교와 다음 보강

**2026-11-09 갱신:** 아래는 11월 6일 조사 당시 기록입니다. 길이 미확정·루트·재귀 인덱스·역할별 관계와 여러 저장소의 관측 근거를 공통 모델에 보강했습니다. 최신 분리 배열·종료값·추천 구현은 [저장 관계 기반 추론 보강](structure-inference-relations-2026-11-09.md), 그 이전 보강은 [중간언어·자료구조 보강](structure-ir-refinement-2026-11-09.md)을 따릅니다. 아래 미구현 서술은 당시 상태입니다.

2026-11-06. 버퍼 작성자 추적의 쓰기 폭 제한을 제거한 뒤, 자료구조 추론을 같은 논리 구조의 여러 구현으로 비교했습니다. 이번 단계에서는 추론 알고리즘과 UI·애니메이션을 변경하지 않았습니다. 아래의 다음 보강은 설계이며 구현 완료 항목이 아닙니다.

## 실행 결과와 추론 결과

정상 C 예제 9개에 대해 예상 출력·논리 구조를 먼저 `predictions.json`에 저장하고 API를 실행했습니다. 9개 모두 예상 출력과 정상 종료가 일치했고, 공개 사건 2,436개에서 IR gap은 없었습니다. 구조 추론의 일치는 별도로 평가했습니다.

| 구현 형태 | 현재 확인된 표현 |
| --- | --- |
| 연속 구조체 배열의 포인터 트리 | 노드 5개·자식 간선 4개의 트리 후보 |
| 이름 변경·필드 순서 변경 | 기존 트리와 같은 구조 이력 |
| 레코드의 정수 자식 인덱스 | 노드·인덱스 관계 후보는 있으나 활성 길이 미확정 때문에 정상 목적지 4개가 inactive-target으로 분류됨 |
| 값·왼쪽·오른쪽을 별도 배열에 저장 | 두 개의 인덱스 그래프 후보. 하나의 논리 트리로 결합되지 않음 |
| 재귀 인자로 `2*i+1`, `2*i+2`를 전달 | 일반 배열·접근 관계까지만 생성. index-tree 후보 없음 |
| 비슷한 숫자·같은 길이의 무관한 배열 | 배열 보기만 유지. 그래프 오인식 없음 |
| 잠시 순환을 만들었다 복원한 포인터 트리 | 순환 상태와 복원된 트리 상태가 모두 남음 |
| 노드별 별도 동적 할당 | 5개 노드를 연결한 트리 후보. 별칭 루트 후보도 별도로 존재 |
| 부모 포인터가 추가된 트리 | 자식 관계의 트리 후보 유지. linked 후보의 부모 보조 역할은 미연결이며 실제 포인터 기록은 존재 |

분리 배열의 `-1`은 접근 전에 `i < 0`으로 종료하지만, 현재 인덱스 그래프의 끝 값은 out-of-bounds로 남습니다. 이는 해당 코드가 잘못된 메모리를 읽었다는 뜻이 아닙니다. 중간언어에는 정상 조기 반환이 기록됐고, 추론이 그 종료 근거를 연결하지 못한 것입니다.

## 우선순위 1: 경계와 상태의 의미

`record-index-views.mjs`는 일반 배열의 논리 길이를 null로 두면서 목적지 판단에서 길이가 확인되지 않은 경우까지 inactive-target으로 분류합니다. 다음 보강은 **물리 범위 안**, **실제로 사용을 관찰함**, **논리 활성 범위를 모름**, **확인된 비활성 범위**를 구분해야 합니다. 용량 전체를 자동으로 논리 노드로 확정해서 해결하지 않습니다.

정수 종료값도 단순히 -1이나 0이라는 숫자로 인식하지 않습니다. 실제 비교, 선택한 분기, 접근 전에 종료한 호출/반복의 관계가 근거입니다. 같은 값이 다른 경로에서는 실제 인덱스로 사용될 수 있으므로 종료 규약의 범위와 실행 시점을 유지합니다. 근거가 없으면 미확정으로 남기며 추론 경고를 C 런타임 ERROR로 바꾸지 않습니다.

## 우선순위 2: 호출을 통과하는 인덱스 관계

`index-relations.mjs`의 정적 인덱스 의존성은 선언 초기화·대입을 따라가지만, 위 재귀 사례에서는 자식 산식이 매개변수로 전달되는 연결이 빠집니다. 실제 호출의 인자 슬롯 → 매개변수 → 해당 호출 프레임의 배열 접근을 연결해야 합니다. 재귀 깊이·호출별 실제 저장소와 인덱스를 구분하고, 같은 변수명이나 같은 숫자라는 이유로 연결하지 않습니다.

연결된 산식은 배열 기반 트리 표현의 후보입니다. `2*i+1`이 등장했다는 이유만으로 최소 힙·최대 힙·알고리즘 이름을 확정하지 않습니다. 기존 계산을 재실행하거나 추가 CALC를 만들지 않습니다.

## 우선순위 3: 여러 저장소의 공통 논리 노드

기존 value-index 후보는 개별 배열 안의 값→인덱스 관계를 보존합니다. 다음 단계는 여러 저장소를 같은 논리 인덱스 영역으로 묶을 근거입니다. 공통 호출 슬롯·커서의 실제 전달, 같은 논리 인덱스로 접근한 값·링크의 역할, 역할별 목적지 관계를 사용합니다. 길이·초깃값·이름의 유사성만으로 묶지 않습니다.

논리 노드는 여러 `objectId + offset + size`에 대응할 수 있어야 합니다. 왼쪽·오른쪽 링크, 부모 링크, 별도 값 배열을 합치더라도 실제 저장소와 원래 관계는 보존합니다. 동일 대상의 배열 보기와 트리 보기는 동시에 존재할 수 있습니다. 보조 부모 역할도 원래 포인터 기록에서 연결하며 실제 간선을 지우지 않습니다.

## 사용자 지정과 UI 연결 경계

자동 후보·관측 사실·사용자 지정·기대 조건 검사는 기존 [자료구조 표현 설계](structure-view-validation.md#사용자-지정과-기대-조건-검사-2026-11-04-설계)를 따릅니다. 사용자 지정 UI/저장 API는 아직 구현되지 않았습니다.

UI는 후보가 틀리거나 부분적이어도 원래 상자·배열·포인터와 코드 위치를 보여줄 수 있어야 합니다. 사용자 선택이 자동 추천보다 우선하되 원래 후보와 근거를 유지합니다. 사용자 정의 구조의 역할·기대 규칙이 연결되지 않으면 검사 불가로 남기며, 이름만으로 구현의 결함을 판정하지 않습니다.

이 보강은 기존 중간언어 위의 관계 메타데이터입니다. READ·WRITE·CALC·FLOW·SPACE의 실행 사실과 순서는 유지하며 애니메이션 도구·동작·배치를 새로 정하지 않습니다.
