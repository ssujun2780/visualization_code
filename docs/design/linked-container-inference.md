# 연결 리스트 계열 공통 추론 보완

2026-11-10. 추론은 확정된 plan/trace를 읽는 시각화 부가 계층입니다. 이 변경은 중간언어 생성·실행 순서·값·수명·애니메이션·UI를 수정하지 않습니다.

## 공통 규칙

1. **현재까지 관측한 역할만 추천의 근거로 사용합니다.** `linked-structure.states[].observedRoleIds`로 시점별 실제 링크 필드 읽기를 기록합니다. 미호출 순회 함수의 AST만으로 목록/트리 추천을 승격하지 않습니다. 정적 후보와 물리적 그래프는 유지합니다. 여기서 `supported`는 관측된 구조에 대한 추천이며 작성 의도나 전체 알고리즘의 증명이 아닙니다.
2. **시작 변수는 정확한 부분 객체 범위로 조회합니다.** 포인터 배열/구조체의 슬롯 크기는 관측된 컴파일러 포인터 자료형에서 얻습니다. 소유 배열의 전체 크기로 슬롯을 넓히지 않습니다. 선택한 슬롯과 일치하는 시작점의 후보를 먼저 둡니다.
3. **미확인은 NULL이 아닙니다.** 저장소 참조 그래프의 역할별 투영에서도 해당 레코드에 필요한 링크가 미관측이면 `partial`입니다. 다른 추천 경로가 이를 완전한 목록이나 트리로 승격하지 않습니다.
4. **물리적 노드와 데이터 구성원을 구분합니다.** 연결 상태의 `membership.physicalNodeIds`, `boundaryNodeIds`, `dataNodeIds`가 각각 물리적 도달 노드·경계 노드·데이터 노드를 나타냅니다. 더미 노드는 메모리·원래 topology에 남기고, 추천의 `representedNodeCount`는 논리적 데이터 개수로 계산합니다. 더미만 남은 목록은 데이터 0개입니다.
5. **원형 목록도 연결 리스트의 한 표현입니다.** 관측이 완전하고 현재 시작점에서 도달하는 하나의 단순 고리는 `linked-list`, `variant: circular`로 추천합니다. 시작 데이터 노드를 더미로 제외하지 않습니다. 꼬리가 고리에 진입하거나 분기·공유·미확인 관계가 있는 그래프는 같은 근거로 단정하지 않습니다. 비순환 `chain` 기대 조건을 원형 후보에 붙이지 않습니다.
6. **정수 인덱스도 실제 시작 변수와 연결합니다.** 기존 레코드·분리 배열·표 형태의 관계 간선 위에 `rooted-index-structure`를 추가합니다. AST의 실제 인덱스 피연산자와 값 전달 기록이 특정 정수 슬롯에서 해당 배열 영역으로 이어져야 합니다. 이름·같은 숫자·같은 크기만으로 연결하지 않습니다.
7. **삽입/제거 정책은 노드 식별 순서로 확인합니다.** `endpointOperations` 및 상태별 `endpointPolicies`에 관측된 양끝 편집을 기록합니다. 삽입과 제거를 모두 관측하고 방향을 구분할 근거가 있을 때 FIFO는 queue, LIFO는 stack, 양끝 조작은 deque 후보가 됩니다. 한 원소만 넣었다 빼는 경우는 FIFO/LIFO를 구분하지 않습니다. 대량 교체·재배열·미확인 연결·기록 공백은 이전 동작 근거를 끊습니다. 근거 범위는 `observed-episode`이며 프로그램 전체 실행에 대한 보장이 아닙니다.

## 인덱스 시작점별 보기

`indexed-root-views.mjs`는 이미 추론된 관계를 읽고 현재 시작 인덱스에서 도달하는 순서만 별도로 제공합니다. 전역 그래프를 변경하지 않습니다.

```c
links[6] = 2;
links[2] = 5;
int head = 6;  /* 6 → 2 → 5 */
links[6] = 5;  /* 현재 head 목록은 6 → 5 */
```

현재 목록에서 빠진 `2 → 5`는 실제 저장소에 남아 있으므로 전역 간선에서 삭제하지 않습니다. 사용 목록과 빈 슬롯 목록이 같은 저장소를 사용해도 각 시작 변수에 별도 후보가 있습니다.

주요 메타데이터:

| 항목 | 의미 |
|---|---|
| `root: {kind: index-slot, objectId, offset, size}` | 실제 정수 시작 슬롯 |
| `rootEvidence` | 시작값 읽기, 실제 인덱스 피연산자, 대상 접근의 실행 식별자 |
| `relationStructureId` / `roleIds` | 재사용하는 기존 관계 후보·링크 역할 |
| `states[].orders` | 현재 노드 식별자·인덱스 순서·종료 상태 |
| `rootAlive` / `storageAlive` | 시작 변수와 기반 저장소의 수명 |
| `coverage` / `historyGap` | 상태·시작점 수 제한과 생략 여부 |

시작값은 직접 대입뿐 아니라 실제 기록된 바이트 복사도 반영합니다. 종료 표지는 기존 순회 조건에서 관측한 경계만 사용합니다. 자기 인덱스를 가리키는 대표 노드를 빈 목록 표지로 바꾸지 않습니다. 미관측 링크와 제한에 의해 빠진 정보는 완전한 목록의 근거가 되지 않습니다.

## 추천 메뉴와 사용자 지정

상위 5개는 향후 우클릭 메뉴에 제공할 추천입니다. 서로 다른 표현을 최대 5개로 제한하고, 같은 표현의 다른 후보/역할은 `alternatives`에 보존합니다. 후보가 적으면 억지로 채우지 않습니다. 사용자 지정 우선과 `intent: unconfirmed`는 유지합니다. 이번에는 메뉴·화면 배치·애니메이션을 구현하지 않았습니다.

정렬 정책은 `exact-root-node-coverage-behavior-strength-stable-id-v4`입니다. 선택한 시작점, 노드 누락 여부, 증거 강도, 서로 다른 명령 위치, 안정적인 식별자 순으로 정렬합니다.

## 구현과 검증 범위

- `structure-presentation.mjs`, `structure-storage.mjs`: 공통 추천·범위·완전성 처리
- `linked-views.mjs`: 시점별 관측 역할과 물리/논리 구성원
- `indexed-root-views.mjs`: 기존 인덱스 관계에 대한 시작점별 보기
- `linked-container-policy.mjs`: 노드 식별 순서에 따른 동작 정책
- `structure-inference.mjs`, `structure-overlay-contract.mjs`: 읽기 전용 추론 단계 연결과 근거/범위 검증
- `tests/ir-linked-inference-policy.test.js`: 7개 보완점과 관련 반례, 64비트 정수·부분 객체·바이트 복사·사용자 지정 확인
