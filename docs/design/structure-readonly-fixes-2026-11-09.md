# 추론 계층 분리와 여덟 항목 보완

## 실행 모델과의 경계

자료구조 추론은 시각화를 위한 선택적 소비자입니다. AST·LLVM 연결, 중간언어 명령 생성, 계측값 기록, 실행 검증이 먼저 끝납니다. 추론 결과를 이 과정에 다시 입력하지 않습니다.

`buildIRPlan`과 `recordIR`에서 추론 호출을 제거했습니다. `structure-inference.mjs`는 확정된 계획·실행 기록의 **별도 복사본**을 읽기 전용으로 사용하고, 자체 `structureBindings`와 후보·추천 메타데이터를 생성합니다. 호출자의 객체를 동결하거나 수정하지도 않습니다.

- `events`, 값, 명령 ID, 호출·반환 순서, 객체·프레임 수명, 종료 상태는 추론기가 변경할 수 없습니다.
- `inference.status`, `inference.diagnostics`는 실행 상태·진단과 별도입니다. 후보 검증 실패는 해당 추론 단계와 종속 후보만 제외합니다. 실행에 ERROR를 삽입하지 않습니다.
- 작업자는 추론 시작 전에 완성된 실행 기록을 전달합니다. 그 이후의 추론 시간 초과·작업자 실패에서도 완료된 실행을 보존합니다. 제한 시간 내 부분 실행을 복구할 때에는 추론을 실행하지 않습니다.
- 기존 소비자와의 호환을 위해 **새 응답 객체**의 `trace.structures`와 `plan.structureBindings`에도 메타데이터를 제공합니다. 이는 원본 실행 모델의 수정이나 다음 실행의 입력이 아닙니다.

```js
const execution = await traceModel(source, {inference: false});
// execution.trace.structures는 빈 배열이고, 핵심 실행 기록은 완성되어 있습니다.
const metadata = inferStructures(execution.plan, execution.trace);
// metadata만 시각화에 전달할 수도 있습니다.
```

별도 추론 호출에 원시 관찰이 없다면 원시 관찰에만 있는 일부 런타임 배열 설명과 과거 연결 요약은 생략될 수 있습니다. 기본 `traceModel` 호출은 해당 관찰도 추론에 제공합니다.

## 여덟 항목

| 항목 | 공통 처리 |
| --- | --- |
| 1. 내부 별칭과 인덱스 좌표 | 기반 배열 범위에서 유효하지 않은 시작 인덱스 후보를 만들지 않습니다. 잘못된 추론 후보 때문에 정상 실행 전체가 `engine-error`로 바뀌지 않습니다. |
| 2. 병렬 배열의 시작점 변경 | 실제 같은 인덱스 출처로 읽은 두 끝점 슬롯을 함께 연결합니다. 어느 쪽이든 변경되면 기존 간선을 미확인 상태로 만들고, 다시 관측한 관계만 활성화합니다. |
| 3. 주소 비교의 종료 오인 | 주소 비교만으로 실노드를 숨기지 않습니다. 관측된 루프 종료·반환·break와 같은 주소의 대응이 있어야 경계로 취급합니다. 실제 payload를 읽은 순환 목록의 시작 노드는 보존합니다. |
| 4. 임시변수·함수·논리 가드 | 값의 동일성을 보존하는 전달과 계산 의존성을 구분합니다. 계산 피연산자의 정확한 관찰 ID를 따라 임시변수·인자·반환을 연결하되, 배열 원소의 과거 계산까지 섞지 않습니다. `if(next)`, `next!=0`, `!next`, continue 형태도 저장 버전과 실제 순회 근거로 연결합니다. |
| 5. 여러 WRITE로 된 큐 갱신 | 커서 증가와 경계에서 0으로 되감는 두 갱신을 한 작업의 증거로 연결합니다. 포인터 커서는 관측 객체·바이트 오프셋·원소 크기로 좌표를 얻습니다. 중간 WRITE·CALC를 삭제하거나 합치지 않습니다. |
| 6. 계산된 링크 | 재귀 호출의 실제 전달과 주소 접근, 레코드 범위 또는 같은 인덱스 출처를 연결합니다. 상대 원소 오프셋·바이트 오프셋의 원래 값과 계산·대상 범위를 보존하며, 저장값을 직접 인덱스라고 바꾸지 않습니다. |
| 7. 순회·행렬 그래프 | 인접 범위표의 하한/상한, 이를 사용하는 실제 루프, 목적 정점 접근으로 압축 저장의 관계를 연결합니다. 행렬은 비교에 사용한 두 정점과 각 축의 같은 커서 버전을 확인합니다. 존재 표시와 0인 속성값을 구별합니다. |
| 8. 근거 저장소의 수명 | 끝점·루트·범위표가 바뀌거나 종료되면 관계 상태를 갱신합니다. 속성 배열만 종료되면 속성에 `ended-source`를 표시하고 과거 값과 살아 있는 연결 관계를 구별합니다. |

`observed-traversal-graph-candidate`는 위 6·7의 관측 근거를 담는 시각화 메타데이터이며 새 실행 명령이 아닙니다. 반복 갱신·관계 변경도 시간별 상태로 남깁니다. 후보의 근거는 이름·예제 번호·정답이 아니라 컴파일러 식별자와 실제 실행 의존성입니다.

추론은 여전히 후보입니다. 방문하지 않은 링크, 다른 구현 형태, 모든 사용자 의도를 확정하지 않습니다. 특히 계산된 링크의 이번 확장은 실제 재귀 전달·주소 사용이 확인되는 경우에 집중했습니다. 사용자 지정 우선 규칙과 상위 다섯 추천 계약은 유지합니다.

## 검증

- `tests/ir-inference-readonly-regressions.test.js`: 추론 비활성화/별도 실행, 입력 불변성, 잘못된 선택적 메타데이터의 실패 격리, 주소 표식과 종료 경계의 구별, 임시 링크 가드 네 형태, 큐 두 형태, 끝점 변경·속성 수명, 두 오프셋 표현, 압축/행렬 그래프, 숫자만 같은 반례.
- 관련 기존 검사: 공통 관계·수명, 루트 별칭, 순환 목록, 명시적 작업 스택, 표현 추천·사용자 지정. 전체 예제 모음은 재실행하지 않습니다.
- 이전 감사의 관련 원시 관찰을 재변환하여, 기존 정상 기록의 사건·객체·프레임·반환 전달을 JSON 기준으로 비교합니다. 이는 새로 C를 컴파일한 검사와 구별합니다.
- 결과 위치: `test-results/codex_code-results/structure-fixes-2026-11-09-readonly/`. 새 C 변형의 실제 API 검사는 `final-tests.txt`, 원시 관찰 재변환은 `replay.mjs`와 사례별 JSON에 보관합니다.

관련 추론·추천 검사 **48개 통과**. 후속 계층 분리 검사도 재확인했습니다. 이전 감사의 관련 사례 **36개**를 원시 관찰에서 재변환했고 모두 실행 완료·추론 진단 0건입니다. 이 중 이전에도 정상 기록이 있던 **29개, 사건 21,375개**는 사건·객체·프레임·반환 전달이 그대로였습니다. 이전 추론 검증 때문에 공개 결과가 `engine-error`였던 7개도 완료 기록을 반환합니다. 집계는 `verification-summary.json`에 있습니다.

추가 실행 실패·부분 복구 검사 4개 중 3개는 통과했습니다. 기존 `ir-partial-limits.test.js`의 바이트 한도 검사는 `phase: incomplete`인 WRITE에도 `value.decimal`을 요구하여 실패했습니다. 동일 관찰을 Git HEAD의 기존 `recordIR`로 변환해도 사건 전체와 해당 미완료 WRITE가 동일합니다(`limit-baseline-comparison.json`). 이 검사나 중간언어의 미완료 사건 처리는 이번 추론 수정으로 변경하지 않았습니다.

UI 및 캐릭터 애니메이션 구현은 이 변경에 포함하지 않습니다.
