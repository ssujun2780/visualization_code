## 결론과 근거 범위

문제는 CALC 하나에 국한되지 않았습니다. 계산 입력, 조건 선택 순서, 라이브러리 효과, 자동 객체 수명, 종료 시 프레임 소유권, 자료구조 상태 추론에 결함이 있었습니다. 일부 경로의 성공을 공통 모델 전체의 완료로 보고한 판단도 잘못됐습니다. 이번 수정은 기존 모델을 유지하며 확인한 공통 경로를 보완합니다.

프로덕션 scripts/model에서 NoN 예제 번호, 13277, regex_equivalence, expectedStdout/expectedOutput를 기준으로 결과를 맞추는 분기는 정적 검색에서 발견하지 못했습니다. 이는 과적합 가능성이 전혀 없다는 증거가 아닙니다. 실제로 좁은 전제에 의존한 규칙과 빈 입력도 통과하던 검사가 확인됐습니다.

## 검증 방식

- 모든 예제를 다시 실행하지 않았습니다. 변경된 경로의 독립 회귀 검사와 No29만 실행했습니다. 기존 테스트에 포함된 No7·No28 검사는 해당 수명·assert 경로 확인에 한정했습니다.
- No29는 기존 예측 파일과 소스 해시를 고정하고 API 실행 전 엔진 해시를 기록했습니다. stdout뿐 아니라 54개 과정 조건과 16개 수정 조건을 확인했습니다.
- 과정 조건에는 72개 호출 프레임, 노드 7개 할당·해제 순서, 실제 임시 구조체 7개의 수명, 키 복사 후 객체 동일성, 포인터 해제 전 연결 변경, 조건 생략, 출력 순서가 포함됩니다.
- 별도 입력으로 이름이 겹치는 사용자 함수, VLA 탈출, 직접·상호 재귀, 필드 순서 변경, 순환·공유 자식·불완전 연결, 부분 바이트 변경을 확인했습니다.
- 정상 기록에서 입력값·출력 바이트·복사 범위·객체·분기 근거를 일부러 지우거나 바꿔 공통 계약이 거부하는지도 검사합니다. 일부 입력을 지운 뒤 dataInputs/steps까지 함께 지우는 경우도 포함합니다.
- 저장된 과거 기록의 재검사·구조 재투영은 C 재실행이 아닙니다. 오래된 산출물의 결함을 현재 코드의 결함으로 그대로 합산하지 않았습니다.

실행 로그와 해시·과정 비교는 test-results/audit-*.txt, test-results/no29-audit-fixed-2026-11-04 및 test-results/no29-audit-verified-2026-11-04에 보존합니다. 최초 통합 검사에서 드러난 실패 로그도 삭제하지 않습니다.

## 남은 범위

검사 통과는 기록한 사실의 일관성을 뜻합니다. 처음부터 관찰하지 않은 동작까지 완전하게 구현했다는 보증이 아닙니다. coverage의 irGaps가 비어 있어도 unboundSourceWork, 변환별 unobserved 및 개별 지원 범위를 함께 봐야 합니다.

No29에서 현재 연결의 이진 트리 후보는 만들지만 BST 키 역할과 전체 서브트리의 대소 관계 검증은 아직 없습니다. ordering.status는 unknown입니다. 간접 호출을 통한 재귀 관계·반환 별칭·부모/자식의 의미 구분·임의 인덱스 그래프도 자동으로 확정하지 않습니다.

사용자 정의 할당기의 완전한 수명 계약, 외부 함수 포인터·스트림의 모든 의미 연결, 모든 라이브러리 미초기화 전파와 C 미정의 동작 검사는 미완성입니다. 비지역 점프 및 모든 컴파일러 확장도 지원 완료로 보고하지 않습니다. 애니메이션과 재생 UI는 여전히 이번 작업 범위 밖입니다.
