# 중간언어 과정과 자료구조 관계 보강

후속 반영: 추천 상위 5개와 사용자 지정 우선·고정·자동 복귀 API는 [자료구조 표현 정책](structure-presentation-policy.md)에 정리했습니다. UI는 포함하지 않습니다.

그 이후 추가 감사에서 확인한 보존용 비트필드 READ, 익명 레코드, 센티널 루트, VLA, 분리된 카운터 및 과도한 추천의 수정은 [후속 공통 모델 보완](structure-followup-fixes-2026-11-09.md)을 따릅니다. 아래 내용은 최초 보강 기록입니다.

2026-11-08 조사에서 확인한 문제를 2026-11-09 공통 모델에 반영했습니다. 예제 번호·변수 이름·예상 출력은 모델의 분기 조건으로 사용하지 않습니다. AST의 식·선언·필드 식별자와 실제 관측된 값·주소·호출·수명을 사용합니다. 원본 C 식을 다시 실행하거나 의미 분석을 위해 소스 문자열을 재검색하지 않습니다.

## 중간언어 과정

| 조사 항목 | 반영 내용 |
|---|---|
| I01: 접힌 상수식의 중간 단계가 잘못 표시됨 | `sizeof *p + 3*sizeof(N*)`처럼 컴파일러가 접은 식은 하나의 CALC를 유지합니다. `foldedExpression`에 전체 AST, 입력 근거, 결과, `intermediateValues: not-observed`를 기록합니다. 단일 step은 `kind: folded-expression`, `operator: expression`입니다. 관측하지 않은 곱셈 중간값을 만들어 넣지 않습니다. |
| I02: 형변환에 `*`, `?:`가 표시됨 | 단독 변환 CALC의 연산자는 `cast`로 기록합니다. 원래 피연산자 식, 입력/출력 자료형과 실제 값은 유지합니다. |
| I03: 포인터 배열의 암묵적 0 초기화 루프가 노출됨 | InitListExpr 안의 소스 연산 소유자가 없는 포인터 비교와 그 SSA 결과를 쓰는 분기만 내부 관측으로 처리합니다. 실제 NULL 쓰기, 사용자가 작성한 비교·호출·분기는 보존합니다. LLVM 블록 이름으로 숨기지 않습니다. |
| I04: offsetof 주소식이 여러 CALC로 분리됨 | 컴파일러가 해석한 OffsetOfExpr를 계산 묶음의 피연산자로 허용합니다. 바깥 캐스트·주소 차감은 같은 순수 소스 식이면 한 CALC가 됩니다. 호출·부작용 경계는 그대로 유지합니다. |
| 초기값 없는 전역변수의 실행 차단 | 단일 번역 단위 컴파일에 `-fno-common`을 적용했습니다. C의 0 초기화를 유지하면서 내장 WASM 백엔드의 `common global` 생성 실패 경로를 피합니다. 원본에 초기값을 삽입하지 않습니다. |

기존 다섯 종류 READ·WRITE·CALC·FLOW·SPACE는 그대로입니다. 애니메이션 구현은 변경하지 않았습니다.

## 추론 후보의 의미 수정

- 길이 미확정은 비활성이 아닙니다. 레코드 인덱스 간선에 `physicalBounds`와 `activeMembership`을 별도로 기록합니다. 실제 목적지를 관측했다면 연결을 보존하며, 용량 전체를 활성 노드로 만들지 않습니다.
- 종료 비교만으로 데이터 노드를 더미 센티널로 제외하지 않습니다. 해당 노드의 스칼라 멤버 READ가 관측되면 더미 제외 판정을 해제합니다. 이는 관측된 데이터 소비를 보존하는 보수적 규칙이며, 모든 센티널의 의미를 확정하는 판별기는 아닙니다.
- 순회 함수에 직접 전달한 배열 decay·객체 주소도 루트의 근거입니다. 별도 root 포인터 변수가 필수 조건이 아닙니다. 실제 매개변수 객체와 호출 식별자를 연결합니다.
- 같은 레코드 계열의 참조 필드는 전체 저장소 관계에 남깁니다. `roles`는 저장소 역할, `traversalRoles`는 읽으며 순회한 역할입니다. 역할별 `roleTopologies`와 전체 `storageTopology`를 분리합니다. 여러 후보 중 유일하게 가장 넓은 순회 묶음이 있으면 기본 투영으로 사용하고, 다른 투영도 보존합니다.
- 전진 커서로 읽어 다른 배열에 복사했다는 사실만으로 FIFO 소비를 추천하지 않습니다. 그러한 경우 `cursor-interval-candidate`로 낮추고 근거 부족을 기록합니다.
- 원소 이동식 FIFO/LIFO는 같은 저장소의 실제 복사 READ→WRITE와 길이 변화, 삽입·반출 위치로 연결합니다. 한 프레임에 반복된 연산도 길이 변경 구간으로 나눕니다. 구간이나 소비가 모호하면 미확정입니다.
- deque는 양쪽 끝의 삽입·삭제 근거를 함께 평가합니다. `roleAlternatives`에 지지 사건, 반례, 설명하지 못한 접근을 남깁니다. 후보의 모순은 C 실행 오류를 뜻하지 않습니다.
- 인덱스 트리는 산식 일부만으로 만들지 않습니다. 같은 배열의 노드 인덱스 영역과 부모/자식 관계 근거를 요구합니다. 재귀 인자→매개변수→실제 자식 접근은 동적 값 의존성으로 연결하며 `childAccessExecutionIds`에 남깁니다. 산식 후보의 지원 여부와 자료구조 의도는 별개입니다.

## 여러 저장 방식에 공통인 관계 층

`storage-relations.mjs`는 기존 중간언어 위에 다음 메타데이터를 추가합니다.

### storage-reference-graph

구조체의 직접 자기 참조에 제한하지 않고, 관측된 포인터 슬롯과 대상 범위를 기록합니다. 자식 포인터 배열, flexible array member, 중첩 레코드/union, 구조체 없는 포인터 배열도 같은 규칙을 사용합니다. 필드 역할과 실제 슬롯은 따로 구분합니다.

`changes`는 사건별 간선 변경과 객체 종료를 보존합니다. 슬롯 일부가 미확정 바이트로 덮이면 이전 참조를 무효화합니다. 같은 주소에 새 객체가 생겼다는 이유로 끝난 객체의 참조를 새 객체로 옮기지 않습니다. 대용량 배열의 용량만큼 노드를 미리 생성하지 않습니다.

`queryStorageReferences(graph, trace, options)`로 특정 사건까지의 상태를 조회합니다.

```js
queryStorageReferences(graph, trace, {
  afterExecutionId: 'x123',
  roleIds: ['field:ast456'], // 실제 후보의 역할 식별자
  view: 'tree',
  expected: 'tree'
});
```

`roleIds`는 선택사항이며 여러 관계를 분리하여 표시할 수 있습니다. `view`는 사용자 표현 선택으로 기록하고 관측 사실을 바꾸지 않습니다. `expected`의 tree/forest/chain은 선택한 관측 위상의 순환·공유 자식·분기 등을 검사합니다. 결과는 `satisfied-observed-topology`, `contradicted`, `incomplete`, `not-checkable` 등으로 구분합니다. 경고는 구조 기대 조건에 대한 것으로 C 런타임 오류가 아닙니다. 사용자 정의 자료구조의 임의 불변식 검증, 선택 UI와 설정 저장은 아직 구현하지 않았습니다.

### storage-dependencies

- 배열/레코드에서 읽은 정수값이 실제 다른 접근의 주소 입력에 도달한 경로를 기록합니다. 단순 값 전달은 `value-index-use`, 산술을 거친 경로는 `computed-address-use`로 구분합니다.
- 여러 배열을 동일한 동적 인덱스 출처로 접근한 사실을 `coindexed`로 묶습니다. 같은 크기나 같은 값이라는 이유로 합치지 않습니다.
- 구조체 배열의 원소 내부 접근은 `sourceRecord`·`targetRecord` 범위도 남깁니다. 실제 읽은 필드 범위를 대체하지 않습니다.
- 각 관계는 해당 접근 시점의 증거입니다. 과거 모든 관계를 현재 그래프인 것처럼 합치지 않습니다.

이 층은 CSR, 분리 간선 배열, trie 인덱스 배열, 상대 바이트 오프셋 등의 **관계 누락을 줄이는 기초 모델**입니다. 모든 배열을 완성된 논리 그래프로 자동 결합하거나 CSR/trie/skip-list 등의 알고리즘 이름을 확정하는 구현은 아닙니다. 유저 지정에 사용할 근거를 제공하며 불명확한 의미는 그대로 남깁니다.

### separate-array-structure

포인터·길이·용량이 구조체 밖에 있어도, AST의 인덱스/비교/할당 크기 의존성과 실제 배열 쓰기·길이 증가가 일치하면 하나의 동적 배열 후보로 연결합니다. 지역 임시변수를 거친 할당 크기도 선언 의존성으로 추적합니다. 상태마다 실제 backing object, 바이트 폭, 길이, 용량, 수명을 기록합니다. 여러 용량 후보나 불명확한 소유 관계는 확정하지 않습니다.

## 검증과 한계

- 관련 단위/통합 검사 54개 통과, 별도 포인터 부분 덮어쓰기·주소 재사용 검사 1개 통과. 마지막 역할 출력 보강 뒤 관련 계약/위상 검사 6개도 통과했습니다.
- 이번 조사에서 해당 경계와 관련된 39개 C 예제만 API로 실행했습니다. 모두 정상 종료했고 사전 예상 출력과 일치했습니다. 마지막 메타데이터 보강은 저장한 실제 관측을 다시 변환하여 확인했습니다. 15,037개 공개 사건의 값·순서·내용은 이 메타데이터 재변환 전후 동일했습니다. 이 수치는 수정 전 전체 모델과 동일했다는 뜻이 아닙니다. I01~I04는 의도적으로 공개 표현을 수정했습니다.
- 결과를 맞추기 위해 예제 원본·기존 예측을 바꾸지 않았습니다. 이전 No1~No46이나 조사 예제 85개 전체를 다시 실행하지 않았습니다.
- 관계 층은 실제 관측을 보존하는 모델이며 임의 자료구조의 의도를 완전히 알아내는 기능이 아닙니다. 방문하지 않은 영역, 종료 표식의 의미, 복잡한 소유권, 임의 사용자 불변식은 추가 근거나 사용자 지정이 필요할 수 있습니다.

실행 기록, 재변환 방법, 대상별 검사 근거는 [보강 검증 결과](../../test-results/structure-ir-fixes-2026-11-08/REPORT.ko.md)에 있습니다.
