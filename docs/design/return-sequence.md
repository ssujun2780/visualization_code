# 중간언어의 반환 전달 → 함수 공간 정리

2026-11-09. 이 계약은 **공통 중간언어 생성 모델**의 규칙입니다. 렌더러에서 이미 종료된 필드를 붙잡는 방식이 아니라 생성되는 `trace.events` 자체의 순서를 정합니다. UI와 애니메이션 구현은 별도 작업입니다.

## 직접 대입 예제의 실제 API 결과

`int c = add(a, b);`에서 `a=10`, `b=20`인 경우입니다.

| 사건 | 역할 |
| --- | --- |
| `x20 WRITE/return.value` | 반환구에 30 기록 |
| `x21 FLOW/return` | 수신 위치 `c`와 수신 사건 `x23`, 정리 사건 `x24` 명시 |
| `x22 FLOW/resume` | 호출자 복귀, 같은 반환값 연결 |
| `x23 WRITE/write` | `c=30` 대입 |
| `x24 SPACE/frame.end` | 반환한 함수 공간과 `endedObjects` 정리 |

원래 27개 사건을 유지하며 가상의 대입이나 복사를 추가하지 않습니다. 이후 `main`의 반환과 정리는 원래 진행대로 이어집니다.

## 범용 연결 규칙

- 함수 이름·변수 이름·값의 일치로 연결하지 않습니다. 실제 호출 ID, 반환 ID, 피연산자와 주소 사용 관계로 연결합니다.
- 직접 WRITE는 그 저장이 완료된 다음 정리합니다.
- 복합식은 반환값을 소비하는 CALC들을 따라 기존 결과 WRITE까지 연결합니다. CALC 자체가 마지막 관측 소비자라면 그 사건을 완료 지점으로 사용합니다.
- 중첩 호출은 호출 사건의 실제 `WRITE/argument`를 찾습니다. 라이브러리처럼 별도 인자 WRITE가 없는 호출은 관측된 호출 인자 전달이 수신 작업입니다.
- 재귀와 `return f()`는 각 활성화의 반환구 WRITE를 구별합니다.
- 조건 판정·주소 사용·함수 포인터 사용은 실제 소비 사건을 유지합니다. 무조건 변수 대입을 꾸며내지 않습니다.
- 구조체는 이미 관측된 ABI 반환 저장소와 복사를 사용합니다. 후속 복사는 컴파일러의 같은 소스 표현식 범위, 저장 범위와 실제 작성자 연결을 모두 확인합니다. 이후 별개 문장의 복사를 반환 대입으로 오인하지 않습니다.
- `void`·미사용 결과는 추가 수신 사건을 만들지 않습니다. 완료된 수신 작업이 없는 중단 기록도 미래 대입으로 채우지 않습니다.

`SPACE/frame.end`만 필요한 수신 작업 뒤로 이동합니다. READ·CALC·WRITE·FLOW 등의 상대 순서는 유지합니다. 공개 실행 ID와 모든 실행 참조를 최종 순서에 맞춰 다시 연결한 뒤 자료구조 추론과 계약 검증을 수행합니다. 문자열·원본 코드·AST ID·원시 관찰 ID는 실행 참조와 혼동하지 않습니다.

## 필드

- `FLOW/return.delivery.receivers`: 수신 사건·활성화·종류·동작·실제 목적지.
- `FLOW/return.delivery.completionExecutionId`: 전달 완료 사건.
- `FLOW/return.delivery.frameEndExecutionId`: 이어서 처리할 공간 정리 사건.
- `SPACE/frame.end.cleanupAfterExecutionId`: 먼저 완료되어야 하는 전달 사건.
- `recordedOrder`: 정리 순서를 정규화하기 전 공개 관찰 순번. 원시 관찰의 정확한 식별자는 기존 `observationIds`에 보존합니다.
- 객체의 `runtimeLifetime`: 실제 생성·종료의 원시 관찰 ID. 공개 `endedBy`는 공간 정리 사건을 가리킵니다.

C 실행 엔진과 원시 관찰의 수명 종료는 변경하지 않습니다. 공개 공간 정리를 뒤로 배치했다고 종료된 메모리의 읽기·쓰기가 허용되는 것은 아닙니다. 저장소 계약은 원래 관찰 순서도 검사합니다. 중간언어는 수신 이전의 공간 정리와 위조된 수신 위치를 오류로 거부합니다.

## 확인

`tests/ir-return-sequence.test.js`에서 직접 대입, 중첩 인자, 재귀, 복합식, 조건·포인터 사용, void·미사용 결과, 구조체 복사, 위조된 연결과 잘못된 정리 순서를 검사합니다. 기존 반환·반복 포인터·구조체 복사·소스 작업 순서 검사도 함께 확인합니다.

직접 대입의 새 API 출력은 `test-results/return-sequence-2026-11-09/trace.json`에, 원시 실행은 같은 폴더의 `observations.trace.json`에 있습니다. 기존 저장 파일을 읽는 것만으로 새 계약이 적용되지는 않으므로, 새 모델로 `plan.json`·`trace.json`을 다시 생성해야 합니다.
