# 자료구조 추천과 사용자 지정 우선 규칙

2026-11-13 화면 소비 방식: 이 문서의 추론·접두 조회 API는 유지합니다. [PS-01~04](prepared-scene.md)의 재생 준비 어댑터가 완성된 실행에서 표현을 한 번 고른 뒤 현재 관계 이력을 미리 조회합니다. 미래 정보는 표현·배치 준비에만 사용하고 실제 값·간선·수명을 앞당기지 않습니다. 현재 UI는 자동·원래 상자·준비된 전체 참조 그래프를 제공하며 아래 API의 모든 지정 UI가 구현된 것은 아닙니다.

2026-11-09. 공통 모델의 정책과 조회 API입니다. 2026-11-13에 [기본 화면 연결](structure-visualization.md)을 추가했습니다. 카드의 표현 선택·기본 도형은 연결했으며, 우클릭 역할 편집·설정 파일 저장·재연결 UI는 별도입니다.

## 적용 규칙

2026-11-13 범위 보완: 배열 후보에도 `coverage.selectedStorageBytes`, `representedStorageBytes`, `omittedStorageBytes`를 기록합니다. 전체 객체를 선택한 경우 일부 바이트만 담은 배열은 `storage-subrange`로 구분하고 전체 후보보다 뒤에 둡니다. 포인터 관계의 역할 범위에는 현재까지 저장이 관측된 필드도 포함합니다. 순회한 필드만 고른 보기는 순회하지 않은 다른 저장 연결을 `excludedRoleIds`로 명시합니다. 전체 저장 그래프와 역할별 순회 보기는 모두 유지하며, 사용자 지정이 항상 우선합니다.

구조체 배열의 필드 쓰기에서는 해당 시점에 이미 알려진 컴파일러 원소 배치로 소유 레코드를 식별합니다. 그 레코드를 가리키는 포인터를 나중에 읽을 때까지 필드를 별도 정점으로 만들지 않습니다. 미래 포인터 캐스트나 미래의 배열 배치를 과거 근거로 사용하지 않습니다.

1. 선택한 대상의 추론 후보를 **최대 5개** 추천합니다. 서로 다른 자료구조 표현을 기준으로 중복을 합치며, 같은 표현의 여러 역할 해석은 `alternatives`에 보존합니다. 후보가 부족하면 5개를 채우지 않습니다.
2. 같은 관계군에서 노드가 빠지는 부분 보기는 뒤에 두고, 관측된 동작·위상의 근거 강도, 서로 다른 명령 위치의 근거, 안정적인 식별자로 정렬합니다. 하나의 연결 역할을 반복하는 비순환 사슬은 연결 리스트를 먼저 추천합니다. `coverage.selectedRoleIds`, `excludedRoleIds`, `representedNodeCount`, `familyNodeCount`, `omittedNodeCount`로 선택·제외된 범위를 명시합니다. 모든 노드를 포함해도 일부 역할을 빼면 `role-projection`이며 전체 관계 판정으로 표시하지 않습니다. 같은 위치를 반복해서 읽는 것만으로 순위가 바뀌지 않습니다. `rank`는 확률이나 의도 확정도가 아닙니다. 미래 근거와 현재까지 반례가 확인된 후보는 추천하지 않습니다.
3. **사용자 지정이 자동 추천보다 우선**합니다. 추천에 없는 배열·트리·사용자 정의 표현도 지정할 수 있습니다. 재조회·새 추론·후보 소멸·관측된 모순만으로 자동 해제하거나 다른 표현으로 바꾸지 않습니다.
4. 사용자가 ‘자동 추론으로 돌아가기’를 선택하면 해당 지정만 해제합니다. 자동 모드의 기본 표현은 현재 추천 1위이며, 추천이 없으면 기본 상자 표현입니다.
5. 사용자 지정은 해당 표현의 조건만 적용합니다. BST나 heap을 추천했더라도 일반 트리로 지정하면 BST 정렬·heap 순서 조건을 상속하지 않습니다. 일반 트리의 기본 기대 조건은 `tree`이고, `expected: null`로 기대 조건 검사를 끌 수 있습니다.
6. 원래 후보와 실제 값·포인터·공유·순환·수명·중간언어 사건은 유지합니다. ‘트리로 지정’은 순환을 지우거나 실제 그래프를 수정하는 작업이 아닙니다. 모순은 표현을 유지한 채 구조 경고로 다룹니다.

대상은 `structureId`, 하나 또는 여러 `objectId`, 또는 `objectId + offset + size` 범위 묶음입니다. 같은 객체 안의 다른 범위를 구별합니다. 설정은 `programId + runId + 대상 + slot`에 묶이며, 같은 저장소의 배열 보기와 트리 보기는 서로 다른 `slot`으로 독립 지정할 수 있습니다.

객체 조회는 컨테이너·현재 상태의 원소 저장 범위까지 연결합니다. 포인터 상자를 선택하면 그 시점에 관측된 대상도 조회하며, 과거 대상이나 수명이 끝난 할당을 주소값으로 되살리지 않습니다. 포인터 상자와 실제 배열은 별도 저장 객체로 유지합니다. 세부 변경과 검증은 [공통 추론 보완](structure-common-fixes-2026-11-09.md)을 참고하십시오.

새 실행에서 객체 식별자가 재사용되더라도 이전 실행의 지정을 자동 적용하지 않습니다. `plan`과 함께 저장한 컴파일러 앵커는 명시적인 `reconnectStructurePresentation` 호출로 같은 코드의 선언·호출·필드 대응을 확인합니다. 재할당은 요청 사건까지의 교체 기록을 따르며, 모호함·범위 축소·코드 변경은 설정을 보존하고 재연결 필요로 반환합니다. 관계와 조건은 원자적으로 이동합니다. [UR-09~11](user-structure-relations.md)을 따릅니다. 파일/서버 저장 및 재연결 선택 UI는 별도입니다.

## 공통 API

자동 후보에 없는 연결도 [사용자 지정 관계 API](user-structure-relations.md)로 지정할 수 있습니다. `relationBinding`은 역할 매핑이며 원본 실행 기록이나 자동 추론 후보를 수정하지 않습니다. 표현 설정과 함께 저장하면 같은 공통 조회·조건 검사에 연결됩니다. UI는 별도입니다.

구현은 `scripts/inference/structure-presentation.mjs`이며 `scripts/inference/index.mjs`에서도 export합니다. 생성 모델은 추론을 호출하지 않습니다. 아래 `trace`는 `createInferenceView(result, inference).trace`로 만든 별도 조회용 객체이며 원본 실행 기록은 변경하지 않습니다. 추천은 클릭 대상과 시점에 따라 달라지므로 trace 생성 시 모든 대상에 대해 미리 계산하지 않고 조회 시 계산합니다.

```js
const target = {objectId: object.id};

// 자동 후보: 0~5개, rank·근거·역할 대안 포함
const recommendations = recommendStructureViews(trace, {
  target, afterExecutionId
});

// 새 설정 객체 반환. 이전 설정과 trace를 수정하지 않음
preferences = setStructurePresentation(preferences, trace, {
  target,
  view: 'tree',
  slot: 'primary'
});

const presentation = resolveStructurePresentation(trace, {
  target, afterExecutionId, preferences, slot: 'primary'
});
// mode: manual, source: user, locked: true, view: tree,
// expected: tree, recommendations: 현재 자동 추천 최대 5개

preferences = clearStructurePresentation(preferences, trace, {
  target, slot: 'primary'
});
```

`setStructurePresentation(..., {view: 'auto'})`도 해당 지정의 해제입니다. `view: 'custom:my-structure'`처럼 추천에 없는 식별자도 허용합니다. 사용자 정의 표현의 렌더러나 규칙 검사기를 자동으로 만들어 주지는 않습니다.

`roleIds`는 지정한 관계만 선택할 때 사용합니다. 사용자 지정 시 생략하면 추론 후보의 역할/하위 유형 조건을 몰래 상속하지 않고 대상 전체에 대한 표현 지정을 남깁니다. 역할 식별자는 후보의 원본 모듈에 대응하며, 예를 들어 저장소 참조 그래프는 `field:ast...` 형식입니다.

`plan`과 함께 지정하면 [UR-12](user-structure-relations.md)의 필드·배열·인덱스 역할 앵커를 저장합니다. 재실행 시 선택 역할과 조건 속의 역할 식별자를 함께 복원합니다. 같은 루트의 다른 역할 조합은 구별하며, 유일한 근거가 없으면 사용자 지정을 유지하고 재연결 필요로 반환합니다.

후보 자체의 저장소·관리 역할·비교 함수 신원도 [UR-13](user-structure-relations.md)으로 대응합니다. 같은 저장소의 서로 다른 후보를 하나로 합치지 않으며, 자동 추천 순위를 재연결 정답으로 사용하지 않습니다.

`resolveStructurePresentation`의 주요 반환값:

| 필드 | 의미 |
|---|---|
| `mode`, `source`, `locked` | 자동/사용자 지정 및 고정 여부 |
| `view`, `roleIds`, `expected` | 적용할 표현·역할·기대 조건 |
| `recommendations` | 사용자 지정과 별도로 유지하는 현재 추천 최대 5개 |
| `inferredCandidateId` | 자동 선택의 근거. 사용자 지정이면 null |
| `contractPolicy` | 선택한 표현만 적용하며 추론 하위 유형 조건을 상속하지 않음 |

## 기존 추론 결과와의 연결

현재 배열·격자, 동적 배열, 리스트/트리/그래프 위상, 큐·스택·deque, 인덱스 트리 등의 관측 메타데이터를 추천 후보로 연결합니다. 단순히 트리 모양이라는 이유로 BST를 추천하지 않습니다. 힙 추천은 실제 인덱스 관계·비교 근거와 관측 순서 조건을 함께 요구하며, 그래도 작성 의도는 `unconfirmed`입니다.

향후 추론 모듈은 해당 structure에 다음처럼 `presentationCandidates`를 제공할 수 있습니다. 특정 예제나 변수 이름을 등록하는 방식이 아닙니다.

```js
{
  view: 'bst',
  status: 'supported', // 또는 partial
  supportingExecutionIds: ['x10', 'x20'],
  contradictingExecutionIds: [],
  discoveredAtExecutionId: 'x20',
  roleIds: ['left-role', 'right-role'],
  expected: 'bst-order'
}
```

이 예시는 확장 계약입니다. 기본 정수와 관측된 복합 키의 BST 후보·`bst-order` 검사는 별도 `ordered-tree-candidate`로 제공합니다. 실제 비교·이동 근거가 있어야 하며, 해석되지 않은 비교자는 검사 불가로 남깁니다. [BST 기본 판별](bst-inference.md)을 참고하십시오.

`queryStorageReferences`에도 같은 정책을 연결했습니다. 저장소 그래프에 고정하려면 `target: {structureId: graph.id}`로 설정하고 조회에 `preferences`와 `slot`을 넘깁니다. 저장된 사용자 지정은 조회에 들어온 다른 자동 표현/기대 조건보다 우선합니다. 기존의 직접 `view` 인자는 그 조회에서만 쓰는 표현이며, 지속 고정에는 `setStructurePresentation`을 사용합니다.

저장소 그래프의 기존 기대 조건은 tree/forest/chain 위상 검사 범위를 따릅니다. 표현 조회의 `expectationCheck`는 [공통 관계와 조건 조합](structure-composition.md)의 `queryStructureConditions`를 사용합니다. 자동 추천은 선택한 후보 ID·역할로 검사를 고정하며, 일반 tree 지정은 BST 등 하위 종류 조건을 상속하지 않습니다. 지원하지 않는 사용자 규칙은 이유가 있는 `not-checkable`, 관측 부족은 `incomplete`, 서로 다른 대안 판정은 `ambiguous`로 남깁니다. 사용자 C 실행 오류와 구별합니다.

`setStructurePresentation`의 선택적 `conditionBindings`는 색·저장 높이·키·종료 표지의 record/array 역할 연결을 저장합니다. `avl`과 `red-black`의 기본 기대 조건은 각각 해당 전체 조건 조합입니다. 단순 균형이나 색 조건만 검사하려면 `expected:'avl-balance'` 또는 `'red-black-rules'`로 명시합니다. 색 역할 후보는 실제 연산으로 제공하지만 빨강/검정 의미는 수동 지정합니다. UI는 별도입니다.

2026-11-12: min/max-heap, disjoint-set, segment-tree, fenwick-tree, range-aggregate, queue/stack/deque, hash-table, trie 지정에도 해당 기대 조건을 연결합니다. 관측 근거가 없으면 이유 있는 not-checkable/incomplete이며 사용자 지정을 해제하지 않습니다. [변경·검증 대응표](../validation/inference-common-completion-2026-11-12.md).

## 확인 범위

2026-11-14: 포인터 상자의 추천은 그 시점의 참조 대상을 따라가며, 주소를 담는 별칭 슬롯 자체를 정점으로 세지 않습니다. NULL로 바뀐 루트에서 과거 연결을 되살리지 않습니다. 일반 저장소 그래프보다 추가 위상 근거가 있는 표현을 우선하되 트리 계열 점수를 일괄 올리지 않습니다. 같은 강도에서는 partial보다 supported를 우선하고, 기존 선택 범위·구성원·역할 누락 우선순위를 보존합니다. 완전한 슬롯 관계와 부분 필드 관계, 중첩 리스트·이진 트리 반례를 함께 검사했습니다.

2026-11-11 그래프 범위 보완: 선택한 배열 전체 안의 한 시작 슬롯만 설명하는 후보는 `coverage.scope='contained-root'`로 구분합니다. 정확히 그 슬롯을 선택하면 기존 루트 우선 규칙을 적용하지만, 전체 배열을 선택하면 부분 후보의 내부 완전성을 전체 선택 영역의 완전성으로 취급하지 않습니다.

다른 정점 영역과 동일한 인덱스 READ에서 유래한 조건부 상태 WRITE는 `relationRole.kind='conditional-vertex-state'`로 연결합니다. 상태 배열은 배열을 우선 추천하고, 실제 관측된 갱신 관계는 그래프 대안으로 남깁니다. 그 관계의 모양만으로 독립적인 트리를 우선 추천하지 않습니다. 방문 완료·최단거리·탐색 알고리즘을 확정하는 표지는 아닙니다. 사용자 지정과 상위 5개 제한은 유지합니다. [검증 기록](../validation/graph-storage-fixes-2026-11-11.md).

`tests/ir-structure-presentation.test.js`에서 다음을 확인했습니다.

- 5개 상한, 중복 후보의 역할 대안 유지, 안정적인 정렬, 부족한 후보를 채우지 않음.
- 시점 이전의 근거만 사용하고 다른 객체/하위 범위의 후보를 섞지 않음.
- BST/heap 추천과 독립적인 일반 트리 고정, 후보 소멸·JSON 저장/복원 후에도 유지.
- 대상·실행·보기 slot별 격리와 자동 복귀, 임의 사용자 표현.
- 실제 C 배열/포인터 트리 추천과 실제 순환을 보존하는 사용자 트리 경고.

기존 저장소 조회의 flexible child array, 미확정 바이트 덮어쓰기·주소 재사용 검사도 함께 확인합니다. 예제 전체나 UI 검사는 실행하지 않습니다.

## 추론과 실행의 분리

2026-11-12: [힙·대표 관계·구간 집계 계약](priority-partition-range-inference.md)의 분리 집합·구간 트리·Fenwick 후보도 같은 최대 5개·수동 지정 우선 경로에 연결했습니다. 일반 부모 종료 검사처럼 직접 인덱스 동등 비교만 있으면 해시로 추천하지 않습니다. 실제 키→버킷 숫자 변환 근거를 추가로 요구합니다. 이력 상한 이후의 오래된 정상 상태도 현재 추천으로 사용하지 않습니다.

추론은 확정된 실행 기록을 읽는 선택적 시각화 계층입니다. 명령·값·실행 순서·수명·실행 성공 여부를 수정하지 않습니다. 실패·시간 제한은 별도 추론 진단으로 처리합니다. 구현 경계와 후속 보완은 [추론 계층 분리](structure-readonly-fixes-2026-11-09.md)를 따릅니다.

## 부가 관계와 합성 보기

2026-11-10 연결 리스트 보완에서는 정확한 시작 슬롯을 우선하고, 미관측 링크를 불완전 상태로 유지하며, 더미를 제외한 데이터 개수와 원형 목록 표현을 구분합니다. 인덱스 시작점별 목록 및 노드 삽입·제거 정책도 추천에 연결합니다. 상위 5개는 향후 우클릭 추천 메뉴용이며 UI는 별도입니다. 세부 계약은 [연결 리스트 공통 추론 보완](linked-container-inference.md)을 참고하십시오.

역방향 경고는 주소가 한 번 서로 향했다는 이유만으로 활성화하지 않습니다. 관측된 순회 역할, 실제 역관계의 성립·변경 이력이 있어야 합니다. 부모·소유자·캐시 포인터는 별도 관계로 유지합니다.

물리 배열 추천은 구조체 내부 필드와 포인터로 연결된 저장 범위도 포함합니다. 행 인덱스 관계의 `scope: observed-edges`에서는 확인된 연결의 트리 형태를 `partial` 후보로 제시할 수 있습니다. 미방문 칸을 종료 표지로 채우거나 트라이 등의 의미를 확정하지 않습니다. 부모 인덱스의 화면 방향은 저장된 간선 방향과 별개입니다.

`composed-container-candidate`는 두 스택 사이의 실제 값 출처와 입출 순서를 대조한 큐 후보입니다. `composed-reference-candidate`는 서로 다른 레코드의 연결 경로를 그래프 또는 `nested-containers` 보기로 묶습니다. 원래 배열·레코드·중간 연결 노드는 그대로 남습니다. 이 메타데이터를 위한 UI나 애니메이션은 이번 작업에 포함하지 않았습니다.

변경 항목과 검사 근거는 [초심자·혼합 구현의 8개 보완](structure-novice-eight-fixes-2026-11-09.md)을 참고하십시오.

트리 관계의 후속 보완에서는 구성원 식별자의 합집합과 실제 표시 수로 누락 범위를 계산합니다. 부모 포인터·자식 배열·첫 자식과 형제 연결의 논리적 보기는 원본 포인터 그래프와 분리합니다. 세부 계약은 [트리 관계의 논리적 보기](tree-inference-projections.md)를 참고하십시오.

## 겹치는 인덱스 후보와 포인터 선택 범위 보완

2026-11-10. 추천 정책 v6에서는 같은 루트 슬롯·현재 루트 인덱스에서, 같은 relation 또는 **실제 관측된 연결 배열 역할**을 공유하는 후보들을 범위 비교용 관계군으로 묶습니다. coindexed 후보의 공동 인덱스 근거가 조회 시점까지 관측되어야 합니다. 서로 다른 후보가 공유하는 키/부가 배열, 같은 숫자 인덱스, 같은 길이만으로 관계군을 합치지 않습니다. 다른 루트, 종료된 저장소, 미래 후보도 제외합니다.

관계군 안에서 구성원 인덱스 합집합으로 가족 크기와 생략 수를 계산합니다. 이는 추천 범위의 비교이며 원래 coindexed 후보·간선·저장소를 합치는 작업은 아닙니다. 전체 트리와 부분 경로가 함께 있으면 부분 경로의 실제 누락을 반영하고, 각 부분 표현은 대안으로 유지합니다.

포인터를 통한 선택은 관측된 현재 대상의 pointee 크기를 사용합니다. 할당의 남은 부분 전체를 자동 선택하지 않습니다. 크기가 미확정이면 위치를 가리키는 최소 범위만 사용하며, 이를 읽었다거나 객체 크기가 확정됐다는 의미로 사용하지 않습니다. 원래 배열 보기는 해당 위치와 겹치므로 계속 선택할 수 있습니다.

연결 구조의 간접 조회는 현재 도달 구성원과 겹치는 후보를 사용합니다. 다른 후보의 시작 슬롯이나 과거 구성원만 겹쳐서는 선택하지 않습니다. 직접 선택한 NULL 시작 슬롯·비워진 루트·실제 센티널 구성원은 유지합니다. 따라서 전체 트리 조회에 다른 자식 NULL 슬롯의 빈 리스트가 끼어들지 않습니다.

이 변경은 추론 추천·조회 계층에만 적용됩니다. 생성 모델, 실행 사건, 원래 자료구조 후보와 UI는 변경하지 않습니다. [검증 기록](../validation/bst-recommendation-fixes-2026-11-10.md)을 참고하십시오.

## 공통 근거 보강 (2026-11-13)

- 큐 관리자의 수명이 겹치지 않으면 같은 끝점 쌍으로 조합하지 않습니다. 해당 시점까지 미설명 접근이 있으면 추천도 partial로 유지합니다.
- 트리의 모든 구성원을 보존하고 제외한 역할이 각 자식 연결의 정확한 역연결임이 관측된 경우, 주 트리 표현을 우선할 수 있습니다. 제외 역할과 역연결의 사건 근거를 coverage.auxiliaryInverseRoles에 공개하며 전체 그래프 보기와 사용자 선택은 유지합니다. 자식 누락·알 수 없는 연결·무관한 역할에는 이 우대를 적용하지 않습니다.
- 정수 인덱스가 담긴 구조체 배열도 문자 입력 → 슬롯 주소 → 관측된 자식 이동 → 입력 종료 후 반환 필드의 근거를 조합합니다. 관측하지 않은 슬롯을 NULL 또는 종료로 간주하지 않습니다. 트라이 조건은 관측된 관계에 한정되며 사용자 의도나 전체 용량의 완전성을 뜻하지 않습니다.
