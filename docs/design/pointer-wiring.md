# 지속 포인터 배선 시제품

상위 문서는 [시각화](visualization.md)·[UI](ui.md)입니다. 이 문서는 지속 포인터 배선과 선택·접기의 세부 명세입니다.

2026-11-09 구현. 실행 기록의 객체 ID와 바이트 오프셋으로 연결점을 만든다. 변수 이름, 자료구조 이름, 예제 번호는 배치·배선의 입력이 아니다. 자료구조 추론과 중간언어 생성 코드는 수정하지 않는다.

## 구성

1. `memory.js`: 각 SPACE/READ/WRITE 시점의 저장소를 재생한다. 배열·구조체의 원소/멤버는 컴파일러 자료형과 접근 오프셋으로 표시한다. 기록된 바이트 복사에서는 현재 원본의 포인터 정체성도 복사하고, 겹치는 바이트 쓰기는 이전 정체성을 무효화한다.
2. `pointer-graph.js`: 살아 있는 저장소의 현재 참조만 그래프로 만든다. 다중 포인터도 동일한 연결 규칙이다. NULL에는 선이 없고, 해제된 대상은 수명 종료 표시를 남긴다. one-past는 역참조 가능한 원소로 그리지 않는다.
3. `world.js`: 기존 좌표를 유지하며 새 객체·커진 배열에 필요한 공간을 확보한다. 수동 고정된 객체는 국소 조정에서 제외한다. 실패한 배선 주변에는 최대 4개 객체를 18 단위씩, 사건당 최대 2회만 조정한다.
4. `pointer-wiring.js`: 함수·힙·정적 영역 내부와 영역 사이의 배선을 나눈다. 각 영역 내부에서는 원소 상자를 피하고, 영역 사이에서는 돗자리와 도구·입출력 영역 전체를 장애물로 취급한다. 경계의 고정된 통로를 통해 각 부분을 연결한다.
5. `pointer-router.js`: libavoid-js 0.5.0-beta.5의 WASM 직교 라우터를 유지한다. 장애물 추가·이동·크기 변화, 끝점 변경, 새 장애물에 막힌 경로를 공간 인덱스로 찾는다. 영향 없는 표시 경로는 그대로 둔다.
6. `pointer-lanes.js`: 새 경로가 기존 경로와 같은 구간을 쓰면 평행 차선에 배치한다. 이미 배치된 다발을 통째로 재정렬하지 않는다. 5 단위 간격을 우선하고 좁은 공간에서는 간격을 줄인다. 확보하지 못한 간격은 품질 검사에 남는다.
7. `pointer-worker.js` / `pointer-client.js`: WASM 계산을 Web Worker에서 수행한다. 값 변경·카메라 이동·애니메이션 프레임은 배선 요청을 만들지 않는다. 기하·참조 그래프만 캐시하고, 드래그 대기열은 최근 요청으로 제한한다.

## 경로 보존과 실패 처리

- 연결 ID는 출발 객체와 출발 오프셋으로 고정한다. 재대입은 해당 선의 끝점을 바꾼다.
- 공통 영역 통로의 슬롯과 상자의 도착 포트는 기존 연결에 대해 유지한다. 새 연결이 들어와도 기존 슬롯을 밀지 않는다.
- 기존 경로는 최단 경로가 새로 생겼다는 이유만으로 옮기지 않는다. 새 장애물과 겹치거나 끝점이 바뀐 부분만 탐색한다.
- libavoid의 전체 교차 개선과 비싼 연결점 통합 최적화는 끈다. 한 번에 최대 32개 연결만 native 정돈기에 넣고, 완료한 차선은 고정한다. 장애물 가시성 그래프는 같은 라우터에 남는다.
- 계층 변경 후 native 연결점 캐시가 경로를 만들지 못하면 해당 영역의 native 인덱스만 재구축하여 실패한 선을 재시도한다. 유효한 표시 경로와 차선 예약은 보존한다. 복구 횟수는 측정값의 `repairedRoutes`에 기록한다.
- 결과가 대각선이거나 장애물을 관통하면 표시하지 않고 미배선으로 보고한다. 장애물을 관통하는 임시 직선으로 대체하지 않는다.
- 재생기는 각 사건의 전후 배선이 준비될 때까지 기다린다. 중간언어를 건너뛰거나 계산 사건을 추가하지 않는다. 캐시된 경로는 표현 상태이며 실행 상태가 아니다.
- 임의 시점 이동을 위해 실행 상태를 128개 사건마다, 최대 32개 체크포인트로 보관한다. 메모리·자료형은 불변 데이터를 공유하고 변경 가능한 컨테이너만 복사한다.
- 2026-11-13: 배치·배선의 탐색 재현은 [PS-06](prepared-scene.md)를 따른다. 정상/스킵/되감기 모두 원본 순서로 만든 표시 이력을 사용한다. 이력용 라우터는 연결 변경을 같은 순서로 처리하며, 되감기는 저장된 통로·차선·경로를 읽는다. 드래그 미리보기용 라우터와 분리하여 사용자의 탐색 경로가 다음 배선에 섞이지 않게 한다.
- 수동 이동은 이력 라우터를 재시작하지 않는다. 저장된 시점의 영역 통로·단말 슬롯·부분 경로를 복원한 뒤, 바뀐 영역만 기하 차이를 적용한다. 무관한 경로와 차선은 유지하며, 끝점이 그대로여도 새 장애물에 가려진 선은 갱신한다. 국소 수정의 기준은 직전 탐색 화면이 아닌 같은 원본 시점이므로 되감기 후에도 결과가 같다.

## 초기 메모리

최종 객체 목록에서는 이름·자료형 등 정체성만 사용한다. 최종 바이트와 최종 참조 목록은 과거 상태에 적용하지 않는다. 전역 포인터 초기값은 SPACE 사건의 메모리 스냅샷을 컴파일러 자료형으로 읽고, **그때까지 관찰된** 할당 주소와 연결한다. 정수 값이 주소와 같다는 이유로 포인터로 해석하지 않는다. 이미 확정된 할당 정체성은 주소가 재사용되어도 바꾸지 않는다.

기본 배열은 최초 최대 12개 원소와 실제로 관찰·참조된 원소를 표시한다. 따라서 거대한 미접근 배열을 통째로 확장하지 않는다. 사용자가 [서랍 크기](drawer-windows.md)를 지정하면 들어갈 칸만 표시하고 가려진 원소의 간선은 해당 서랍의 대표 연결점을 사용한다. 완전한 스크롤 기반 배열 가상화는 후속 과제다.

## 조작

`animation.html`의 예제 메뉴에 포인터·재연결·함수, 포인터 배열·구조체, 대규모 포인터 연결망을 추가했다. 실제 예제 API를 통해 현재 중간언어 생성 모델과 연결된다. 선에 커서를 두면 출발·도착 원소를 표시하고 해당 선을 강조한다. 상자를 선택하면 관련 선을 강조한다. 기존 상자·돗자리 드래그, 확대·축소, 화면 이동을 사용한다.

2026-11-13 기본 선 가독성 정정: 일반 참조선은 옅은 청회색·가는 선으로 표시하고, 호버·선택 등 기존 관심 상태에서만 강조합니다. 포인터 배열 원소의 선은 연결 ID로 정한 고정 7색·배경 테두리·축소 시 두께와 화살촉 보정을 유지합니다. 중첩 배열과 구조체 안의 포인터 배열도 원소의 컴파일러 자료형/직계 포함 관계로 구분하며, 구조체 배열 안의 단일 포인터 필드를 포인터 배열로 취급하지 않습니다. 색은 자료형/자료구조 의미가 아니며 여러 연결에서 반복될 수 있습니다. 호버·선택 강조의 기존 색/굵기와 관심 밖 선의 흐림, SS-03 자료구조 내부 연결선은 유지합니다. 경로·차선·끝점·실행 기록은 바꾸지 않습니다. 구현은 `pointer-appearance.js`, `canvas.js`의 공통 그리기 경로이며 [검증](../validation/pointer-contrast.md)을 참고합니다.

### 컨테이너 접기와 정확한 선택 범위

- 배열·구조체와 중첩된 배열·구조체의 `▸/▾`로 각각 접고 펼친다. 제목 더블클릭, 컨테이너 선택 후 도구막대의 접기/펼치기, 캔버스에서 Enter도 지원한다. Esc 또는 빈 공간 클릭으로 선택을 해제한다.
- 바깥 컨테이너, 내부 컨테이너, 원소·멤버 상자는 별도의 논리 ID다. 실제 포인터 인접 관계와 포함 관계를 섞지 않는다. 컨테이너 선택은 내부 포인터 전체를 선택하지 않는다.
- 상자/선 클릭·호버와 현재 연산은 실제 포인터선으로 이어진 전체 연결 성분을 강조한다. 다중 포인터·공유 대상·순환을 포함하며, 부모 포함 관계나 동일한 화면 대표점만으로 별개의 연결을 합치지 않는다. 나머지 선은 흐리게 표시한다. 선택은 배선·실행 상태를 바꾸지 않는다.
- `&array`와 `&array[0]`, 구조체 주소와 첫 멤버 주소는 같은 숫자 주소라도 컴파일러가 기록한 대상 자료형·크기에 따라 별도의 컨테이너/원소에 연결한다. 중첩 배열의 행 주소도 해당 행 컨테이너로 연결한다.
- 접힌 자손의 선은 보이는 컨테이너를 화면 연결점으로 사용한다. 논리적인 출발·도착 ID는 유지하므로 접힌 부모 클릭이 자손 선 전체 강조로 확장되지 않는다. 양끝이 모두 접힌 내부 자손인 선은 숨기고 `내부 연결 N개`로 표시한다.
- 접기 상태는 실행 위치와 분리된 표시 설정이다. 부모를 접었다 펴도 중첩 자식의 접기 상태는 유지한다. 실행 값과 수명, 중간언어 순서는 바꾸지 않는다. 값은 현재 재생 경계에서 읽으며 다음 WRITE의 값이 먼저 보이지 않도록 한다.
- 배열·구조체 내부 상자는 클릭으로 선택하고 컨테이너 제목으로 바깥 객체를 이동한다. 클릭만으로 객체가 고정되거나 이동하지 않도록 드래그 임계 거리를 둔다.

공통 로직은 `object-view.js`, `world.js`, `pointer-graph.js`와 `canvas.js`에 있다. `animation-object-selection.test.js`에서 중첩 구조, 자료형별 끝점, 부모 선택 범위, 접기 후 연결 정체성, 메모리 패딩, WRITE 전 값 표시를 검사한다. `verify-folding.mjs`로 저장된 실제 실행의 최대 참조 시점을 펼침→전체 접기→복원하며 검사할 수 있다.

## 연구와 구현의 관계

- [Ordered Bundles](https://arxiv.org/abs/1209.4227): 공통 통로와 구분되는 차선이라는 구성을 참고한다. 논문의 전체 최적화 알고리즘을 구현했다고 주장하지 않는다.
- [libavoid](https://www.adaptagrams.org/documentation/libavoid.html): 장애물 회피 직교 라우팅·가시성 그래프·트랜잭션을 사용한다.
- 기존 배치 보존, 영역별 배선, 변경 연결의 제한된 탐색, 점진적인 차선 예약과 복구는 이 시제품의 공통 계층이다.

## 검증 및 한계

`scripts/animation/verify-pointers.mjs`는 실제 C 실행 기록의 선택한 시점을 검사한다. `scripts/animation/benchmark-wiring.mjs`는 컴파일 시간을 제외하고 24/100/300/1000개 연결과 160개 집중 연결을 검사한다. 전체 교차 통계는 별도 감사 비용으로 측정하며 브라우저 재생 프레임에서는 수행하지 않는다. 상세 수치와 재현 명령은 `test-results/pointer-wiring/REPORT.md`에 둔다.

현재 최적 교차 수·일정한 차선 간격·실시간 16ms 완료를 보장하지 않는다. 좁은 통로에 많은 선이 몰리면 차선이 매우 촘촘해지거나 일부 겹침이 남는다. 직각으로 교차하는 두 선은 연결 지점이 아니다. 실제 연결은 끝점 화살표로 구분한다. 경로 캐시는 최대 12개 기하 상태를 보관하므로 오래된 시점으로 돌아가면 다시 배선할 수 있다. 원소 위치는 보존하지만 모든 과거 배선 모양의 영구 재현은 보장하지 않는다.

별도 발견: `examples/c/animation/pointer-network-index-formulas.c`의 곱셈 기반 인덱스 표현은 자료구조 추론 검증에서 `인덱스 트리 후보와 실제 배열 범위가 일치하지 않습니다.`로 중간언어 생성을 중단했다. 원본 코드와 실패 기록을 보존했다. 배선과 분리된 추론 문제이며 이번 수정으로 해결되었다고 간주하지 않는다. 실행 가능한 대규모 화면 예제는 동일한 포인터 종류·규모에 순환 오프셋 인덱스를 사용한다.
