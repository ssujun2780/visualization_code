# 실행 관계 분석기 확장 설계

2026-11-12 작성한 확장 설계입니다. 사용자 승인으로 **독립 v2 분석·조회 계층**을 구현한 뒤, 후속 승인으로 [기본 컴파일 근거 수집·현재 작업 화면 연결](work-context-view.md)을 추가했습니다. 기존 v1 기본 API·중간언어·자료구조 추론 규칙과 원본 공간은 유지합니다. API는 [v2](execution-relations-v2.md), 분석 검증은 [대응표](../validation/execution-relations-v2.md), 화면 검증은 [연결 보기 대응표](../validation/work-context-view.md)를 따릅니다. 새 trace append 증분 세션은 미구현입니다.

## E-01 목적과 불변 조건

[실행 관계 계약](execution-relations.md)의 R-01~R-07을 유지합니다. 자료구조 추론 결과가 정확하다고 가정하되, 그것만으로 함수의 처리 의도·완료 범위·알고리즘 정확성이 알려졌다고 가정하지 않습니다.

- 원본 plan/trace의 명령·사건·값·자료형·순서·생성/소멸·호출/반환·오류를 수정하지 않습니다. 분석용 복사본만 사용합니다.
- 스택·힙·전역·정적, 호출 돗자리, 실제 변수·원소·멤버·포인터는 시각화의 기준입니다. 추가 보기는 실제 저장소에 연결되며 새 할당/복사가 아닙니다.
- SPACE·READ·CALC·WRITE·FLOW와 기존 ERROR의 애니메이션 대응을 유지합니다. 작업 묶음으로 원본 명령을 합치거나 건너뛰지 않습니다.
- 결과에는 관계·근거·시점만 둡니다. 좌표·카메라·선 색·재생 속도·자동 정지·장면 상태를 결정하지 않습니다.
- 생성 모델·추론기·렌더러 구현을 가져오거나 C를 재실행·재컴파일·재파싱하지 않습니다. 이름·예제 번호·정답·숫자 유사성을 판정 근거로 삼지 않습니다.

## E-02 확인한 현재 구현과 확장점

| 현재 경로 | 현재 역할 | 제안하는 확장 |
| --- | --- | --- |
| `context.mjs`, `records.mjs` | 읽기 전용 스냅샷, 명령/사건/객체/프레임 색인과 접근 배치 | 공통 관찰·출처·제어 문맥 색인, 입력 기능 점검 |
| `calls.mjs` | 실제 호출 진입과 포인터 인자 참조 | 스칼라/포인터 인자·반환의 명시적 전달 연결, 호출 상태의 시점 조회 |
| `ranges.mjs` | 직접/하위 호출 접근 집합, 닫힌 호출 요약, 범위 비교 | 접근 델타 기반 누적, 작업별 접근, 근거 있는 경계 영역 |
| `copies.mjs` | 직접 READ·일부 비트 보존 cast·명시적 copy의 전달 | 임시 저장·인자·선택·반환을 포함한 출처 그래프, 계산과 복사 구별 |
| `registry.mjs`, `engine.mjs` | 독립 판정기 순차 실행·실패 격리 | 선행 기능을 선언하는 판정 단계와 부분 결과·예산 처리 |
| `result.mjs` | 관계 v1 형식과 근거 참조 검사 | v2 형식·시간·정체성 검사와 v1 호환 |
| `work-context.mjs`, `index.mjs` | 경계 이후의 현재 작업 조회, 역사적 관계 조회 | 작업 문맥·역할·출처·관계 유효성 조회 확장 |

현재 복사 분석은 임시 저장소의 READ를 만났을 때 원래 원소까지 계속 추적하는 범용 출처 분석이 아닙니다. 현재 `activation-range`의 닫힌 요약은 호출 종료 후 성립하며, 임의의 루프 경계를 호출 시작에 예측하지 않습니다. 현재 코드가 아래 확장 규칙까지 구현했다고 해석하지 않습니다.

## E-03 입력 계약

기존 공개 진입점 `inferExecutionRelations(plan, trace, options)`와 Async/Worker/CLI 경계는 유지합니다. 아래 옵션은 v2 선택 경로에 구현했습니다. `compilerFacts`와 보조 관찰의 자동 생산/수집을 이 분석기가 담당하지는 않습니다.

| 입력 | 필수 여부·책임 |
| --- | --- |
| `plan` | 필수. 현재 IR v3의 명령 정의·자료형·선언/스코프·소스 노드·표현식·이미 연결된 제어/관찰 메타데이터 |
| `trace` | 필수. 같은 프로그램/실행의 정규 사건·피연산자/steps·객체/프레임 수명·참조·실제 메모리 효과 |
| `structureInference` | 선택. 같은 실행의 구조·원소/노드/멤버와 저장 범위 대응. 시점별 관계를 조회할 때 해당 시점까지 성립한 대응만 사용 |
| `compilerFacts` | 선택·신규 제안. 기존 컴파일 결과에서 추출한 제어 영역·def-use·루프 초기화/조건/증감·접근식의 구조화된 사실. 새 C 소스 입력이나 분석기 내부 파싱은 허용하지 않음 |
| `observationEvidence` | 선택·신규 제안. 기존 보조 관찰의 plan/trace와 정규 사건 대응표. 정규 기록에 없는 근거만 보완하며 새 시각화 사건으로 승격하지 않음 |
| `outputSchemaVersion` | 신규 제안. 기본 1 유지, 확장 소비자가 2를 명시. v1에 새 정보를 억지로 끼워 넣지 않음 |
| `limits` | 신규 제안. 분석 시간·관계 수·출처 간선 수·확장 깊이/조회 예산. 제한 도달 시 partial과 미해결 범위를 반환 |

보조 자료에는 schema·프로그램/실행 또는 소스 스냅샷 식별자·정규 instruction/observation 대응이 필요합니다. 다른 실행의 보조 자료는 거부합니다. 관찰 시점은 정규 사건과 내부 관찰 순서로 연결하며, 대응이 없으면 사용하지 않습니다.

`compilerFacts`가 없으면 경계 분석 등의 capability를 unavailable로 남기고 기존 관찰 기반 분석은 계속합니다. 현재 plan에 모든 루프/SSA 정보가 있다고 가정하지 않습니다. 누락된 필드와 필요한 연결을 `missing-evidence`로 보고하며 생성 모델을 자동 수정하지 않습니다.

입력은 `scope(programId, runId)`와 스냅샷으로 구분합니다. v2는 plan/trace/선택 입력의 내용 지문을 저장해 같은 ID에 다른 기록이 들어오는 혼합도 검출합니다. 지문은 키를 정렬하고 배열 순서를 유지하는 canonical JSON의 UTF-8 SHA-256을 사용합니다. 증분 입력은 이전 prefix의 동일성을 확인합니다. 지문은 판정용 특징이 아니며 관계의 의미를 정하지 않습니다.

## E-04 정체성과 분석 단위

| 대상 | 식별·경계 |
| --- | --- |
| 실제 저장소 | 실행 scope + objectId + createdBy. 숫자 주소 재사용으로 합치지 않음 |
| 저장 범위 | 같은 저장소의 `[offset, offset + size)` 바이트 범위. 비트필드는 확보된 비트 범위도 보존 |
| 원소/멤버 | 컴파일러 배치와 구조 대응으로 범위에 연결. 이름·원소 수 유추로 폭을 정하지 않음 |
| 값 관찰 | executionId + 필요 시 그 사건에 속하는 observationId/내부 step. 현재 슬롯 값과 이미 읽은 사본을 구별 |
| 호출 | 실제 activationId와 callExecutionId. 같은 함수의 재귀 호출도 각각 유지 |
| 작업 인스턴스 | 실제 소스 노드/제어 영역 + activationId + 확인된 동적 진입. 같은 줄이라는 이유로 합치지 않음 |
| 논리적 구조 요소 | 구조 결과의 실행·시점·구조/요소 ID와 원래 저장 범위. 여러 저장소가 한 노드를 구성해도 개별 근거 유지 |

빈 구간, 원소 접근이 없는 호출, NULL·one-past·미해결 참조를 표현할 수 있어야 합니다. 접근이 없는 참조를 크기 1의 READ로 만들지 않습니다. 생명주기 소유 프레임, 선언 스코프, 힙을 할당한 호출은 별도 정보입니다. 할당한 함수가 끝났다고 힙 객체가 사라지는 것으로 해석하지 않습니다.

## E-05 출력 v2와 호환

v1 결과·기존 함수의 기본 응답은 유지합니다. v2는 별도 분석 결과이며 plan/trace에 넣지 않습니다. v1 읽기 어댑터는 기존 관계만 정규화합니다. v1로 표현할 수 없는 관계를 조용히 버리는 v2→v1 자동 변환은 제공하지 않습니다.

v2 최상위 계약:

```text
schemaVersion: 2
scope: { programId, runId }
snapshot: { inputDigests, eventCount, lastExecutionId, recordingStatus }
status: completed | partial | failed | skipped | not-implemented
capabilities: 단계별 지원 여부·누락 근거·제한 사유
relations: 근거와 성립 시점을 갖는 불변 관계/관계 버전
changes: 현재 바인딩·경계 후보 등 상태 관계의 activate/invalidate/close 기록
provenance: 관찰 참조 노드와 역할별 의존 간선
coverage: 분석한 범위·지원하지 않은 범위·미해결 수·잘린 범위
diagnostics: 분석 자체의 진단
```

`completed`는 실행한 분석 단계의 정상 완료입니다. 모든 코드·의도·관계를 이해했다는 뜻이 아닙니다. 결과의 실행 상태와 개별 관계의 판정 상태도 구별합니다.

관계 공통 필드:

| 필드 | 계약 |
| --- | --- |
| `id`, `kind` | 원본 식별자/근거를 이용한 결정적 ID와 범용 관계 종류 |
| `status` | 기존 supported / ambiguous / insufficient / contradicted 유지. 근거가 있는 한정된 명제에만 supported 사용 |
| `availableAtExecutionId` | 필요한 실행 근거가 모두 관찰된 최초 정규 사건. 같은 사건 내부의 근거는 observation/step 참조로 구별 |
| `activationIds`, `workScopeIds` | 관련 실제 호출과 작업 인스턴스. 소유·실행·출처 역할은 각각 표시 |
| `participants` | 종류가 있는 storage / region-set / value / activation / port / structure-element 참조. 상수는 실제 명령/리터럴 참조이고 가상 저장 객체가 아님 |
| `evidence` | 실제 execution·관찰·plan 노드·선행 관계 ID. 큰 목록은 공유된 근거 참조로 저장 |
| `extent` | observed-access / bounded-domain / reference-only 등을 구별. prefix/closed/interrupted와 direct/subtree를 별도 표시 |
| `details` | 관계별 범위 집합·전달 종류·조건·요약 근거. 좌표나 현재 메모리 값의 복제본은 금지 |

region-set은 빈 집합과 불연속 집합을 허용합니다. boundingRange는 화면 외곽 범위일 뿐 접근 집합이 아닙니다. 값·프레임·객체 상세는 원본에서 조회합니다. 상태 관계의 후속 변경을 이전 버전에 직접 적어 미래의 종료/반례 시점이 과거 조회에 새지 않도록 합니다.

port는 원본에 존재하는 매개변수/반환구·입출력 채널의 실제 참조입니다. 해당 activation/call/parameter index/channel과 실행 근거를 포함합니다. 메모리 객체로 위장하거나 없는 호출 프레임을 만들지 않습니다.

예: `dst[j] = src[i] + bias`는 `value-dependency`에 읽은 세 관찰/상수의 출처, 실제 CALC 결과, 실제 WRITE를 연결합니다. 전달 종류는 calculated입니다. `storage-copy`로 표시하거나 새로운 계산/쓰기 사건을 만들지 않습니다.

## E-06 범용 분석 규칙

### E-06a 접근과 호출별 영역

- 완료된 실제 접근과 기록된 메모리 효과를 저장 범위에 정규화합니다. 단순 READ, 명시적 범위 복사의 원본, 라이브러리 요약의 읽기 범위는 근거 종류를 구별합니다. 요약을 내부 READ 명령들로 생성하지 않습니다.
- 읽기·쓰기·참조 전달을 별도 집계합니다. 지역 스칼라 장부 작업도 정확한 관찰로 보존하되 자동으로 배열 처리 구간이나 payload 복사로 분류하지 않습니다.
- 호출 직접 접근과 하위 호출을 포함한 접근을 구별합니다. 그래프/트리에서는 대응 요소 집합도 제공하며 연속 배열 구간으로 강제 변환하지 않습니다.
- 집합은 정확한 구간 합집합·노드/간선 집합입니다. 반복 횟수·접근 순서·중복 횟수는 별도로 남깁니다. 인덱스가 2,4,8이면 중간 원소를 사용한 것으로 채우지 않습니다.
- ERROR/실패한 시도는 확정된 읽기·쓰기 효과에 넣지 않습니다. 관측된 시도는 별도로 연결하고 기존 fault를 그대로 참조합니다. 부분 기록의 호출을 종료·완료로 만들지 않습니다.

### E-06b 경계식과 접근식

- 기존 컴파일 메타데이터에서 인덱스/포인터 초기값·진행·조건과 실제 접근식의 def-use를 연결합니다. 런타임 값은 해당 시점의 실제 관찰에서만 가져옵니다.
- 초기 지원은 근거가 갖춰진 정수/포인터의 아핀 접근, 단조 증감, 비교 경계입니다. 자료형·signedness·변환·바이트 폭·가능한 wrap/overflow·같은 객체 여부를 확인할 수 있어야 합니다.
- 분석은 수학적 범위 관계의 정규화이며 C 식 실행기가 아닙니다. 불명확한 호출 결과·부수효과·알 수 없는 별칭 효과·정수 제약을 추정 계산하지 않습니다.
- `for(k=u;k<v;k++) q[k]`의 경계가 확인되면 `[u,v)`를 bounded-domain으로 표시합니다. break/return/추가 조건으로 실제 접근은 그 부분집합일 수 있습니다. 전체 방문이나 최종 결과를 보장하지 않습니다.
- stride/2차원/불연속 인덱스는 입증된 집합 표현으로 유지합니다. `q[index[k]]`의 대상은 관찰한 인덱스로 추가하며 단순 직사각형이나 연속 범위를 추측하지 않습니다.
- 경계 값·기준 포인터·관련 별칭의 WRITE, realloc/free, 영향이 불명확한 호출 이후에는 의존 경계 후보를 무효화하거나 재관찰합니다. 이전 인자 값을 계속 적용하지 않습니다.
- 한정된 경계는 supported일 수 있지만, 크기/끝이 불명확한 대상은 reference-only 또는 insufficient입니다. 배열 전체 할당 크기는 실제 사용 구간의 대체 근거가 아닙니다.

### E-06c 값의 출처와 전달

- value / address / control / callee 간선을 구별합니다. 현재 피연산자 조회는 READ에서 멈추고, 출처/역사 조회만 그 READ의 메모리 생산자까지 따라갑니다.
- 저장 범위별 생산자 관찰을 구간 색인으로 연결합니다. 부분 WRITE는 그 부분의 출처만 바꾸고, 나머지 바이트·멤버를 같은 쓰기의 결과로 만들지 않습니다. 이는 출처 색인이며 값 계산/메모리 시뮬레이터가 아닙니다.
- 관찰된 임시 저장/다시 읽기, 명시적 parameter index/call ID, return 수신 계약, 선택된 실제 분기 경로를 따라갑니다. 재귀/다중 호출/콜백은 정확한 호출 연결이 있을 때만 통과합니다.
- 동일한 값/비트라는 이유만으로 복사라고 판단하지 않습니다. 실제 def-use와 변환 근거가 먼저 필요합니다. 같은 폭의 비트 일치는 그 연결의 보조 검사입니다.
- 직접 identity 전달, 비트 보존 cast, 계산, 값 변환, 실제 선택, 인자/반환, 범위 복사, 상수 채우기, 미해결을 구별합니다. 선택되지 않은 입력은 전달 원본으로 넣지 않고 판단 근거로 유지합니다.
- 명시적 memmove 등 겹치는 복사는 기록된 효과의 원본 시점/범위를 따릅니다. 읽기 이전에 덮어쓴 원소의 옛 값을 임의로 되살리지 않습니다. 정규 기록만으로 세부 대응을 알 수 없으면 범위 수준 관계까지만 반환합니다.
- 구조체 필드마다 실제 출처와 시점을 유지합니다. 다른 원소에서 온 필드, 패딩, 일부 비트, 중간 원본 변경 때문에 하나의 일관된 전체 원소 복사라고 증명할 수 없으면 부분 전달로 남깁니다.
- 해제/호출 종료 이전에 읽어 확보한 사본의 출처는 역사적 관계입니다. 현재 원본이 살아 있는 것처럼 되살리지 않습니다.

### E-06d 구간·전달 관계의 조합

- 같은 저장소의 부모/자식과 관련 형제 호출 영역에 대해 동일·포함·겹침·분리를 판정합니다. 실제 집합과 경계 영역끼리의 관계를 혼합하지 않습니다.
- 부모 영역과 자식 영역들의 합집합/교집합 근거가 있을 때만 해당 분할 명제를 제시합니다. 단지 자식 호출 두 개가 있다는 이유로 이분할·전체 커버를 주장하지 않습니다.
- 여러 원본에서 한 목적지로 이어진 실제 전달은 multi-source-transfer로 표현합니다. 입력 수를 2개로 고정하지 않으며 정렬·병합 성공을 뜻하지 않습니다.
- 한 원본의 여러 목적지 전달, 제자리 덮어쓰기, 임시 저장을 거치는 전달 사슬·순환을 같은 출처 그래프에서 표현합니다. 교환 요약은 원래 버전들의 대응과 실제 쓰기 순서가 확인된 뒤에만 추가합니다.
- 합집합 요약은 실제 순서 목록의 대체가 아닙니다. 각 전달과 중간 상태를 항상 조회할 수 있어야 합니다. 관련 없는 작업·제어 전환에서 무조건 인접 사건을 묶지 않습니다.

### E-06e 작업 문맥과 구조 대응

- 표현식·문장·호출·실제 반복 진입에 따른 계층을 구성합니다. 정의 ID만 같거나 같은 줄에 있다는 이유로 다른 반복/호출을 합치지 않습니다.
- 루프 본문은 for/while/do 구분 없이 같은 동적 진입 계약을 사용합니다. 조건·continue·break·중첩 호출의 실제 경로와 source-node 대응이 부족하면 일부 scope만 제공하며 반복 번호를 추측하지 않습니다.
- 각 작업에 직접 입력, 주소/인덱스 입력, 판단 근거, 실제 선택 입력, 계산 결과, 목적지, 참조 변경을 연결합니다. 이 역할은 해당 작업에 한정됩니다. 배열을 전역적으로 '입력 전용'이라고 분류하지 않습니다.
- 구조 대응은 이미 확인된 저장 범위를 논리적 원소/노드/간선에 매핑합니다. 매핑이 여러 개면 대안을 보존합니다. 같은 노드를 가리키는 여러 큐 항목은 별개 저장 항목이며 하나로 합치지 않습니다.
- 구조의 속성·연결 변경은 실제 WRITE/할당/해제와 해당 시점의 구조 대응을 연결합니다. 큐 사용을 BFS, 작은 값 갱신을 최단 경로, 재귀 호출을 트리 탐색으로 자동 확정하지 않습니다.
- 라이브러리는 기존 호출과 관측된 효과/입출력 채널을 연결합니다. 내부 구현이나 추가 호출 돗자리를 생성하지 않습니다. 성공·정상 실패 반환·입력 대기·치명적 중단은 원래 기록의 구분을 따릅니다.
- 관계 조회는 필요한 대상·역할·근거를 반환합니다. 어디를 밝히고 어느 필드를 가까이 펼칠지는 기존 시각화 계층이 결정합니다.

### E-06f 입력에서 출력까지의 예

설명용 코드와 가상의 사건 ID입니다. 이번 작업에서 실행한 코드나 검증 결과가 아닙니다.

```c
tmp = src[i];
dst[j] = tmp + bias;
```

관찰된 접근이 `i=2`, `j=4`에 대응한다고 가정합니다. 분석기는 이 숫자를 선택하거나 예상 정답과 비교하지 않고 관찰 참조를 사용합니다.

| 시점·원본 사건 | 그 시점에 추가되는 관계 |
| --- | --- |
| x10: src[2] READ | 해당 호출의 실제 읽기 범위에 그 원소 범위 추가 |
| x11: tmp WRITE, 생산자 x10 | src[2]의 관찰 → tmp의 직접 복사. src 전체 사용으로 확대하지 않음 |
| x12: tmp READ, 생산자 x11 | 현재 피연산자는 이 READ. 출처 조회는 x11→x10으로 연결 |
| x13: bias READ | 별도의 피연산자 관찰과 출처 유지 |
| x14: x12·x13을 입력으로 CALC | 두 입력의 calculated 관계. src[2]가 단순 이동한 것으로 표시하지 않음 |
| x15: dst[4] WRITE, 생산자 x14 | 실제 목적지와 계산 결과 전달, 쓰기 범위 추가 |

v2의 현재 작업 조회는 x14에서 tmp와 bias의 실제 입력 관찰, x14 계산, 해당 소스 작업 scope를 제공합니다. src[2]는 기원 조회로 연결됩니다. x15 이후에야 확정된 dst[4] 쓰기를 반환합니다. x11 시점 조회에 x14/x15의 실제 결과·대상은 나타나지 않습니다. 정적인 대입식 정의가 알려져 있더라도 미실행 WRITE와 구별합니다.

두 줄은 출처 간선으로 연결되지만 서로 다른 소스 작업을 임의로 하나의 명령/애니메이션으로 합치지 않습니다. src/dst를 다른 자료구조의 저장소로 바꾸거나 인덱스·포인터·필드로 구현해도 같은 관찰/출처 규칙을 적용합니다.

## E-07 시간과 유효성

- 불변 관찰 사실, 현재 바인딩/경계의 상태, 진행 중 작업의 누적 요약을 구분합니다. 복사가 일어났다는 역사적 사실은 이후 덮어쓰기 때문에 거짓이 되지 않습니다.
- 관계의 성립 시점은 모든 런타임 근거보다 빠를 수 없습니다. 정적인 표현식 정의와 현재 확인된 인자에서 얻은 경계는 이후 실제 접근/결과와 다른 종류로 표시합니다.
- 나중 반례는 그 사건의 change로만 반영합니다. 이전 시점 조회의 상태·종료 시점·최종 대상·완성된 접근 집합에 소급 노출하지 않습니다.
- frame.end가 관찰되면 호출 요약을 닫습니다. 그 이전 값 반환/수신은 별도 사실이며 반환과 동시에 정리된 것으로 간주하지 않습니다. ERROR·입력 대기·기록 제한·명시적 종료를 각각 보존합니다.
- 현재 결과를 알 수 없거나 관찰이 누락되면 미해결입니다. 분석 진단·예산 초과를 사용자 C의 ERROR로 바꾸지 않습니다.

## E-08 조회 API와 시각화 연결

기존 v1 `createExecutionRelationQuery(...).at(executionId)`는 성립한 역사적 관계 조회 의미를 유지합니다. 이를 '현재 유효한 관계만'으로 조용히 바꾸지 않습니다.

확장 조회는 `createExecutionWorkQuery(plan, trace, result, {schemaVersion:2})`로 명시적으로 선택합니다. 기존 3인자 v1 응답은 유지합니다. v2의 `at(id)`도 해당 정규 사건 **이후** 경계이며, `before(id)`는 직전 경계, `at(null)`은 첫 사건 이전입니다.

| 추가 조회 항목 | 반환 내용 |
| --- | --- |
| `workScopes` | 살아 있는 호출/표현식/반복 문맥과 대기/종료 상태, 근거 ID |
| `participants` | 이번 작업의 실제 대상·역할·현재 수명·지역/전역/힙·선언/생성 위치 대응 |
| `regions` | current-access / observed-prefix / bounded-domain, direct/subtree, 실제 집합과 외곽 범위 |
| `transfers` | 이번 값 전달의 입력·출력·변환·판단·참조 변경·부분 범위 |
| `structureBindings` | 현재 성립한 논리 요소와 실제 저장소 대응 |
| `historyRefs` | 해당 작업과 연결되는 이전 비교/복사·종료된 호출/저장소의 관찰 참조 |
| `unresolved` | 누락된 관찰/컴파일 근거·잘린 분석·대안. 정상 빈 결과와 구별 |

출처 그래프의 전체 전개는 별도 지연 조회 `origins(valueRef, {atExecutionId, limit})`로 제공합니다. 현재 작업을 조회할 때 과거 모든 생산자를 재귀적으로 펼쳐 전부 현재 피연산자로 강조하지 않습니다.

렌더러는 기존 시간선과 before/after 상태에서 실제 값 반영 시점을 결정합니다. `at`의 after 관계를 사건 시작부터 반영된 값처럼 사용하지 않습니다. 클릭 미리보기와 재생 중 중간 장면의 기존 계약도 그대로입니다. 분석기는 재생 정지·새 장면·좌표를 반환하지 않습니다.

## E-09 처리 단계와 비용

제안 단계는 입력 점검 → 공통 색인/기능 점검 → 관찰·호출·출처 → 접근 집합 → 경계 분석 → 범용 조합 → 구조 대응 → 작업 조회 색인입니다. 각 단계는 선행 capability를 선언합니다. 기존 판정기 `{id, analyze(context)}`는 어댑터로 유지하고 확장 단계만 명시적 의존성을 사용합니다.

- 사건/관찰 색인과 소스 노드·제어 영역·객체별 생산자 색인은 한 번 구성합니다. 순방향 추가는 해당 사건·관련 슬롯·활성 scope만 갱신합니다.
- 부모마다 모든 자식 사건을 복사해 저장하지 않습니다. 직접 접근 델타와 호출 포함 관계를 보존하고 subtree 집계는 조회/종료 시 공유·캐시합니다. 깊은 호출은 반복형 순회로 처리합니다.
- 모든 호출 쌍·객체 쌍을 비교하지 않습니다. 같은 저장소/구조·호출 관계·실제 전달로 연결된 대상만 후보로 삼습니다.
- 출처는 공유 DAG와 구간 생산자 참조로 유지합니다. 전체 기원 전개와 큰 접근 집합은 지연/페이지 조회하며, 잘린 결과는 complete로 표시하지 않습니다.
- 시점 이동은 관련 prefix와 상태 변경 로그를 조회합니다. 모든 시점의 전체 메모리/레이아웃 스냅샷을 생성하지 않습니다. 사건 내부 애니메이션 프레임마다 분석하지 않습니다.
- 단계 실패는 그 단계/의존 결과의 coverage와 진단에만 반영합니다. 나머지 분석·원래 실행/시각화는 유지합니다.
- 시간·공간은 입력과 실제 의존 간선/출력 관계량에 따라 증가합니다. 깊은 재귀/밀집 의존에서 항상 선형이라고 보장하지 않습니다. 후속 구현의 임시 기본 예산은 [v2 API](execution-relations-v2.md)에 명시했으며, 운영 규모의 최종 예산 검증은 남아 있습니다.

증분은 별도 후속 구현입니다. `append`를 제공할 경우 같은 scope와 이전 prefix 지문이 일치하는 사건 suffix만 받습니다. prefix 수정/다른 실행/구조 결과 변경은 영향 색인 무효화 또는 재분석을 명시하고 이전 분석에 조용히 덧붙이지 않습니다. 구조 결과 교체가 저장 접근 사실까지 변경하지는 않습니다.

## E-10 향후 검증 계약

아래 표는 설계에서 정한 검사 계약입니다. 후속 구현에서 수행한 관련 검사는 [v2 검증](../validation/execution-relations-v2.md)에 별도로 기록합니다. 기대 관계·정체성·범위·순서·성립 시점을 먼저 고정하고 해당 공통 경로만 검증하며, 전체 기존 예제 모음을 자동 반복하지 않습니다.

| 검사군 | 고정할 기대·반례 |
| --- | --- |
| 원본/호환 | plan/trace·호출/반환·값·수명 불변, 기존 v1 API 의미 유지, v2 opt-in |
| 표현 다양성 | 이름/리터럴 변경, 배열/포인터/끝 포인터/멤버/인덱스 기반, for/while/do·재귀/반복 구현 |
| 영역 | 불연속·stride·중첩/겹치는 영역, 실제 집합과 외곽 구분, 원소를 읽지 않은 종료 호출 |
| 경계 | 조기 반환·break·경계 재대입·별칭·불명확 호출·unsigned wrap 가능성에서 과잉 확정 금지 |
| 출처 | 같은 숫자의 다른 원소, 임시 저장/선택/인자/반환/재귀, 다중 입력 계산을 복사로 오인하지 않음 |
| 부분 상태 | 구조체 필드 혼합·패딩·비트필드·중간 원본 수정, overlapping copy, 실제 관찰이 부족한 요약 |
| 수명/시점 | 주소 재사용·realloc·해제 후 보관한 값, 현재 참조와 역사 구별, 미래 반례/최종 범위 누출 금지 |
| 잘못된 논리 | 종료는 정상이나 원소/연결/필드 선택이 잘못된 코드의 실제 관계를 그대로 표시 |
| 제어/공백 | 부분 실행·입력 대기·ERROR·관찰 누락·지원하지 않는 제어에서 미확정/중단 범위 보존 |
| 규모/격리 | 깊은 호출·많은 포인터/별칭·넓은/희소 접근·큰 의존 그래프·예산 초과·판정기 실패 |
| 나중 화면 검증 | 기존 돗자리·수명·출처를 유지하며 구조/관련 구간/연산/코드가 재생 중 동시에 읽힘. API 통과와 별도 판단 |

## E-11 제안 구현 순서와 승인 경계

1. v1 호환·v2 검증·공통 관찰/수명/출처 색인.
2. 명시적 인자/반환/선택·임시 저장의 전달, 계산/복사/참조 구별.
3. 접근 델타·현재 영역/종료 요약·부분 상태·관계 유효성.
4. 확보된 컴파일 근거 범위 안의 경계 분석과 부족한 근거 보고.
5. 작업 scope·범용 조합·구조 대응·v2 조회·자원 예산.
6. 별도 승인 후 기존 시각화 소비 연결과 실제 화면 검증.

각 단계는 관련 반례와 공통 경로로 검증합니다. 이름별 알고리즘 분기·별도 의미 IR·자동 정답 판정은 만들지 않습니다. 1~5의 독립 분석/조회에 이어, 후속 승인으로 6의 기본 입력·화면 연결을 구현했습니다. 상세 경계와 검증은 [연결 보기](work-context-view.md)를 따릅니다. append 세션·일반 자동 배치와 운영 규모의 최종 예산 보장은 남아 있습니다.
