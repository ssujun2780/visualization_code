# C 실행 관찰과 시각화 설계

화면 문서는 [애니메이션·시각화·UI 안내](presentation.md)로 분리했습니다. 이 문서는 코드 분석·명령 정의·관찰·실행 및 화면과의 연결 계약을 담당합니다. 아래 모델 보강 기록의 더미·미구현 설명은 해당 보강 당시의 범위이며 현재 화면 상태는 분리 문서에서 확인합니다.

No20·No21 보강에서는 제어 흐름만 남은 논리식의 CALC·FLOW 연결, C 호출과 내부 ABI 슬롯 구분, void 한정 타입을 적용했습니다. 자료구조 보기는 이름 대신 필드·인덱스·복사·할당 관계와 실제 상태를 근거로 일반 배열·동적 배열 후보를 남깁니다. 논리 보기 ID와 실제 저장 객체·수명을 구분하고 재할당·별칭·중간 상태를 유지합니다. 아직 그림이나 애니메이션을 생성하지는 않습니다. 구체적인 기록 형식과 한계는 [공통 C 모델](c-model.md)에 있습니다.

실수 변환과 매크로로 확장된 판정도 같은 계산 묶음 규칙을 적용합니다. 변환 전후의 C 자료형을 기록하고 내부 비교·정수 확장은 원래 소스 식의 CALC에 포함합니다. 매크로의 정의와 사용 위치는 필요한 경우 컴파일러 토큰의 확장 정보를 추가 수집해 연결합니다. 접힌 순수 builtin 식도 실제 상수 소비값을 결과로 연결하며, 실행되지 않은 호출이나 관찰하지 않은 비트를 만들지 않습니다.

스칼라 반환구에도 컴파일러에서 얻은 C 반환형을 유지합니다. 인자 운반의 출발점은 호출 시점에 관찰한 상수·계산·다른 호출의 반환값이며, 매개변수에 값을 쓰는 사건 자신을 출발점으로 사용하지 않습니다. 호출마다 입력 생산자를 보관해 재귀와 반복에서도 구별하며 추가 식 평가나 READ는 생성하지 않습니다.

구조체 값 전달·반환도 기존 다섯 작업 형식을 사용합니다. 멤버 초기화의 자료형·경로·강조 범위를 AST와 LLVM 배치에 연결하고, 복사된 매개변수는 별도 상자로 표현할 정보를 남깁니다. 내부 byval/sret 주소를 C의 포인터 전달로 해석하지 않으며, 관찰한 복사 상태로 반환구와 호출 복귀를 연결합니다. 포인터 멤버는 복사 후에도 원래 대상과 소속을 유지합니다. 숨겨진 복사 호출은 내부 관찰 근거로 보존하고 소스에 작성한 복사 호출과 구별합니다. 애니메이션은 아직 더미입니다.

공용체는 하나의 공유 저장소로 유지하고, 명시적으로 접근하거나 초기화한 멤버를 컴파일러 필드 참조로 구분합니다. tag 값만 보고 내용을 바꾸거나 멤버를 결정하지 않습니다. 라이브러리 쓰기도 실제 인자·효과 주소와 멤버 경로를 연결하며 별칭이 겹치면 후보를 유지합니다. 열거형에는 컴파일러의 상수 이름·값·기반형·부호 정보를 보존하고 u 배지 규칙을 적용합니다. 디버그 정보가 생략된 선언은 미확정으로 보고합니다. 세부 기록 형식은 [공통 C 모델](c-model.md)에 있습니다.

비트필드의 READ/WRITE는 멤버의 논리값·C 자료형·비트 범위를 사용하고, 물리적인 저장 단위와 내부 추출·삽입은 관찰 근거로 보존합니다. 변경하지 않은 필드의 값 출처도 유지합니다. 실제 소스 식의 연산은 계속 CALC에 남기며, 내부 주소 변환을 계산으로 추가하지 않습니다. 접힌 unsigned 상수에는 피연산자 자료형을, 토큰 결합 매크로에는 컴파일러 확장 위치를 연결합니다. 이 보강도 기존 다섯 작업 형식의 기록 정보이며 애니메이션은 더미입니다.

작성일: 2026-10-28. 실행 전 중간언어 확정·단계 실행 계약 정리: 2026-10-30. AST·LLVM 위치 연결 우선·제한된 원본 조회 적용: 2026-11-02. 아래 전체 지원 범위는 설계 목표이며, 첫 단계의 일부를 CLI 시제품으로 검증했습니다.

목표는 자료구조의 실제 형태, 연산 과정, 값의 출처와 알고리즘의 실행 순서를 보여주는 것입니다. 확정된 구조는 코드 → AST·LLVM 분석 → 중간언어 완성 → GDB처럼 소스 단계별 실행 → 해당 중간언어 명령과 1대1로 대응하는 애니메이션입니다. 중간언어 자체가 캐릭터의 작업 지시서이며, 실행 전에 작업 경계를 확정합니다. 계측은 실행 중 얻은 실제 값·주소·선택 경로를 이미 정의된 명령에 연결합니다. 실제 C 계산은 기존 컴파일러와 런타임이 담당합니다.

화면의 현재 규칙과 구현 상태는 [애니메이션](animation.md)·[시각화](visualization.md)·[UI](ui.md)에 분리했습니다. [문서 안내](presentation.md)에서 각 책임과 세부 명세를 확인할 수 있습니다. 초기 재생·함수·조건·배선 개발 과정과 당시 검사 수치는 [화면 개발 이력](../validation/animation-prototype-history.md)에 보존합니다.

현재 웹은 단일 C11 소스를 Clang/WASI 도구로 컴파일하고 실행합니다. 기본 CLI 모델은 AST의 소스 작업별 명령 정의와 LLVM 관찰 계획을 분리하고 실제 실행값을 스키마 3의 plan.json·trace.json에 연결합니다. --compile-only는 사용자 C를 실행하지 않고 명령 정의를 생성합니다. 일괄 trace API, 입력 대기 실행 세션, 비캐릭터 재생 UI의 구현 범위는 구분합니다. 입력 세션은 같은 실행을 유지하며 입력 요청 사이의 구간을 관찰·재생하지만, 모든 명령 직전의 실제 실행 정지와 편집 화면 전체의 통합까지 완성한 것은 아닙니다. 자세한 현재 범위는 [공통 C 모델](c-model.md)과 [입력 세션](interactive-input.md)을 따릅니다.

2026-11-04 누적 감사에서는 소스 연산자·현재 READ 입력·실제 저장 범위·수명·분기 선택을 공통 계약으로 검사하도록 보완했습니다. 삼항 선택은 FLOW 뒤에 선택된 가지의 작업을 배치합니다. 재귀 자료구조의 현재 도달성과 물리 저장 공간·과거 링크는 구분하며, 연결 모양만으로 BST 같은 의미를 확정하지 않습니다. 검사 통과를 모든 C 의미의 지원 완료로 해석하지 않습니다. 확인된 결함과 남은 범위는 [공통 모델 감사](model-audit-2026-11-04.md)에 기록합니다.

## 상세 표시와 간결 표시

저장·전송은 [공통 정의 분리](execution-storage.md)를 사용합니다. 자료형·표현식·위치를 표로 분리해도 복원한 사건과 값·출처는 같습니다. 이는 간결 표시나 사건 생략이 아니며 재생 전에 기존 스키마 3으로 복원합니다.

중간언어 기록은 항상 상세 기준이며, 간결 표시는 기록을 삭제·재정렬하지 않습니다. 표시 모드와 도구·전달·조건의 연출은 [애니메이션 설계](animation.md), 조작과 구현 상태는 [UI 설계](ui.md)에 분리했습니다. 함수 반환 수신 작업과 공간 정리 순서는 계속 [생성 모델 계약](return-sequence.md)을 따릅니다.

## 코드에서 중간언어로 변환하는 과정

아래는 실행 전에 완료해야 하는 변환 과정입니다. `int c = a + b * 2;`를 예로 사용하며, 식별자와 명령 표기는 설명용입니다. LLVM IR은 실행·계측용이고, SPACE·READ·CALC·WRITE 등의 중간언어는 시각화 작업을 정의하는 별도 형식입니다.

### 1. AST·LLVM을 우선 분석하고 결과를 재사용

변환의 최초 입력은 편집기에서 작성하거나 파일에서 읽은 **원본 C 코드 문자열(source)**입니다. 예를 들어 a와 b가 선언된 전체 프로그램에서 다음 문장 자체를 텍스트로 입력받습니다.

```c
int c = a + b * 2;
```

**분석 순서는 AST·LLVM과 코드 위치 연결 → AST·LLVM 정보 우선 사용 → 없는 정보만 해당 원본 범위 확인입니다.** 중간언어 생성 모델은 원본 전체를 별도로 읽어 문장·계산식·제어 구조를 재구성하지 않습니다. AST의 소스 의미와 LLVM의 실행·관찰 정보를 연결하며, 필요한 정보가 이미 있으면 그대로 재사용합니다.

| 필요한 정보 | 우선 사용할 자료 |
| --- | --- |
| 선언·문장·괄호·연산자·대입·호출·제어 구조 | AST 노드와 소스 범위 |
| 계산 묶음·우선순위·자료형·명시적/암시적 변환 | AST의 식 구조와 의미 정보 |
| `&&`·`||`·`?:`의 평가 경로와 생략 대상 | AST와 컴파일러의 확정 정보; 실제 선택은 실행 관측 |
| 실제 연산·값의 생산과 사용·계측 지점 | LLVM과 디버그 정보 |
| 매크로 정의·호출 위치와 확장 관계 | 컴파일러의 전처리·소스 위치 정보 |

예를 들어 `0 && f()`의 오른쪽 호출이 LLVM에 없어도 AST에 식이 남아 있으면 그것으로 작업과 생략 조건을 정의합니다. 실제 호출이 관측됐다고 기록하지 않습니다. `a + b * 2`와 `sum += j + 1`의 CALC 묶음도 AST로 결정합니다. 기존 묶음 규칙의 결함이나 AST 텍스트 덤프 파서의 정보 누락을 원본 전체 재분석으로 우회하지 않고, 해당 규칙과 정보 추출을 보완합니다.

원본 확인은 다음 조건으로 제한합니다. 현재 공통 위치 모듈은 토큰 끝과 표시 문자열 조회에 이 규칙을 적용합니다. 외부 헤더·매크로 위치 등의 전체 지원은 후속 범위입니다.

- 필요한 정보와 누락 사유를 먼저 정하고, 기존 AST·LLVM·디버그·전처리 정보로 해결되는지 확인합니다. 이미 확보한 정보에는 원본 확인을 요청하지 않습니다.
- 작성된 리터럴·식의 표기를 그대로 표시해야 하거나, 컴파일러 정보만으로 소스 범위를 확정할 수 없는 경우에만 해당 범위의 텍스트·토큰을 확인합니다. 단순 원문 추출과 문법·의미 재분석을 구분합니다.
- 컴파일한 소스 스냅샷의 위치 정보를 사용하고, 필요한 최소 범위만 읽습니다. 문자열·주석을 구별하는 컴파일러의 토큰 정보를 우선 사용하며, 연결이 불확실하면 미대응으로 남깁니다. 원본으로 자료형·실행값·실행 순서를 추측하지 않습니다.
- AST·LLVM의 파싱 결과와 노드·위치·생산자 조회 인덱스는 변환 내에서 공유합니다. 원본 범위 조회도 소스 스냅샷·범위·목적별 결과를 재사용하며, 반복·호출마다 소스를 다시 분석하지 않습니다. 변환 간 캐시를 도입한다면 소스·헤더·컴파일 설정·컴파일러가 바뀔 때 무효화합니다.
- 예외 확인의 사유·대상 노드·범위·근거를 남겨 중복 확인을 점검할 수 있게 합니다. 예외 처리 때문에 매 명령마다 원본을 읽는 경로를 만들지 않습니다.

```text
C 코드(텍스트: source)
  → Clang → AST + LLVM + 디버그·전처리 정보
  → AST·LLVM과 원본 위치 연결, 조회 인덱스 공유
  → AST·LLVM 정보 우선 사용
  → 중간언어 명령 정의 + 관찰 연결
       └─ 필요한 정보가 부족할 때만 원본의 지정 범위 확인
```

현재 호출도 `instrumentLLVM(analysis.llvm, source, { ...options, ast: analysis.ast })` 형태로 원본 텍스트를 함께 전달합니다. source-map.mjs는 원본 스냅샷과 해시를 보존하고, 먼저 컴파일러 위치를 연결합니다. 텍스트 AST 덤프에 빠진 마지막 토큰 길이와 표시 문자열만 사유·범위를 남겨 원본에서 확인하며, 위치·토큰·범위 조회를 재사용합니다. case 값은 AST·LLVM에서 가져옵니다. 행·열·바이트 범위와 편집기용 UTF-16 범위를 plan에 남기며, 연결할 수 없는 범위는 누락으로 명시합니다. 세부 필드는 [공통 모델의 위치 연결](c-model.md#위치-연결과-제한된-원본-조회)을 따릅니다.

Clang이 같은 소스와 컴파일 설정에서 AST, LLVM IR, 디버그 정보를 생성합니다. AST에서는 선언·스코프·자료형·형 변환·식의 결합 구조를 얻고, LLVM에서는 실제 실행 연산과 값의 생산·사용 관계를 얻습니다. 디버그 정보는 두 표현을 원본 소스 위치와 연결하는 근거입니다. 현재 시제품은 이 텍스트 출력을 JavaScript로 분석합니다.

```text
VarDecl c : int
└─ 초기화 식: +
   ├─ LValueToRValue
   │  └─ a : int
   └─ *
      ├─ LValueToRValue
      │  └─ b : int
      └─ IntegerLiteral 2 : int
```

LValueToRValue는 저장 장소를 나타내는 식에서 값을 얻는 변환으로, 이 예제에서는 a와 b의 READ를 연결할 근거입니다. 상수 2는 입력 리터럴이므로 READ를 만들지 않습니다. 곱셈이 덧셈의 오른쪽 자식이라는 구조가 우선순위를 나타냅니다. 이 단계에서 a와 b의 실제 값이나 최종 결과를 계산해 넣지 않습니다.

2026-11-04 CALC 내부 연출 합의: 이미 확보한 입력값을 AST의 왼쪽 부분부터 받아들이며 진행합니다. 괄호와 C 연산자 우선순위는 유지합니다. a+b*2라면 a를 먼저 받아 두고, b*2의 결과가 준비되면 더합니다. 이를 (a+b)*2로 바꾸지 않습니다. 이 연출 순서는 실제 READ·호출·증감·WRITE의 관측 순서를 바꾸는 규칙이 아닙니다.

예를 들어 (a+1>b*2)&&(c-1!=0)는 하나의 CALC 안에서 다음과 같이 표현합니다. 아래의 단계는 별도 중간언어 명령이 아닙니다.

```text
a+1을 받아 계산 → b*2를 받아 계산 → 앞쪽 >의 참/거짓 불빛
→ c-1을 받아 계산 → 뒤쪽 !=의 참/거짓 불빛
→ 전체 &&의 참/거짓 불빛
```

왼쪽이 거짓인 &&와 왼쪽이 참인 ||는 실제로 생략된 오른쪽 입력을 받아들이거나 계산하지 않습니다. 생략 표시를 남긴 채 전체 판정으로 이어갑니다. READ 결과는 읽은 시점의 고정값으로 취급하고 출처를 유지합니다. 계산 중 원본 상자의 현재값으로 바꾸지 않습니다. 관측 steps는 결과를 연결하는 근거이며 원소 배열 순서가 연출 순서는 아닙니다. AST의 expression 트리와 각 관측 단계의 노드·입력 연결로 연출을 구성합니다. 현재는 규칙만 기록하며 애니메이션과 별도 연출 표지는 더미 상태를 유지합니다.

### 2. AST의 소스 작업을 중간언어 명령으로 정의

AST의 의미 정보로 선언은 SPACE, 값 읽기는 READ, 계산식은 CALC, 초기화 저장은 WRITE로 분리합니다. 계산식의 최상위 묶음을 먼저 확정하고 하위 산술·비교·논리·변환 노드를 그 CALC에 소속시킵니다. LLVM 연산마다 독립 CALC를 만든 뒤 실행이 끝나고 합칠지를 판단하지 않습니다.

정적 sizeof는 이 계산 묶음의 크기 입력입니다. 컴파일러가 계산 전체를 접어 LLVM에 결과 상수만 남겨도, AST에서 정의한 CALC를 실제 상수 소비 지점에 연결해 유지합니다. 입력 크기는 컴파일러 자료형 정보, 결과는 실제 전달값에서 얻으며 compiler-folded 근거를 남깁니다. 런타임 평가가 필요한 sizeof(VLA)는 기존 실행 관찰을 사용합니다.

```text
P_c    SPACE c : int
R_a    READ a → v_a
R_b    READ b → v_b
K_c    CALC v_a + v_b * literal(2) → v_result
W_c    WRITE c ← v_result
```

v_a, v_b, v_result는 실행값을 연결할 입력·결과 참조이며 별도의 사용자 변수 상자가 아닙니다. K_c의 내부에는 `*`와 `+` 노드 및 둘의 의존관계를 둡니다. 각 노드의 C 자료형과 형 변환도 보존합니다. 반복 실행 시에는 이 정의를 재사용하며, 실행 회차는 나중에 구별합니다.

`sum += j + 1`도 이 단계에서 기존 sum 값과 `j + 1`을 더하는 K 하나와 최종 WRITE로 정의합니다. 복합 대입의 AST 노드가 값을 변경한다는 이유로 그 계산 부분을 두 CALC로 나누지 않습니다. 호출이나 중간 대입이 있으면 해당 FLOW·WRITE를 정의하고, 그 결과가 어느 CALC 입력으로 전달되는지도 연결합니다. 논리식은 평가 조건과 생략 가능한 하위 식까지 정의하되 어느 경로가 선택됐는지는 미리 채우지 않습니다.

### 3. LLVM에서 실제 관찰할 연산을 추출

해당 예제의 LLVM은 다음 형태입니다. 이름·정렬·디버그 표기는 단순화했으며, i32는 이 예제의 wasm32 대상에서 사용하는 int의 표현입니다.

```llvm
%a_value = load i32, i32* %a
%b_value = load i32, i32* %b
%mul = mul nsw i32 %b_value, 2
%add = add nsw i32 %a_value, %mul
store i32 %add, i32* %c
```

load·mul·add·store에서 각각 읽기·곱셈·덧셈·쓰기 관찰 지점을 정의합니다. `%mul`, `%add`는 컴파일러의 값 식별자이므로 사용자 변수 상자로 노출하지 않습니다. 이 코드의 a와 b 읽기 순서는 해당 컴파일 결과의 순서이며, 연산자 우선순위가 모든 피연산자의 평가 순서를 보장한다는 뜻은 아닙니다.

c의 alloca는 함수 진입으로 앞당겨질 수 있습니다. 물리적 저장 공간 확보와 소스 선언 도달을 구별하여, alloca의 관찰과 `llvm.dbg.declare` 위치에 추가할 선언 관찰을 같은 SPACE에 연결합니다. 상자의 표시 시점은 선언 도달을 기준으로 합니다.

### 4. AST 작업과 LLVM 관찰 지점을 명시적으로 연결

LLVM의 소스 위치를 AST의 범위·노드에 대응시키고 자료형과 값의 생산·사용 관계를 함께 확인합니다. 변수 이름의 의미나 줄 번호만으로 명령을 추측하지 않습니다. 목표 연결은 다음과 같습니다.

| LLVM 관찰 지점 | 연결할 중간언어 | 실행 중 수집할 정보 |
| --- | --- | --- |
| c의 저장 공간 확보 + 선언 도달 | P_c | 실제 저장 공간과 선언 진입 |
| a의 load | R_a | 대상 객체·주소·읽은 값 |
| b의 load | R_b | 대상 객체·주소·읽은 값 |
| mul | K_c의 `*` 내부 노드 | 피연산자와 실제 곱셈 결과 |
| add | K_c의 `+` 내부 노드 | 피연산자와 실제 덧셈 결과 |
| c의 store | W_c | 대상 객체·주소·저장값 |

곱셈과 덧셈의 관찰 지점은 둘이지만 연결할 CALC 정의는 K_c 하나입니다. bindings에는 명령 ID, 내부 식 노드, 필요한 관찰 역할을 보존합니다. 같은 명령의 입력과 최종 결과를 생산하는 관찰 지점도 식별합니다. 연결이 불확실하거나 컴파일 과정에서 사라진 연산은 관측 가능 범위와 근거를 명시하며, 실행되지 않은 계산의 관측값을 만들어 넣지 않습니다.

### 5. 관찰 호출을 삽입하고 실행 코드를 준비

관찰 계획에 따라 LLVM에 `__cvm_emit` 호출을 삽입합니다. 곱셈을 예로 들면 다음과 같습니다. 아래는 호출 의미를 설명하는 의사코드입니다.

```text
곱셈 직전 관찰: 관찰 지점 ID와 실제 피연산자 전달
%mul = 원래 프로그램의 곱셈
곱셈 직후 관찰: 관찰 지점 ID와 실제 결과 %mul 전달
```

읽기·쓰기에는 접근 대상·범위를, 계산에는 피연산자·결과를 전달하도록 관찰 코드를 준비합니다. 실행 시 관찰기는 오류 조건을 검사하고 실제 결과를 수집합니다. 원래 C 식을 기록용으로 재실행하지 않습니다. 실행 모드에서는 계측 LLVM을 WebAssembly로 컴파일·링크하여 준비하고, 실제 C 계산은 이 프로그램이 수행합니다. 중간언어를 실행하는 별도의 C 인터프리터를 만드는 방식이 아닙니다.

### 6. 실행 전에 중간언어 변환을 완료

변환의 산출물은 중간언어 명령 정의(plan), 명령과 관찰 지점의 연결(bindings), 계측된 실행 코드입니다. 명령의 식별자·입출력·자료형·소스 위치·계산 묶음·제어 연결을 검사합니다. compile-only는 사용자 프로그램을 실행하지 않고 명령 정의와 계측 LLVM 등의 변환 산출물을 반환합니다. 단계 정지·재개에 필요한 경계의 실제 구현은 후속 작업입니다.

| 실행 전에 확정할 내용 | 실행하면서 채울 내용 |
| --- | --- |
| P_c, R_a, R_b, K_c, W_c의 정의와 연결 | 각 명령의 실행 회차와 호출 프레임 |
| K_c의 식 구조, 자료형, 상수 2 | a=10, b=20 같은 실제 입력값 |
| `*`와 `+`를 같은 K_c에 연결하는 규칙 | 곱셈 결과 40, 덧셈 결과 50 같은 실제 관측값 |
| 저장 대상 c의 선언 및 접근 정의 | 실제 객체·주소와 저장값 |
| 조건식의 평가 경로와 분기 목적지 | 선택된 경로와 생략된 작업 |

위의 10·20·40·50은 실행 정보의 예시입니다. 변환 단계에서 정답을 미리 넣지 않습니다. 이후 단계 실행에서는 이미 확정된 K_c의 실행 한 건에 중간값과 최종값을 연결하며, 애니메이션도 K_c 한 건에 대응합니다.

현재 구현은 공통 위치 인덱스로 LLVM 관찰 연산과 AST를 연결하고, AST 노드별 계산 소속을 미리 정한 뒤 관찰 지점을 명령에 배정합니다. `a + b * 2`와 순수 계산인 `sum += j + 1`은 각각 CALC 하나이며, 내부 연산 결과는 steps에 보존합니다. No4에서 복합 대입의 중복 CALC, ++/-- 계산형 누락, do-while 조건 위치를 수정·검증했습니다. 이 구현이 모든 부작용·논리식 결합을 완전히 지원하거나 단계 정지·재개까지 구현했다는 뜻은 아닙니다.

## 실행 전 중간언어 완성과 단계 실행

```text
C 코드(텍스트)
  → Clang의 AST·LLVM 생성 → AST·LLVM과 원본 위치 연결
  → AST·LLVM 정보 우선 사용 → 없는 정보만 원본의 필요한 범위 확인
  → 중간언어 명령 정의 완성
  → 실제 실행 코드의 관찰 지점 연결
  → 다음 소스 실행 단계까지 진행하고 정지
  → 해당 명령의 실제 실행 정보 확보
  → 중간언어 명령별 애니메이션 실행
  → 재생 제어에 따라 다음 단계 진행
```

중간언어의 완성이란 명령 종류, 소스 위치, 계산 묶음, 입력·출력 연결, 분기·호출·반복의 실행 연결을 실제 실행 전에 정한다는 뜻입니다. 실행되지 않을 경로의 명령도 정의합니다. 실제 값과 주소, 동적 할당의 크기·대상, 분기 선택과 반복 횟수는 실행하면서 채웁니다. 실행 후 관찰 목록을 보고 CALC의 개수나 애니메이션 작업 경계를 새로 정하지 않습니다.

단계 실행은 소스 문장과 조건 평가·함수 진입·복귀 등의 경계를 기준으로 합니다. 한 단계에는 여러 중간언어 명령이 있을 수 있습니다. 실행 제어기가 해당 단계의 관측값을 확보하고 정지하면 그 명령들을 순서대로 애니메이션에 전달합니다. 애니메이션 완료 또는 명시적인 건너뛰기 이후 다음 단계로 진행합니다. 실행 속도와 애니메이션 속도는 따로 조절하되, 기본 단계 모드에서 프로그램 전체를 먼저 끝까지 실행하는 것을 전제로 하지 않습니다.

예를 들어 `int c = a + b * 2;`는 실행 전에 다음 시퀀스로 확정합니다. 아래는 설명용 표기이며 별도의 API 문법이 아닙니다.

```text
SPACE c : int
READ a → 입력①
READ b → 입력②
CALC 입력① + 입력② * 2 → 결과
WRITE c ← 결과
```

실행 중 입력①=10, 입력②=20이 관측되면 CALC 하나에 곱셈 중간 결과 40과 최종 결과 50을 연결합니다. 연산자 우선순위와 C 자료형·변환을 보존하며, 내부 결과는 steps 정보로 남깁니다. steps를 별도 명령이나 애니메이션으로 늘리지 않습니다. 상수 2는 입력 리터럴이므로 별도 READ가 필요하지 않습니다.

`sum += j + 1`의 계산 부분도 기존 sum 값과 `j + 1`을 더하는 CALC 하나로 정하고, 최종 저장은 WRITE로 분리합니다. 산술·비교·논리·형 변환의 묶음과 `&&`·`||`·`?:`의 평가 조건을 AST에서 먼저 정의합니다. 단락 평가로 생략된 부분은 실행 정보에 생략 상태로 남기며, 생략된 READ·호출·계산을 만들어 넣지 않습니다. 식 내부 평가 경로와 계산 완료 후 if 본문 등으로 이동하는 FLOW를 구별합니다.

알루는 왼쪽 값과 연산자를 받은 시점에 결과가 확정되면 바로 결과를 표시할 수 있습니다. `0 && ...`는 거짓, 0이 아닌 값의 `|| ...`는 참이며 오른쪽은 실행하지 않습니다. 그 외에는 실제 오른쪽 평가 결과를 기다립니다. 이는 상수뿐 아니라 실제로 읽은 변수 값에도 적용합니다. 강조된 코드의 도움말은 결과가 확정된 이유와 생략된 식을 설명합니다. 현재 중간언어에는 helpMarker(status="stub")로 이유·강조 범위·생략 범위를 예약하며, 도움말 UI와 연출은 후속 작업입니다. 구현 필드는 [논리식·삼항식 평가와 도움말 더미](c-model.md#논리식삼항식-평가와-도움말-더미)를 따릅니다.

`c = f() + (x = 3);`에서는 함수 호출·반환과 x에 쓰는 작업을 FLOW·WRITE로 보존하고, 그 작업이 제공한 값을 덧셈 CALC의 입력에 연결합니다. 이미 전달받은 반환값·대입식 결과를 이용하기 위해 독립 READ를 추가하지 않습니다. 실제 호출·읽기·쓰기 순서는 관측을 따르며, 식을 보기 좋게 표시하려고 실행 기록을 사후 재정렬하지 않습니다.

증가·대입이 논리식 내부에 있어도 같은 원칙을 적용합니다. 예를 들어 `a && b && c++ < limit`의 외부 논리식은 한 CALC로 기록하되, 실제 평가된 `c++`의 증가 CALC와 WRITE는 별도 작업으로 유지합니다. 내부 쓰기만으로 대기 중인 외부 식을 완료하지 않으며, 단락 평가로 생략된 증가는 기록하지 않습니다. 2026-11-12의 구현과 검증 범위는 [논리식 경계 보완](../validation/logical-boundaries-fixes-2026-11-12.md)을 따릅니다.

같은 식을 반복 실행하면 명령 정의는 재사용하고 실행 회차별 기록을 만듭니다. instructionId는 정의를, executionId와 activationId는 해당 실행과 호출을 식별합니다. 실행 중 수집한 정보가 부족하거나 실패한 경우에도 명령 경계는 유지하고 미완료·실패 상태와 관측 범위를 남깁니다.

## 유지할 원칙

분기나 case의 이동은 실제 작업에 연결하는 원인·진입 정보로 보존합니다. No3에서 case 3 선택 → default로 fall-through → break의 경로와 대입을 결정한 분기 실행을 연결했습니다. 합류 이후 작업에는 끝난 분기의 원인을 붙이지 않습니다. 복합 대입의 계산형과 저장형도 구분하며, 이 정보 보강으로 기존 작업 수나 애니메이션 더미의 범위를 바꾸지 않습니다.

가장 기본적인 재생 단위는 소스 문장의 실행입니다. 선언 → 그 초기화 → 다음 문장 순서를 지키고, 한 순수 계산식의 비교·산술은 CALC 하나에 실제 중간 결과를 담습니다. 비교 결과를 저장형으로 넓히는 컴파일러 보조 연산은 비교에 흡수하되 C의 부호·폭 변환은 보존합니다. 출력도 해당 호출에 연결하는 것을 목표로 합니다. 현재는 실제 전달 바이트와 관찰된 버퍼 쓰기 출처를 연결하며, 최종 stdout 문자열을 임의로 나누어 과거 호출에 배정하지 않습니다. 버퍼 출력과 직접 출력이 섞여 호출 순서와 전달 순서가 달라지면 실제 전달 순서를 보존하고 차이를 보고합니다. No1–9에서 소스 작업 순서를 검증하며 애니메이션 대응은 더미로 유지합니다.

- 기본 형식은 READ, WRITE, CALC, FLOW, SPACE 다섯 가지입니다. 추가 문법은 우선 피연산자, 자료형, 의존관계, 수명, 작업 시퀀스로 표현합니다.
- 중간언어 명령 하나는 애니메이션 작업 하나에 직접 대응합니다. 한 작업에 여러 화면 프레임이나 시작·완료 단계가 있을 수 있지만, 재생기가 LLVM 기록을 다시 해석해 행동 단위를 정하지 않습니다. 복합 C 문장은 필요한 중간언어 명령 시퀀스로 변환합니다.
- C의 자료형과 실행 규칙을 유지하면서, 하드웨어 명령 때문에 나뉜 동작은 사람이 읽기 좋은 표현식으로 묶습니다.
- 소스 문장의 진행을 기준으로 작업을 배치합니다. `int first=10;`은 `SPACE first → WRITE immediate(10)`이며, 그 뒤 다음 선언으로 넘어갑니다. 물리적인 줄 나눔이나 컴파일러의 선행 스택 확보 순서로 작업 순서를 정하지 않습니다.
- 같은 출력 호출의 연속된 본문·줄바꿈 조각은 하나의 WRITE로 표현합니다. 서로 다른 호출은 유지하며, 원시 출력 전달 횟수를 캐릭터의 작업 횟수로 삼지 않습니다. 호출 연결을 확인할 수 없는 출력은 추측해서 합치지 않습니다.
- 소스에 작성된 복사, 임시변수, 반복 비교, 명시적 할당과 저장 순서를 보존합니다. 컴파일러가 추가한 내부 보조 작업은 관측 근거로 분리합니다. 함수 이름이나 알고리즘의 목적만 보고 표준 동작으로 치환하지 않습니다.
- 실행 상태, 관찰 기록, 화면의 박스와 위치, 캐릭터 동작을 분리합니다. 실행 속도는 애니메이션 속도와 독립적입니다.
- 계측에서 얻지 못한 정보는 미관측으로 남깁니다. 설명용 모델과 추정한 자료구조는 실제 관측과 구분합니다.

## 분석과 실행의 연결

1. 각 소스와 헤더를 같은 컴파일 설정으로 전처리하고 분석합니다. 자료형, 선언, 스코프, 원본 표현식과 위치를 등록합니다.
2. AST의 원본 작업과 계산식 전체를 기준으로 중간언어 명령 또는 명령 시퀀스를 확정하고, 각 명령에 고유 번호를 부여합니다. 여러 LLVM 연산이 같은 CALC에 속할 수 있으며, 실행 기록에서 묶음의 경계를 다시 추론하지 않습니다. 별도 관찰 계획은 이 명령에 필요한 실제 실행값을 수집하도록 연결합니다. 매크로는 사용 위치와 확장 위치를 함께 보관합니다.
3. 함수 진입, 스코프 수명, 식의 값, 메모리 접근에 관찰 코드를 연결합니다. 이 번호가 컴파일러 변환을 거쳐 실제 계측 위치에 전달되도록 구현해야 합니다.
4. 실행 제어기를 통해 다음 소스 단계까지 진행하고, 값과 주소, 실제 분기, 할당 결과를 해당 명령의 실행 정보로 기록합니다. 라이브러리는 별도 관찰 지원을 연결합니다.
5. 정지한 단계의 실행 정보를 이미 완성된 명령 정의에 연결하고, 명령별 애니메이션을 실행합니다. 다음 단계의 정지·재개, 호출 안으로 진입할 경계, 애니메이션 완료·건너뛰기의 연결은 후속 실행 제어 구현 사항입니다.

행 번호만으로는 한 줄의 여러 접근, 암시적 변환, 매크로를 구분하기 어렵습니다. AST 작업과 계측 지점의 명시적인 연결이 필요합니다. 초기 실험에서는 최적화 영향을 줄이고 원본 작업의 관찰 범위를 먼저 검증합니다. 현재 번들 컴파일러에 플러그인 옵션만 추가하면 되는 작업으로 가정하지 않습니다.

## 중간 표현의 계약

생략된 주소 계산의 입력 근거와 관측 참조는 [주소 출처 계약](address-origin-contract.md)의 `input.addressOrigin`으로 인계합니다. 기저 사건을 실제 주소값 생산 사건으로 위조하거나 주소 계산을 독립 명령으로 늘리지 않습니다.

중간 표현은 관찰 계획과 실행 결과를 연결하는 공통 형식입니다. C 프로그램의 계산 자체는 기존 실행 환경이 담당합니다.

| 형식 | 관찰하는 작업 | 주요 정보 |
| --- | --- | --- |
| READ | 값이나 주소의 사용 | 객체와 필드 경로, 실제 접근 위치, 폭, 값, 이전 쓰기 |
| WRITE | 초기화와 대입, 출력 | 대상, 실제 저장값, 이전 기록 상태, 값과 주소의 출처 |
| CALC | 산술, 비교, 논리, 변환, 주소 계산 | 식의 구조, 피연산자별 자료형, 실제 결과, 평가 여부 |
| FLOW | 분기, 반복, 진입과 복귀, 종료 | 실제 선택 경로, 목적 호출과 위치, 종료 이유 |
| SPACE | 객체와 프레임의 생성, 종료, 크기 변경 | 수명, 저장 영역, 크기, 이전 객체와의 관계 |

호출과 반환, 복사, 교환, 증가, 입력과 출력은 기본 형식의 시퀀스입니다. 검사와 오류는 명령의 조건 및 결과로 표현합니다. 각 명령에는 입력·대상·결과·상태 변화를 명확히 연결하여 대응하는 행동을 바로 선택할 수 있게 합니다. 하나의 행동에 수반되는 여러 상태 변화와 별개의 행동 명령을 구분합니다. 작업 내부의 중간 결과나 실패 지점도 보존합니다. 원시 계측 사건의 번호는 명령의 관측 근거이며, 그 자체를 최종 명령 번호로 간주하지 않습니다.

2026-11-03 확정: 상수·일반 숫자·주소의 계산은 모두 같은 CALC 형식과 알루 도구로 표현합니다. 이 구분으로 별도의 애니메이션 명령 종류를 만들지 않습니다. C의 자료형·부호·폭·포인터 원소 단위 규칙은 유지하며, 실제 주소와 값은 관측 결과를 사용합니다. 예를 들어 int 원소가 4바이트인 대상의 `p + 2`는 원소 두 칸 이동하는 CALC 하나이고, 내부의 8바이트 환산을 별도 계산 애니메이션으로 펼치지 않습니다. 기존 소스 식 묶음과 READ·WRITE·FLOW 경계는 유지합니다.

각 메모리 박스에는 컴파일 대상의 ABI에서 얻은 바이트 크기를 부가 정보로 표시합니다. 포인터 상자의 크기와 가리키는 객체의 크기는 각각의 저장 공간 정보입니다. 이 정보는 sizeof의 설명이나 용량 확인에도 사용합니다. Shift+클릭으로 여러 박스를 선택하면 선택 범위의 총 바이트 수를 보여주는 기능을 후속 시각화 항목으로 둡니다. 선택·합산의 세부 규칙과 UI는 시각화 구현 단계에서 구체화하며, 이번 결정은 구현 완료를 뜻하지 않습니다.

포인터 간 거리는 원소 기준(2칸), 바이트 기준(8B), 함께 표시(2칸·8B)를 선택할 수 있게 합니다. C 식의 결과 2는 그대로 유지하며 CALC의 distance 부가 정보로 표시 단위를 전환합니다. 원시 바이트 계산과 원소 크기 환산을 별개의 소스 뺄셈 애니메이션으로 늘리지 않습니다. 현재 모델에는 거리 정보와 끝 다음 참조 정보까지 연결하며, 표시 선택 UI는 후속 작업입니다.

관찰 계획에는 다음 필드를 둡니다.

```text
schemaVersion, programId, instructionId, kind
source: 파일 ID, 내용 해시, 원본 범위, 매크로 위치
declarationId, scopeId, typeId
operands: 값·주소·조건의 의존관계
observe: 수집할 값과 접근 정보
checks: 수명·범위·초기화·연산 조건
scene: 장면 묶음과 표현식 내부 구조
```

실행 사건에는 다음 필드를 둡니다.

```text
schemaVersion, runId, eventId, instructionId
activationId, scopeInstanceId, phase
target: objectId, 객체 내부 위치, 접근 크기, 필드 경로
value: typeId, 폭, 실제 비트 또는 정밀도를 잃지 않는 표현
dataInputs, addressInputs, controlInputs, previousWrite
evidence, initialization, diagnostic, sceneInstanceId
```

`instructionId`는 코드상의 작업이고 `eventId`는 특정 실행에서 발생한 사건입니다. 반복마다 사건 번호를 새로 만들고, 재귀 호출에는 별도 호출 번호를 부여합니다. 변수 이름만으로 객체를 연결하지 않습니다.

`phase`는 접근 시도, 완료, 실패를 구분합니다. 검사에 실패한 쓰기는 시도와 오류만 기록하고 완료 사건을 만들지 않습니다. 기록이 끊긴 실행은 마지막 확인 상태와 미완료 구간을 표시합니다.

`evidence`는 실제 관측, 컴파일러가 확정한 정보, 추론, 설명 모델, 미관측을 구분합니다. 초기화 여부는 별도 상태이며, 미관측 값을 쓰레기값으로 표시하지 않습니다. 정수와 실수의 원본 비트, 포인터 폭을 JavaScript Number 변환으로 잃지 않도록 전달합니다.

## 자료형과 객체

실행마다 언어 버전, 대상 ABI, 바이트 순서, 자료형 크기·정렬, char의 부호, 라이브러리와 계측 범위를 기록합니다. 현재 wasm32와 향후 네이티브 실행의 주소 크기나 배치를 같다고 가정하지 않습니다.

- 박스는 논리적인 C 객체입니다. 실제 주소가 관측되지 않은 지역변수에 가짜 스택 주소를 만들지 않습니다.
- 배열과 구조체 필드는 부모 객체 내부의 경로와 위치로 식별합니다. 여러 서랍과 격자 표현이 같은 메모리를 공유합니다.
- 기본 정수 표시는 `int`처럼 하고 unsigned만 u 배지로 구별합니다. 배열에는 전체 크기·차원과 원소의 자료형·비트 폭을 각각 보존합니다. `int[5]`는 32비트 int 다섯 개이며, 전체가 160비트인 단일 정수가 아닙니다.
- 초기화된 필드와 패딩 바이트를 구분합니다. 구조체의 패딩을 값이 잘못됐다는 이유로 표시하지 않습니다.
- 정적 객체의 초기값과 수명은 호출 프레임과 별개입니다. 함수 안의 static도 호출이 끝났다고 제거하지 않습니다.
- 스코프 종료는 객체의 현재 수명을 끝내지만 과거 기록은 유지합니다. 같은 주소를 다음 변수가 사용해도 다른 객체입니다.
- 객체의 수명 등록과 초기화문의 실행을 구분합니다. goto로 초기화문을 건너뛴 변수도 이후 접근에서 식별하고 미초기화 상태를 유지합니다. 화면에서 선언 시 상자를 펼치는 연출이 이 수명 정보를 대신하지 않습니다.
- const로 접근하는 경로와 실제 객체의 수정 가능성을 구분합니다. 문자열 리터럴과 원래 const인 객체의 수정도 별도로 판정합니다.

## 표현식과 제어 흐름

`_Generic`은 컴파일러가 선택한 연관 항목과 미평가 제어식을 소스 메타데이터로 남깁니다. 선택된 식·실제 호출만 기존 명령으로 실행하며 가짜 런타임 분기는 만들지 않습니다. `_Alignof`는 컴파일러 배치·대상 ABI에서 정렬 정보를 얻어 소스 계산에 연결합니다. 접힌 정렬 비교도 실제 소비된 상수값을 결과로 연결하므로 출력 직전에 이유 없는 1이 나타나지 않게 합니다.

| 사례 | 관찰 및 애니메이션 규칙 |
| --- | --- |
| `a+b*2` | 식의 트리와 C 자료형을 보존하고 한 알루 장면으로 묶습니다. 실제 입력과 결과를 사용합니다. |
| `x=i++`, `x=++i` | 식이 제공하는 값과 i에 저장된 새 값을 별도로 연결합니다. |
| `a[i++]+=2` | 대상 식을 한 번 평가한 결과를 사용합니다. 계측 때문에 i를 다시 증가시키지 않습니다. |
| `f()+g()`, 함수 인자 | C의 필수 순서와 값 의존성을 보존한 뒤, 허용되는 피연산자 사이에서 기본 좌→우를 적용합니다. 안전한 재배치가 불가능한 구간은 기존 순서와 제외 사유를 남깁니다. 실제 실행과 중간언어 순서는 항상 일치시키며 [평가 순서 계약](evaluation-order.md)을 따릅니다. |
| `&&`, `||`, `?:` | 실제 평가한 부분만 사건을 만들고, 선택하지 않은 부분은 미평가로 표시합니다. |
| 쉼표 연산자 | 앞 식의 평가와 부수 효과를 거쳐 뒤 식으로 진행합니다. 인자 구분 쉼표와 구분합니다. |
| 정수 승격과 형 변환 | 입력형, 계산형, 결과형을 보관합니다. unsigned의 순환과 signed의 범위 초과를 구분합니다. |
| 나눗셈, 나머지, 시프트 | 0으로 나눔, 표현 불가능한 정수 몫, 시프트 범위 등 대상 언어의 조건을 검사합니다. |
| 실수 | NaN, 무한대, 음의 0을 유지합니다. 반올림과 예외를 JavaScript 연산으로 대신 판정하지 않습니다. |
| 일반적인 `sizeof`, `_Alignof` | 컴파일러의 확정값을 사용합니다. 피연산자를 관찰하려고 실행하지 않습니다. VLA 관련 평가는 별도 지원 대상입니다. |
| for, while, do, switch | 실제 조건과 선택한 경로를 FLOW로 기록합니다. switch의 연속 진입도 보존합니다. |
| break, continue, goto, return | 실제 목적지로 이동하고 벗어나는 스코프를 종료합니다. break 뒤에 반복 증가를 추가하지 않습니다. |

부수 효과가 있는 식을 기록용으로 재계산하지 않습니다. 미초기화 대상의 이전 값을 얻으려고 추가로 읽지도 않습니다. 기록 함수와 관찰용 메모리는 사용자 코드의 계측 대상에서 제외합니다.

## 초기화와 메모리

- `int a;`는 초기화되지 않은 상태로 등록합니다. `static int a;`의 초기값과 수명은 다르게 등록합니다.
- `int a[4]={1};`, 지정 초기화, 중첩 구조체 초기화의 나머지 필드는 컴파일러의 C 초기화 규칙대로 반영합니다.
- `malloc`의 새 영역을 0으로 표시하지 않습니다. `calloc`은 0 비트로 채운 결과를 기록하며, 모든 자료형의 의미가 보편적으로 0 또는 NULL이라고 단정하지 않습니다.
- 바이트 복사는 초기화 상태와 출처도 전달합니다. 미초기화 바이트의 복사와 그 값을 조건·주소·계산에 사용하는 일을 구분합니다.
- 배열 경계와 객체 수명, 필드 접근 정보를 함께 확인합니다. 전체 할당 범위 안에 있다는 사실만으로 모든 접근이 유효하다고 판정하지 않습니다.
- 널 문자도 저장 공간을 차지합니다. 문자열 길이, 할당 용량, 현재 확인된 종결 위치를 별도로 보관합니다.
- 읽을 수 없는 주소나 해제된 영역을 오류 표시를 위해 추가로 읽지 않습니다. 유효한 영역에서 관측한 마지막 상태를 사용합니다.

양수 크기의 realloc은 호출 결과와 포인터 대입을 구분합니다. 실패하면 기존 할당이 남고, 원본이 반환값을 바로 대입했다면 포인터에는 NULL이 저장됩니다. 성공하면 이전 할당 수명 종료와 새 할당을 연결합니다. 주소가 같아도 객체 이력을 새로 연결하되 화면 박스 위치는 유지할 수 있습니다. 크기 0의 동작은 언어 버전과 대상 라이브러리 정책을 따로 기록합니다.

포인터는 원시 주소와 해석된 참조를 함께 보관합니다. 이중 포인터와 함수 포인터도 실제 대상을 단계적으로 추적합니다. 같은 주소가 재사용됐다는 이유만으로 오래된 포인터를 새 객체에 자동 연결하지 않습니다. 출처 추적이 부족하면 대상 불확실 상태로 남깁니다.

포인터 서랍은 해당 시점의 원본 객체를 보여주는 보기입니다. 열거나 고정하는 행동은 C 프로그램의 READ 사건이 아닙니다. 평면 배열의 격자·트리·그래프 표현은 근거가 있는 표시 제안으로 관리하며, 원래 메모리 구조와 객체 식별을 유지합니다.

No21~No34에서는 구조체 노드를 트리로 배치하는 경우와 배열·리스트·그래프 등이 함께 있는 경우를 검토합니다. 이름과 예제 분류 대신 실제 연결·인덱스 관계·실행 변화를 근거로 후보를 만들고, 기존 위치를 유지하며 변경 부분을 갱신하는 배치 기준도 확인합니다. 세부 검증 기준은 [자료구조 표현·배치 검증](structure-view-validation.md)에 정리합니다. 현재 중간언어 과정 검증과 향후 실제 배치·애니메이션 검증은 구분합니다.

자동 추론과 별도로 사용자가 배열부터 사용자 정의 자료구조까지 표현과 저장소 대응을 지정·고정할 수 있게 합니다. 표현 선택과 기대 조건 검사는 분리하며, 기대한 구조와 실제 상태가 다르면 Warning으로 표시하는 설계입니다. 갱신 중인 상태와 정보 부족은 확정된 위반과 구분하고, 지정 때문에 실제 값·연결·중간언어를 변경하지 않습니다. 사용자 지정 UI와 범용 검사기는 아직 구현하지 않았으며 구체적인 계약은 자료구조 표현·배치 검증 문서의 사용자 지정 절에 따릅니다.

## 함수와 라이브러리

함수 선언(프로토타입)과 정의는 이름·매개변수·반환형·본문을 설명하는 정보이며, 호출 프레임을 미리 생성하지 않습니다. 실제 호출마다 스택 영역에 독립된 돗자리인 프레임을 만들고, 재귀 호출도 별개의 공간으로 취급합니다. 반환 시 `SPACE/frame.end` 한 작업과 `endedObjects` 목록으로 남은 자동 지역변수를 함께 정리합니다. 내부 블록만 먼저 끝나면 해당 객체는 `SPACE/object.end`로 종료하며, 이미 종료한 객체를 반환 시 다시 정리하지 않습니다. 정적 객체와 힙 객체는 프레임과 독립된 수명을 유지합니다. 포인터 상자를 치워도 참조 대상까지 자동으로 해제하지 않습니다.

현재 중간언어 생성 모델은 Clang의 수명 표식과 AST의 선언·스코프를 연결해 이러한 종료를 기록합니다. 원시 주소 확보와 객체 수명 시작을 구분하고, 같은 주소를 재사용하는 새로운 수명에는 새 객체 ID를 부여합니다. 원관측의 실제 종료 지점은 보존하며, 반환 직전 정리는 프레임 종료 작업에 묶어 실제 수신 작업 뒤에 배치합니다. 이 계약은 애니메이션 구현과 독립된 생성 모델의 책임입니다.

인자는 실제 평가 결과를 호출 프레임으로 전달합니다. 반환은 반환형 변환과 반환값 확보를 거친 뒤 프레임을 끝내고 복귀합니다. 호출한 쪽의 대입 변환은 별도 작업입니다. 함수 포인터의 호출 대상도 관측해서 연결합니다.

`inline` 함수에도 독립된 호출 프레임과 같은 인자·반환 규칙을 적용합니다. 지정자와 선언 연결은 AST에서, 실제 정의의 연결 속성은 LLVM에서 얻어 중간언어의 함수 정보에 남깁니다. `inline`이라는 이유로 호출자 안의 매크로 작업 묶음으로 바꾸거나 인자식을 다시 평가하지 않습니다. 현재 계측은 최적화 패스를 끄므로 호출 과정을 유지하며, 기계어 수준의 인라인 치환을 재현하는 애니메이션은 만들지 않습니다. 필요한 외부 정의가 없으면 실행 전 링크 오류 한 건으로 기록합니다.

매크로는 확장된 AST의 작업을 현재 함수 실행 문맥에서 기록합니다. 형 변환과 계산 판정은 일반 표현식과 공유하고, 반복·중첩 확장의 위치는 컴파일러 토큰과 실제 SSA 입력 연결로 구별합니다. 교환 매크로의 임시 상자·읽기·쓰기·수명 종료도 원래 순서를 유지합니다. 매크로별 도구·작업 묶음의 시각적 표현은 이후 애니메이션 설계에서 정하며, 현재는 별도 함수 호출이나 원자적인 교환 동작으로 대체하지 않습니다.

C 구조체의 값 전달·반환·대입은 필드 값을 새 대상에 전달합니다. 포인터 필드는 주소값을 전달하므로 참조 대상은 공유합니다. 임시 객체와 복합 리터럴도 고유 객체와 수명으로 등록합니다. 정상 복귀, exit, abort, 충돌, 사용자 중단을 구분하고 실제로 없었던 반환이나 free를 추가하지 않습니다.

여러 소스의 사용자 정의 함수는 동일 설정으로 분석·계측합니다. static 함수의 내부 연결과 지역 static의 정적 수명을 구분합니다. 헤더에 같은 이름이 보인다는 이유만으로 선언과 객체를 합치지 않습니다.

| 라이브러리 종류 | 초기 관찰 범위 |
| --- | --- |
| malloc, calloc, realloc, free | 요청, 성공·실패, 객체 수명, 초기화 상태, 포인터 결과를 전용 연결부에서 기록합니다. free(NULL)은 제거할 객체가 없는 호출입니다. |
| 메모리를 읽거나 쓰는 외부 호출 | 링크된 WASM의 실제 스칼라 접근을 함수 이름과 무관하게 관찰합니다. 추적 객체의 읽기 출처와 WRITE/write.range를 기록하며, 복사·채움 등의 명시적 계약은 의미를 보강합니다. |
| 터미널 입출력 | 실제 WASI 입력·출력 바이트와 메모리 접근을 연결합니다. 출력할 함수의 이름 목록으로 관찰 여부를 결정하지 않습니다. 포맷 적용은 실제 라이브러리가 수행합니다. |
| rand, time 등 | 실제 반환값과 외부 입력을 기록합니다. 재생 중 다시 호출하지 않습니다. |
| 관찰 지원이 없는 외부 함수 | 호출 입출력과 확인 가능한 영향만 표시하고 내부는 미관측으로 둡니다. 정확성에 필요한 영향이 누락되면 상세 시각화의 지원 범위를 제한합니다. |

최적화된 libc의 실제 접근, API 계약에 따른 설명, 관찰용 구현의 접근을 구분합니다. 설명용 문자 순회를 원래 libc가 실제 수행한 사건으로 기록하지 않습니다. scanf 실패 시 대입하지 않은 대상에 임의의 초기값을 넣지 않습니다.

기본 경로의 명세와 제한은 [공통 관찰 모델](c-model.md)에 있습니다. 라이브러리 내부 객체·산술·할당 규칙까지 모두 관찰하는 것은 아닙니다. 이미 수집한 사건은 coverage.observationAccounting으로 공개 명령 반영·다른 명령으로 전달·보조 처리·미도달 선언 예약을 구분하며, 설명 없이 제외된 사건은 누락으로 보고합니다.

## 오류와 관찰 한계

공개 기록의 오류는 세부 진단을 가진 단일 ERROR 표시 블록으로 취급하며 기본 C 작업 다섯 형식과 구분합니다. 오류의 그림·연출·조작은 [시각화](visualization.md#오류의-표현--설계-확정미구현)·[애니메이션](animation.md)·[UI](ui.md)의 책임입니다. 표시를 위해 실행되지 않은 작업을 추가하지 않습니다.

문법과 타입 오류는 실행 준비 단계의 오류로 표시합니다. 경고만으로 실행을 실패 처리하지 않습니다. 실패한 컴파일 결과로 정상적인 실행 프레임을 만들지 않습니다.

초기 정책은 확인된 범위 초과, 해제 후 접근, 잘못된 해제, 위험한 연산을 가능한 한 원래 효과 전에 잡고, 마지막 유효 상태와 접근 시도를 남기는 것입니다. 실제 접근 위반이나 충돌이 나면 확보한 기록까지만 보여줍니다. NULL 할당 반환처럼 정상적으로 가능한 실패 결과는 그대로 전달합니다.

초기화 여부, 관측된 비트, 값의 출처는 별도로 관리합니다. 화면의 쓰레기 표현은 의미가 정해진 정상 값이라는 뜻이 아닙니다. `a*0`에서 0이 관측됐더라도 앞선 미초기화 값 사용 기록을 지우지 않으며, 정의되지 않은 동작 이후를 보장된 C 실행으로 제시하지 않습니다. 초기화 상태를 안전하게 전달할 수 없는 경로는 지원 한계를 표시합니다.

오류에는 실패한 명령, 대상과 접근 범위, 원인 계산, 할당과 마지막 쓰기를 연결합니다. 알고리즘상 잘못된 값은 사용자 기대나 검증 조건이 없으면 자동으로 확정할 수 없습니다. 출처 추적은 원인 탐색을 돕는 기능입니다.

ASan, MSan, UBSan은 참고 가능한 계측 사례입니다. 완성된 시각화 기록을 제공하지 않으며, 대상 플랫폼과 컴파일러에 따라 지원 범위가 다릅니다. 현재 브라우저 도구에서 사용 가능하거나 함께 결합 가능하다고 가정하지 않습니다.

## 기록과 원하는 실행 시점의 재생

여기서 되돌아간다는 것은 C를 역방향으로 실행하거나 쓰기를 하나씩 취소하는 것이 아니라, 원하는 중간언어 실행 위치로 이동해 그때의 상태와 이후 애니메이션을 다시 보는 것입니다. 명령 정의는 한 번 저장하고, 실행 기록은 명령 번호·실행 순번·호출 문맥·실제 값·변경 범위와 출처를 연결합니다. 동일 명령의 반복·재귀 실행을 구별합니다.

초기 상태와 빠짐없는 변경 기록으로 원하는 명령 직전의 시각화 상태를 복원하고, 해당 명령부터 같은 대응 애니메이션을 재생합니다. 가까운 이전 체크포인트에서 변경 기록을 적용하면 처음부터 재구성하는 비용을 줄일 수 있습니다. 객체·값·초기화 상태·포인터·호출 프레임·명령 간 전달값·입출력 위치가 복원 대상이며, 네이티브 프로세스 전체를 복원하는 기능과는 별개입니다. 모든 쓰기에 이전 값을 중복 보관하는 것은 필수 조건이 아닙니다. 데이터·주소·제어 의존관계와 범위 복사의 출처는 계속 보존합니다.

큰 반복은 애니메이션 프레임 대신 사건 묶음과 체크포인트로 저장합니다. 예산 때문에 상세 기록을 생략했다면 구간에 누락 표시를 둡니다. 기록이 없는 구간은 검증된 재실행 수단 없이 자세히 복구할 수 없습니다. 재실행은 입력·난수·외부 효과와 대상 환경을 통제할 수 있을 때만 사용합니다.

오래 걸리는 반복과 무한 반복의 증명은 구분합니다. 시간·작업량 한도와 진행 상태를 보여주고, 같은 상태의 반복은 정지 의심으로 표시합니다. 계측 횟수와 애니메이션 시간으로 네이티브 성능을 단정하지 않습니다.

## 지원 단계와 확인 사례

1. **연결 실험:** 정수 지역변수, 복합 산술식, 조건, 함수 진입·반환을 관측해 원본 작업 번호가 사건과 장면까지 유지되는지 확인합니다.
2. **기본 C:** 배열·포인터·동적 할당·문자열, 반복·재귀, 구조체·정적 객체·여러 파일과 기본 입출력을 확장합니다.
3. **확장 C:** 함수 포인터와 복합 초기화, union·비트필드·가변 길이 배열을 각각 확인합니다. 저장 영역 공유와 부분 비트 변경은 기존 메모리 모델의 확장으로 처리합니다.
4. **별도 범위:** setjmp/longjmp, volatile, restrict 관련 가정, 원자 연산·스레드, 신호·인라인 어셈블리·운영체제 API는 상세 관찰 조건을 정한 뒤 지원합니다. 지원 전에는 이를 정확히 추적한다고 표시하지 않습니다.
5. **C++:** 컴파일러의 실행 처리를 유지하고 생성자·소멸자, 임시 객체, 참조, 상속·가상 호출, 예외와 스택 해제를 관찰합니다. 원시 메모리의 할당 수명과 그 안에서 생성되는 C++ 객체 수명을 구분합니다.

다음은 전체 설계의 확인 사례입니다. 현재 자동 테스트는 첫 산술식, 대입과 값의 출처, 괄호·음수 정수 연산, 암묵적 반환, 미초기화·0 나눗셈·오버플로 및 미지원 구문 거부를 실제 Clang/WASI에서 확인합니다. 그 밖의 아래 사례는 후속 구현의 검증 목표입니다.

| 사례 | 확인할 결과 |
| --- | --- |
| `int a=10,b=20; int c=a+b*2;` | C의 계산 결과 50과 입력 의존관계가 한 표현식 장면에 연결됩니다. |
| `int i=2; int x=i++; int y=++i;` | x=2, i=4, y=4이며 중간 증가가 빠지지 않습니다. |
| `int a[2]={5,6}; int i=0; a[i++]+=2;` | i=1, a[0]=7이며 대상 식은 한 번 평가합니다. |
| `0 && f()`, `1 || f()` | f의 호출 사건이 없습니다. |
| `sizeof(i++)`에서 i가 일반 int | i를 변경하는 사건이 없습니다. |
| unsigned 최댓값에 1 더하기 | 대상 폭에 따른 순환을 signed 범위 초과와 구분합니다. |
| `int a[4]={1};` | 나머지 세 원소는 초기화된 0입니다. |
| 같은 이름의 전역·매개변수·블록 변수 | 선언과 수명으로 서로 다른 객체를 식별합니다. |
| goto로 건너뛴 `int x=1;` 이후 x 사용 | 선언문이 실행되지 않았다는 이유로 객체를 놓치거나 1을 저장하지 않습니다. |
| 동일 배열을 참조하는 int*와 int** | 하나의 실제 메모리와 다단계 참조를 유지합니다. |
| 포인터 필드가 있는 구조체의 값 전달·반환 | 구조체 객체는 구분하고 참조 대상의 공유를 유지합니다. |
| 구조체의 start와 end를 각각 대입 | 두 저장 사이의 혼합된 중간 상태가 남습니다. |
| scanf 실패를 검사하는 `||` | 실패 분기에서 아직 초기화되지 않은 n을 추가로 읽지 않습니다. |
| realloc 성공·이동·실패 | 할당 수명과 반환값 대입을 각각 보존합니다. |
| free 이후 별칭 접근 | 이전 객체와 연결된 실패 시도를 표시하고 새 주소 재사용과 혼동하지 않습니다. |
| reverse 예제 | 널 문자 공간이 부족한 최초 쓰기를 잡고 정상적인 이후 실행을 꾸미지 않습니다. |
| plus 예제 | 조건 전에 발생하는 짧은 배열 접근과 사용하지 않은 변환을 보존합니다. |
| 회의 구조체 합병정렬 | 재귀 프레임들이 두 배열을 공유하고, 후위 증가와 필드별 저장을 보존합니다. |
| adress 예제 | 정적 구조체·포인터가 남고, 지역변수 계산 후 격자에 순서대로 저장됩니다. |
| 큰 반복·난수·기록 제한 | 재생 결과가 당시 값과 일치하며 기록 누락 구간을 명시합니다. |

## 구현 전 확인할 조건

지역변수가 컴파일러의 반환 저장소를 공유하더라도 화면의 이름·함수 소속·수명은 분리합니다. 중간언어의 `storageAlias`와 `resultDeliveries`로 실제 저장 관계와 반환 목적지를 연결하며 추가 복사 애니메이션의 근거로 삼지 않습니다. 실패한 복합식에는 이미 얻은 입력만 표시하고 결과값을 만들지 않습니다. 기록 제한으로 변환하지 못한 구간은 정상 실행 장면으로 보충하지 않습니다. 세부 계약은 [관찰·저장소·중단 경계](ir-observation-boundaries.md)에 정리했습니다.

2026-11-06 기록 계약 보강: 숫자 조건식의 원래 CALC와 관찰된 FLOW를 연결하고, 컴파일러의 보조 진릿값 변환을 중복 애니메이션 단위로 만들지 않습니다. 매크로 범위가 겹치는 논리식도 AST 정체성으로 피연산자와 최종 분기를 연결합니다. 생성기 내부 변환 실패는 사용자 C의 런타임 오류와 구분하며, 원시 관찰을 보존하되 검증에 실패한 중간언어를 정상 재생 기록으로 제공하지 않습니다. 추론 및 애니메이션 구현은 변경하지 않았습니다.

최소 계측 실험에서 대상 도구의 AST 접근과 계측 확장 방법, 원본 번호 전달, 안전한 값 수집, 라이브러리 연결, 기록 비용을 확인한 뒤 실행 백엔드를 선택합니다. 브라우저와 데스크톱이라는 포장 방식만으로 이 조건이 해결되지는 않습니다.

첫 구현의 완료 기준은 코드 위치와 사건의 대응, 정확한 값·분기·수명, 잘못된 접근 직전의 중단, 기록 재생의 동일성입니다. 공간 배치와 간선 라우팅의 정교화는 이 계약 위에서 진행합니다.
