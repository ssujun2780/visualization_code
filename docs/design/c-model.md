# 공통 C 중간언어 모델 v0.2

현재 구현된 CLI 엔진입니다. 단일 C11 소스를 입력받아 번들 Clang으로 분석하고, 소스 이름이나 알고리즘별 관찰 지점 없이 LLVM 8 코드에 공통 관찰 함수를 삽입합니다. 실제 계산과 분기는 컴파일된 C가 수행합니다. JavaScript는 관측값과 관계를 기록합니다.

현재 담당 범위는 코드 → 중간언어 변환과 그 정확성 검증입니다. scripts/animation/stub.mjs에는 중간언어 명령 하나와 해당 실행 정보를 받는 빈 함수만 두었습니다. 애니메이션 구현·재생·체크포인트 이동은 후속 작업이며, 현재 계측 경로에 더미 호출을 추가하지 않습니다. 중간언어는 이후 애니메이션과 1대1로 대응할 수 있도록 정의하되, 지금은 실제 연출을 구현하지 않습니다.

```text
C 소스 → Clang AST + LLVM + 디버그 정보
      → 소스 작업별 중간언어 명령 정의 + 내부 관찰 계획
      → compile-only는 여기서 반환
      → 계측된 C의 실제 실행 → 관측값을 정의된 명령에 연결
      → 중간언어 실행 기록 + 객체·프레임·참조
```

## 입력과 출력

```sh
pnpm trace:c examples/c/instrumentation-basic.c
pnpm trace:c 코드.c --stdin 입력.txt --out-dir test-results/my-code
pnpm trace:c 코드.c --compile-only --out-dir test-results/ir-only
pnpm trace:c 코드.c --with-observations --out-dir test-results/ir-debug
```

기본 출력은 `test-results/c-model`입니다. 실행 성공과 C의 종료 코드는 별도입니다. CLI는 기록을 정상적으로 마쳤으면 0, 관측 오류·미지원·제한 중단이면 1을 반환합니다. C의 실제 종료 코드는 trace.json의 exitCode에 저장합니다.

| 파일 | 내용 |
| --- | --- |
| original.c | 입력 소스 그대로 |
| original.ast.txt | 소스의 실제 자료형·암시적 변환을 포함한 Clang AST |
| original.ll | Clang이 생성한 실제 LLVM 코드와 디버그 정보 |
| instrumented.ll | 공통 관찰 함수가 추가된 LLVM 코드 |
| plan.json | 스키마 3. 소스 작업의 명령 정의, 표현식, 선언·스코프·함수, 관찰 연결 |
| trace.json / trace.jsonl | 스키마 3. 명령별 실행 ID·실제 값·대상·출처·상태 변화. 실행 모드에서 생성 |
| observations.plan.json / observations.trace.json | --with-observations 선택 시 내부 LLVM 관찰 계획과 원시 사건. compile-only에는 계획만 생성 |
| stdout.txt / diagnostics.txt | 프로그램 출력과 컴파일·도구 진단 |

API는 `scripts/model/index.mjs`의 `compileCToIR(source, options)`와 `traceModel(source, options)`입니다. 전자는 사용자 C를 실행하지 않고 plan, ast, llvm, instrumentedLLVM, compilerDiagnostics를 반환합니다. 후자는 실제 실행의 trace, stdout, stderr도 반환합니다. 둘 다 Worker와 시간 제한을 사용합니다. includeObservations 옵션으로 내부 관찰 자료를 추가할 수 있습니다. 예상 정답이나 예제별 타입 분류를 받는 인자는 없습니다.

## 기본 사건

| 형식 | 구현된 관찰 |
| --- | --- |
| READ | 실제 메모리 읽기의 시작·완료를 한 실행에 연결. 주소·폭·값·출처 또는 실제 입력 스트림 구간 |
| WRITE | 실제 store, 초기화, 함수 인자·반환값, 지원하는 라이브러리의 쓰기 효과 |
| CALC | 소스 표현식과 실제 중간 결과·최종 결과. 독립적인 주소 연산, 비교·변환·선택 |
| FLOW | 함수 호출·복귀, 간접 호출, 분기·반복, switch, 종료 |
| SPACE | 전역 저장 영역, 함수 프레임, 스택 할당, 동적 할당·재할당·해제 |
| ERROR | 오류 한 건을 나타내는 블록. 이후 정상 사건을 만들어 넣지 않음 |

정적 명령의 instructionId는 i 계열이며, 반복·재귀 실행마다 x 계열 eventId/executionId가 생깁니다. activationId는 호출을 구별합니다. 내부 관찰의 m 계열 지점 ID·e 계열 사건 ID는 observationIds와 선택적 원시 출력에서 추적합니다. 실행 상태는 complete/incomplete/failed입니다. 실제 읽기·쓰기의 대상과 출처, dataInputs/addressInputs/controlInputs는 공개 IR의 실행 ID에 연결합니다. 정수 값은 비트열과 문자열로 보존합니다. 소스 위치와 식의 구조는 명령 정의에 두고 실행마다 다시 복사하지 않습니다.

ir-plan.mjs가 AST의 소스 작업으로 공개 명령을 만들고 내부 관찰 지점을 bindings로 연결합니다. ir-record.mjs는 실행이 끝난 관측 자료를 해당 명령의 실행 기록으로 정규화합니다. 애니메이션에서 작업 경계를 다시 정하지 않습니다. 부수 효과 없는 표현식의 CALC는 실제 중간 결과를 steps에 담아 한 실행으로 묶습니다. 호출·쓰기·제어 이전·메모리 접근에 필요한 주소 계산을 무조건 가로질러 합치지 않습니다. 컴파일러의 보조 bitcast·PHI·메모리 초기화용 호출 경계는 별도 캐릭터 작업으로 만들지 않되 출처와 메모리 효과를 보존합니다.

함수 인자의 ABI 저장은 매개변수 상자 생성 이후의 전달 명령에 연결합니다. 사용자 함수의 복귀와 호출 지점의 복귀 관찰을 중복 실행하지 않으며, 프레임 종료에 수반되는 지역 객체 종료는 endedObjects로 함께 기록합니다. 표준 함수의 호출 경계에서 얻은 쓰기·할당 효과는 복귀 전에 배치합니다. 원래 사용자 함수 본문의 실행 순서를 바꾸는 방식은 아닙니다.

상수 계산이나 실행 경로 제거로 관찰 지점이 없는 소스 작업도 source-only 정의로 보존하고 실제로 실행됐다는 사건은 만들지 않습니다. 매핑이 확실하지 않은 작업은 coverage.unboundSourceWork/unmappedObservations/irGaps에 남깁니다. 대형 초기화 목록과 문자열은 소스 메타데이터를 요약하고, 실제 값은 메모리 기록에서 보존합니다. ir-schema.mjs는 명령·실행의 형식 일치와 출처 ID를 검사합니다.

### 부호 정보와 C 형 변환

자료형에 DWARF encoding, signedness, sizeBits를 보존하고 객체·값의 cType에 연결합니다. typedef와 const 등은 바탕 자료형의 부호 정보를 이어받습니다. unsigned 자료형의 표시 정보는 `display: {label: "int", badges: ["u"]}` 같은 형식입니다. 값의 decimal은 C 자료형에 따라 해석하며, 원본 비트와 signed/unsigned 양쪽 해석도 유지합니다. 화면 렌더러는 아직 연결되지 않았습니다.

같은 폭의 int→unsigned int 변환은 LLVM에서 별도 명령이 사라질 수 있습니다. Clang AST에서 IntegralCast를 찾고, 위치·자료형·생산 연산이 유일하게 대응하는 실제 SSA 값 뒤에 변환 관찰을 추가합니다. 공개 IR에서는 CALC의 steps[].conversion 또는 독립 변환 명령에 fromType, toType, explicit, sameWidth, bitsUnchanged, fromValue를 보존합니다. 피연산자를 다시 평가하지 않습니다. 이후 출처 연결도 공개 IR 실행 ID로 변환합니다.

unsigned→signed도 같은 방식으로 보존합니다. 컴파일 중 상수 계산됐거나 위치 대응이 모호한 변환은 실행 사건을 추측해서 만들지 않고 `coverage.cConversions.unobserved`에 남깁니다. 현재는 단일 소스에서 위치를 확인할 수 있는 정수 변환을 보완하며, 모든 매크로·최적화·표현식 형태의 소스 대응을 완성한 것은 아닙니다.

### 컴파일 중 정리된 단락 평가

`0 && ++x`, `1 || ++x`처럼 AST의 리터럴 왼쪽 값으로 오른쪽 생략이 확정되는 식에는 FLOW/short-circuit 관찰을 연결합니다. operator, left.truth, right.evaluation="skipped", 생략한 원본 범위·식, reason을 기록합니다. 오른쪽에 읽기·연산·쓰기 사건이나 가상의 결과값을 추가하지 않습니다.

관찰 함수는 그 식의 결과를 실제로 사용하는 초기화·단순 대입·호출·반환 직전에 배치합니다. 실행되지 않은 경로의 소비 지점에서는 관찰 함수도 실행되지 않습니다. 소비 사건의 controlInputs는 생략 결정 사건을 참조합니다. observedConsumerValue는 실제 LLVM 피연산자로부터 받고, 생략 이유는 컴파일러 AST의 정보임을 구분합니다. 이는 컴파일 중 사라진 식의 하드웨어 실행 시점을 관측했다는 의미가 아닙니다.

현재 보완 대상은 리터럴·괄호·확인 가능한 단항 연산과 폭을 줄이지 않는 정수 변환으로 왼쪽의 참·거짓을 확인할 수 있는 경우입니다. 일반 상수식 전체를 별도 C 해석기로 계산하지 않습니다. 위치·실행 문맥을 안전하게 연결하지 못한 생략 결정은 coverage.shortCircuits.unobserved에 남기며, 실행 사건을 임의로 만들지 않습니다. 일반 동적 단락 평가는 기존 LLVM 분기 기록을 유지합니다.

## 메모리와 구조

- 주소가 재사용돼도 할당·호출마다 객체 ID를 새로 발급합니다. 전역·정적 객체는 함수 반환으로 종료하지 않습니다.
- 물리적 할당과 자료형으로 본 영역을 분리합니다. 큰 할당 내부에 구조체가 있어도 이를 새 물리적 할당으로 중복 생성하지 않습니다.
- 배열의 원소형·개수와 구조체의 필드 배치는 컴파일러 정보에서 얻습니다. 중첩 배열을 격자 형태로 표현할 근거도 여기서 얻을 수 있습니다.
- 포인터 필드에 실제 저장된 주소를 연결합니다. 동일한 레코드 타입의 연결에서 순환·부모 수를 계산해 그래프, 트리·숲, 연결 체인을 후보로 제안합니다. 변수명·구조체명·필드명의 의미로 판정하지 않습니다.
- 타입이 확인되지 않은 void 포인터나 정수 쌍에 그래프·격자의 의미를 임의로 부여하지 않습니다. 사용자 의도에 따른 고급 자료구조 인식은 후속 작업입니다.
- 초기화가 확인되지 않은 영역과 외부 호출 때문에 상태를 확인할 수 없는 영역을 구분합니다. 미관측 상태를 곧바로 쓰레기값이라고 단정하지 않습니다.
- 일반 READ/WRITE의 value.bytesHex 미리보기는 최대 64바이트입니다. 접근 크기와 생략 여부를 함께 표시합니다. 구조별 요약은 마지막 참조 기록이며, 그 객체의 최종 수명은 별도 필드로 확인합니다.

### 초기 상태와 복사 결과의 값 보존

초기화된 전역·정적 저장 영역은 등록 시 실제 메모리의 memoryState를 남깁니다. 컴파일러가 만든 상수 배열 템플릿도 포함하므로, 부분·지정 초기화의 나머지 0까지 컴파일 결과 그대로 보존합니다. memcpy/memmove의 완료 WRITE에는 원본 객체·범위와 복사 직후 목적지의 memoryState를 기록합니다. 이후 READ를 기다리지 않고 초기 상태를 복원할 수 있습니다.

memoryState는 memory-ranges-v1 형식입니다. 각 범위는 offset, length, initialization과 선택적인 data를 가집니다. 값은 hex 바이트 또는 반복 바이트(fill)로 저장합니다. 미초기화·초기화 여부 미관측 영역은 바이트를 읽지 않고 상태만 남깁니다. calloc/memset의 확정된 채움 효과는 짧은 fill 기록을 사용합니다. 구조체 값 전달의 ABI 복사와 realloc으로 보존된 범위도 초기화 상태와 함께 저장합니다.

관찰 스냅샷은 기존 SPACE/WRITE 사건의 추가 데이터이며 프로그램의 READ를 늘리지 않습니다. 이는 C 식을 다시 평가한 결과가 아닙니다. 한 실행의 관찰 스냅샷에는 압축 후 대략 8MiB의 기록 예산을 적용하며, 초과한 값은 초기화 여부를 유지한 채 snapshot-budget 사유로 미관측 처리합니다. 생략된 값을 0으로 복원하지 않습니다. coverage.memorySnapshots에서 캡처·생략 통계를 확인할 수 있습니다.

scripts/model/memory-state.mjs의 materializeMemory는 메모리 구간 하나의 스냅샷을 실제 메모리나 미래 READ 없이 해독합니다. bytes와 별도로 initialization, known 마스크를 반환하므로 버퍼의 기본 0을 미관측 값으로 오인하지 않습니다. 명령별 시각화 상태 전이, 임의 실행 위치의 상태 복원, 체크포인트, 웹 재생 화면과 블록 수명 처리는 아직 구현하지 않았습니다. 원하는 시점의 재생에는 초기 상태·변경 기록·선택적인 체크포인트를 사용하며 모든 쓰기의 이전 값은 필수 데이터가 아닙니다.

### 문자열 라이브러리의 쓰기 효과

외부 strcpy/strcat/strncpy 호출은 함수 진입 전에 추적 중인 원본의 종결 문자와 접근 범위를 확인하고, 복귀 관찰에서 실제 목적지 바이트를 수집합니다. 공개 IR에서는 해당 WRITE/copy를 복귀 전에 배치합니다. sourceObjectId/sourceOffset/sourceSize, target, memoryState를 포함하며 호출 정보는 명령 정의의 callee에 있습니다. strcat은 추가되는 범위만 쓰기로 남깁니다. strncpy는 최대 n바이트만 원본을 확인하며, 종결 문자가 없으면 임의로 추가하지 않고 짧은 원본 뒤의 0 채움은 paddingSize로 구분합니다.

readRegions에는 API가 사용하는 원본과 strcat의 기존 목적지 문자열 범위가 있습니다. dataInputs와 callExecutionId는 공개 IR의 값 출처·호출 실행을 연결합니다. 원시 ID는 관측 근거로 구분합니다. previousMemoryState는 선택적인 이전 상태 자료이며 원하는 위치를 다시 보는 기능의 필수 조건은 아닙니다. 미초기화 영역의 이전 바이트는 읽지 않습니다. 문자열의 종결 문자는 includesNullTerminator/terminatorOffset으로 구분합니다. 내부 구현의 개별 읽기 순서나 가상의 READ 사건을 만들지 않습니다.

입출력 스트림은 WASI 경계에서 실제 전달된 구간을 READ/input 또는 WRITE/output으로 기록합니다. 표준 입출력 버퍼링 때문에 출력 구간과 개별 printf 호출의 대응이 항상 확정되는 것은 아닙니다. 현재 활성 호출이 있으면 연결하고, 출처를 확정할 수 없는 프로세스 출력은 독립 스트림 명령으로 남깁니다. scanf/fgets의 지원되는 목적지 쓰기에는 실제 바이트와 메모리 상태를 연결합니다.

추적된 초기화 상태로 확인할 수 있는 범위에서는 종결 문자 누락, 미초기화 읽기, 목적지 범위 초과와 겹치는 문자열 복사를 호출 전에 중단합니다. 원본·기존 목적지가 미관측 상태이거나 추적되지 않은 경우에는 효과를 추측하지 않고 기존 외부 효과의 coverage.gaps 및 미관측 처리를 유지합니다. 이는 모든 문자열 함수나 라이브러리 내부를 계측한 것은 아닙니다.

## 지원 범위와 한계

현재 경로는 정수·float·double, 배열, 구조체, 포인터, 재귀·함수 포인터, 조건·반복·switch·점프를 컴파일된 공통 연산으로 관찰합니다. 구조체의 값 전달·반환에 필요한 ABI 복사도 처리합니다. malloc/calloc/realloc/free, memcpy/memmove/memset과 일부 문자열·입력 함수는 별도 API 효과 관찰을 연결했습니다.

지원하는 검사에는 추적 객체의 미초기화 읽기, NULL, 할당 범위·수명 위반, 잘못된 free/realloc, 정수 제수 0, 일부 정수 범위·시프트 오류가 있습니다. 완전한 C 미정의 동작 검사기는 아닙니다.

- 스택 저장 영역은 기본적으로 함수 수명으로 추적합니다. C의 모든 블록 수명·VLA 해제·포인터 출처 규칙과 부분 배열 경계까지 완전하게 검사하지 않습니다.
- 라이브러리 내부 동작은 관찰하지 않습니다. API 효과를 관찰하더라도 내부 오류를 발생 전에 모두 차단할 수 있다는 뜻은 아닙니다. 미지원 외부 효과는 coverage.gaps에 남깁니다.
- atomic/volatile, 인라인 어셈블리, 벡터·확장 실수 연산 등 미지원 항목은 실행 전에 거부합니다. 단일 파일과 번들 WASI 표준 라이브러리를 사용하며 사용자 헤더·여러 번역 단위 입력은 아직 없습니다.
- 수집 결과는 이 WASM 실행의 결과입니다. 네이티브 컴파일러의 메모리 배치·평가 순서·성능을 대표하지 않습니다.
- 웹 편집기와 캐릭터 애니메이션에는 아직 연결하지 않았습니다.

상태는 completed, fault, limited, unsupported, compile-error, engine-error를 구분합니다. 미지원이나 도구 오류를 정상 실행으로 표시하지 않습니다.

## 실행 제한

기본 내부 관찰 제한은 100,000개, 컴파일과 실행을 합친 제한은 25초입니다. `--max-events`와 `--timeout-ms`로 조정하며 최대 설정은 1,000,000개와 120초입니다. 관찰 수는 정규화한 IR 실행 수와 다릅니다. Worker 시간 제한에서는 전달된 관찰까지만 IR로 변환하며 최대 255개 관찰과 출력이 남지 않을 수 있습니다. 실패·미완료 명령을 완료로 표시하지 않습니다. compile-only도 Worker 시간 제한을 적용합니다.

이번 스키마 3 구조 변경은 사용자 요청에 따라 예제 C 실행이나 동작 테스트를 진행하지 않았습니다. 문법·모듈 연결 검사만 수행하며, 동작 검증과 기존 스키마 2 검증기의 필드 변경은 이후 제공되는 예제로 진행합니다. 애니메이션 더미와 재생·시점 복원 기능은 현재 개발 범위 밖입니다.

기존의 최소 정수 시제품은 `pnpm trace:prototype`, 정규식 전용 수동 계측 실험은 `pnpm trace:regex`로 유지합니다. 두 실험의 예상값 파일이나 소스별 관찰 지점은 이 기본 모델에서 읽지 않습니다.
