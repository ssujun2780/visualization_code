### 상세 기록과 직접 전달 규칙 — 2026-11-04

중간언어는 항상 비간결 기준으로 기록합니다. plan.presentation.recording과 기본 mode는 detailed입니다. 간결 모드는 이동·운반·계산 내부 단계 등의 표현만 줄일 수 있고, READ/CALC/WRITE·호출·수명 사건이나 값을 기록에서 지울 수 없습니다. 명령 종류는 기존 다섯 가지와 오류를 유지하며 개별 애니메이션은 더미입니다.

일반 대입은 대상 상자로 이동하여 필요한 값을 읽고 계산한 뒤 쓰는 연출을 기본으로 합니다. 주소가 관찰되기 전에는 목적지를 추측하지 않고, 이동 편의를 위해 부수효과·평가 순서를 바꾸지 않습니다. plan.compoundUpdates는 AST 복합 대입의 계산·대상·오른쪽 노드와 single-value/expression 구분입니다. `total += value`, `total -= value`처럼 오른쪽이 단일 값이면 대상 상자에서 갱신하는 연출에 사용할 수 있습니다. 기존 값 읽기, C 변환, 계산, 쓰기는 모두 남습니다. 별도의 이동·알루·덤프트럭 명령은 만들지 않습니다.

`int sum = f();`는 sum 생성 → 호출과 내부 작업 → 반환값을 sum에 대입하는 순서입니다. 반환값은 이를 기다리는 다음 실제 소비 작업으로 연결합니다. 직접 초기화면 WRITE, `f()*2`라면 CALC, `g(f())`라면 호출 인자, `return f()`라면 반환구가 됩니다. 반환구에서 바로 전달하는 연출을 위해 가상의 중간 상자를 추가하거나 실제 정리·복귀·WRITE 순서를 앞당기지 않습니다.

plan.resultDeliveries는 AST 부모 관계와 이미 정의된 호출·복귀·소비 명령의 정적 후보입니다. trace.resultDeliveries는 호출마다 실제 반환구·반환·복귀와 직접 입력 슬롯을 연결합니다. consumer에는 실행 ID·역할·입력 번호와 관찰된 목적지를 두고, availableAtExecutionId 이전에는 그 목적지가 확정됐다고 취급하지 않습니다. 주소·제어 의존성만으로 값 대입을 추정하지 않으며 주소·함수 대상 사용은 별도 관계로 구분합니다. 사용하지 않은 반환값, void, 미복귀, 미연결 상태도 명시합니다. 이 목록은 기존 사건 사이의 전달 관계이며 추가 명령이나 이전 상태를 바꾸는 쓰기가 아닙니다.

구조체가 ABI 반환 저장소에 이미 쓰인 경우에는 별도의 호출자 WRITE를 만들지 않습니다. 컴파일러 return-storage 슬롯의 실제 주소, 반환 스냅샷의 대상 범위, 기존 WRITE 근거가 일치할 때 storageDelivery와 storage-delivered 상태로 연결합니다. 이 경로의 대상 확인 시점은 반환 스냅샷입니다. 근거가 없으면 이유를 명시한 unresolved로 남깁니다.

논리식의 기본 설명은 양쪽 피연산자를 보여줍니다. index.mjs의 describeLogicalWork(plan, event)는 기존 evaluation·소스 정보로 읽기 전용 설명을 제공합니다. detailed에서는 생략된 오른쪽도 explanationOnly와 생략 이유로 보여주고, compact에서는 이를 숨깁니다. 생략된 오른쪽의 truth는 null이며 실제 실행 결과처럼 빨강·초록을 만들지 않습니다. 설명용 확인을 위해 `++`, 함수 호출, 포인터 역참조를 실행하지 않습니다. 현재 저장 상태로 안전한 설명용 결과를 계산하는 기능과 화면 토글·불빛은 아직 구현하지 않았습니다.

연결 구조의 루트 후보는 필드 이동이 없는 선언 별칭·직접 호출 인자 관계를 전이적으로 따라갑니다. `원본 포인터 → 여러 매개변수·지역 별칭 → 순회 변수`의 경로는 structureBindings.linkRootOrigins에 선언·호출 ID로 남깁니다. 후보 선언이 같아도 실행 객체 ID·offset·수명은 별개이며 같은 함수의 다른 호출에서 본 목록을 합치지 않습니다. 함수 반환이 별칭을 유지한다는 의미는 정적으로 추측하지 않습니다.

### 조건 소비자·호출 ABI·범위 보기 보강

2026-11-04 보완: 계산 묶음은 LLVM 결과 생성 방식보다 먼저 AST의 부수효과 없는 소스 표현식으로 정합니다. 산술·비교·논리를 같은 묶음 판단에 포함하며, 논리식이 PHI 결과를 만들었는지에 따라 하위 비교를 별도 CALC로 분리하지 않습니다. 논리식 내부의 조건 분기와 PHI로 이어지는 연결 간선은 묶음을 끝내지 않습니다. 대입·반환·인자 전달 같은 소비 지점에는 소스 표현식의 최종 관측 결과 하나를 전달합니다. 호출·증감·쓰기·쉼표·삼항 선택의 실행 경계는 기존 순서를 유지합니다.

계산 결과를 모으는 동안 다음 READ가 같은 AST 표현식에 속하는지 확인합니다. 같은 표현식의 하위 계산과 입력 읽기는 계속 하나로 묶고, 다른 표현식의 읽기가 시작되기 전에 이전 CALC를 확정합니다. 행 번호 정렬이나 주소 의존성만으로 완료 여부를 판단하지 않습니다. 다음 표현식에서 오류가 발생해도 이미 완료된 이전 CALC는 complete로 유지하며, 같은 표현식 안의 오류는 기존 failed 처리를 유지합니다.

같은 식 내부에서 배열 인덱스·주소에 필요한 하위 CALC가 시작되면 부모 계산을 보류하고 하위 계산과 READ 이후 이어갑니다. 부모의 일부 결과를 전체 식의 complete로 내보내지 않습니다. 아직 끝나지 않은 부모의 단락 평가 결과를 사용하는 작업에는 partialCalculationInputs로 실제 관측 단계·값·입력 출처를 연결합니다. 일반 data/address/control 의존성은 이미 확보된 입력에 연결하므로 미래의 전체 CALC 완료를 소비하는 순환을 만들지 않습니다. 이 메타데이터는 새 명령이나 C 식 재평가가 아닙니다.

CALC의 steps에는 실제 관찰된 하위 계산을, nestedEvaluations에는 내부 논리식의 평가·생략 근거를 남깁니다. 복합식에 여러 생략이 있으면 helpMarkers로 기존 더미를 연결합니다. 포인터나 스칼라 자체를 조건으로 사용하는 경우에도 AST 조건과 LLVM 입력 생산자를 연결하여 truth CALC 및 FLOW 조건의 C int 0/1을 기록합니다. 원본 재평가나 오른쪽 피연산자의 추가 실행은 없습니다.

CALC의 입력은 READ·하위 위치 계산·함수 반환 등으로 이미 확보한 시점의 값과 그 생산 사건입니다. 원본 상자를 나중에 다시 읽어서 계산하지 않습니다. inputs는 그 고정값과 출처를, expression은 AST의 괄호·우선순위·좌우 관계를, steps는 관측된 내부 결과를 나타냅니다. steps의 각 항목은 별도 중간언어 명령이나 독립 애니메이션이 아닙니다. 단락 평가로 건너뛴 입력은 읽거나 임의의 값으로 채우지 않습니다.

함수 호출 자체와 인자 계산은 기존 FLOW·CALC·WRITE 경계를 유지합니다. 반환값을 소비하는 산술·비교 묶음은 그 반환값을 고정 입력으로 받아 하나의 CALC가 됩니다. 예를 들어 a+f(b)*2의 곱셈과 덧셈을 다시 두 명령으로 분리하지 않습니다. 호출 전에 같은 외부 식의 일부 관측이 생겼으면 인자 계산을 먼저 완료하고 소비자 기록을 호출별로 보관하여 복귀 후 완성합니다. 재귀 호출도 문맥이 섞이지 않으며, 호출 내부 오류 시 기다리던 식에 최종값을 만들지 않습니다. 삼항 선택·PHI를 거친 입력의 관측값에도 AST의 C 자료형과 표시값을 연결하며 실수·포인터의 원래 표현을 유지합니다.

CALC 내부 연출은 AST의 괄호·연산자 우선순위를 유지하면서 왼쪽 부분부터 값을 받아 진행하는 것으로 합의했습니다. inputs나 steps의 배열 순서를 그대로 재생 순서로 사용하지 않습니다. 자세한 예시는 execution-visualization.md에 기록하며, 애니메이션 구현·개별 연출 표지는 아직 추가하지 않습니다.

조건식 guard와 assert의 묶음 처리는 기존 AST 메모리 접근 경계를 존중합니다. 원소 위치를 구하는 CALC를 먼저 완료하고 READ한 값을 전체 비교 CALC로 전달합니다. 이를 위해 guard-conditions와 assertions는 같은 createAddressBoundaryTest를 사용합니다.

assertions.mjs는 컴파일러의 assert.h spelling/expansion 위치와 noreturn 실패 호출을 근거로 표준 assertion 계약을 연결합니다. 조건 CALC와 FLOW assert.check에 passed/failed를 남기고, 헤더의 지원용 ||는 원시 관측 근거로 보존합니다. 사용자 매크로의 의미 있는 ||는 유지합니다. 조건의 부수효과는 관측된 한 번만 기록하고 논리식의 단락 평가·부정을 유지합니다. 현재 번들 헤더 확장을 지원하며, 컴파일러가 분기를 제거해 런타임 위치가 없는 상수 assert는 coverage.assertions.unbound에 남깁니다. 실행하지 않은 검사를 만들어 넣지 않습니다.

CompoundLiteralExpr는 LLVM 주소 원점·실제 접근 위치·ABI 배치로 연결합니다. 생성 정의의 sourceTemporary, C 자료형·소스 위치·필드 경로를 보존하고, 컴파일러가 미리 확보한 저장소는 소스에서 처음 실제 사용하는 시점에 표시합니다. 건너뛴 복합 리터럴은 표시하지 않습니다. 실제 초기화·복사·수명 종료는 그대로 기록하며 모호한 대응은 coverage.sourceTemporaries.unresolved에 남깁니다.

if·while·do·for의 논리식이 PHI/select 값을 만들지 않고 분기로만 낮춰져도, conditionGuards는 관찰된 피연산자 판정과 조건 영역을 벗어나는 CFG 간선을 연결합니다. 완료 시 CALC의 int 참거짓과 FLOW branch를 남기고, 평가·생략한 오른쪽 피연산자 및 기존 도움말 더미를 보존합니다. 순수한 하위 계산은 한 논리식 CALC로 묶으며 부작용·사용자 호출은 실제 순서대로 유지합니다. conditionConsumers는 이미 값으로 구현된 논리식의 소비자도 연결합니다. 중첩·반복·재귀 상태는 호출 활성별로 구분합니다. 식이나 호출을 다시 실행하지 않으며, 관찰할 소비자가 없는 완전 상수 접힘 등은 기존 미연결 보고를 유지합니다.

호출 정의와 binding의 callProjection은 소스 인자 번호와 ABI 슬롯, 숨겨진 슬롯의 역할, C 반환형과 사용·폐기 여부를 기록합니다. LLVM 메모리 intrinsic의 volatile 플래그와 sret 운반 슬롯은 공개 C 인자에서 제외하고 backendArguments에 보존합니다. 알려진 메모리 intrinsic의 반환 계약은 관찰한 목적지 인자와 연결하되, backendValue와 contract 근거를 함께 남깁니다. 일반 호출의 관측 반환값을 바꾸거나 라이브러리 내부 프레임을 추가하지 않습니다. 알 수 없는 대응은 추측해서 자르지 않고 coverage.callABI.unresolved로 보고합니다.

void는 kind:void, 크기 0의 타입 설명으로 유지하며 실제 void 저장 객체를 만들지는 않습니다. DWARF의 null 기저형을 void 파생 한정자에 연결하여 const void*와 void* const, typedef 및 중첩 포인터의 한정 위치를 구분합니다.

structureBindings.arrayRoles는 AST의 필드 정체성·인덱스/stride·필드 비교에서 배열 역할 후보를 만듭니다. 실행에서는 실제 데이터 접근·할당 범위·필드 상태로 후보를 검증합니다. 필드명·타입명·예제 이름과 예상 출력으로 역할을 결정하지 않습니다. 원소형은 관찰한 타입 후보와 stride가 맞는지 확인하고, 여러 후보가 남으면 임의로 하나를 선택하지 않습니다.

trace.structures의 array는 실제 객체 범위 위의 지연된 타입 보기이며, dynamic-array는 소유 객체·data 필드에 연결된 논리 보기입니다. states는 사건 ID, 실제 backingObjectId와 오프셋, 길이·용량·원소 폭, 중간/유효 상태를 남깁니다. 보기 ID는 재할당 동안 유지하고 backingHistory와 latestValidState로 물리 객체 교체를 연결합니다. 포인터 출처의 원래 할당이 끝나면 주소가 같아도 새 할당에 자동 연결하지 않습니다. 종료·과거 상태를 살아 있는 최종 상태로 표시하지 않습니다.

보기는 추가 SPACE나 READ를 만들지 않으며 전체 용량만큼 셀을 생성하지 않습니다. 기존 스냅샷에서 필요한 메타데이터 필드 바이트만 해독하고 타입·노드 조회를 재사용합니다. 초기화용 컴파일러 객체는 사용자 구조 후보에서 제외하고, 실제 간선 없는 레코드 집합만으로 트리·리스트를 추천하지 않습니다. 현재 역할 후보는 필드 기반 인덱스 접근·복사 목적지/stride와 사용량·용량 비교를 대상으로 하며, 임의 자료구조나 알고리즘의 의미를 증명하는 완성된 분류기는 아닙니다. 자동 배치·그림·애니메이션은 아직 구현하지 않았습니다.

2026-10-30에 정리한 목표 실행 계약은 다음과 같습니다. 구체적인 변환 절차와 예제는 [코드에서 중간언어로 변환하는 과정](execution-visualization.md#코드에서-중간언어로-변환하는-과정), 이후 실행 제어는 [실행 전 중간언어 완성과 단계 실행](execution-visualization.md#실행-전-중간언어-완성과-단계-실행)을 따릅니다.

```text
C 코드(텍스트)
      → Clang의 AST·LLVM 생성 → AST·LLVM과 원본 위치 연결
      → AST·LLVM 정보 우선 사용 → 누락된 정보만 해당 원본 범위 확인
      → 중간언어 명령 정의 완성 + 내부 관찰 지점 연결
      → compile-only는 여기서 반환
      → 다음 소스 단계까지 실제 실행하고 정지
      → 해당 명령의 실제 값·주소·선택 경로 연결
      → 중간언어 명령별 애니메이션 실행
      → 다음 단계 진행
```

현재 구현은 실행 전에 plan과 관찰 연결을 생성한 뒤, 계측 실행 완료·중단 후 recordIR로 기록을 정규화합니다. 위의 단계별 정지·재개와 애니메이션 완료 대기는 아직 구현하지 않았습니다. 현재의 실행 후 기록 정리 방식을 목표 실행 순서로 해석하지 않습니다.

중간언어의 명령 종류·계산 묶음·소스 위치·입출력·실행 연결은 실행 전에 확정해야 합니다. 실행 중에는 실제 값·주소·분기 선택과 실행 회차를 채웁니다. 기본 표시 순서는 소스 문장의 실행 순서입니다. 선언한 상자와 초기화 작업을 마친 뒤 다음 문장으로 진행하며, 한 계산식의 산술·비교·논리는 내부 결과를 포함한 CALC 한 번으로 정의합니다. 물리적인 줄 번호로 사건을 정렬하지 않으므로 같은 줄의 여러 문장·반복·함수 호출도 실제 실행 순서를 유지합니다.

비교 결과의 LLVM i1 → C int 확장은 같은 비교 단계에 흡수합니다. 최종 관측값의 C int 타입과 두 원시 사건의 ID를 steps[].observationIds에 보존하고, 비교를 두 번 표시하지 않습니다. signed → unsigned 같은 실제 C 변환은 별도의 중간 결과로 유지합니다. 이 결합은 같은 AST 노드·계산 묶음에 속한 직접 생산자 연결이 확인될 때만 적용합니다.

## 변환 과정과 현재 구성 요소

중간언어 생성 모델은 **AST·LLVM과 원본 위치를 먼저 연결한 뒤, AST·LLVM에서 확보한 정보를 우선 사용하고, 없는 정보만 원본의 해당 범위에서 확인합니다.** 문장·계산식·대입·호출·제어 구조와 자료형·변환은 AST로 정의하고, 실행 연산·값의 생산과 사용·관찰 위치는 LLVM으로 연결합니다. 원본 전체를 별도로 분석하는 단계를 기본 경로에 두지 않습니다. 복합 대입 계산 묶음도 원본 재분석 없이 AST 소속 관계로 결정합니다.

원본 확인은 작성된 표기를 표시하거나 컴파일러 정보로 확정할 수 없는 소스 범위를 보완할 때 등으로 제한합니다. 필요한 정보·누락 사유를 먼저 명시하고 최소 범위만 확인합니다. 이미 확인한 분석 결과와 범위 조회는 재사용하며, 실행 회차마다 소스를 다시 읽어 의미를 분석하지 않습니다. 자세한 조건은 설계 문서의 [AST·LLVM 우선 및 결과 재사용](execution-visualization.md#1-astllvm을-우선-분석하고-결과를-재사용)을 따릅니다.

현재 source는 validateSource의 입력 검사 후 Clang에 전달되며, `instrumentLLVM(analysis.llvm, source, { ...options, ast: analysis.ast })`에도 전달됩니다. 2026-11-02부터 source-map.mjs가 위치 연결·원본 범위 조회를 공통으로 담당합니다. LLVM 디버그 위치별 AST 후보를 먼저 연결하고, 이후 의미 분석과 명령 생성에서 같은 인덱스와 범위 캐시를 사용합니다. 실행 회차마다 원본을 다시 분석하지 않습니다.

`int c = a + b * 2;`는 AST에서 선언·두 읽기·계산식·저장을 식별한 뒤 계산식 전체에 CALC 정의 하나를 부여합니다. 이를 위해 원문을 다시 문법 분석하지 않습니다. LLVM의 두 load는 각각 READ에, mul과 add는 같은 CALC의 내부 노드에, store는 WRITE에 연결합니다. c의 물리적 저장 공간 확보와 선언 도달은 SPACE의 서로 다른 관찰 근거로 연결합니다. 실제 값은 이 정의를 만든 뒤 실행하면서 받습니다.

### 위치 연결과 제한된 원본 조회

plan.sourceMap은 컴파일 당시 원본 스냅샷·SHA-256, LLVM 위치별 AST 후보, 원본 조회 사유·범위·통계와 연결 누락을 보존합니다. bindings의 sourceMapping은 관찰 지점의 컴파일러 위치와 AST 후보 ID를 연결합니다. 후보가 있다는 사실만으로 의미 대응이 확정된 것으로 취급하지 않으며, 명령별 sourceNodeId와 bindings가 실제 선택을 나타냅니다.

명령의 source에는 파일, 시작·끝 행/열, UTF-8 바이트 오프셋, 편집기용 UTF-16 editorRange를 둡니다. 끝은 제외 범위입니다. 같은 행의 여러 문장과 여러 행의 식을 구별하고, 한글·이모지 앞뒤에서도 편집기 강조 범위를 유지합니다. 반복문의 분기는 conditionSource를 강조하며 statementSource에 전체 반복문 범위를 따로 둡니다. 원본은 스냅샷으로 보존하므로 편집 중인 새 코드에 이전 실행의 위치를 잘못 적용하지 않도록 해시를 비교할 수 있습니다.

원본 조회 사유는 텍스트 AST에 없는 마지막 토큰 길이(token-end-not-in-compiler-dump), 확정된 범위의 표시 문자열(display-source-text), 매크로 사용 범위의 누락된 끝 경계(macro-range-not-in-compiler-dump)입니다. 마지막 경우에는 사용자 코드의 AST 시작점이 있고 끝이 매크로 정의 파일이나 역순 위치를 가리키는 대입·선언·반환 등의 범위만 대상으로 합니다. 최대4096바이트의 제한된 토큰 경계 조회로 표시 범위를 보완하고 동일 시작점의 결과를 재사용합니다. 원래 spellingRange와 보완 근거를 유지하며, 끝 경계를 얻지 못하면 macro-range-unresolved로 남깁니다. case 상수와 문자열 리터럴, 자료형과 값의 의미는 AST·LLVM에서 가져옵니다. 원문으로 C 식을 다시 해석하거나 평가하지 않습니다.

헤더·사용자 매크로의 spelling 위치가 함수의 사용 범위를 벗어나면 Clang의 전처리 토큰 확장 위치를 추가 수집합니다. AST는 변환당 한 번 파싱하고, 이 위치 수집도 필요할 때만 한 번 수행하며 런타임에서는 반복하지 않습니다. 함수·부모 범위와 컴파일러의 인자 순서·사용자 토큰 근거로 노드를 연결하고 모호한 확장은 compiler-macro-location-unresolved로 남깁니다. plan.sourceMap.macroExpansions에 AST ID·원래 spelling·사용 위치를 보존하고 compilerMacroTokenPasses·compilerTokenMappings로 수집 여부를 확인합니다. 확장 토큰이 매크로 시작점만 제공할 때 함수형 매크로의 닫는 괄호는 최대4096바이트의 표시 전용 경계 조회로 보완하며, 사유는 macro-invocation-end-not-in-compiler-dump입니다.

매크로 비교식은 확장 위치만으로 가까운 AST 노드를 고르지 않습니다. compiler token occurrence 범위(tokenRange), LLVM 비교 predicate·자료형·SSA 피연산자의 생산자를 대조합니다. 같은 인자가 매크로 안에서 반복되더라도 각 토큰 occurrence와 읽기 생산자를 구별합니다. 논리식의 PHI와 결과 확장도 실제 입력 생산자·선택 상수·논리 AST 조상으로 연결해 최종 C int와 단락 평가 정보를 보존합니다. 함수 호출이나 증감 인자를 재평가하지 않으며 특정 매크로 이름에 맞춘 규칙을 두지 않습니다.

컴파일러가 부수 효과 없는 것으로 명시한 builtin 호출은 AST의 계산 묶음에 포함할 수 있습니다. 내부 비트 검사·정수 확장은 같은 소스 CALC의 단계와 원시 관찰에 보존하며, 공개 입력에는 실제 C 값과 실제 생산자를 연결합니다. 사용자 함수가 builtin의 입력을 만들면 실제 호출·복귀를 유지하고 그 반환값을 소비합니다. 상수 인자의 순수 builtin 식과 실수 상수 계산이 접혔을 때는 실제 상수 소비값에 foldedCalculations를 연결합니다. NaN·무한대의 의미는 컴파일러 builtin 정보로 남기되 관찰하지 않은 비트는 생성하지 않습니다. 실수↔정수, float↔double 변환도 AST cast kind와 LLVM 생산자를 연결해 fromType·toType·explicit 및 실제 결과 cType을 보존합니다.

sourceStatus는 mapped, implementation, unmapped로 구분합니다. 헤더·매크로 등 현재 스냅샷에 없는 범위는 sourceMap.gaps와 unmappedInstructions로 남깁니다. 확인하지 못한 위치를 정확한 범위처럼 만들어 넣지 않습니다. 전처리 위치와 모든 문법의 의미 연결을 완전히 지원한다는 뜻은 아닙니다.

## 입력과 출력

```sh
pnpm trace:c examples/c/instrumentation-basic.c
pnpm trace:c 코드.c --stdin 입력.txt --out-dir test-results/my-code
pnpm trace:c 코드.c --compile-only --out-dir test-results/ir-only
pnpm trace:c 코드.c --with-observations --out-dir test-results/ir-debug
```

기본 출력은 `test-results/c-model`입니다. 실행 성공과 C의 종료 코드는 별도입니다. CLI는 기록을 정상적으로 마쳤으면 0, 관측 오류·미지원·제한 중단이면 1을 반환합니다. C의 실제 종료 코드는 trace.json의 exitCode에 저장합니다.

| 파일 | 내용 |
| --- | --- |
| original.c | 입력 소스 그대로 |
| original.ast.txt | 소스의 실제 자료형·암시적 변환을 포함한 Clang AST |
| original.ll | Clang이 생성한 실제 LLVM 코드와 디버그 정보 |

## 기본 사건

### 분기 원인과 case 연결

plan.controlFlow.labels는 case/default의 소스 위치와 소속 switch를, edges는 소스로 확인된 fall-through 연결을 보존합니다. FLOW/switch 실행의 selection에는 실제 선택한 case 값·레이블·소스 위치가 들어갑니다. 연속된 case가 같은 내부 블록을 공유해도 소스 레이블을 구분하며, 정확히 대응시키지 못한 경우 후보 레이블과 coverage의 누락 사유를 남깁니다.

실제로 일어난 fall-through는 trace.flowTransitions에 기록합니다. 각 항목은 정적 edgeId, 원시 관찰 ID, 제어 원인 실행 ID, 다음 작업의 beforeExecutionId를 가집니다. 다음 작업은 incomingTransitions로 이를 참조합니다. 이는 기존 작업의 진입 경로 정보이며 별도의 애니메이션 명령을 늘리지 않습니다. 주석으로 경로를 만들거나 생략하지 않습니다.

controlInputs는 관측된 분기 결정을 해당 경로의 작업에 연결합니다. 컴파일러 제어 흐름에서 경로가 다시 합쳐지는 지점(postdominator)과 도달 영역을 구하고, 실제 선택된 간선만 활성화합니다. 중첩 분기의 원인을 함께 유지하되 합류 지점에서는 끝내며, 반복 조건을 다시 평가하면 이전 회차의 결정을 교체합니다. 호출 프레임별로 상태를 분리하여 재귀 호출 간 결정을 혼동하지 않습니다. 함수당 2,048개 내부 블록을 넘으면 이 분석을 생략하고 control-flow-block-limit을 명시합니다. 종료 경로가 없는 구간은 가상 종료점을 사용해 합류를 보수적으로 처리합니다.

복합 대입은 Clang AST의 ComputeLHSTy·ComputeResultTy로 승격 후 계산형을 확인합니다. CALC 명령의 calculationType·storageType과 각 steps의 cType을 구분해 기록하고, 정수 승격·축소·같은 폭의 부호 변환을 보존합니다. 예를 들어 `unsigned char a = 250; a += 10;`은 int 계산값 260과 저장값 4를 구분합니다. 부호 변환 때문에 실제 LLVM 명령이 없는 경우 기존 SSA 값을 관측하는 변환 사건을 넣으며, C 식 자체를 다시 실행하지 않습니다.

복합 대입 대상의 READ·WRITE는 AST 왼쪽 대상의 저장형을 사용합니다. 배열 원소·구조체 멤버·역참조도 같은 규칙이며, LLVM 접근형과 일치할 때 연결합니다. 인덱스·포인터·오른쪽 하위 식의 관찰은 각자의 자료형을 유지합니다. 이 접근 연결은 계산 결과 생산자 탐색과 분리하므로 같은 폭의 부호 변환을 찾을 때 대상 읽기를 결과로 오인하지 않습니다. No6의 `arr[i++] += 5`에서는 이전 인덱스를 한 번 사용하고 READ·WRITE에 int가 붙는지 검증했습니다.

후위 증가가 인덱스 안에 있어 별도 LValueToRValue 노드가 없는 경우에도, LLVM dbg.declare와 포인터 생산 경로를 AST 선언·필드 경로에 연결해 저장소 READ를 구분합니다. 커서 size_t 읽기를 최종 int 원소 읽기로 오인하지 않으며, 저장소의 부호·폭과 뒤따르는 변환은 분리합니다. 모호한 선언·재해석 포인터·union/bitfield를 근거 없이 이 경로로 덮어쓰지 않습니다.

공개 CALC의 operator는 묶음·단독 기록 모두 명령 정의의 소스 연산자를 사용합니다. `+=`·`*=`를 실행 기록에서 add·mul로 바꾸지 않습니다. LLVM 연산명은 내부 관찰 기록에 보존하며, 값·입출력 출처·순서·전위/후위 구분은 그대로 유지합니다.

2026-11-03 설계 기준: 상수·숫자·주소의 계산은 CALC 하나의 형식으로 통일하고 별도 도구나 명령 종류로 나누지 않습니다. 자료형에 따른 C 계산 규칙과 실제 관측값은 유지하며, 기계적인 바이트 환산은 내부 정보로 둡니다. 객체의 바이트 크기는 컴파일 대상의 ABI에서 가져와 박스의 부가 정보로 표시합니다. Shift+클릭으로 선택한 박스들의 총 바이트 수 표시는 후속 시각화 기능입니다. No10에서 발견한 포인터 증가·차이·끝 다음 참조의 보완 사항은 모델에 반영했으며 UI·애니메이션은 더미 상태입니다.

포인터 ++/--는 AST의 전위·후위 연산과 LLVM getelementptr를 기존 update CALC에 연결합니다. 실제 주소 이동값을 사용하고, 후위 연산의 이전 값 전달과 저장할 새 주소를 구분합니다. 새로운 주소 계산 명령 종류는 만들지 않습니다.

포인터 차이의 LLVM ptrtoint → sub → 원소 크기 환산은 하나의 AST 계산 단계로 연결합니다. ABI로 얻은 실제 원소 크기와 LLVM 의존관계가 일치할 때 환산 관찰을 합치며, 최종 관측값에 AST의 C 결과형을 붙입니다. 공개 CALC steps에는 소스 뺄셈의 결과 한 번만 남고 원시 관찰 ID는 모두 유지합니다. distance에는 elementSizeBytes, elementDistance, byteDistance, defaultUnit과 units를 기록합니다. 기본 원소 표시·바이트 표시·두 단위 함께 표시는 같은 정보로 선택할 수 있으며 C 식의 결과는 항상 원소 간 거리입니다. 중첩 계산에서는 해당 steps 항목에 거리를 두고 전체 식의 결과와 구분합니다.

포인터 값의 reference와 references 항목에는 targetObjectId, targetOffset, onePast, status, dereferenceable을 둡니다. 관측된 기반 객체를 주소 계산·저장·다시 읽기·사용자 함수 인자/반환까지 전달하여 배열 끝 다음 주소가 인접 객체로 잘못 연결되지 않게 합니다. one-past는 배열과의 연결을 유지하지만 역참조할 수 없습니다. 주소 조회나 메모리 접근 검사 범위를 단순히 넓히지 않습니다. 이 정보는 각 관찰 시점 및 마지막 관찰의 상태이며 완전한 C 포인터 출처 모델을 뜻하지 않습니다.

No12 보완: 접근의 AST 후보는 LLVM 실제 접근형과 호환되는지 먼저 확인합니다. 포인터 슬롯과 배열 원소를 같은 위치의 작은 AST 범위라는 이유로 같은 READ로 연결하지 않으며, 명령의 accessType과 실행 value.type의 일치도 검사합니다. AST의 int (*)[3] 같은 배열 포인터 표기는 기존 pointer → array → scalar 형식에 연결해 CALC에도 같은 자료형을 유지합니다.

정적 sizeof는 컴파일러가 확인한 크기 입력으로 계산 묶음에 포함합니다. 이 때문에 계산을 쪼개거나 배열 내용을 읽지 않습니다. VLA처럼 실제 평가가 필요한 sizeof는 정적 크기 입력으로 처리하지 않습니다. 컴파일 때 접힌 정수 계산은 AST로 CALC를 미리 정의하고 bindings.foldedCalculations에 저장·인자·반환의 LLVM 상수 소비 지점을 연결합니다. 실행 정보는 그 소비 지점의 실제 전달값을 사용하고 evidence를 compiler-folded로 남깁니다. C 식을 재평가하거나 얻지 못한 내부 결과를 만들지 않습니다. 같은 원시 소비 사건이 계산과 소비 작업의 근거가 될 수 있으며 각각의 공개 실행 ID와 전달 관계는 구분합니다.

반환값을 지역 객체 정리 후 공통 ret로 전달하는 경우, LLVM 반환 슬롯의 실제 저장 관찰과 AST ReturnStmt를 연결합니다. bindings.returnSourceFor와 returnSites로 실행된 반환문의 작업을 선택하므로 반환값 전달·FLOW의 강조 범위와 SPACE 정리의 닫는 중괄호를 구분합니다. 여러 반환 경로와 main의 암시적 반환을 단순히 유일한 소스 반환문으로 추측하지 않습니다.

반환구의 C 자료형은 Clang의 함수형 표기와 반환 표현식에 적용된 변환에서 확보합니다. 공통 LLVM 반환 슬롯이 C 자료형을 잃었어도 함수 반환 관찰에 이 자료형을 연결하여 WRITE return.value의 value.cType과 정적 returnType에 유지합니다. 실제 반환 비트와 폭은 관찰값을 사용합니다. 상수·복수 반환문·main의 암시적 반환도 같은 규칙을 사용하며 원문 반환식을 재평가하지 않습니다. 복잡한 함수 포인터 반환형을 단순한 정수 반환형으로 잘라 추정하지 않습니다.

함수 포인터는 선형 메모리 주소 대신 kind=function인 참조와 실제 tableIndex로 기록합니다. 컴파일된 함수 포인터 등록 관측으로 함수 정의 ID를 연결하고, 간접 호출에는 실제 진입 함수와 calleeInputs를 보존합니다. 등록 관측은 사용자 READ·저장소·명령을 추가하지 않습니다. null/unresolved를 구분하며 같은 비트의 데이터 객체를 호출 대상으로 추측하지 않습니다. void는 반환값을 소비하지 않으며, 비void도 if/반복문의 본문 등 문장 위치에서는 discarded로 표시합니다. 조건·계산·대입의 실제 소비는 used로 유지합니다.

인자 입력은 FLOW call 시점의 실제 전달값·생산자·C 인자 번호·ABI 인자 번호를 보관하고 WRITE argument에서 재사용합니다. 매개변수 저장을 인자 전달 작업에 합칠 때 자신을 입력 생산자로 연결하지 않습니다. 상수 입력에는 가짜 실행 ID를 만들지 않고 계산·중첩 호출 결과는 실제 CALC·FLOW resume에 연결합니다. 반복과 재귀에서도 호출별 입력을 유지합니다. 라이브러리 콜백처럼 호출자 생산자를 알 수 없는 경우에는 실제 관찰한 인자값과 미확인 근거를 남깁니다. argument inputs의 자기 참조와 존재하지 않는 실행 ID는 검증에서 거부합니다.

구조체 멤버 접근은 컴파일러의 C 멤버 배치와 LLVM 주소 생산자를 연결합니다. 각 READ/WRITE 정의의 memberPath·targetPath에 중첩 멤버와 배열 경로를 보존하고, 초기화 항목의 AST 범위를 얻으면 그 항목을 강조합니다. 필드의 C 자료형은 실제 접근형과 일치할 때 연결합니다. 비트필드처럼 LLVM 필드 번호와 C 멤버 배치가 다른 경우에는 일치 여부를 확인하지 않고 경로를 붙이지 않습니다. record 자료형의 members는 타입 ID를 참조하므로 자기 참조 구조체에서도 직렬화 가능한 타입 그래프를 유지합니다.

비트필드는 AST FieldDecl·bitfield 표식과 DWARF DIFlagBitField, 필드 폭·오프셋·저장 단위 시작을 별도로 연결합니다. 공개 READ/WRITE의 value는 관찰한 저장 비트에서 해독한 논리 필드값이며, 기반 C 자료형·부호·u 배지를 유지합니다. target.bitOffset·bitSize와 정의의 memberPath·targetPath로 필드를 구분합니다. storageTarget·storageValue·storageAccessType에는 원래 물리 접근을 보존합니다. 명명되지 않은 비트나 패딩을 독립적인 C 변수로 만들지 않습니다.

비트 추출·삽입·다른 필드 보존을 위한 내부 마스크와 주소 변환은 해당 접근의 내부 관찰입니다. 실제 오른쪽 식의 시프트·마스크, 복합 대입, 전위·후위 연산, 함수 호출 및 C 값 변환은 유지합니다. 컴파일러가 삽입한 포인터 bitcast는 근처에 CStyleCastExpr가 있다는 이유만으로 사용자 CALC가 되지 않습니다. 캐스트 종류와 입력·결과의 자료형을 대조합니다.

비트별 초기화와 마지막 쓰기는 희소 범위 bitInitializationRanges로 추적합니다. 한 필드 저장은 그 필드 범위만 갱신하므로 변경되지 않은 필드의 출처를 유지합니다. 미초기화 저장 단위를 보존하려는 내부 읽기를 사용자 값 읽기로 취급하지 않으며, 실제로 읽는 필드가 초기화되지 않았다면 오류를 기록합니다. 일반 바이트 쓰기·복사·채움은 해당 비트 범위도 갱신합니다. 컴파일러 저장 배치가 연결되지 않은 경우 coverage.bitfields.unresolved로 남깁니다. 현재 연결 경로는 지원되는 64비트 이하의 LLVM 정수 저장 단위를 대상으로 합니다.

필드 삽입으로 상수 표기가 이동·마스킹되더라도 AST의 단일 정수 리터럴을 확보했다면 WRITE 입력에 원래 리터럴과 C 자료형을 유지합니다. 컴파일러가 이미 없앤 원래 식의 값을 임의 계산하지 않습니다. 인코딩된 상수만 남은 경우에는 관찰한 저장 필드값을 stored-field-value 입력으로 구별하고, 원래 저장 피연산자는 backendValue, 소스 대입식은 expression에 보존합니다.

일반 CALC의 접힌 정수 피연산자도 AST 피연산자 자료형과 실제 LLVM 비트를 연결합니다. unsigned64의 높은 비트나 보수 값은 signed 표기만으로 표시하지 않고 C 자료형·decimal·u 배지를 보존합니다. 원본 LLVM 표기는 literal에 남깁니다. 토큰 결합 매크로의 `<scratch space>` 위치도 AST 위치로 인식하여 사용자 식의 연결이 필요할 때만 기존 컴파일러 매크로 토큰 경로를 사용합니다. 이미 확보한 식의 의미를 원본 코드에서 다시 분석하거나 별도로 실행하지 않습니다.

공용체도 같은 멤버 경로를 사용합니다. Clang MemberExpr의 FieldDecl 참조를 LLVM의 공용체 포인터 변환과 연결하여, 자료형·주소가 같은 두 멤버도 구분합니다. 공용체 내부의 구조체·배열 접근도 이 경로를 이어갑니다. 지정 초기화는 선언과 관련 WRITE의 initialization.unionSelections에 선택한 필드, 중첩 경로, 비트 범위와 소스 위치를 남깁니다. LLVM이 초기화를 통째로 복사해도 이 정보를 보존하며, 별도 멤버 WRITE나 READ를 만들어 넣지 않습니다. 배열은 AST에 있는 초기화 항목만 따라가며 선언된 전체 용량으로 확장하지 않습니다.

포인터로 전달한 멤버 경로는 호출·효과 정의의 memoryArguments에 보존합니다. 실행 효과의 주소가 실제 포인터 인자와 일치하면 memoryAccesses로 연결합니다. 같은 주소를 가리키는 서로 다른 멤버 인자가 있으면 후보들을 유지하며 임의로 하나를 고르지 않습니다. 모든 간접 쓰기에서 멤버가 식별되는 것은 아닙니다. 주소가 같다는 이유만으로 선택 멤버를 추측하지 않습니다.

공용체 멤버들은 하나의 저장소를 공유합니다. unionSelections는 초기화 시 선택의 근거이지 이후의 활성 멤버를 강제하는 상태가 아닙니다. 별도의 tag 쓰기는 그 tag만 변경하며, 공용체 내용을 지우거나 다른 멤버 WRITE를 추가하지 않습니다. 원시 바이트 쓰기·별칭 때문에 선택 멤버를 확정할 수 없으면 바이트 변화와 미확정 상태를 유지합니다.

열거형 cType은 kind:enum, enumTypeId, underlyingType, enumerators를 가집니다. DIEnumerator의 이름·정수 값·부호와 기반형을 보존하고 typedef·const를 거쳐도 유지합니다. 정수 값은 큰 값의 정밀도 손실을 피하도록 십진 문자열로 기록합니다. EnumConstantDecl 참조는 expression.enumConstant에서 해당 정의에 연결합니다. C11 열거 상수 식 자체의 자료형과 열거형 저장 객체의 기반형은 구별하며, 기반형이 unsigned라면 기존 u 배지를 적용합니다. 모든 열거형을 unsigned로 가정하지 않습니다.

plan.enumDeclarations에는 소스 열거형의 선언·상수 참조 연결을 남깁니다. 현재 번들 Clang은 저장 객체 없이 상수 이름만 사용한 일부 열거형의 DWARF 정보를 생략합니다. 이런 선언은 이름·AST 위치를 보존하되 status:unresolved와 coverage.compilerEnums.unresolved로 보고하며, 값이나 기반형을 임의 계산하지 않습니다. 이름만으로 구분할 수 없는 중첩 enum 태그도 추측하지 않습니다. 이 보강은 다섯 일반 명령어의 메타데이터이며 새 명령어나 애니메이션 구현을 추가하지 않습니다.

구조체 값 인자는 독립 객체의 SPACE와 WRITE argument로 기록하며 원래 구조체 cType, 복사 범위·스냅샷을 전달합니다. 내부 byval 포인터는 abiValue에 보존하고 공개 전달값은 kind:aggregate로 구별합니다. 호출 인자에서 숨겨진 sret 인자를 제외한 뒤 C 인자 번호를 연결합니다. 일반 포인터 인자는 이 처리와 구별합니다. 구조체·바이트 복사는 관찰된 포인터 필드의 대상 ID를 함께 전달하여 공유 대상과 one-past 소속을 유지합니다.

구조체 반환은 숨겨진 sret 저장 영역에서 실제 관찰한 상태를 WRITE return.value의 반환구와 연결합니다. 기존 복사 스냅샷을 재사용할 수 있으면 재사용하고, 별도 C 연산이나 메모리 복사를 실행하지 않습니다. 실제 sret 쓰기·중첩 호출 완료로 실행된 ReturnStmt를 선택하며 FLOW return, SPACE frame.end, 호출 줄의 FLOW resume을 연결합니다. 스칼라·포인터·void 사용자 함수에도 호출 복귀를 남깁니다. 숨겨진 LLVM 복사 호출의 ID는 backendCallObservationId·backendReturnObservationId에 보존하며 공개 callExecutionId·returnExecutionId는 실제 FLOW 호출·반환·복귀만 참조하도록 검증합니다. 소스에 직접 작성한 memcpy 호출은 독립된 호출·효과·복귀를 유지합니다.

No13 보완: 논리 부정은 logical-not.mjs에서 AST UnaryOperator !와 LLVM 영/NULL 비교·i1 xor·확장·분기 관계를 연결합니다. 분기 방향을 뒤집어 !를 구현한 경우 공개 CALC와 condition에는 C의 int0/1을 기록하고 backendCondition·truthEvidence에는 관찰된 원래 비트와 극성을 유지합니다. sourceDestinations는 소스 참·거짓에 해당하는 실제 목적지를 명시합니다. 중첩 !의 극성과 비교·실수 판정도 관찰된 LLVM 관계로 연결하며, 논리식 하위 분기의 일부만 보고 전체 결과로 추정하지 않습니다. 추가 읽기나 C 함수 재호출은 없습니다.

호출이 만든 SPACE·WRITE 등의 효과는 현재 호출 실행 문맥의 callExecutionId에 연결합니다. 따라서 malloc/free뿐 아니라 calloc/realloc 같은 반복 호출의 생성·수명 종료도 실제 호출 회차를 따릅니다. 매크로 대입은 복구된 표시 범위와 AST 대입형을 사용하며 NULL이라는 이름이나 특정 파일·변수에 분기하지 않습니다.

| 형식 | 구현된 관찰 |
| --- | --- |
| READ | 실제 메모리 읽기의 시작·완료를 한 실행에 연결. 주소·폭·값·출처 또는 실제 입력 스트림 구간 |
| WRITE | 실제 store, 초기화, 함수 인자·반환값, 지원하는 라이브러리의 쓰기 효과 |
| CALC | 소스 표현식과 실제 중간 결과·최종 결과. 독립적인 주소 연산, 비교·변환·선택 |
| FLOW | 함수 호출·복귀, 간접 호출, 분기·반복, switch, 종료 |
| SPACE | 전역 저장 영역, 함수 프레임, 스택 할당, 동적 할당·재할당·해제 |
| ERROR | 오류 한 건을 나타내는 블록. 이후 정상 사건을 만들어 넣지 않음 |

정적 명령의 instructionId는 i 계열이며, 반복·재귀 실행마다 x 계열 eventId/executionId가 생깁니다. activationId는 호출을 구별합니다. 내부 관찰의 m 계열 지점 ID·e 계열 사건 ID는 observationIds와 선택적 원시 출력에서 추적합니다. 실행 상태는 complete/incomplete/failed입니다. 실제 읽기·쓰기의 대상과 출처, dataInputs/addressInputs/controlInputs는 공개 IR의 실행 ID에 연결합니다. 정수 값은 비트열과 문자열로 보존합니다. 소스 위치와 식의 구조는 명령 정의에 두고 실행마다 다시 복사하지 않습니다.

ir-plan.mjs가 AST의 소스 작업으로 공개 명령을 만들고 내부 관찰 지점을 bindings로 연결합니다. 현재 ir-record.mjs는 실행 완료·중단 후 관찰 자료를 해당 명령의 실행 기록으로 정규화합니다. 목표 구조에서는 변환 단계에 확정한 명령 경계를 그대로 사용하여, 정지한 소스 단계의 관측값을 해당 실행 회차에 연결해야 합니다. 기록 정리기와 애니메이션에서 명령 개수나 작업 경계를 새로 결정하지 않습니다.

CALC의 식 구조와 소속 관찰 지점은 실행 전에 정하고, 실제 중간 결과는 실행 중 얻어 steps에 채웁니다. `a + b * 2`의 곱셈·덧셈, `sum += j + 1`의 RHS 덧셈·복합 대입 계산은 각각 같은 CALC의 내부 정보입니다. 저장은 WRITE로 유지합니다. AST 노드별 계산 소속을 관찰 지점 연결 전에 정하며, 호출·부작용·조건부 평가를 임의로 합치지 않습니다. No4에서는 복합 대입이 회차당 CALC 하나인지, ++/--의 계산형이 유지되는지, do-while 분기가 실제 조건식 위치를 가리키는지 확인했습니다.

함수 호출·중간 쓰기·조건부 메모리 접근에 필요한 작업과 순서는 보존합니다. 반환값·대입식 결과가 이미 전달됐다면 그것을 CALC 입력으로 연결하며 불필요한 READ를 추가하지 않습니다. 논리식 내부 분기는 미리 정의한 평가 경로로 다루고, 생략된 작업의 값을 만들어 넣지 않습니다. 컴파일러의 보조 bitcast·PHI·메모리 초기화용 호출 경계는 별도 캐릭터 작업으로 만들지 않되 출처와 메모리 효과를 보존합니다.

### 소스 문장 순서와 상자 생성

공개 중간언어는 프로그래머가 작성한 문장의 진행을 표현합니다. `int first=10; int second=20;`은 `SPACE first → WRITE 10 → SPACE second → WRITE 20`입니다. 한 줄에 문장이 여럿 있어도 이 순서를 따르고, 여러 줄에 걸친 표현식은 해당 표현식의 작업으로 처리합니다. 줄 번호로 실행 사건을 정렬하지 않습니다. 분기·반복·호출은 실제 관측 경로를 따릅니다.

고정 크기 지역변수의 물리적 저장 공간은 컴파일러가 함수 진입 때 미리 확보할 수 있습니다. 수명 표식이 있는 할당은 원시 `SPACE/storage.reserve`로 주소·크기만 기록하고, 실제 `llvm.lifetime.start` 실행 시 객체를 등록합니다. `llvm.dbg.declare` 위치에 추가한 관찰로 선언문 도달을 확인하여 공개 `SPACE/object.begin`을 내보냅니다. `reservationObservationId`는 물리적 공간 확보, `storageObservationId`는 객체 등록, `declarationObservationId`는 선언 진입 근거입니다. 초기화에 필요한 읽기·계산·함수 호출은 상자 생성 뒤에 이어집니다. `WRITE`의 상수 입력은 `inputs[].value.literal`에 남아 immediate 도구에 대응할 수 있습니다.

초기화 없는 선언도 도달하면 상자가 생기며, 실행되지 않은 선언은 상자를 만들지 않습니다. 이름·소스 위치가 없고 포인터로 외부에 노출되지 않는 컴파일러 내부 임시 저장 공간과 직접 읽기·쓰기는 공개 작업에서 제외하고 값의 출처만 이어 줍니다. 원시 관찰은 유지합니다. 매개변수 전달과 전역·정적 초기화는 기존 수명 규칙을 유지합니다.

번들 Clang의 `-O1 -disable-llvm-passes` 조합으로 수명 표식을 생성하되 LLVM 최적화 패스는 실행하지 않습니다. AST의 선언·스코프·저장기간과 LLVM 수명 표식·주소를 연결합니다. `llvm.lifetime.end` 실행은 `SPACE/object.end`에 종료 위치와 선언·스코프 ID를 남깁니다. 반복문 블록에 재진입하면 동일 주소라도 새 객체 ID와 초기화 상태를 사용합니다. 단순히 선언문을 다시 통과한 것만으로 객체를 새로 만들지는 않으며, 이 경우 `coverage.sourceOrder.declarationReentries`를 남깁니다.

함수 선언·정의 정보는 호출 공간을 만들지 않습니다. 실제 호출별 `SPACE/frame.begin`이 스택의 돗자리를 펼칩니다. 함수 반환 경로의 정리는 `SPACE/frame.end.endedObjects`로 묶으며, 앞서 블록에서 종료된 객체는 중복 정리하지 않습니다. 중첩 블록의 종료와 반환 사이에 다른 공개 작업이 없을 때도 같은 방식으로 묶고 정확한 종료 지점은 원관측에 보존합니다. `static`과 힙 객체는 프레임 정리 대상에서 제외합니다. 컴파일러 내부 정리 경로의 switch는 소스의 switch 작업으로 노출하지 않습니다.

수명 표식이 없는 지역변수는 함수 반환까지 추적하는 기존 동작을 유지하며 `coverage.automaticLifetimes.unmarkedLocals`에 표시합니다. 선언을 건너뛴 점프 뒤 실제 접근이 관측되면 이미 등록된 저장 공간을 접근 직전에 노출하고 `declaration-boundary-not-observed`를 남깁니다. 등록되지 않은 접근은 `untracked-memory`로 보고하며 선언 도달을 관측한 것처럼 표시하지 않습니다. 모든 C 수명 규칙을 완성했다는 뜻은 아닙니다.

No7의 블록 종료·정적 변수·호출별 지역변수, 반복문 재진입, break/continue/goto/조기 반환, 반환된 힙 객체, 수명 종료 뒤 접근 및 재진입 후 미초기화 읽기는 `node --test tests/ir-lifetime.test.js`로 검증합니다. 애니메이션은 더미 상태를 유지합니다.

No1의 선언·연산·재대입 순서, 상수 입력과 최신 쓰기 의존관계는 `node --test tests/ir-source-order.test.js`로 검증합니다. 전체 예제 모음의 현재 API 검증이 완료됐다는 의미는 아닙니다.

함수 인자의 ABI 저장은 매개변수 상자 생성 이후의 전달 명령에 연결합니다. 사용자 함수의 복귀와 호출 지점의 복귀 관찰을 중복 실행하지 않으며, 프레임 종료에 수반되는 지역 객체 종료는 endedObjects로 함께 기록합니다. 표준 함수의 호출 경계에서 얻은 쓰기·할당 효과는 복귀 전에 배치합니다. 원래 사용자 함수 본문의 실행 순서를 바꾸는 방식은 아닙니다.

상수 계산이나 실행 경로 제거로 관찰 지점이 없는 소스 작업도 source-only 정의로 보존하고 실제로 실행됐다는 사건은 만들지 않습니다. 매핑이 확실하지 않은 작업은 coverage.unboundSourceWork/unmappedObservations/irGaps에 남깁니다. 대형 초기화 목록과 문자열은 소스 메타데이터를 요약하고, 실제 값은 메모리 기록에서 보존합니다. ir-schema.mjs는 명령·실행의 형식 일치와 출처 ID를 검사합니다.

### 부호 정보와 C 형 변환

자료형에 DWARF encoding, signedness, sizeBits를 보존하고 객체·값의 cType에 연결합니다. typedef와 const 등은 바탕 자료형의 부호 정보를 이어받습니다. unsigned 자료형의 표시 정보는 `display: {label: "int", badges: ["u"]}` 같은 형식입니다. 값의 decimal은 C 자료형에 따라 해석하며, 원본 비트와 signed/unsigned 양쪽 해석도 유지합니다. 화면 렌더러는 아직 연결되지 않았습니다.

일반 int의 기본 표시는 `int`이며 signed 정보를 별도 글자로 덧붙이지 않습니다. 부호 정보는 중간언어에 보존하고 unsigned만 u 배지로 구별합니다. 배열은 전체 형식과 원소 형식을 나눕니다. `int[5]`의 cType은 `kind: "array"`, `count: 5`, `dimensions: [5]`, `sizeBits: 160`이며, elementType은 signedness가 signed인 32비트 int입니다. 배열 자체를 160비트 int로 해석하지 않습니다. 다차원 배열은 elementType을 중첩하며 typedef 이름과 원소의 u 배지도 유지합니다. DWARF의 배열·부분범위 정보와 Clang의 자료형 문자열을 사용하고, 결과를 캐시합니다. 원본 C를 다시 해석하지 않습니다.

포인터는 `kind: "pointer"`, 주소 폭, pointee, qualifiers를 재귀적으로 보존합니다. `const char *`의 const는 pointee에, `char *const`의 const는 포인터 자체에 있습니다. typedef와 이중 포인터에도 같은 규칙을 적용합니다. 연산의 의미 AST가 확인되면 그 노드를 우선 사용하므로 같은 위치의 배열→포인터 변환을 char→int 승격으로 오인하지 않습니다. 이 승격은 비교 CALC의 내부 단계에 남으며, 포인터 덧셈의 공개 연산자와 memcpy 같은 소스 함수 이름도 보존합니다. LLVM 이름은 backendCallee와 원시 관찰에 따로 있습니다.

일반 원소·필드·역참조 대입도 AST의 대입식 자료형을 LLVM store에 연결합니다. 복합 대입처럼 실제 저장 폭과 일치할 때만 적용하며, 인덱스 계산이나 우변의 자료형을 대상형으로 덮지 않습니다. 예를 들어 `b[3] = -5`는 WRITE 정의와 실행값 모두 signed int/32비트를 갖습니다.

같은 폭의 int→unsigned int 변환은 LLVM에서 별도 명령이 사라질 수 있습니다. Clang AST에서 IntegralCast를 찾고, 위치·자료형·생산 연산이 유일하게 대응하는 실제 SSA 값 뒤에 변환 관찰을 추가합니다. 공개 IR에서는 CALC의 steps[].conversion 또는 독립 변환 명령에 fromType, toType, explicit, sameWidth, bitsUnchanged, fromValue를 보존합니다. 피연산자를 다시 평가하지 않습니다. 이후 출처 연결도 공개 IR 실행 ID로 변환합니다.

unsigned→signed도 같은 방식으로 보존합니다. 컴파일 중 상수 계산됐거나 위치 대응이 모호한 변환은 실행 사건을 추측해서 만들지 않고 `coverage.cConversions.unobserved`에 남깁니다. 현재는 단일 소스에서 위치를 확인할 수 있는 정수 변환을 보완하며, 모든 매크로·최적화·표현식 형태의 소스 대응을 완성한 것은 아닙니다.

### 논리식·삼항식 평가와 도움말 더미

`0 && ++x`, `1 || ++x`는 공개 중간언어에서 논리 CALC 한 건입니다. 결과는 C의 int 0/1이며, evaluation에 leftTruth, right="skipped", reason을 기록합니다. 오른쪽에는 읽기·계산·쓰기 사건이나 가상의 결과값을 추가하지 않습니다. 내부 관찰의 FLOW/short-circuit은 컴파일러가 접은 결정을 복구하는 근거이며 별도 공개 FLOW로 표시하지 않습니다.

상수 왼쪽의 생략 결정은 결과를 실제 사용하는 초기화·단순 대입·호출·반환 직전의 관찰로 연결합니다. 실행되지 않은 소비 지점에서는 관찰도 실행되지 않습니다. observedConsumerValue는 실제 LLVM 피연산자로부터 받고, 생략 이유는 AST에서 얻습니다. 소비 작업의 dataInputs가 논리 CALC를 참조합니다. 이는 컴파일 중 사라진 식의 하드웨어 실행 시점을 관측했다는 의미가 아닙니다.

변수 왼쪽의 논리식은 실제 분기 관찰을 사용합니다. AST의 논리식과 LLVM의 비교·분기·PHI·확장을 연결하며, 논리 결과에 필요한 보조 icmp/zext를 별도 애니메이션 명령으로 늘리지 않습니다. 중첩 식과 호출·반복 회차의 결정을 구별합니다. ++/--의 READ → CALC → WRITE 등 실제 부작용은 순서대로 유지합니다. 순수 비교식 자체가 있는 경우 그 비교 작업과 내부 진릿값 변환도 구별합니다.

plan.evaluations에는 식과 피연산자의 AST ID·소스 범위·자료형을 둡니다. 논리식 정의의 helpMarker는 `{kind:"logical-short-circuit", status:"stub", when:"right-skipped"}`입니다. 실행에서 실제 오른쪽 생략이 확인되면 CALC의 helpMarker에 reason, evaluationNodeId, highlight, skippedSource를 남깁니다. 향후 강조된 코드에 “왼쪽만으로 참/거짓이 결정되어 오른쪽은 실행하지 않습니다”라는 도움말을 붙일 표지입니다. 현재 툴팁·불빛·애니메이션은 구현하지 않습니다.

삼항식은 plan.evaluations의 condition/true/false 범위에 연결합니다. 내부 분기는 별도 공개 이동 명령을 만들지 않으면서 선택된 작업의 controlInputs를 유지합니다. PHI/select는 선택된 값과 조건 출처를 소비 작업으로 전달하며, 조건 CALC를 다시 생성하지 않습니다. 소비 작업의 inputEvaluations에는 selected/skipped, conditionTruth, 결정·결과 출처가 들어갑니다. 반복 실행에서도 선택되지 않은 갈래의 이전 값을 출처로 섞지 않습니다.

`expression-ownership.mjs`는 컴파일러가 연결한 AST 노드와 부모 관계를 우선하고, LLVM의 값 생산자·분기 입력·PHI 유입 간선을 함께 확인합니다. 같은 소스 위치를 가진다는 이유만으로 삼항 선택을 논리 CALC에 포함하지 않습니다. PHI/select의 입력은 삼항식의 각 가지와 대응시키며, 위치가 없는 논리 PHI는 실제 분기에서 확인한 AST 소속을 사용합니다. 조건 영역은 분기 입력의 SSA 의존 관계로 구하고, 위치만 같은 무조건 이동이나 바깥 선택 가지는 포함하지 않습니다. 조건 내부의 삼항식은 자체 FLOW를 유지합니다. 선택값은 값 입력, 선택 결정은 제어 원인으로 보존하며 관찰을 위해 C 식을 다시 실행하지 않습니다.

2026-11-04 관련 검증: 재현 코드와 이름·배치·논리 연산자·중첩 선택·상수 가지·호출·증감을 바꾼 회귀 검사 7개, 기존 평가·조건·매크로·CALC 입력 검사 24개가 통과했습니다. 원본 코드 의미 재분석 횟수는 재현 실행에서 0이며, 컴파일러 위치에 연결된 AST와 LLVM 관측값을 사용합니다. 기존 No5 검사의 선택 결정 연결은 값 입력이 아닌 controlInputs와 decisionExecutionIds를 검사하도록 정정했습니다. 이 항목은 수정 전 모듈로도 동일한 값·제어 분리 결과임을 확인했습니다.

`i == 4 ? '\n' : ' '`는 비교 CALC → 갈래 선택 → 선택값 전달로 기록합니다. 삼항식 전체를 반환값 10/32의 추가 CALC로 합치지 않습니다. 공개 비교값은 C int의 0/1이고, LLVM i1은 원시 관찰에 남깁니다. 원본의 형 변환에 대응하지 않고 SSA 소비자도 없는 i1 확장은 공개 계산에서 제외합니다. `(unsigned long long)(a < b)`처럼 소스에 존재하는 변환은 유지합니다.

일반 상수식 전체를 별도 C 해석기로 계산하지 않습니다. 컴파일 중 접힌 결정의 미관측은 coverage.shortCircuits.unobserved, 식 결과의 미연결은 coverage.expressionEvaluations.unbound에 남깁니다. 모든 매크로·조건문 직접 분기 형태를 완전히 지원한다는 뜻은 아닙니다. No5, 변수 왼쪽, 중첩 논리식, 조건값과 다른 선택 결과, 반복된 갈래 선택, compile-only 표지를 검증했습니다.

### 컴파일 시 타입 선택과 정렬 조회

`_Generic`의 연관 항목은 AST 어댑터가 GenericAssociation으로 보존합니다. Clang의 selected 표지를 사용하며 타입 이름 비교로 C 호환 규칙을 재구현하지 않습니다. plan.compileTimeSelections에 제어 타입·선택 항목·선택된 식·미평가 제어식·선택되지 않은 항목을 기록하고, 관련 CALC·WRITE·FLOW 정의는 selectionIds와 단일 선택의 selection으로 연결합니다. 소스 트리의 evaluationState는 미평가·미선택을 구분합니다. 실제 바인딩 후보에서 그 부분을 제외하고, 계산 묶음과 접힌 식도 선택된 식만 사용합니다. 별도 런타임 타입 검사·분기를 생성하지 않습니다.

`_Alignof(type-name)`는 alignof 메타데이터에 queriedType·byteAlignment·operandEvaluation·근거를 남깁니다. 필요한 경우 기존 LLVM 생성 호출에 Clang record layout 출력을 요청하며 별도 사용자 실행이나 원문 의미 재분석을 하지 않습니다. 레코드의 정렬·packed·명시적 정렬은 컴파일러 배치 보고서를, 기본형·포인터는 같은 대상 ABI 어댑터를 사용합니다. typedef의 정렬 속성과 선언 가시성도 구별합니다. 비교가 접혔으면 기존 foldedCalculations로 실제 상수 소비값에 연결합니다. 타입별 객체를 만들거나 sizeof를 정렬값으로 사용하지 않습니다. 모호한 배치, 추가 선언 근거가 필요한 GNU 표현식 정렬 등은 coverage.compilerTypeQueries.unresolved에 남깁니다.

## 메모리와 구조

No21~No34는 실제 중간언어 과정에 더해 자료구조 표현·배치의 판단 근거를 확인하는 예제로 사용합니다. 코드·입력과 관찰된 연결에서 보기 후보를 검토하고, 동일 객체를 배열·트리·그래프 등으로 함께 표현할 때 필요한 정보도 확인합니다. 범위와 예제별 기대 항목은 [자료구조 표현·배치 검증](structure-view-validation.md)을 따릅니다. 자동 배치 구현 완료를 뜻하지는 않습니다.

- 주소가 재사용돼도 할당·호출마다 객체 ID를 새로 발급합니다. 전역·정적 객체는 함수 반환으로 종료하지 않습니다.
- 물리적 할당과 자료형으로 본 영역을 분리합니다. 큰 할당 내부에 구조체가 있어도 이를 새 물리적 할당으로 중복 생성하지 않습니다.
- 배열의 원소형·개수와 구조체의 필드 배치는 컴파일러 정보에서 얻습니다. 중첩 배열을 격자 형태로 표현할 근거도 여기서 얻을 수 있습니다.
- 포인터 필드에 실제 저장된 주소를 연결합니다. 동일한 레코드 타입의 연결에서 순환·부모 수를 계산해 그래프, 트리·숲, 연결 체인을 후보로 제안합니다. 변수명·구조체명·필드명의 의미로 판정하지 않습니다.
- 타입이 확인되지 않은 void 포인터나 정수 쌍에 그래프·격자의 의미를 임의로 부여하지 않습니다. 사용자 의도에 따른 고급 자료구조 인식은 후속 작업입니다.
- 초기화가 확인되지 않은 영역과 외부 호출 때문에 상태를 확인할 수 없는 영역을 구분합니다. 미관측 상태를 곧바로 쓰레기값이라고 단정하지 않습니다.
- 일반 READ/WRITE의 value.bytesHex 미리보기는 최대 64바이트입니다. 접근 크기와 생략 여부를 함께 표시합니다. 구조별 요약은 마지막 참조 기록이며, 그 객체의 최종 수명은 별도 필드로 확인합니다.

### 초기 상태와 복사 결과의 값 보존

초기화된 전역·정적 저장 영역은 등록 시 실제 메모리의 memoryState를 남깁니다. 컴파일러가 만든 상수 배열 템플릿도 포함하므로, 부분·지정 초기화의 나머지 0까지 컴파일 결과 그대로 보존합니다. memcpy/memmove의 완료 WRITE에는 원본 객체·범위와 복사 직후 목적지의 memoryState를 기록합니다. 이후 READ를 기다리지 않고 초기 상태를 복원할 수 있습니다.

memoryState는 memory-ranges-v1 형식입니다. 각 범위는 offset, length, initialization과 선택적인 data를 가집니다. 값은 hex 바이트 또는 반복 바이트(fill)로 저장합니다. 미초기화·초기화 여부 미관측 영역은 바이트를 읽지 않고 상태만 남깁니다. calloc/memset의 확정된 채움 효과는 짧은 fill 기록을 사용합니다. 구조체 값 전달의 ABI 복사와 realloc으로 보존된 범위도 초기화 상태와 함께 저장합니다.

관찰 스냅샷은 기존 SPACE/WRITE 사건의 추가 데이터이며 프로그램의 READ를 늘리지 않습니다. 이는 C 식을 다시 평가한 결과가 아닙니다. 한 실행의 관찰 스냅샷에는 압축 후 대략 8MiB의 기록 예산을 적용하며, 초과한 값은 초기화 여부를 유지한 채 snapshot-budget 사유로 미관측 처리합니다. 생략된 값을 0으로 복원하지 않습니다. coverage.memorySnapshots에서 캡처·생략 통계를 확인할 수 있습니다.

scripts/model/memory-state.mjs의 materializeMemory는 메모리 구간 하나의 스냅샷을 실제 메모리나 미래 READ 없이 해독합니다. bytes와 별도로 initialization, known 마스크를 반환하므로 버퍼의 기본 0을 미관측 값으로 오인하지 않습니다. 블록 수명은 컴파일러 수명 표식과 VLA 스택 복원 관측으로 추적합니다. 명령별 시각화 상태 전이, 임의 실행 위치의 상태 복원, 체크포인트, 웹 재생 화면은 아직 구현하지 않았습니다. 원하는 시점의 재생에는 초기 상태·변경 기록·선택적인 체크포인트를 사용하며 모든 쓰기의 이전 값은 필수 데이터가 아닙니다.

### 문자열 라이브러리의 쓰기 효과

외부 strcpy/strcat/strncpy 호출은 함수 진입 전에 추적 중인 원본의 종결 문자와 접근 범위를 확인하고, 복귀 관찰에서 실제 목적지 바이트를 수집합니다. 공개 IR에서는 해당 WRITE/copy를 복귀 전에 배치합니다. sourceObjectId/sourceOffset/sourceSize, target, memoryState를 포함하며 호출 정보는 명령 정의의 callee에 있습니다. strcat은 추가되는 범위만 쓰기로 남깁니다. strncpy는 최대 n바이트만 원본을 확인하며, 종결 문자가 없으면 임의로 추가하지 않고 짧은 원본 뒤의 0 채움은 paddingSize로 구분합니다.

readRegions에는 API가 사용하는 원본과 strcat의 기존 목적지 문자열 범위가 있습니다. dataInputs와 callExecutionId는 공개 IR의 값 출처·호출 실행을 연결합니다. 원시 ID는 관측 근거로 구분합니다. previousMemoryState는 선택적인 이전 상태 자료이며 원하는 위치를 다시 보는 기능의 필수 조건은 아닙니다. 미초기화 영역의 이전 바이트는 읽지 않습니다. 문자열의 종결 문자는 includesNullTerminator/terminatorOffset으로 구분합니다. 내부 구현의 개별 읽기 순서나 가상의 READ 사건을 만들지 않습니다.

### 함수 이름에 의존하지 않는 메모리 관찰

현재 기본 경로는 사용자 LLVM 계측에 더해 링크된 WASM의 스칼라 load/store를 관찰합니다. wasm-memory.mjs는 원래 접근이 성공한 뒤 주소·크기·읽기/쓰기를 기록하며, 원래 연산과 값은 유지합니다. 추적 객체와 겹치는 읽기는 readRegions와 이전 WRITE 출처로, 쓰기는 실제 바이트를 담은 WRITE/write.range로 연결합니다. 기존 복사·채움 계약이 있는 호출은 그 의미 있는 WRITE를 사용해 중복을 피합니다. strlen·sscanf·snprintf·strchr 등의 이름별 관찰기를 추가할 필요가 없습니다. 모든 호출 지점에 잠재적 입출력·범위 쓰기 정의를 만들고, 실제 발생한 효과만 실행 기록을 생성합니다.

외부 호출이 사용자 콜백을 호출하면 콜백 진입 전에 누적된 쓰기를 반영합니다. 직접 외부 호출의 콜백 인자에 외부 함수 자체의 인자를 잘못 연결하지 않으며, callbackOfCallExecutionId로 둘의 관계를 표시합니다. 실제 콜백 매개변수 값은 함수 진입 계측에서 얻습니다. 외부 함수 포인터를 거친 재호출의 출처 구분은 아직 완전하지 않습니다.

라이브러리의 읽기는 실제 기계 접근 범위이며 문자열 종결 문자보다 넓은 워드 읽기를 포함할 수 있습니다. 이는 소스에서 새 READ를 실행한 것이 아닙니다. 라이브러리 내부 산술·소스 프레임·내부 할당 객체를 모두 시각화한다는 의미도 아닙니다. malloc 계열의 수명·초기화 계약은 여전히 명시적으로 필요합니다.

### 실제 입출력과 호출 연결

출력 함수 이름으로 수집 여부를 결정하지 않습니다. WASI fd_write에 실제 전달된 iovec 바이트가 기준이며 output.delivery에 보존합니다. 추적 중인 사용자 버퍼의 직접 출력은 전달한 호출에 연결하고, 런타임 버퍼의 지연 출력은 관찰된 마지막 쓰기 호출을 출처로 연결합니다. bufferWriterCallExecutionId는 버퍼 작성 호출을 별도로 보존합니다. 이 후자는 메모리 쓰기 출처이며 모든 사용자 정의 스트림의 의미를 보장하지 않습니다. 포맷을 다시 해석하거나 C 함수를 재실행하지 않고 버퍼링 정책도 변경하지 않습니다. 이전 stdio-observer.mjs의 __fwritex 경로는 메모리 관찰 기능이 없는 관찰기용 호환 경로입니다.

공개 IR에서는 동일한 호출 실행·활성 프레임·출력 채널에 속하고 스트림 바이트 위치가 이어지는 연속 출력 조각을 하나의 WRITE/output으로 합칩니다. 예를 들어 본문과 줄바꿈이 따로 관측돼도 `"안녕하세요\n"`은 한 출력 작업입니다. text에는 합친 바이트를 해독한 문자열, bytesHex에는 정확한 바이트, streamOffset에는 첫 위치, byteLength에는 합계, observationIds에는 모든 원시 조각의 ID를 보존합니다. 실제 채널별 출력 순서를 유지할 수 있을 때 해당 호출 안의 FLOW/call → WRITE/output → FLOW/resume 위치에 배치합니다.

서로 다른 출력 호출은 같은 소스 위치가 반복 실행돼도 합치지 않습니다. output-events.mjs는 실제 전달의 ID·바이트 오프셋·내용이 일치하는 범위만 중복 표시에서 제외합니다. 연결되지 않은 나머지 바이트는 공개 output에도 남기고 unattributed-stdio-delivery를 보고합니다. coverage.stdioOutput에는 전달·검증·미연결 바이트 수가 있습니다. 문자열 내용이 같다는 이유만으로 과거 호출을 추정하지 않습니다.

버퍼에 A를 넣고 직접 B를 출력한 뒤 버퍼를 비우면 실제 전달은 BA입니다. 호출 순서 AB로 옮기지 않고 전달 순서를 보존하며 output-delivery-order를 보고합니다. 아직 전달되지 않은 버퍼가 오류나 강제 종료로 사라지면 기본 경로에서는 출력 사건으로 복원하지 않습니다. 사용자 지정 스트림·버퍼의 논리적 수용 시점과 모든 호출별 대응은 미완성입니다. stdin은 실제 읽은 바이트를 READ/input으로 기록하고, 변환 성공 여부와 별개인 이 입력 사건을 실제 목적지 WRITE/write.range와 구분합니다.

명시적인 문자열 계약에서는 종결 문자 누락, 미초기화 읽기, 목적지 범위 초과와 겹침을 호출 전에 검사합니다. 공통 메모리 관찰은 기존 추적 객체에 대한 접근을 기록하는 기능이며, 모든 라이브러리 오류를 미리 차단하는 기능은 아닙니다. 알려진 할당 없이 외부 함수가 포인터를 반환하면 external-return-storage-untracked로 표시합니다. 내부 복사의 미초기화 전파 같은 의미도 공통 바이트 관찰만으로 모두 판정할 수 없습니다.

### 관찰 기록의 누락 검사

coverage.observationAccounting은 원시 사건 전체를 공개 명령에 반영, 다른 명령으로 전달, 명시적 컴파일러 보조 처리, 미도달 선언의 저장 공간 예약으로 구분합니다. 어느 분류에도 속하지 않으면 unexplained와 observations-without-disposition을 남깁니다. 이 검사는 이미 수집한 사건이 사라지는 문제를 찾으며, 처음부터 계측하지 않은 내부 의미까지 완전하다는 증거는 아닙니다.

### 공통 작업 계약과 관측 경계

ir-schema.mjs에서 calc-contract.mjs와 work-contracts.mjs를 적용합니다. CALC는 소스 연산자·실제 입력값·입력 출처와 실행 순서를 검사합니다. 이미 관찰된 AST 값 경계도 함께 확인하므로 입력·단계·데이터 연결을 동시에 지운 기록을 빈 입력 목록으로 통과시키지 않습니다. 주소 계산 후 READ, 함수 호출, 삼항 선택, 단락 평가의 경계를 유지하며 C 식을 다시 실행하지 않습니다.

READ/WRITE의 물리 객체·범위·값, 복사 스냅샷의 바이트 범위, 출력 바이트, SPACE의 객체·프레임 수명, FLOW의 조건값·선택·관측 근거, 모든 의존 관계의 선후를 검사합니다. 위반은 정상 완료로 반환하지 않습니다. coverage.workContracts.semanticCompleteness는 구조 검증만으로 의미적 완전성을 보장하지 않는다고 명시합니다. 이 검사는 처음부터 관찰하지 않은 작업이나 모든 C 문법 지원을 증명하지 않습니다.

이름별 malloc/free/memset 등의 계약은 컴파일러가 외부 호출로 분류한 경우에만 적용합니다. 같은 이름의 사용자 함수는 실제 본문과 공통 메모리 관찰로 처리합니다. 외부 전역은 링크된 실제 주소와 컴파일러 자료형으로 등록하며, 사용자 코드에서 stdout 등의 저장 공간을 읽을 때도 물리 객체를 연결합니다.

삼항식은 조건을 얻은 뒤 FLOW/conditional을 기록하고 선택된 가지의 READ·호출·WRITE로 이어집니다. 논리 조건은 실제로 읽은 값만 한 CALC에 넣으며 생략된 가지를 평가하지 않습니다. VLA의 스택 저장·복원은 컴파일러 관리 정보로 처리하며 실제 복원 시 해당 자동 객체의 SPACE/object.end를 기록합니다. 종료 함수에 의한 정리에서도 각 프레임과 객체의 원래 소유권을 보존합니다.

누적 결함의 확인 범위와 수정 근거는 [2026-11-04 공통 모델 감사](model-audit-2026-11-04.md)에 기록합니다.

## 지원 범위와 한계

### 값 출처와 최종 진단 보강 (2026-11-04)

컴파일러 보조 명령을 접을 때 값·주소·제어·호출 대상 의존성을 구분합니다. 숨겨진 스칼라 저장과 읽기가 같은 범위의 실제 단일 쓰기로 연결되면 그 값을 소비자에게 전달합니다. 리터럴 반환은 컴파일러의 상수 값과 소스 위치를 보존하고 앞선 분기는 controlInputs에만 남깁니다. 변수·계산·호출 결과의 전달도 같은 경로를 사용하며 부분 쓰기나 여러 생산자를 임의의 값 하나로 합치지 않습니다.

`coverage-resolution.mjs`는 최종 AST/LLVM 바인딩으로 앞선 진단을 갱신합니다. observationMappingHistory와 cConversions.initiallyUnobserved에 이력을 남기고, 실제 해결된 항목과 아직 미해결인 항목을 분리합니다. 상수 접힘이나 타입이 연결된 리터럴 피연산자에서 복구한 변환은 AST 노드·자료형·실제 입력 비트를 확인합니다. 계획의 바인딩 완료와 실행에서 관측된 변환을 구별하고, 실행되지 않은 변환을 관측됐다고 표시하지 않습니다. 원본 코드를 다시 읽거나 C 식을 재실행하지 않습니다.

자료구조에는 기존 관찰을 이용한 정수 목적지 그래프·독립 커서 FIFO 후보를 추가했습니다. 지원 범위와 미확정 상태는 [자료구조 표현·배치 검증](structure-view-validation.md)의 보강 절에 정리합니다. No30의 원래 작업 1211개와 실제 값을 유지하면서 네 보완점의 비교 29개가 통과했습니다. 관련 범용 검사 33개만 실행했으며 예제 전체를 다시 실행하지 않았습니다.

### 상수 변환의 소비 지점 연결 보강 (No31)

`conversion-consumers.mjs`는 AST의 변환을 기존 CALC/WRITE의 실제 소비 지점에 연결합니다. 접힌 부분식의 입력, 조건부 식에서 선택한 상수 가지, 컴파일러가 정한 정수 배열 초기화 위치를 지원합니다. 배열은 원소 크기·중첩 인덱스·관측된 초기화 바이트 범위를 확인하며 부분적이거나 미초기화된 바이트로 값을 확정하지 않습니다. 구조체·union의 임의 집계 배치를 이 경로에서 추측하지 않습니다.

`conversionConsumers`는 컴파일러 근거와 관측한 consumerValue를 분리합니다. 변환 결과 자체가 소비값이면 observed-at-consumer이며, 큰 상수식 내부의 변환처럼 중간값이 관측되지 않았다면 compiler-folded-unobserved로 남기고 conversionValue를 만들지 않습니다. 선택되지 않은 가지는 not-executed이고 실행 근거가 부족하면 unobserved입니다. cConversions의 resolved는 소비 지점 연결이 해결됐다는 의미이며 모든 내부 중간값을 관측했다는 의미가 아닙니다. 새 애니메이션 명령이나 C 식의 재실행은 추가하지 않습니다.

No31의 누락된 변환 6개가 소비 지점에 연결됐으며 기존 1,262개 작업의 순서·값·접근은 새 메타데이터를 제외하고 동일했습니다. 수정 전 예측 파일과 원본 코드는 그대로 사용했습니다. 힙 배열·소유 관계·타입 보기 보강의 범위는 [자료구조 표현·배치 검증](structure-view-validation.md)에 기록합니다.

### 반환 경유 출처와 자료구조 관계 보강 (No32)

`observed-value-flow.mjs`의 sourceRead는 가장 가까운 메모리 READ까지, reads는 기록된 값 보존 경로의 READ들을 추적합니다. resultDeliveries의 실제 호출·반환·복귀 식별자를 이용하며 재귀 호출을 구별합니다. 호출 인자나 주소·제어 의존성을 결과의 출처로 바꾸지 않고, 산술과 축소 변환·값 변화에서는 복사 추적을 중단합니다. 실행마다 공통 추적기를 하나 만들어 배열 작업과 자료구조 후보가 재사용합니다. 원본을 다시 분석하거나 C 식을 재실행하지 않습니다.

이 출처 관계를 이용해 배열 값 기반 인덱스 연결과 인덱스별 집계 후보를 추가했습니다. 상태·근거·한계는 [자료구조 표현·배치 검증](structure-view-validation.md)의 No32 절에 기록합니다. SPACE·READ·CALC·WRITE·FLOW의 종류나 실행 순서를 늘리지 않으며 애니메이션은 더미 상태입니다. No32 관계 보완 당시 기존 1,006개 사건 및 반환 전달은 동일했고, 보완점 39개와 기존 과정 비교 38개가 통과했습니다. 변형 검사에서 별도로 발견한 복합 조건식 CALC 입력 누락은 이후 위 AST·LLVM 소속 연결 보완으로 수정했습니다.

### 기존 실행 지원 범위

현재 경로는 정수·float·double, 배열, 구조체, 포인터, 재귀·함수 포인터, 조건·반복·switch·점프를 컴파일된 공통 연산으로 관찰합니다. 구조체의 값 전달·반환에 필요한 ABI 복사도 처리합니다. malloc/calloc/realloc/free, memcpy/memmove/memset과 일부 문자열·입력 함수는 별도 API 효과 관찰을 연결했습니다.

지원하는 검사에는 추적 객체의 미초기화 읽기, NULL, 할당 범위·수명 위반, 잘못된 free/realloc, 정수 제수 0, 일부 정수 범위·시프트 오류가 있습니다. 완전한 C 미정의 동작 검사기는 아닙니다.

- 자동 객체의 블록 수명은 컴파일러 수명 표식과 스택 복원으로 추적합니다. 나머지 표식 없는 객체는 함수 수명 추적으로 대체하고 누락을 보고합니다. 관찰한 VLA 복원 이후의 접근은 수명 위반으로 처리하지만, C의 모든 블록 수명·비지역 점프·포인터 출처 규칙과 부분 배열 경계까지 완전하게 검사하지 않습니다.
- 라이브러리의 스칼라 메모리 접근을 관찰하지만 내부 산술·소스 프레임과 추적되지 않은 내부 객체는 만들지 않습니다. 사용자 정의 할당기, 사용자 버퍼를 쓰는 스트림, 외부 함수 포인터 경유 콜백의 정확한 의미 연결은 추가 지원이 필요합니다. 모든 라이브러리 오류의 사전 검출·미초기화 전파를 보장하지 않습니다.
- 링크된 WASM에서 지원하지 않는 bulk-memory·SIMD 등의 명령을 만나면 관찰을 생략하지 않고 실행 준비를 실패시킵니다. 현재 번들의 wasm32 스칼라 경로를 대상으로 합니다.
- atomic/volatile, 인라인 어셈블리, 벡터·확장 실수 연산 등 미지원 항목은 실행 전에 거부합니다. 단일 파일과 번들 WASI 표준 라이브러리를 사용하며 사용자 헤더·여러 번역 단위 입력은 아직 없습니다.
- 수집 결과는 이 WASM 실행의 결과입니다. 네이티브 컴파일러의 메모리 배치·평가 순서·성능을 대표하지 않습니다.
- GDB처럼 소스 단계별로 정지·재개하고 애니메이션 완료 후 다음 단계로 진행하는 실행 제어는 아직 없습니다. 웹 편집기와 캐릭터 애니메이션에도 연결하지 않았습니다.

상태는 completed, fault, limited, unsupported, compile-error, engine-error를 구분합니다. 미지원이나 도구 오류를 정상 실행으로 표시하지 않습니다.

## 실행 제한

기본 내부 관찰 제한은 100,000개, 컴파일과 실행을 합친 제한은 25초입니다. `--max-events`와 `--timeout-ms`로 조정하며 최대 설정은 1,000,000개와 120초입니다. 관찰 수는 정규화한 IR 실행 수와 다릅니다. Worker 시간 제한에서는 전달된 관찰까지만 IR로 변환하며 최대 255개 관찰과 출력이 남지 않을 수 있습니다. 실패·미완료 명령을 완료로 표시하지 않습니다. compile-only도 Worker 시간 제한을 적용합니다.

스키마 3 초기 변경 당시의 정적 검사 이후, 제공된 No1–9와 공통 회귀 검사를 진행했습니다. tests/model.test.js는 includeObservations의 원시 관찰 계약을, tests/ir-*.test.js는 공개 중간언어 계약을 검사합니다. 이름·행·주석·값 변형, 추가 라이브러리 호출, 비계측 실행과의 비교를 포함합니다. 전체 C 지원 완료를 뜻하지 않으며 애니메이션과 재생기는 현재 개발 범위 밖입니다.

기존의 최소 정수 시제품은 `pnpm trace:prototype`, 정규식 전용 수동 계측 실험은 `pnpm trace:regex`로 유지합니다. 두 실험의 예상값 파일이나 소스별 관찰 지점은 이 기본 모델에서 읽지 않습니다.

## 다차원 배열의 작업 관계 보강

다차원 저장소는 컴파일러의 중첩 배열 자료형에서 차원·원소 크기·바이트 stride를 얻고, 실제 접근한 객체와 바이트 범위를 좌표에 대응시킵니다. 기존 행 단위 배열 정보를 유지하면서 셀·셀 구간·부분 셀 접근을 구분합니다. AST의 각 접근 노드와 축을 연결하므로 대입의 LHS와 RHS를 섞거나 열 범위를 행 인덱스에 적용하지 않습니다. 근거가 부족한 차원·범위는 미확정으로 남깁니다.

한 CALC에 포함된 형 승격의 입력은 공개 executionId만으로 구분하지 않습니다. 내부 observationId와 step의 실제 입력 관계를 따라 각 READ를 연결하며, 값이 같다는 이유로 출처를 합치지 않습니다. 산술이나 값이 달라지는 변환을 단순 복사로 취급하지 않습니다.

array-work의 computedDependencies는 실제 READ → CALC → WRITE의 계산 의존 관계입니다. 단순 값 전달인 transfers와 구분하며, 각 READ에서 추적을 멈춰 과거 저장 이력을 다시 펼치지 않습니다. 실제 입력·계산·저장 사건과 선택의 제어 원인을 따로 보존하고, 함수 반환은 일치하는 호출·반환·복귀 기록으로만 연결합니다.

array-cursor-path는 다차원 접근의 축 역할과 관측된 커서 객체를 연결합니다. 커서의 원래 스칼라 값, 실제 메모리 접근 좌표, 반복 경계의 요약을 구별하고 순차 갱신의 중간 상태와 객체 수명을 유지합니다. 커서 값을 인덱스 식으로 다시 계산하거나 이동 경로에 있는 모든 셀을 읽었다고 기록하지 않습니다.

이 정보는 기존 실행에 붙는 표현용 관계입니다. 새 중간언어 명령·메모리 READ·C 식 실행을 추가하지 않습니다. 평탄 배열을 임의의 격자로 확정하거나, 접근 패턴만으로 특정 알고리즘과 작성 의도를 확정하지 않습니다.

## 주소 계산의 AST·LLVM 연결

`read-access.mjs`는 READ뿐 아니라 GEP의 기저 SSA 값과 컴파일러 저장 경로를 연결합니다. 선언 식별자, 구조체 필드의 순번·바이트 배치·자료형, 배열 인덱스의 실제 SSA 생산자 또는 컴파일러 상수를 대조합니다. 포인터 뺄셈의 음수 인덱스와 호출 결과의 주소도 연결하며, 호출 결과는 해당 CallExpr를 정적 원점으로 삼고 실제 대상 객체는 실행 관측으로 결정합니다. 함수를 다시 호출하거나 소스 식을 재평가하지 않습니다.

검증된 연결은 관찰 명령과 공개 계획의 `addressBinding`에 보존합니다. `c-semantics.mjs`의 semanticNodeId와 `ir-plan.mjs`의 주소 연산 분류·계산 소유권이 같은 AST 노드를 사용합니다. 매크로 시작 위치에 여러 표현식이 겹쳐도 단순 LValueToRValue를 CALC로 만들지 않습니다. lvalue 내부의 저장 위치 선택은 별도 연산 단계로 중복 표시하지 않으며, CALC 계약 검사는 유지합니다. 필드·인덱스 근거가 모호하면 정확한 연결로 확정하지 않습니다.

매크로의 호출도 이미 확인한 CallExpr 연결을 우선합니다. 관측기의 포인터 PHI/select는 실제 선택된 입력에서 객체 출처를 전달하며, 다른 분기의 이전 반복 값을 가져오지 않습니다. 두 경로 모두 예제명이나 변수명에 따른 동작 분기가 없습니다.

No34는 중간언어 9,677개 사건으로 실행을 완료했습니다. 관련 검사 30개와 사전 예측 대비 과정 검사 54개가 통과했습니다. 실제 값·회전·해제와 자료구조 후보의 정확성은 별도 검사합니다. 이후 보강한 관계 역할·종료 경계와 남은 추론 한계는 [자료구조 표현 검증](structure-view-validation.md)의 No34 절에 기록합니다.

## boolean 표현과 LLVM 정수 표기의 연결

Clang AST의 `bool` 표기와 LLVM 디버그 자료형의 `_Bool`을 동일한 boolean 자료형으로 연결합니다. 저장 공간의 크기는 대상 ABI에서 얻으며, LLVM의 계산형 `i1`을 별도의 1비트 C 객체로 표시하지 않습니다. `boolean-representation.mjs`는 boolean 자료형, 실제 SSA 생산자·소비자, 저장 접근을 근거로 저장형과 계산형 사이의 보조 변환을 내부 관측으로 분류합니다. 같은 boolean 값을 복사할 때 공개 과정은 READ → WRITE이며 값의 출처는 유지합니다. 정수·실수·포인터를 boolean으로 바꾸거나 boolean을 정수로 바꾸는 실제 C 변환은 보존합니다. 모든 trunc/zext를 일괄 숨기거나 CALC 검증을 완화하지 않습니다.

매크로 안 정수 상수와 LLVM 피연산자를 연결할 때는 컴파일러가 확인한 정수 자료형과 비트 폭으로 비교합니다. unsigned 최댓값이 LLVM에서 `-1`로 출력되더라도 같은 비트 패턴이면 같은 상수 근거입니다. 이 연결은 소스 자료형·부호 표시를 바꾸지 않으며, 관측값을 맞추기 위해 C 식을 재실행하지 않습니다.

구조체 반환 직후 같은 소스 위치에 생성되는 LLVM 메모리 복사는 원래 함수의 추가 호출이 아닙니다. `aggregate-bindings.mjs`는 LLVM 메모리 intrinsic과 일치하는 실제 소스 CallExpr가 있을 때만 호출로 연결합니다. 컴파일러가 삽입한 복사는 WRITE/copy로 남겨 함수 호출 → 반환 → 복귀 → 실제 저장 순서를 보존합니다.

반복문의 같은 호출 위치는 매번 같은 SSA 결과 이름을 재사용합니다. 포인터 반환의 객체 출처는 최초 호출 때만 등록하지 않고 각 실제 반환 때 갱신합니다. 해당 호출의 return.value에서 얻은 출처를 우선하여 하위 객체·one-past·수명 종료 정보를 보존하며, NULL 반환은 이전 호출의 출처를 이어받지 않습니다. malloc 계열의 새 할당 계약으로 발급한 객체 ID도 유지합니다.

여러 단락 평가 경로가 하나의 PHI로 합쳐지면 모든 유입 값의 AST 소속과 실제 predecessor를 확인하여 전체 논리식을 연결합니다. 현재 평가에서 지나간 분기의 READ 근거만 모으고 이전 반복의 결과를 재사용하지 않습니다. enum case가 같은 LLVM 블록을 공유할 때는 기존 EnumConstantDecl·DWARF 값과 switch 비트 폭으로 각 라벨을 구별합니다.

함수 호출 인자는 내부 주소 계산의 피연산자 목록과 구별합니다. 내부 GEP가 만든 주소는 관측된 인자 값 하나로 남기고 기저·인덱스의 원인은 addressInputs에 연결합니다. 소스 READ·CALC·반환값의 값 출처는 유지하며, 주소를 만드는 첫 의존 사건을 임의로 그 주소의 값 생산자로 표시하지 않습니다.

No35의 `ab` / `a(b|c)` 입력을 동결된 예측과 비교한 최종 기록은 사건 30,664개, 정상 종료 0, 과정 검사 37개 통과입니다. 같은 모델로 No34도 사건 9,677개와 과정 검사 54개를 재확인했습니다. 두 기록 모두 런타임 진단·IR gap·미해명 관측이 없으며 원본과 사전 예측은 변경하지 않았습니다. 이 결과는 해당 입력과 관련 범용 검사에 대한 근거이며, 모든 입력이나 자료구조 자동 분류의 완성을 뜻하지 않습니다.

## 관측된 관계 역할과 컨테이너 기반 구조 후보

`linked-views.mjs`는 AST의 순회 커서·직접 호출 인자에 나타난 필드 재귀 관계로 `roleGroups`를 만들고, 실행 중 실제 역방향 참조를 보이는 보조 필드를 구분합니다. 전체 저장 연결인 `storageTopology`와 역할별 `roleTopologies`를 함께 보존합니다. 근거가 있는 부분집합이 하나일 때만 대표 `topology`로 선택하므로, 부모 링크를 자식 간선에 섞어 트리를 순환 그래프로 만들지 않습니다. 여러 후보가 남으면 강제로 하나를 고르지 않습니다.

종료 경계는 커서와 기준 주소의 실제 비교에서 확인합니다. `boundaries`에는 객체 ID·하위 객체 바이트 범위·근거 사건을 남깁니다. 같은 할당 안의 다른 하위 객체를 함께 제외하지 않으며, sentinel을 가리키는 실제 간선도 유지합니다. 경계의 분류는 근거가 관측된 시점부터 적용하고, 수명이 끝난 대상은 빈 구조로 처리하지 않습니다.

역관계는 개별 필드끼리 모두 일치해야 하는 조건이 아니라, 역할 집합 안에서 실제 반대 간선이 있는지 검사합니다. 예를 들어 부모의 두 자식 필드 중 해당 노드를 가리키는 하나가 있으면 역관계가 성립합니다. 순차 쓰기의 중간 불일치는 삭제하지 않고 `warningEpisodes`로 시작·해소·수명 종료를 구분합니다. 정상 복구, 미해결 종료, 관찰 범위 이탈을 구별하며, 함수 반환만으로 불일치가 고쳐졌다고 판단하지 않습니다.

`record-index-views.mjs`는 기존 배열·동적 배열 후보의 컨테이너 정체성, 자료형, 실제 인덱스 접근과 값 의존 관계로 `record-index-graph-candidate`를 추가합니다. 레코드 정수 필드 또는 레코드가 가리키는 정수 배열의 값이 같은 컨테이너의 실제 인덱스로 사용된 근거를 연결합니다. 숫자나 자료형이 같다는 이유만으로 간선을 만들지 않습니다. 현재는 같은 컨테이너 안의 관계를 지원하며 컨테이너 사이의 의미 연결은 확정하지 않습니다.

논리 노드는 동적 배열의 활성 길이를 따르고 용량과 임시 레코드를 구별합니다. 포인터 배열은 슬롯과 대상 레코드를 따로 기록하며, 관측된 대상 객체의 정체성과 수명을 유지하므로 주소 재사용으로 이전 대상을 되살리지 않습니다. 필드 관계·소유 배열 관계·자기 인덱스 후보는 별도로 남기고 `displayPolicy.mergeRelations=false`로 임의 합치기를 막습니다.

`states`는 실제 사건에 따른 값·연결·활성 범위 변화를 기록합니다. 직접 확인한 개별 관계는 `observed`, 같은 필드에 일반화한 관계는 `inferred`로 구별합니다. 발견 이전 상태에 후보를 투영한 경우 `retrospective`와 `not-yet-observed`를 표시합니다. 미관측 값, 활성 범위 밖의 대상, 종료 표식일 수 있는 숫자는 각각 unknown·미해결 상태로 보존하며 정상 간선이나 오류로 단정하지 않습니다. 출력 상한의 생략 수와 `coverage.complete`는 기록 보존 범위를 뜻하며 의미 추론의 완성도를 뜻하지 않습니다.

이 보강은 기존 READ/CALC/WRITE/FLOW/SPACE에 붙는 표현용 관계이며 추가 READ나 C 식 재실행을 만들지 않습니다. 알고리즘 명칭·색 의미·Red-black 불변식, 임의 컨테이너와 간접 호출의 의미를 자동 확정하지 않습니다. `linked-projection-contract.mjs`와 `record-index-contract.mjs`는 관계의 객체 범위·역할·시점·관측 근거를 독립 검사하며, 사용자 프로그램의 실제 순환이나 미해결 연결 자체를 변환 오류로 거부하지 않습니다.

2026-11-05 최종 API 실행에서 No34·No35는 각각 사건 9,677개·30,664개, 종료 코드 0이며 과정 검사 54개·37개와 구조 독립 검사 30개가 통과했습니다. 두 예제의 원본·사전 예측·기존 사건 순서 및 의존 관계는 유지됐고 런타임 진단·IR gap·미해명 관측은 없었습니다. 관련 구조 검사 12개도 통과했습니다. 근거는 `test-results/structure-refinement-2026-11-04/`에 보관합니다(디렉터리 날짜는 작업 시작일).

이 과정에서 발견한 같은 비트 폭 정수 변환의 소유 식 연결도 보완했습니다. `instrument.mjs`는 합성 `c.integral-cast`에 이미 확보한 `semanticNodeId`를 보존합니다. 중첩 멤버·배열 접근은 시작 위치가 같을 수 있으므로 좌표만으로 더 짧은 기저 포인터 식을 재선택하지 않습니다. 필드 READ → 변환 CALC → WRITE와 별도의 주소 READ를 유지하며, 한 줄 재현 및 관련 검사 5개로 확인했습니다.
