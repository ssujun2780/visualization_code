# 생략된 주소 계산의 출처 인계 — 구현

2026-11-12. 사용자 승인: 주소 계산을 불필요한 독립 명령으로 늘리지 않고 모델·실행 관계 분석기·시각화 계약을 맞춥니다. 중간언어의 다섯 명령, 사건 순서와 실제 연산·값·수명은 유지합니다. 자료구조 추론기는 변경하지 않습니다.

## 관측과 공개 입력

`input.executionId`는 해당 값을 실제 생산한 공개 사건입니다. 생략된 GEP의 기저/인덱스 사건을 대신 넣지 않습니다. 해당 값은 실제 관찰에서 얻으며 `input.value.reference`는 같은 관측의 객체 ID·바이트 오프셋·onePast·수명 상태를 유지합니다.

```js
input.addressOrigin = {
  schemaVersion: 1,
  kind: 'observed-address',
  observationKind: 'elided-calculation', // 또는 call-argument
  observationId: '원시 관찰 ID',
  instructionId: 'LLVM 관찰 계획의 명령 ID',
  dataInputs: ['기저/인덱스의 실제 값 생산 사건'],
  addressInputs: ['저장소 등 주소 근거 사건'],
  controlInputs: [],
  calleeInputs: [],
  evidence: '관측 근거 종류'
};
```

- `elided-calculation`: 컴파일러 연결에서 administrative로 분류된 실제 주소 관찰입니다. 역할별 의존성을 한 번 해석하며, 상자 생성은 주소 근거입니다. 참조 정체성은 원시 주소 관찰에서 인계합니다.
- `call-argument`: LLVM 상수 주소처럼 별도 SSA 관찰이 없는 입력입니다. 실제 호출 순간의 포인터 관찰을 사용합니다. `observedAt.executionId`, `parameterIndex`로 해당 공개 호출·인자와 연결하며 `input.executionId`는 null입니다. 나중 매개변수 값에서 호출 시점으로 소급하지 않습니다.
- 관측기는 포인터 인자의 참조를 호출 시점에 기록합니다. LLVM 상수 GEP/bitcast/addrspacecast에 전역 기호가 하나이면 컴파일러가 명시한 원래 저장소를 유지하고 오프셋은 실제 관측값에서 얻습니다. 성공한 기호 연결은 캐시합니다. 배열 끝 주소가 인접 객체 시작과 같아도 함수 인자는 호출 당시의 객체 세대를 전달받습니다.
- 원본 C를 다시 읽거나 식을 평가하지 않습니다. 소스 이름·예상 정답·같은 숫자로 연결하지 않습니다. 새 메모리 접근이나 독립 CALC도 만들지 않습니다.

모델과 분석기는 같은 형식 검사를 사용합니다. 참조 객체는 그 시점에 생성되어 있어야 하고 의존 사건은 소비자보다 앞서야 합니다. 호출 인자의 관찰·정적 호출 연결·매개변수 번호가 일치해야 합니다. 위조/미래 근거를 정상 출처로 받아들이지 않습니다.

## 분석과 반환

분석기는 같은 사건 안의 `transform: address` 출처 노드를 만들고 `addressOriginRef`로 원본 입력을 가리킵니다. 새 실행 사건이나 메모리 값 복제는 아닙니다. 기저·인덱스·제어·피호출 관계를 분리하고 근거가 없으면 주소 출처 부족을 보고합니다. 주소를 넘긴 사실을 배열 내용의 READ/복사로 바꾸지 않습니다.

`FLOW/resume.inputs`에 보존된 호출 당시 인자는 복귀값 피연산자가 아닙니다. 실제 반환·읽기·효과의 기록 연결만 복귀 출처에 사용합니다. void 호출에 반환값 생산자를 요구하지 않습니다. 사용하지 않은 실제 반환 관측은 삭제하지 않습니다.

반환 포인터가 접힌 주소식에 사용되어 다음 함수 인자로 전달되면, 실제 인자 WRITE가 수신 작업입니다. 주소 메타데이터의 의존 관계도 수신 탐색에 사용하여 원래 함수의 공개 공간을 인자 수신 전에 정리하지 않습니다. 실제 C 수명은 바꾸지 않습니다.

## 표시

- 일반 생산 사건은 기존 화살표 규칙을 사용합니다.
- 저장소 생성 자체가 실제 주소 생산자인 직접 `&변수`는 기존 공개 생산 사건을 유지합니다. 생성된 객체의 주소와 그 상자 안의 포인터 값은 구별하여 `&변수`로 표시합니다.
- 접힌 주소 입력은 실제 포인터 기저 슬롯/반환구, 또는 관측된 원본 객체·오프셋에서 목적지로 연결합니다. 이동 값은 실제 주소값입니다.
- 배열/멤버 주소는 `&원본[원소]`, 포인터 기저는 `포인터 기반 주소`로 구별합니다. 해당 선을 원소 내용 READ로 강조하지 않습니다.
- 기존 전체 경로·순차 강조·도착 후 값 반영 시간선을 재사용합니다. 숨긴 컴파일러 상수 저장소를 화살표 때문에 다시 표시하지 않습니다.
- 메타데이터 없는 과거 기록의 출처를 추측하여 채우지 않습니다. 새 실행 기록을 생성해야 이 계약이 적용됩니다.
