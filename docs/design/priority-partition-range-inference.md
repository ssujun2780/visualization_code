# 힙·대표 관계·구간 집계 추론

2026-11-12. 아래 PPR 조항은 이번에 구현한 범위입니다. 모든 우선순위 큐·분리 집합·구간 자료구조 구현의 자동 인식을 의미하지 않습니다. `structure-composition.md` RC-01~08, 읽기 전용 추론 경계와 추천 상위 5개·사용자 지정 우선 정책을 유지합니다.

## PPR-01 인덱스 힙

AST 인덱스 산식의 `<<`, `>>`를 기존 곱셈·나눗셈 관계와 연결합니다. 상수 시프트 폭을 구조적으로 확인하고 실제 CALC 입력·출력이 일치하는 관측에만 근거를 부여합니다. 변수명, 함수명, 파일명이나 값의 우연한 정렬로 인식하지 않습니다. 자료형의 오버플로·음수 시프트 의미를 수학식으로 덮어쓰지 않습니다.

완료된 연속 순회의 시작점을 인덱스 관계의 base로 지정할 수 있습니다. 1번부터 `i <= n`으로 순회했다면 관측 범위는 `[1,n+1)`이며 사용 원소는 n개입니다. 용량·마지막 인덱스·원소 수를 구분합니다. 중도 종료, 범위 변수 변경, 미확정 경계는 기존과 같이 사용 범위를 확정하지 않습니다.

힙이라는 후보와 현재 최소/최대 순서 조건은 별개입니다. 교환 중간의 위반 상태를 보존합니다. 원소·레코드의 실제 비교 속성, 원래 배열 저장소와 기존 조회 API를 유지합니다.

## PPR-02 대표 원소와 병합

`representative-partition-candidate`는 배열 또는 레코드 배열의 정수 인덱스 필드를 대상으로 합니다.

1. 저장된 부모 값과 그 원소의 인덱스를 비교하거나 음수 종료 조건을 검사합니다.
2. 실제 반환값이 해당 인덱스에서 왔거나, 대표 탐색 루프가 해당 커서에서 정상 종료했음을 확인합니다. 숫자가 같은 것만으로 연결하지 않습니다.
3. 대표 확인 결과가 다음 WRITE의 주소와 값으로 전달되어 두 루트를 연결했을 때 병합 근거를 남깁니다.
4. 기존 경로가 같은 대표에 도달하며 실제 연결이 단축된 쓰기는 압축으로 기록합니다. 같은 부모 재대입은 압축으로 세지 않습니다.

일반 부모 트리는 `representative-forest`로 유지하며 병합을 관측하지 않았다면 분리 집합으로 추천하지 않습니다. 실제 읽거나 쓴 원소만 구성원 후보에 넣고, 배열 용량이나 초기화 스냅샷만으로 모든 원소를 추가하지 않습니다. 구성원 목록은 관측된 슬롯 범위이며 예약 슬롯과 논리적 구성원이 항상 같다는 뜻은 아닙니다.

각 상태는 원래 슬롯·부모 값·대표까지의 경로·집합 구성원과 근거 사건을 포함합니다. 실제 순환은 `contradicted`, 알려지지 않은 부모는 `incomplete`, 수명 종료는 `ended`입니다. 이를 C 실행 오류로 바꾸지 않습니다. `queryDisjointSet(candidate, trace, {afterExecutionId})`로 조회합니다.

## PPR-03 구간 집계

`range-aggregate-candidate`는 실제 입력 원소를 읽어 저장한 잎과, 같은 저장소의 자식 값을 읽어 계산한 쓰기를 연결합니다. 지원 계산은 덧셈·곱셈·비트 연산과 관측한 min/max 선택입니다. 중간 지역변수와 매개변수는 기존 값 출처 경로로 따라갑니다. 두 비교 입력 및 자기 갱신의 구조 보존은 [EXT-02·04](structure-extensions.md)를 따릅니다.

- `leaves`와 `coverage`는 최초 관측한 입력 좌표와의 **역할 연결**입니다. 이후 잎에 상수를 대입해도 그 좌표 역할은 유지할 수 있습니다. 현재 값이 원래 입력 배열의 값과 같다는 의미는 아닙니다.
- 현재 값은 `writeExecutionId`의 실제 기록입니다. `readExecutionIds`, `children[].writeExecutionId`로 읽은 시점의 자식 버전을 구분합니다. 나중 값을 과거 읽기에 사용하지 않습니다.
- 자식 갱신이 부모에 아직 전파되지 않았다면 `stale`입니다. 이 상태는 조상까지 전파되며 정상 집계로 추천하지 않습니다.
- 부분/일괄 덮어쓰기의 출처가 없으면 기존 집계 근거를 무효화합니다. 이전 정상 값을 재사용하지 않습니다.
- 실제 입력 인덱스가 연속일 때만 `[start,end)` 구간을 부여합니다. 단순히 합이 같다는 이유로 범위를 추정하지 않습니다.

관측된 자식 구간이 겹치지 않고 부모 구간을 연속해서 나누면 `segment-tree` 후보를 제시합니다. 인덱스 산식도 보조 근거로 유지합니다. 관계 근거가 부족하면 `range-aggregate`로 남깁니다. `queryRangeAggregate(candidate, trace, {afterExecutionId})`로 조회합니다.

## PPR-04 Fenwick 관계

1번 기반 `i & -i`, 0번 기반 `i | (i+1)` 및 `(i & (i+1))-1`을 AST 연산 구조·실제 CALC·동일 커서의 다음 접근으로 연결합니다. 선언 이름이나 특정 배열 길이는 사용하지 않습니다.

비트 인덱스 이동만으로 Fenwick 트리라고 추천하지 않습니다. 실제 집계 쓰기와 입력 좌표 구간이 함께 확인되어야 합니다. 인덱스 이동에 필요한 다음 접근을 관측한 시점부터 근거를 사용할 수 있으며 미래 접근을 이전 상태에 소급하지 않습니다.

## PPR-05 추천·불완전성·검증

새 후보는 공통 추천 경로에 들어가며 최대 5개와 사용자 고정 우선 규칙을 유지합니다. UI는 변경하지 않습니다. 부모 종료 검사 같은 직접 인덱스 동등 비교는 연관 조회 근거로 남길 수 있지만, 해시 추천에는 실제 키→버킷 숫자 변환 근거가 추가로 필요합니다. 포인터 주소 계산만으로 해시 변환을 만들지 않습니다.

새 상태 수와 구성원 수의 기본 상한은 각각 2048입니다. 상태 이력은 앞부분과 최신 상태를 남기며, 생략된 중간 구간 조회는 `incomplete`/`historyGap`으로 표시합니다. 마지막 정상 상태를 현재 상태인 것처럼 추천하지 않고, 실제로 다시 관측한 최신 상태는 자체 근거에 따라 판단합니다. 공통 출력 한도로 보관 수를 더 줄일 수 있습니다. 작은 상태의 모든 구성원·경로·구간을 확인하는 검사와 근거 변조 거부 검사를 함께 둡니다. [RC-07](structure-composition.md#rc-07-실행-기록과-시간-경계)을 따릅니다.

## 아직 지원하지 않는 범위

- 모든 힙 세부 종류와 임의 비교자 의미. 포인터 부모 우선순위와 관측한 복합키 사전식 비교는 EXT-01·02에서 지원합니다.
- 임의 대표 종료 규약과 rank/size 정책의 정확성 보장. 자기 대표 포인터와 관리 역할의 일부 연산 근거는 EXT-01·03에서 지원합니다.
- 입력 좌표 연결이 전혀 관측되지 않은 상수 초기화 구간 구조, 모든 사용자 정의 비교/집계와 지연 태그 연산. 관측한 min/max, 가산 태그 전달, 실제 공유 노드는 EXT-02·04·05에서 지원합니다.
- 다른 단위·저장소로 재배치되는 잎 좌표의 자동 재연결, 모든 사용자 정의 집계 함수.

위 항목도 원래 배열·포인터·읽기·쓰기 기록은 그대로 남습니다. 이 구현은 표현 후보를 추가하며 중간언어의 지원 문법이나 실제 실행을 변경하지 않습니다.
