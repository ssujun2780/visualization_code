# 문자열 경로와 트라이 추론

## TR-01 범위와 근거

공통 추론기는 원본 실행의 저장 관계, AST 자료형·필드 배치, 실제 값 전달을 읽습니다. 파일명·변수명·정답·특정 문자 집합은 판정 근거가 아닙니다. `sequence-lookup-candidate`는 관측된 문자열 경로의 후보이며 작성자의 의도를 확정하지 않습니다. 중간언어 사건·값·수명은 변경하지 않습니다.

RC-01~03에 따라 저장 관계의 투영과 의미 조건을 분리합니다.

- `pointer-tree-views.mjs`: 물리 포인터를 보존하는 논리 관계.
- `sequence-lookup-views.mjs`, `sequence-evidence.mjs`: 입력 소비, 간선 라벨, 종료 표지의 실행 근거.
- `sequence-conditions.mjs`: 관계·라벨·종료 역할로 트라이 조건을 검사합니다.
- `sequence-contract.mjs`: 결과를 실제 사건·저장 범위에 대조합니다.

## TR-02 저장 방식의 투영

1. **희소 포인터 배열:** 같은 레코드 계열의 포인터가 실제 역참조에 사용된 근거로 자식 역할을 발견합니다. 개수 변수가 없어도 관측한 비NULL 대상은 연결합니다. 배열 용량 전체를 구성원으로 만들지 않으며 미확인 슬롯은 완전한 관계라고 주장하지 않습니다. 개수 근거가 있는 배열은 기존 유효 접두 범위를 유지합니다.
2. **분리 인덱스 배열:** 기존 행 관계를 그대로 소비합니다. 종료 배열은 자식 인덱스를 실제로 전달받아 접근한 근거로 연결합니다. 숫자 값이 같다는 이유만으로 연결하지 않습니다.
3. **자식/형제:** 부모 필드에서 시작한 커서가 자신이 가리킨 레코드의 다른 필드를 따라 갱신되는 실제 READ→WRITE를 확인합니다. 형제들은 같은 부모의 자식으로 투영하고 원래 포인터 경로 식별자를 유지합니다. 형제 사슬의 순환은 `relationConflicts`에 보존하며 트라이 추천을 막습니다.
4. **부모 내부 간선 레코드:** AST의 레코드 배열 배치, 부모 포함 범위, 간선의 대상 포인터 역참조를 함께 확인합니다. 내부 Edge가 보유한 포인터를 논리적으로 부모→자식으로 투영합니다. 문자열 포인터를 자식 노드로 취급하지 않습니다.

지역 순회 포인터가 사라졌다는 이유만으로 살아 있는 저장 노드도 사라진다고 판단하지 않습니다. 실제 레코드 주소로 초기화한 근거가 있는 경우 해당 저장 노드를 별도 루트 후보로 유지합니다. 저장 객체 수명은 원래 기록을 따릅니다.

## TR-03 입력 선택과 종료 역할

- `indexed-symbol`: 실제 입력 원소의 값이 자식 슬롯 주소 계산에 참여하고 입력 커서/인덱스가 전진한 근거를 연결합니다. 입력 문자와 선택 슬롯의 관측 대응을 저장합니다.
- 포인터 배열의 `indexed-symbol` 근거는 접근 당시 가장 최근의 슬롯 관측에 연결합니다. `slotRange`(객체·오프셋·크기), `storedEdgeId`, `targetNodeId`, `slotObservationExecutionId`를 보존합니다. 라벨은 같은 실제 포인터 칸과 참조 대상에만 적용합니다. 역할 이름이 필드 수준에서 원소 수준으로 구체화돼도 이 정체성은 유지되며, 단순히 `slot` 접미사를 지워 다른 원소·노드의 라벨을 합치지 않습니다. 참조 대상을 바꾼 새 전이는 새 접근 근거가 필요합니다.
- `compared-symbol`: 형제 탐색의 비교 피연산자가 실제 입력 원소와 노드의 문자 필드인 경우입니다.
- `compared-segment`: 현재는 외부 `strncmp`/`memcmp`의 성공 결과, 그 결과에 종속된 자식 선택, 비교 길이와 같은 입력 포인터 전진을 요구합니다. `strlen`의 동일 라벨 출처를 확인하면 NUL 종료 길이 계약을 사용합니다. 아니면 관측한 비교 길이만 사용합니다.
- `terminalEvidence`: 입력 원소가 0인 정상 루프 종료 후 반환한 현재 노드의 스칼라 속성을 종료 표지 후보로 연결합니다. 별도 배열은 실제 노드 인덱스 전달이 필요합니다. 원래 숫자도 보존하며 비0이면 `accepted=true`, 관측 값이 없으면 `null`입니다. 보조 필드가 비0이라는 이유만으로 표지를 만들지 않습니다.

`for` 종료 정리 때문에 반환의 `controlInputs`가 비어 있어도, 같은 호출의 마지막 정상 루프 종료와 AST 루프/반환 범위가 연결되고 그 사이 WRITE·호출·분기가 없는 경우에만 종료 근거를 복원합니다. 소스 문자열이나 LLVM 블록 이름에 의존하지 않습니다.

## TR-04 조건, 조회와 추천

다음을 함께 만족한 관측 상태만 `conditions.trie='supported-observed'`가 됩니다.

- 루트 하나, 관측된 순환·공유 자식·형제 관계 충돌 없음.
- 각 논리 간선에 관측 근거가 있는 비어 있지 않은 라벨.
- 같은 부모의 서로 다른 간선 라벨 사이에 동일·접두어 충돌 없음.
- 입력 종료 후 반환에서 확인한 종료 역할 있음.

`b` 경로가 있어도 그 노드의 종료 표지가 0이면 저장된 단어로 표시하지 않습니다. 압축 경로의 `ca`와 완성된 `car`도 구분합니다. 라벨 메모리가 해제되거나 읽힌 값이 없으면 라벨을 확정하지 않습니다.

`querySequenceLookup(trace, {candidateId, afterExecutionId})`는 해당 시점 상태를 복사해서 반환합니다. 발견 전에는 `null`입니다. `queryStructureRelations`에도 간선의 `labels`, 노드의 `terminalMarkers`를 전달합니다. 추천은 `partial` 상태의 `trie` 후보이며 상위 5개 제한과 사용자 지정 우선을 유지합니다. UI·애니메이션은 구현하지 않습니다.

## TR-05 한계

자동자나 일반 문자 라벨 그래프와 의미가 겹칠 수 있으므로 의도는 `unconfirmed`입니다. 미방문 전이, 삽입만 있고 조회가 없는 코드, 사용자 정의 문자열 비교 함수, 임의의 압축 표현 전체를 지원한다고 주장하지 않습니다. 기본 상태 기록 한도는 2,048개, 문자열 라벨은 256바이트입니다. RC-07의 공통 이력 규칙에 따라 생략된 중간 구간 조회는 `historyGap:true`로 표시하며, 보관된 앞부분·최신 상태와 구별합니다. `querySequenceLookup` 결과에도 `historyGap`을 제공합니다. 원시 문자 숫자는 보존하고 출력용 `text`는 ASCII 범위에서만 제공합니다.

검증 결과와 범위 밖 생성 오류는 [트라이 보완 검증](../validation/trie-structures-fixes-2026-11-11.md)에 있습니다.
