# 저장 방식·관리 역할·복합 관계의 확장

2026-11-12. 아래 EXT 조항은 명시한 범위의 구현 계약입니다. RC-01~07과 읽기 전용 추론 경계를 유지합니다. 자료구조의 의도와 현재 조건의 충족은 별개입니다.

## EXT-01 포인터 관계

`pointer-partition-candidate`: 부모 필드의 실제 비교 → 커서 대표 반환 → 반환값의 주소·값 전달 → 실제 연결 쓰기를 추적합니다. 자기 참조·NULL·별도 종료 노드와의 동등 비교가 확인된 종료 규약을 지원합니다. 별도 종료 노드는 저장소에는 남지만 논리적 구성원에서는 제외합니다. 루트 간 연결은 merge, 같은 대표로 향하는 기존 경로의 실제 단축은 compress입니다. 재대입은 압축이 아닙니다. 정적 배열과 동적 할당에 동일하게 적용합니다.

정수·포인터 대표 관계 모두 과거 병합 이력과 현재 연결을 구분합니다. `activeMergeExecutionIds`에는 지금도 두 구성원이 같은 대표에 속하는 병합만 남습니다. 풀 초기화로 모두 분리되면 과거 이력을 삭제하지 않고 `representative-forest`로 돌아갑니다. 종료 노드까지 걷고 마지막 원소를 반환한 목록은 대표 관계 후보가 될 수 있지만, 실제 대표 간 병합 없이 분리 집합으로 추천하지 않습니다.

`pointer-priority-candidate`: 키 비교와 후속 연결 변경을 근거로 현재 루트에서 도달 가능한 노드의 부모 우선순위를 검사합니다. 제거된 노드는 원본 저장소에 남아 있어도 현재 힙에서는 빠집니다. 부호 정보와 최소·최대 조건을 구분합니다. skew/pairing/Fibonacci 등 세부 종류는 단정하지 않습니다.

EXT-01/02 비교 정책 연결 보충(2026-11-13): 배열·포인터 노드는 `priority-policy.mjs`의 같은 비교 반환식/제어 경로 분석을 사용합니다. 포인터 노드에서는 비교 결과의 실제 분기 소비, 비교 원소를 건드린 같은 호출 계보의 레코드 연결 쓰기, 호출 반환에서 외부 루트 상자로 전달된 근거를 함께 요구합니다. 별도 할당·배열 풀을 이름이나 주소 숫자만으로 구별하지 않습니다. 숫자·문자열 및 혼합 복합키의 현재 값은 노드의 실제 필드 범위에서 읽습니다. 미관측 동점 경로는 계속 불완전이며, 비교값 출력만으로 힙을 만들지 않습니다.

새 포인터 정책의 `comparisonPolicy`는 비교 함수·레코드 타입·반환 판정 규약을 보존합니다. 같은 루트에서도 정책이 다르면 사용자 선택 재연결 시 구별합니다. 기존 직접 숫자 비교의 연결 근거는 유지합니다. 첫 자식/형제 표현은 기존 저장 간선과 별도의 부모 관계 투영을 사용하며, 삭제·키 수정·문자열 대상 수명·이력 한도는 현재 상태에 반영합니다.

## EXT-02 복합키·선택 집계

추가: 비교용 payload는 안전 정수 좌표와 분리합니다. 안전 정수 밖의 정수는 정확한 10진 문자열, 관측 IEEE 실수는 수치로 보존하며 NaN은 순서 미확정입니다. 포인터 비교 정책은 단독 레코드 범위에서도 제공할 수 있습니다. 배열 힙은 별도 인덱스/활성 범위를, 연결형 힙은 앞 절의 실제 연결·루트 전달 근거를 요구합니다. 비교 정책만으로 힙 노드를 생성하지 않습니다. 대상 저장소 수명이 끝나면 정책 이력과 `ended`를 구분합니다.

구조체 인자는 `copiedFrom`과 COPY의 실제 범위·필드 오프셋을 따라 비교 대상을 복원합니다. 포인터 인자는 필드 READ의 주소 출처에서 인자 식별자를 확인합니다. 주소 숫자가 같다는 이유만으로 인자를 연결하지 않습니다. `composite-priority-candidate`는 비교 반환식과 제어 조건을 기존 비교 결정 도식으로 분석합니다. 필드명·선언 순서·샘플 정렬로 우선순위를 정하지 않습니다. 나머지 연산 같은 키 변환은 EXT-07의 타입을 보존한 변환 식으로만 지원하며, 원래 필드의 단순 순서로 대체하지 않습니다.

비교 정책 발견은 인덱스 트리 발견을 전제로 하지 않습니다. 트리 배치·활성 범위의 근거가 없으면 키 우선순위만 제공하고, 노드를 만들어 채우거나 힙 조건을 만족한다고 표시하지 않습니다(`min/max: unknown`).

포인터 비교 호출의 `a+i`, `&a[i]`도 AST의 배열 기준·인덱스 식과 실제 주소 전달 출처를 연결합니다. 호출 인자·매개변수·도우미 호출을 거친 필드 읽기가 같은 원소 범위를 가리킨다는 근거를 요구합니다. 실행한 부모/자식 산식의 결과가 실제 접근 주소에 전달되어야 하며, 원소 번호가 우연히 같은 것만으로 연결하지 않습니다. 현재 사용 범위는 기존 관리 변수/완료 순회의 관측을 사용하고 용량으로 대체하지 않습니다.

복합키 힙 상태에는 `indexStructureId`, `layoutStatus`와 그 시점에 사용 가능한 산식·접근 근거가 포함됩니다. 여러 인덱스 배치가 남으면 `ambiguous`, 근거가 없으면 `unobserved`입니다. 교환 중간의 위반, 빈 사용 범위, 수명 종료를 보존합니다. 재연결 시 비교 함수와 저장소 신원은 UR-13을 따릅니다.

미관측 비교 분기는 확정된 사전식 순서로 채우지 않습니다. `observedKeyOrder`는 관측한 순서 후보, `policyCoverage`는 비교 결정 도식의 분기 완전성입니다. 미확정 경로가 남으면 `keyOrder:null`로 두고 힙 순서 조건도 unknown으로 유지합니다. 도우미 호출을 경유한 포인터 인자는 실제 READ의 주소 출처와 인자 전달을 따라, 분석 중인 반환값의 호출 프레임 매개변수까지 연결합니다. 가장 가까운 도우미의 인자 번호를 외부 비교 함수의 인자 번호로 대신 쓰지 않습니다.

동적 레코드 배열의 `T*`와 `const T*`는 접근 자료형을 그대로 보존하면서 물리 저장 범위 계산에서 바깥쪽 한정자만 구별하지 않습니다. 구조체 필드·내부 배열의 실제 경계를 넘겨 배열로 확장하지 않습니다.

min/max 집계에는 선택된 값과 **비교한 두 입력**을 모두 남깁니다. 호출과 반환을 거쳐도 같습니다. 관측된 자식 구간이 겹치지 않고 부모 구간을 연속해서 나누면 구간 트리 후보를 제공합니다. 상수 접힘으로 인덱스 CALC 입력이 없다는 이유만으로 이 관계를 버리지 않습니다.

EXT-02 보충(2026-11-13): 비교 함수의 삼항식은 실행된 선택값과 조건 근거를, 상수 반환은 실제 반환 상수를 사용합니다. 비교 결과끼리의 덧셈·뺄셈은 표현식 범위가 기록된 정수형에 들어갈 때만 축약합니다. 키 숫자의 차를 표본값만 보고 순서 비교로 바꾸지 않습니다. 의미가 보존되는 형 변환만 통과시킵니다.

세 방향 반환값은 호출자에서 그 반환값을 실제로 0과 비교한 연산·피연산자 위치로 해석합니다. 지역 변수·호출 반환 전달도 값 출처로 추적합니다. 같은 값의 다른 호출이나 산술 변형 결과를 연결하지 않습니다. 반환값만으로 음수가 앞선다고 가정하지 않으며, 서로 다른 판정 규약은 별개 후보입니다. 참·거짓 표현식은 기존 `truth` 규약을 유지합니다. 호출자 판정이 필요한 정책의 발견 시점은 그 판정 사건 이후입니다.

`!(cmp(a,b) < 0)`처럼 비교가 부정식과 합쳐 기록되면 AST의 직접 감싼 비교 위치와 실제 두 입력으로 원래 판정 연산을 확인합니다. 반환을 전달하는 보조 함수에서도 원래 반환 경로의 조건을 유지합니다. 힙 사용 범위의 순회 근거는 직접 원소 READ뿐 아니라 실제 주소 출처·호출 계보·반복 인덱스가 일치하는 필드 READ, 호출 입력 범위와 `copiedFrom`이 일치하는 구조체 인자 복사도 사용할 수 있습니다. 복사를 가짜 READ 사건으로 만들지 않습니다. 모든 인덱스를 순회 완료해야 하며 같은 인덱스 숫자만으로 해당 배열에 접근했다고 간주하지 않습니다.

단락 평가에서 실행하지 않은 피연산자는 미확정으로 남기고, AST 논리 구조와 실제 비교 근거를 결합합니다. 모든 키 분기의 근거가 확보되기 전에는 완전한 키 순서나 힙 조건을 확정하지 않습니다. 키 산술 변환의 지원 범위는 EXT-07을 따릅니다. 임의 외부 함수와 의미를 확인할 수 없는 형 변환까지 지원한다는 보장은 아닙니다.

EXT-02 문자열 비교 보충(2026-11-13): 우선순위 비교도 BST와 같은 관측 `strcmp` 해석을 사용합니다. 실제 외부 호출과 반환, 인자 읽기 범위, 문자열 종료 바이트, 구조체 필드·복사 출처가 연결될 때만 `nul-terminated-bytes` 키로 기록합니다. 구조체 안 문자 배열과 문자열 포인터, 값 인자와 보조 함수 전달을 구별해 추적합니다. 같은 이름의 사용자 함수는 표준 라이브러리 계약으로 취급하지 않습니다.

내장 문자 배열이 포인터로 변환되어 도우미 인자로 전달되면, 실제 포인터 READ의 대상이 관측 문자열 시작과 일치하고 선언된 문자 배열 필드 범위 안에 있을 때만 해당 필드 출처를 복원합니다. 새 READ 사건을 만들지 않고 실제 READ 식별자에 부가 근거를 붙이며, 복사 출처·문자열 길이·수명 검사를 유지합니다.

`strcmp`의 보장은 음수·0·양수이지 정확히 -1·0·1이 아닙니다. 0과의 비교·논리 판정은 해석하지만 반환값에 상수를 더하는 등의 크기 의존 연산을 사전식 순서로 바꾸지 않습니다. 문자열 키와 숫자 동점 키를 같은 비교 정책에 조합할 수 있습니다.

현재 힙 조건은 당시의 실제 문자열 바이트와 포인터 대상을 읽어 검사합니다. 비교 함수를 다시 호출하지 않아도 문자열 수정·포인터 교체·해제가 있으면 상태를 다시 평가합니다. 미관측·잘린 문자열이나 끝난 대상은 미확정이며 이전 성공 상태로 덮지 않습니다. 자동 후보 재연결은 저장소·함수·판정 규약으로 수행하고 이전 실행의 문자열이나 판정 결과를 복사하지 않습니다.

인덱스 근거 보충: 구조체 전체 복사에 소스 첨자 노드가 직접 붙지 않아도 실제 COPY 목적지 GEP·인덱스 READ·배열 선언 식별자가 일치하면 기존 산식과 연결합니다. 이름이나 값의 일치로 연결하지 않습니다. 실제 `realloc-replaced` 종료와 새 할당의 `copiedFrom`, 같은 호출/소스 위치, 동일한 원소 배치·산식 후보가 연결되면 유지된 바이트 범위 안에서 이전 인덱스 배치 근거를 재사용할 수 있습니다. `layoutEvidence`에는 원래 접근 사건과 재할당 사건을 별도로 남깁니다. 일반 복사·해제·재할당 전 시점·유지 범위를 벗어난 구성원에는 적용하지 않습니다. 현재 값과 사용 범위는 새 저장소에서 관측해야 합니다.

이력 한도 보충: 보관된 복합키 상태의 `indexRelation`은 사용한 인덱스 상태의 정확한 사건을 가리킵니다. 해당 상태가 화면용 이력에서 생략되면 공통 근거 보관 한도 안에서 `proofStates`로만 보존합니다. 조회 시 이 근거로 화면용 빈 구간을 채우거나 이전 정상 판정을 재사용하지 않습니다. 근거가 없으면 검증을 통과시키지 않습니다.

## EXT-03 관리 역할

`management-role-candidate`와 `queryManagementRoles()`는 역할 근거를 별도로 제공합니다.

- 높이: 자식의 같은 필드에서 max를 선택하고 1을 더해 부모에 저장한 근거.
- rank: 대표 병합과 두 대표의 속성 동등 비교 아래 생존 대표의 증가.
- 크기: 병합한 두 대표의 속성을 더해 생존 대표에 저장한 근거.
- 색 후보: 연결된 동료 노드의 상태 비교 후 동료와 공통 부모의 같은 필드를 연동 변경한 근거.

rank/크기는 레코드 필드와 별도 배열을 지원합니다. 별도 배열의 주소 인덱스가 **같은 대표 반환값에서 유래했는지** 확인합니다. 높이 역할이 하나로 확인되면 조건 조회에 `origin: inferred`로 연결하며 사용자 지정이 우선합니다. 색 후보의 선언된 의미는 `mapping: null`로 남깁니다. EXT-07의 관측 조건을 만족하면 별도 `suggestedMapping`을 제공하며, 작성자의 의도나 RB 트리의 지속적인 정상 동작을 확정하지 않습니다.

## EXT-04 지연 갱신

구간 노드의 `children`은 현재 값의 실제 읽기 의존성, `topologyChildren`은 입증된 구간 배치입니다. 자기 갱신 후에도 원래 구조를 유지할 수 있지만 `topologySourceWriteExecutionId`와 `transformed-aggregate`로 구별합니다. 아직 쓰지 않은 자식 값을 계산해 채우지 않습니다.

`deferred-update-candidate`는 같은 입력값이 같은 인덱스 출처를 가진 집계·태그 저장소에 전달되는 관계입니다. 이것만 있으면 `coupled-update-candidate`입니다. 결합 연산과 현재 값은 별도 보존합니다. 덧셈·곱셈·XOR·OR의 결합 및 직접 대입을 구별하며, `*=`와 `tag = tag * delta`에도 같은 출처 규칙을 적용합니다.

부모 태그의 같은 버전을 읽어 입증된 자식 구간들에 전달한 뒤 대기 상태를 실제 해제해야 `observed-propagation`입니다. 결합 태그는 해당 항등원(곱셈 1, 덧셈·XOR·OR 0)으로의 쓰기를 확인합니다. 대입 태그는 별도 존재 표지의 설정·조건 읽기·해제를 확인하며 0도 유효한 대입값입니다. `pending`은 저장된 태그 값, `present`는 관측된 존재 표지이며 서로 대체하지 않습니다.

다음 전파에는 이전 전파의 자식 쓰기를 재사용하지 않습니다. 단순 대입으로 집계 값의 의존성이 달라지면, 구간 관계는 과거 `coverageEvidenceExecutionId`로 명시하고 현재 값의 의존성이라고 꾸미지 않습니다. 임의의 태그 합성 함수를 실행하거나 아직 쓰지 않은 자식 값을 채우지는 않습니다.

## EXT-05 공유 노드

`shared-substructure-candidate`는 같은 프레임 또는 정적 영역의 살아 있는 루트 손잡이별 도달 집합의 교집합·차집합입니다. 같은 값·모양의 별도 노드는 공유가 아닙니다. 공유만으로 불변성·영속성을 보증하거나 재귀 호출 커서를 버전으로 확정하지 않습니다.

## EXT-06 구조 간 선택 관계

정수 인덱스와 포인터 대표 관계가 같은 관측 반환·비교·병합·레코드 복사 계약을 사용합니다. `buildStructureStorageBindings`는 상태별 실제 구성원 범위를 `availableAtExecutionId`/`invalidatedAtExecutionId` 구간으로 내보냅니다. 공유한 같은 범위는 구조별로 독립적으로 남습니다. 한도를 넘겨 생략한 구간을 이전 정상 대응으로 채우지 않습니다.

`partition-selection-candidate`는 대표 비교가 실제 병합과 레코드 복사를 함께 제어한 경우 원본 레코드·선택 위치·끝점 읽기·병합을 연결합니다. 목록은 **관측된 복사 이력**이며 대상 배열의 현재 구성원 목록을 대신하지 않습니다. 단순 동일 값 복사로는 생성하지 않으며 Kruskal/MST 이름·최적성·탐색 완료 색상을 추정하지 않습니다.

## EXT-07 조회·검증·남은 경계

2026-11-13 의미 확대: 비교 키는 기존 스칼라 외에 `bounded-string-bytes`(상수 길이 strncmp), `fixed-bytes`(상수 길이 memcmp), `transformed-integer`를 구별합니다. 비교 길이는 키 신원의 일부이며, 실행마다 바뀌는 길이를 상수로 고정하지 않습니다. NUL에서 멈추는 비교와 NUL을 포함한 고정 바이트 비교를 구별합니다. 사용자 함수의 같은 이름은 표준 함수 의미로 취급하지 않습니다.

변환 키는 관측 정수 연산의 타입·필드 범위·입력 사건을 보존합니다. +, -, *, /, %, 비트 연산과 안전한 시프트의 식을 키로 기록하고 양쪽 피연산자의 같은 변환임을 확인합니다. 원래 필드의 단순 순서로 바꾸지 않습니다. 현재 값에 대한 부가 키 계산은 원본 C 실행이나 IR 사건 추가가 아니며, signed 범위 초과·0 나누기·미관측 값은 unknown입니다. 지원하지 않는 변환을 순서 보존으로 가정하지 않습니다.

EXT-04 복합 태그: `tagSchema: affine-pair`는 별도 곱셈/덧셈 저장소의 `M'=M*a`, `B'=B*a+b`와 같은 호출 계보의 실제 집계 갱신을 연결합니다. 임시 변수와 태그별 도우미 함수도 실제 값 출처를 따라 연결합니다. 합성 방향은 new-after-old이며, 자식에 같은 부모 버전의 두 태그를 전달한 뒤 1/0으로 모두 초기화해야 완전 전파입니다. 초기화 순서는 무관합니다. 한 자식만 갱신한 경우와 단순 동시 쓰기는 완전 전파가 아닙니다. 두 저장소의 현재 값·구간 근거·쓰기 사건을 보존합니다.

EXT-03 색 해석: `mapping`은 선언된 의미를 뜻하므로 자동으로 채우지 않습니다. `encodingHypotheses`는 관측한 색 역할·루트 복구 쓰기·RB 조건과 호환되는 해석이며, 유일하게 근거가 있는 경우 `suggestedMapping`을 제공합니다. 조건 조회의 자동 사용은 `inferred-hypothesis`로 표시하고 명시적 사용자 지정이 우선합니다. 발견 시점 이전에 소급하지 않고, 나중에 조건 위반이 생겨도 색 해석을 바꿔 위반을 숨기지 않습니다. 이것은 작성자의 의도나 알고리즘 정확성 증명이 아닙니다.

새 상태형 후보는 `queryInferredSemantics(candidate, trace, {afterExecutionId})`로 조회합니다. 발견 전에는 null이고 미래 근거를 소급하지 않습니다. 원본 IR 불변, 추천 최대 5개, 사용자 고정 우선 규칙을 유지합니다.

검증기는 실제 사건으로 구성원·연결·반환 출처·복사 오프셋·현재 값·자식 누락과 추가·시간 순서를 검사합니다. 역할 후보와 위반은 실행 오류로 바꾸지 않습니다.

미확정 경계: 비교·대표 반환으로 입증되지 않은 임의 종료 규약과 포인터 인코딩, 모든 비교자·집계, 색 의미, 모든 지연 태그 합성, 영속성 증명, 알고리즘 의도·최적성. 포인터 비교자의 키 순서를 알아내더라도 호출을 가로지르는 배열 인덱스 관계와 활성 범위를 항상 알아내는 것은 아닙니다. 근거가 없으면 원래 배열·포인터·실행 사실을 유지합니다. UI 연결과 화면 가독성은 이번 검증 범위가 아닙니다.
