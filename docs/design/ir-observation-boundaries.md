# 관찰·저장소·중단 경계 보강 — 2026-11-06

대상은 코드 → 중간언어 생성입니다. 자료구조 추론과 애니메이션 구현은 변경하지 않습니다. 이름·예제 번호·예상 출력으로 분기하지 않고 AST 정체성, LLVM SSA, 컴파일러 저장소 및 실제 관찰에 적용합니다.

## 표현식과 호출

- 복합식 도중 오류가 발생하면 완료된 부분 연산과 이미 읽은 실패 연산의 피연산자를 실패 CALC에 연결합니다. 최종 값을 만들거나 이전의 별개 계산까지 실패로 바꾸지 않습니다.
- 겹치는 CallExpr는 소스 위치만으로 선택하지 않습니다. 실제 호출 대상 SSA 생산자와 AST의 호출 대상 식을 연결합니다. 반환된 함수 포인터의 즉시 호출, 역참조·캐스트·콤마·대입을 거친 호출도 내부 호출과 구분합니다.
- 증가·감소의 WRITE에는 lvalue 저장형을 전달합니다. 승격된 계산형과 저장형, 전위·후위 값 전달은 구별합니다.
- 가변 배열 타입은 미정 차원과 요소 타입을 유지합니다. 소스 연산자가 없고 주소 계산에만 소비되는 LLVM 행 간격 계산은 주소 준비로 기록합니다. 소스에 작성한 인덱스 산술은 CALC로 남습니다.
- LLVM 인용 식별자를 공통 문법으로 읽고, 표시 이름은 UTF-8 이스케이프를 복원합니다. 분석·호출·소스 위치 연결에서도 같은 식별자를 사용합니다.

## 실제 저장소와 소스 객체

- 사용자 가변 인자의 저장 영역은 번들 wasm32 ABI, 실제 va_start 결과, 호출 시 관찰한 인자 타입과 값 생산자로 연결합니다. 정렬 패딩은 임의 초기화된 값으로 만들지 않습니다. va_copy는 같은 영역을 참조하며 해당 함수 종료 시 수명이 끝납니다.
- 외부 반환 포인터의 저장 영역은 실제 링크된 WASM 데이터 세그먼트 또는 링커의 `__data_end`로 확인한 정적 영역에서만 보충합니다. BSS처럼 파일에 데이터 바이트가 없는 정적 영역도 포함하며, 이미 알려진 객체와 겹치지 않습니다. 이 근거는 매핑된 정적 바이트를 뜻하므로 `storageEvidence.objectBounds='unknown'`으로 C 객체 경계의 미확정을 명시합니다. 임의 주소나 힙 영역을 유효한 객체로 등록하지 않습니다.
- 컴파일러 dbg.declare가 반환 저장소(sret)를 지역변수로 지목하면, 그 소스 선언에서 지역 SPACE를 만듭니다. `storageAlias`는 호출자 저장소·범위·물리 루트를 연결합니다. 중첩 반환에서도 각 함수의 상자와 수명은 따로 유지하고, 실제 공유 바이트의 쓰기·포인터 출처는 함께 갱신합니다. 가상의 할당이나 복사는 추가하지 않습니다.
- 익명 반환 운반용 저장소는 sret 인자·CallExpr·자료형 크기로 연결하고 실제 사용 시점까지 공개를 미룹니다. `temporaryRole='abi-return-storage'`, `visibility='implementation'`으로 소스의 지역변수나 compound literal과 구별합니다. LLVM alloca가 함수 입구에 있다는 이유로 앞선 소스 줄보다 먼저 상자를 만들지 않습니다.
- 구조체 값 전달의 `dataInputs`는 실제 멤버 쓰기와 완료된 반환값을 가리킵니다. 주소를 만든 SPACE와 내용 값을 만든 사건은 구분합니다. `copiedFrom`에는 범위와 값 생산자를 남기며 원시 관찰을 공개 ID로 덮어쓰지 않습니다.
- 외부 구조체 반환은 숨겨진 반환 슬롯과 관찰된 쓰기·스냅샷으로 FLOW 복귀의 aggregate 값을 구성합니다. 라이브러리 내부 프레임을 만들지 않습니다. 결과 전달은 해당 쓰기와 주소·범위가 일치할 때만 인정합니다.
- 콜백 프레임에는 공개 `callbackOfCallExecutionId`와 근거용 `callbackOfCallObservationId`를 구분합니다.

## 오류와 기록 제한

준비 단계에서 실패해도 이미 확보한 AST·LLVM과 실패 단계·소스 위치를 보존합니다. 작업 계약 위반에는 구조화된 사건 ID와 계약 종류를 붙입니다. 미지원 volatile/atomic 등은 기존대로 실행 전에 거부합니다.

사건 수·관찰 바이트·시간 제한 및 큰 JSON 저장은 [공통 모델의 실행 제한](c-model.md#실행-제한)을 따릅니다. 시간 제한의 원시 기록 보존과 재생 가능한 중간언어의 변환 범위를 별도로 알립니다. 전송 체크포인트는 중단 결과 복구용이며, 사용자용 seek 재생기 구현을 의미하지 않습니다.

## 정상·비효율 코드 점검 후 과정 및 메타데이터 보강

2026-11-06의 `human-style-2026-11-06` 점검에서 확인한 여섯 계열을 공통 모델에서 보완했습니다. 예제명·변수명·예상 출력으로 분기하지 않습니다.

1. **반환 위치:** ReturnStmt 안의 실제 값 생산·저장·제어 이동과 LLVM 반환 블록의 연결을 사용합니다. 공용 반환 블록, VLA 정리, 구조체 반환 저장소가 있어도 실행한 반환 문장을 선택합니다. 명시적 조기 `return;`과 함수 끝의 암시적 복귀를 구별합니다. 원시 실행 순서는 보존하고, 공개 중간언어의 함수 공간 정리는 [반환 전달 이후](return-sequence.md)에 배치합니다.
2. **가변 인자 READ:** VAArgExpr의 커서 저장 경로와 LLVM 주소 생산자를 대조합니다. ABI 커서 읽기와 실제 인자 읽기를 구분하고 후자에 요청한 C 자료형·부호·폭과 표현식 위치를 붙입니다. 실제 값이나 인자 정렬을 다시 계산하지 않습니다.
3. **입력 출처:** WASI가 실제로 쓴 주소·바이트·스트림 오프셋에서 추적을 시작합니다. `READ/input`의 `inputStage='arrival'`은 외부에서 도착한 바이트이고, `inputStage='buffer-read'`는 해당 호출 중 관찰한 입력 관련 버퍼 읽기입니다. `streamReadRegions`에는 주소·범위·바이트·생산 사건을 남깁니다. 호출 복귀와 입력 대상 WRITE도 이 사건에 연결하여, 이미 버퍼링된 입력과 pushback을 외부 입력의 재도착으로 만들지 않습니다.
4. **상수로 접힌 호출:** 컴파일러의 함수 순수성 속성, AST 호출식, 실제 LLVM 상수 소비값을 연결합니다. 독립 식은 기존 CALC의 `compiler-folded` 근거로, 더 큰 계산의 피연산자는 `foldedExpression`으로 남깁니다. 값은 컴파일러가 소비한 정수·실수에서 얻으며 라이브러리 식을 별도로 실행하지 않습니다. 남아 있는 실제 호출과 부작용은 그대로 기록합니다. 상수 접기로 관찰되지 않은 인자는 소스 표현식 근거만 남기고 READ나 값을 꾸며내지 않습니다.
5. **매크로 지역 선언:** Clang 토큰의 spelling/expansion 위치에서 각 확장의 선언 식별자를 연결합니다. 같은 줄의 반복 호출도 별개 declarationId를 가지며, 매크로 정의와 호출 위치는 선언의 `macroExpansion`에 함께 보존합니다.
6. **불투명 포인터:** AST의 실제 record/typedef 선언과 DWARF 자료형을 사용합니다. FILE 같은 불완전 타입도 포인터 타입과 별칭을 유지합니다. 확인되지 않은 크기는 null이고, AST상 불완전성(`incomplete`)과 레이아웃 미확정을 구분합니다. 가상의 멤버·객체 경계를 만들거나 unknown 대상을 유효한 힙 객체로 바꾸지 않습니다.

입력 추적의 근거 수준도 구별합니다. 원래 호스트 입력 주소에서 읽은 바이트는 정확한 스트림 오프셋을 가집니다. 라이브러리의 관찰된 메모리 쓰기는 폭과 관계없이 **호출 단위 출처**로 연결합니다. `writerAccessSize`는 실제 작성 접근의 바이트 수입니다. 부분 덮어쓰기·동일 값 재쓰기에서도 직전 작성자를 범위별로 보존하고, 외부 호출 밖에서 덮어쓴 바이트는 해당 라이브러리 출처를 무효화합니다.

라이브러리 버퍼·상태 읽기는 `libraryReadRegions`로 기록합니다. 입력에 의존하는 호출이었다는 `inputRelated` 근거가 있어도 실제 호스트 입력 바이트의 읽기와 동일하게 취급하지 않습니다. `ungetc('Q', stdin)`처럼 외부 입력에서 얻지 않은 바이트도 작성 호출과 다음 읽기를 연결하며, 새로운 입력 도착을 만들지 않습니다. 이 메타데이터 때문에 라이브러리 내부 애니메이션이나 추가 C 호출을 만들지 않습니다.

호출 단위 출처는 라이브러리 내부의 정밀한 명령별 데이터 흐름 증명이 아닙니다. 덮어쓴 바이트에 원래 오프셋을 추측해서 붙이지 않으며, `streamReadRegions`의 크기를 논리적으로 소비한 문자 수로 단정하지 않습니다. 내부 입력·출력 버퍼와 사용자 배열의 읽기는 소스 호출의 효과·근거입니다. 새 버퍼 전체의 모든 복사·변환을 추적하는 범용 taint 엔진을 구현했다는 뜻은 아닙니다.

`tests/ir-human-process.test.js`는 위 계열과 버퍼링 방식·형식 입력·실수 상수·실제 호출 대조를 검사합니다. `tests/ir-buffer-provenance.test.js`는 1·2·4·8바이트 작성→다음 호출의 읽기, 입력 선조, 겹치는 범위·같은 값 재쓰기·출처 무효화를 검사합니다. 최초 여섯 계열 수정의 관련 사례 기록은 `test-results/human-process-fixes/final/`, 이후 쓰기 폭 제한 제거의 기록은 `test-results/buffer-width-2026-11-06/`에 보존합니다. 원래 감사 기록, 애니메이션, 기록 한도는 이 보강에서 변경하지 않습니다.
