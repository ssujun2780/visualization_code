# 공통 모델의 피연산자 평가 순서

2026-11-10. 코드→중간언어 생성 모델의 실행 정책입니다. UI에서 사건을 재정렬하는 규칙이 아닙니다.

## 기본 계약

1. C의 필수 순서와 선택 규칙을 우선합니다. `&&`·`||`는 필요한 오른쪽만 평가하고, `?:`는 선택된 가지 하나만 평가합니다. 쉼표 연산자는 앞 식의 부수효과까지 완료한 뒤 뒤 식을 평가합니다.
2. 값 생산→사용 의존성을 먼저 고정합니다. 그 제약을 만족하여 **현재 평가 가능한 피연산자 사이에서만** 명시된 방향을 적용하며, 기본은 좌→우입니다. 방향 선호가 필수 의존성을 덮어쓰지 않습니다.
3. 연산자 우선순위·괄호·자료형 변환·전위/후위의 전달값은 바꾸지 않습니다. 함수가 받는 인자의 위치도 바꾸지 않습니다.
4. 원본 C에서 정의되지 않은 동작이었던 식을 유효한 C로 바꾸는 계약은 아닙니다. 원본 Clang 진단은 그대로 보존합니다.

```c
consume(left(), right());
```

기본 실행은 left 호출과 반환값 확보 → right 호출과 반환값 확보 → 두 값을 원래 매개변수 위치로 전달 → consume 실행입니다. 중첩 호출에도 같은 정책을 적용합니다. 함수 지정식 자체에 작업이 있는 `factory()(a(), b())`는 factory → a → b → 선택된 함수 호출 순서입니다.

대입식에서도 `array[index()] = value()`는 index와 대상 주소 평가 → value 평가 → 저장입니다. `+=` 등의 기존 값 읽기도 왼쪽 피연산자의 평가에 속합니다. 대상 주소를 다시 구하거나 식을 두 번 실행하지 않습니다.

## 구현 위치와 근거

- `scripts/model/evaluation-order.mjs`: Clang AST의 피연산자 관계, LLVM 관찰 계획의 semanticNodeId, SSA 값 의존성, 제어 흐름을 연결합니다.
- `scripts/model/compile.mjs`: 기존 분석·관찰 계획으로 평가 구간을 확인합니다. 순서가 이미 맞으면 LLVM을 그대로 사용합니다. 다른 경우 실행 LLVM의 완결된 피연산자 구간을 재배치한 뒤 그 LLVM에서 관찰 계획을 다시 만듭니다.
- `scripts/model/ir-schema.mjs`: 정책과 피연산자 순서 계약을 검사합니다.

대상은 함수 호출, 이항식, 복합 대입, 배열 접근의 피연산자입니다. 논리식·조건식은 별도의 필수 순서/선택 경계를 유지합니다. 초기화 목록의 지정자 순서를 전면 재해석하거나, 미지원 C 문법을 지원하게 만드는 변경은 아닙니다.

AST 노드가 있으면 그 식별자를 먼저 사용합니다. 식별자가 없는 LLVM 보조 명령만 컴파일러 소스 범위를 참고하며, 다른 피연산자 값을 소비하는 주소 계산·형 변환을 해당 피연산자의 입력 평가로 오인하지 않도록 SSA 의존성을 확인합니다. C 소스를 문자열로 다시 분석하거나 고쳐 쓰지 않습니다.

주소 계산의 소속이 미확정이거나 관찰 계획에 없는 LLVM 보조 명령도 정의·사용 연결을 따라갑니다. 예를 들어 `q[k] → q[k].c → q[k].c[0]`의 후속 주소 계산이 `q`와 같은 소스 위치를 가리키더라도 `q`의 입력 평가로 취급하지 않습니다. 실행 명령이 따로 없는 상수 주소를 위해 이동 구간을 만들지 않습니다.

분리 가능한 피연산자 구간 사이에 SSA 의존 간선을 먼저 만들고, 준비된 구간 중 선호 방향에서 앞선 것을 선택하는 위상 정렬을 적용합니다. 일부 구간에 의존성이 있어도 독립적인 나머지 구간은 정렬할 수 있습니다. 식의 결과를 소비하는 후속 명령은 피연산자 이동 구간에 끼워 넣지 않습니다.

조건부 구간은 내부 분기와 PHI를 함께 옮깁니다. 시작·종료 블록이 달라진 경우 PHI의 선행 블록 연결도 갱신합니다. 번호형 SSA 식별자는 순서를 바꿔도 LLVM 문법에 맞도록 이름형으로 변경할 수 있지만, 사용자 변수·메모리·상자를 추가하지 않습니다.

이름 없는 인자·기본 블록·SSA 값은 LLVM의 번호 공간을 공유합니다. 이름 없는 진입 블록이나 종료 명령 뒤의 블록은 원문에 레이블이 생략될 수 있으므로, **재배치 전에 원래 번호를 복원하고 기존 블록의 레이블을 명시**합니다. 그 뒤 정의와 참조를 함께 이름형으로 변경합니다. 이 규칙은 `assert`·noreturn 호출 뒤의 도달 불가능한 블록에도 적용합니다. 문자열·인용된 이름·주석 속 `%숫자`는 변경하지 않으며, 재배치하지 않는 함수의 텍스트는 그대로 유지합니다.

필수 의존성 때문에 선호 방향을 그대로 적용할 수 없으면 의존성이 정한 순서를 유지합니다. 피연산자가 교차하거나 외부 제어 흐름 때문에 안전한 분리를 입증하지 못하면 해당 구간의 컴파일러 순서를 유지하고 이유를 기록합니다. **이러한 제외 사유 자체는 변환 실패가 아닙니다.** 유지한 순서를 좌→우로 적용했다고 표시하지 않습니다. 잘못된 정책 입력이나 내부 계획의 모순은 별도 오류로 검사하며, 원래 미지원인 문법·연산에 대한 지원 범위는 바꾸지 않습니다.

## API와 메타데이터

```js
await traceModel(source); // 기본 좌→우
await traceModel(source, {evaluationOrder: 'right-to-left'}); // 명시적 정책
```

명시적 우→좌도 C가 순서를 선택하도록 허용한 피연산자에만 적용됩니다. 단락 평가·조건 선택·쉼표 연산 순서는 유지합니다. UI 설정이나 주석 표지 문법은 추가하지 않았습니다.

`plan.evaluationOrder`는 기본 정책, 적용 단계, AST 노드별 피연산자 순서와 근거, 실제 재배치한 구간을 기록합니다. `plan.coverage.evaluationOrder`에는 적용 단계·변경한 식 개수·원본 소스 재작성 횟수 0을 남깁니다. 호출 정의도 같은 평가 순서 항목을 가리킵니다. 이 정보는 애니메이션 명령을 새로 만드는 표지가 아닙니다.

- `priority: mandatory-dependencies-before-direction`: 의존성 우선 계약입니다.
- 각 묶음의 `order`는 선호 순서, `effectiveOrder`는 실제 적용한 순서입니다. 피연산자 작업이 교차하여 완전한 순열로 표현할 수 없으면 `effectiveOrder: null`과 `observedOperandSequence`를 남깁니다. 이들은 정적 구간 계획이며 실제 분기·사건은 실행 기록을 따릅니다.
- `constraints`는 `{before, after, value, kind: 'ssa-dependency'}` 형태의 필수 간선입니다. 지역 구간만으로 풀 수 없는 순환은 `unresolvedDependencies`에 남기고 원래 제어 흐름을 유지합니다.
- `status: compiler-order-preserved`, `preservedBecause`는 C의 필수 순서, 값 의존성, 교차 구간, 외부 제어 흐름 등의 제외 사유입니다.
- 호출 정의의 `evaluationOrder.order`에는 실효 순서를 사용하고, `preferredOrder`를 별도로 보존합니다. `coverage.evaluationOrder.preservedExpressions`는 순서를 유지한 묶음 수입니다.

`llvm`는 정책이 적용된 실행 LLVM이고, `observations`는 그 실행에서 나온 실제 관찰입니다. 반환값 수신 뒤 함수 공간을 정리하는 기존 공개 중간언어 계약은 그대로 유지합니다. 저장된 예전 기록은 소급 변경하지 않으며 새로 생성해야 이 정책이 적용됩니다.

## 관련 검증

`tests/ir-evaluation-order.test.js`에서 중첩 호출, 공유 상태, 출력 순서, 대입 대상, 조건부 구간 이동, 간접 호출, 구조체 ABI, 반복·재귀·매크로, 단락 평가와 미평가 식을 확인합니다. 기대 출력은 소스에서 먼저 정하며, 실제 원시 호출 순서와 공개 중간언어 호출 순서도 비교합니다.

전역 구조체 배열 안의 배열, 변수 첨자, 중첩 멤버, 포인터 매개변수, 부수효과가 있는 주소 계산도 확인합니다. LLVM 수준에서는 피연산자 사이의 값 재사용, 일부 구간만 이동 가능한 경우, 교차·외부 제어 흐름, 관찰 메타데이터가 없는 보조 명령을 검사합니다. 과거 실패 코드는 기존 기대값 그대로 통과해야 합니다.

기존 호출 값/주소/ABI, CALC 입력, 표현식 경계, 조건 선택, 매크로 연결, 선언 순서, 반환 전달 검사만 관련 회귀 범위로 사용합니다. 자료구조 추론과 전체 예제 모음은 검사 범위에 포함하지 않습니다.
