# 실행 세션의 입력 대기

2026-11-13: 기본 입력 방식은 [PS-01](prepared-scene.md)의 전체 입력 후 실행입니다. 아래 같은 실행의 입력 대기 계약은 선택 가능한 실행 중 입력 모드에 계속 적용합니다. 각 입력 경계의 확보 기록은 표현 준비 후 재생합니다.

상위 문서는 [애니메이션](animation.md)·[UI](ui.md)입니다. 이 문서는 같은 실행을 유지하는 입력 대기의 실행 제어·화면 연결 계약입니다.

2026-11-10. 코드 → AST·LLVM → 중간언어 작업 경계 → 실제 실행 관찰 → 애니메이션의 원칙을 유지한다. 입력 변경을 위해 프로그램을 다시 실행하거나 과거 기록을 비교·이어 붙이지 않는다.

- 예제 페이지는 `/api/animation/sessions`에서 실행 세션을 시작한다. 기존 일괄 생성 API와 CLI는 유지한다.
- 실행 worker가 컴파일한 WebAssembly 인스턴스·메모리·스택·libc 버퍼를 유지한다. WASI `fd_read(0)`에 전달할 데이터가 없으면 해당 worker를 대기시킨다. 입력 함수 이름으로 대기를 결정하지 않는다.
- 대기 시점까지 관찰된 기록을 기존 공통 변환기로 중간언어에 연결한다. 아직 끝나지 않은 명령은 완료 애니메이션으로 공개하지 않으며, 기록기의 실제 관찰은 보존한다. `running` 부분 기록에서 수신 작업이 아직 관찰되지 않은 반환의 공간 정리는 공통 반환 계약에서 보류한다. 완료 기록의 반환 계약과 원시 수명은 유지한다. 입력 대기는 실행 제어 상태이고 새 중간언어 명령이 아니다. 추론기는 수정하지 않는다.
- 재생기가 현재 기록의 끝에 도착하면 멈추고 입력 돗자리·입력창을 강조한다. 코드에는 입력 호출 위치를 표시한다. 입력 전에는 입력값·입력 결과·후속 계산을 생성하지 않는다.
- ‘입력 전송하고 계속’ 또는 Enter는 새 바이트를 대기 중인 **같은 실행**에 전달한다. Shift+Enter는 전송하지 않고 입력창에 줄바꿈을 넣는다. 기존 Ctrl/Cmd+Enter 전송도 유지하며, IME 조합 확정용 Enter와 키를 누르고 있을 때의 반복 입력은 전송하지 않는다. 이후 관찰된 과정이 추가되고 현재 재생 위치·배치·배율을 유지해 이어진다. 전송한 입력창은 비운다.
- 기본 전송은 터미널의 Enter처럼 동작한다. ‘줄바꿈 추가’를 기본 선택하며, 끝에 LF가 없을 때만 한 번 붙여 명시적인 입력 바이트로 전달한다. 이미 있는 줄바꿈·공백은 보존한다. 선택을 끄면 textarea 내용 그대로 전송하며, ‘입력 종료(EOF)’를 선택한 전송에도 줄바꿈을 덧붙이지 않는다. 기본 모드의 빈 전송은 빈 줄이고 EOF와 다르다. 이미 전달된 libc 버퍼를 읽는 호출에는 불필요한 입력을 요구하지 않는다.
- 이전 시점 탐색은 관찰 기록의 재생이다. 이미 실행한 입력을 바꿔서 과거 실행을 재작성하지 않는다. 새 예제 실행·기록 열기·페이지 종료는 남은 실행 세션을 종료한다. 저장된 완료 기록 열기는 기존 기록 재생으로 유지한다.

실행 제어 시제품은 입력 요청 사이의 실제 실행을 관찰한 뒤 해당 구간을 재생한다. 모든 중간언어 명령 직전에 실제 실행 worker를 정지시키는 전체 단계 실행 제어까지 구현된 것은 아니다.

검증은 두 번의 입력 사이에 변경한 지역값·포인터 대상·호출 횟수·동일 runId 유지, 입력 전 출력/값 미생성, 입력 대기 재생 우회 방지, 명시적 EOF, 요청 중복 거부·세션 정리와 기존 입력·범위 쓰기·출력 재생을 포함한다. 브라우저에서 `scanf`에 `4 xy\n`, 이후 `fgets`에 별도 문자열을 전달하는 과정을 확인한다. 과거 C 예제 전체를 재실행하지 않는다.

2026-11-11: `scanf("%d %d", &m, &n)`에 끝 구분자 없는 `1 100`을 보내면 같은 scanf에서 추가 입력을 기다리는 문제를 재현했다. 줄바꿈 또는 EOF가 있으면 기록과 재생 상태 모두 m=1, n=100이다. 기본 전송의 줄바꿈 처리와 원문 전송/EOF 보존을 추가했고 관련 검사 8개가 통과했다. 제시된 소수 코드에서는 그 뒤 기존 관찰 기록 한도에 도달하는 별도 현상도 확인했으며, 입력 문제 수정에서 한도는 변경하지 않았다. 모듈 분리 작업 중 경로 누락으로 변경 후 브라우저 검증은 보류했다. 중간언어 생성 모델·추론기는 변경하지 않았다.

같은 날 출력 누락을 추가 확인했다. 웹 어댑터의 별도 `maxEvents:10000` 때문에 i=91 부근에서 중단되었고, printf 24회에 비해 실제 전달 출력은 최초 `2\n`만 남았다. 나머지 libc 버퍼는 정상 종료 전에 전달되지 않아 출력 기록을 복원할 근거가 없었다. 같은 소스를 생성 모델 기본 한도로 실행하면 정상 종료·25회 printf·25개 소수 출력과 각 호출 위치 연결이 확인된다. 실행 세션·예제 어댑터의 별도 낮은 값을 제거해 ModelRecorder/traceModel의 공통 기본값(현재 100,000)을 사용한다. 한도를 없애거나 버퍼를 강제로 비우거나 출력 문자열을 추정한 수정은 아니다.

Enter/Shift+Enter 변경은 짧은 두 정수 입력 코드로 브라우저에서 확인했다. `7` 뒤 Shift+Enter를 누르면 `7\n`이 입력창에 남고 전송되지 않았으며, `23`을 덧붙여 Enter를 누르면 EOF 선택 없이 같은 실행에 전달되어 `7 23\n` 출력과 종료 코드 0을 확인했다. 전송 뒤 입력창은 비워졌다. Vite 빌드도 통과했다.
