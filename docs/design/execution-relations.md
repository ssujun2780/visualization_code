# 자료구조 변화의 표현과 실행 관계 추론

2026-11-11 초기 독립 분석에 이어 2026-11-12 [v2 분석](execution-relations-v2.md)과 [현재 작업 연결 보기](work-context-view.md)를 추가했습니다. **일반 자동 배치는 미구현입니다.** 기존 계약은 [화면 문서 안내](presentation.md), [생성·추론 분리](inference-model.md), [자료구조 표현 정책](structure-presentation-policy.md)을 따릅니다.

2026-11-12: [확장 설계](execution-relations-extension.md)와 후속 사용자 승인에 따라 [v2 독립 분석·조회](execution-relations-v2.md)를 구현했습니다. **기본 v1 API와 아래 기존 동작은 그대로**이고 `outputSchemaVersion:2`·조회 `schemaVersion:2`로 확장을 선택합니다. 중간언어와 시각화 연결은 변경하지 않았습니다. 컴파일 근거 수집·append 세션·추가 화면 표현은 미구현이며 [검증 범위](../validation/execution-relations-v2.md)를 구분합니다.

## 현재 구현 범위 — v1 기본 경로

- `scripts/execution-relations/`는 생성 모델·자료구조 추론기·시각화 코드를 가져오지 않는 별도 모듈입니다. 기존 실행 경로에는 자동 연결하지 않았습니다.
- `inferExecutionRelations(plan, trace, {structureInference?})`는 독립 복사본을 동결해 판정기에 제공하며 호출자 원본은 수정하거나 동결하지 않습니다. 구조 추론 결과는 선택 입력이며 실행 식별자가 맞아야 합니다.
- `inferExecutionRelationsAsync`는 같은 API를 독립 Worker와 별도 시간 제한으로 실행합니다. 실패는 부가 결과의 진단으로 반환하며 C 실행 ERROR를 만들지 않습니다.
- 현재 판정기는 `calls`·`ranges`·`copies`입니다. `status: 'completed'`는 등록된 판정기의 실행 성공이며 모든 관계나 C 문법을 이해했다는 뜻이 아닙니다. 빈 목록을 실행하면 종전처럼 `not-implemented`를 반환합니다.
- `registry.mjs`의 후속 판정기 계약은 `{id, analyze(context) -> relation[]}`입니다. context는 기록·선택적 구조 결과와 사건/명령/객체/프레임 조회를 제공합니다. 판정 실패와 잘못된 메타데이터는 다른 판정기의 결과 및 원본 기록과 분리합니다.
- `validateExecutionRelations`는 결과 형식·실행 범위·사건/객체/프레임 참조·저장 범위·근거 시점을 검사합니다. C 실행이나 관계의 의미를 재검증하는 기능은 아닙니다.
- `createExecutionRelationQuery`는 조회 색인을 한 번 만들고 `at(executionId)`에서 성립 시점 이후의 메타데이터만 복사해 반환합니다. `at(null)`은 첫 사건 이전입니다. 객체의 현재 값·장면을 생성하지 않습니다.
- `createExecutionWorkQuery`는 현재 사건의 연산·호출 경로·지역변수 관찰·사용 구간·포인터 참조와 관련 과거 기록을 묶는 별도 조회 API입니다. 아래 작업 문맥 계약을 따르며 장면·메모리 값을 생성하지 않습니다.
- 아직 없는 기능: 알고리즘 의도·정렬/병합의 정확성 판정, 새 기록 추가에 대한 증분 분석, 일반 자동 배치. 기존 v1 관계 조회는 역사적 근거 목록이며 v2의 현재 작업 조회·시점별 관계와 구별합니다.

### 현재 작업 문맥 조회 (구현)

```js
import {createExecutionWorkQuery} from './scripts/execution-relations/index.mjs';
const work = createExecutionWorkQuery(plan, trace, executionRelations);
const current = work.at(executionId); // 이 사건이 끝난 직후의 경계
const initial = work.at(null);        // 첫 사건 이전: 활성 대상 없음
```

| 반환 항목 | 계약 |
| --- | --- |
| `analysisStatus` | 전달받은 관계 분석 상태. 분석 실패를 C 실행 실패로 승격하지 않음 |
| `operation` | 현재 사건/명령 ID·kind/action·기록된 연산자·원본 source 위치·피연산자/내부 step 관찰 참조. value/address/control/callee 간선을 구별하며 재평가하지 않음 |
| `calls` | 실제 진입/정리 사건으로 현재 살아 있는 호출 경로와 사건 소유 프레임을 구별. 호출자 쪽 반환 수신이 피호출자 정리 전에 기록돼도 둘을 유지하며 순서를 변경하지 않음 |
| `locals` | 현재 프레임의 살아 있는 객체와 해당 시점까지의 최신 관찰 사건 참조. 인자 WRITE로 확인된 parameter index/call ID와 이번 연산의 참여 여부. 이름으로 인덱스나 매개변수를 추측하지 않음 |
| `storage` | 현재 참여하는 살아 있는 저장소 ID·크기·실제 focusRanges와 활성 호출 subtree의 관측된 읽기/쓰기 prefix. 포인터를 전달했다는 사실만으로 전체 할당 범위를 사용했다고 표시하지 않음 |
| `references` | `binding`은 현재 슬롯의 최신 관찰, `operand`는 현재 연산이 소비한 관찰의 참조. 오래된 피연산자를 현재 슬롯 연결로 혼동하지 않음. 재대입/참조 없는 덮어쓰기에서 과거 인자 참조를 재사용하지 않으며 one-past는 reference-only |
| `relations` | `operationIds`는 이번 연산의 직접 근거, `contextIds`는 현재 호출·참조 문맥, `historyIds`는 관련 과거 사실. 모두 성립 시점까지 확인된 관계 ID |
| `history` | 완료된 관련 호출, 사라진 저장소, 종료된 호출/저장소에서 온 값의 관찰 출처. 현재 호출·살아 있는 상자와 별도로 유지 |

`phase`는 before-start/active/no-active-frame/fault입니다. 기록된 ERROR/fault만 fault로 표시하며 이 조회 API는 재생·일시정지·입력 대기를 조작하지 않습니다. `calls.stack`의 role은 current/caller/resident-callee이며 resident-callee는 아직 정리되지 않은 공간을 뜻합니다. 현재 연산의 실제 activation ID가 살아 있으면 그것을 current로 사용합니다.

원본 값은 execution ID/observation ID로 기록에서 조회합니다. `latestObservation`은 전체 객체 값의 재구성이 아니며 부분 WRITE 하나를 전체 배열 값으로 간주하지 않습니다. immediate 피연산자만 해당 사건에 기록된 상수를 그대로 제공합니다. READ의 dataInputs는 과거 메모리 생산자로 남기며 현재 피연산자를 찾기 위해 무한히 따라가지 않습니다. 주소 생산자는 따라가 인덱스·포인터 슬롯을 연결합니다. 해제된 대상·닫힌 호출의 READ는 역사적 출처로 남깁니다.

한 번 생성한 조회기는 원본 스냅샷·수명·관찰·호출·관계 색인을 재사용합니다. 순방향 조회는 관련 접근 prefix 캐시를 확장하고 뒤로 이동하면 해당 prefix만 재구성합니다. 시점별 전체 객체 값이나 좌표는 저장하지 않으며 반환값은 독립 복사본입니다. 입력 plan/trace/result를 변경하거나 동결하지 않습니다. 존재하지 않는 사건·다른 실행의 결과는 거부하고 미래/해결되지 않은 피연산자는 unavailable로 남깁니다.

이것은 고정된 기록의 현재 작업을 조회하는 구현입니다. 새 trace append에 대한 증분 추론·범용 후보 버전 관리·화면 배치를 완성한 것은 아닙니다. [검증과 남은 범위](../validation/execution-work-context.md)를 따릅니다.

### 초기 공통 판정 규칙 (구현)

| 관계 종류 | 필요한 실제 근거 | 시간·해석 경계 |
| --- | --- | --- |
| `activation-call` | 부모 프레임의 미복귀 호출과 실제 자식 `frame.begin`, resolved function ID 일치 | 진입 시점에 성립. 저장소 없는 호출도 두 프레임만으로 표현. 자식 프레임이 없는 라이브러리 호출은 별도 호출 공간을 만들지 않음 |
| `pointer-argument` | 실제 인자 WRITE의 call ID·parameterIndex와 관측된 객체/오프셋 참조 | 인자 전달 시점. 인자 슬롯과 참조만 연결하며 배열 전체 사용을 주장하지 않음. one-past 참조를 역참조로 취급하지 않음 |
| `storage-access` | 완결된 READ/WRITE의 실제 객체·바이트 범위, 명시적 copy의 원본 범위 | 사건 시점의 접근 한 건. 지역 스칼라 장부 작업을 배열로 묶지 않음. 컴파일러 lvalue 타입이 있을 때만 원소 크기·멤버 오프셋 부가 |
| `activation-range` | 같은 호출에서 직접 접근한 범위, 또는 실제 자식 호출을 포함한 범위 | `direct`/`subtree`, 읽기/쓰기 집합 분리. 닫힌 호출 요약은 frame.end 이후, 진행 중 기록은 `observed-prefix`. 최소~최대 `boundingRange`와 실제 접근한 `ranges`를 구별 |
| `range-relation` | 동일 객체의 부모/자식 또는 같은 저장소를 쓰는 연속 형제 호출 범위 | 포함·겹침·분리·동일 관계. 임의의 정수 인자로 경계를 예측하지 않음. 모든 형제 쌍을 비교하지 않음 |
| `storage-copy` | WRITE의 유일한 실제 값 생산자를 따라간 READ, 또는 기록의 명시적 메모리 copy 효과 | 원본/목적지 바이트·읽기/쓰기 ID를 보존. 같은 폭의 비트 보존 cast만 통과. 산술·불명확한 다중 생산자·호출 반환 경로는 복사로 추측하지 않음 |
| `copy-sequence` | 같은 호출·원본 객체·목적지 객체의 연속된 payload 복사 기록 | 개별 전달 ID·순서와 연속 sourceRuns를 유지. 지역 스칼라 장부 작업은 무시하되 다른 payload 쓰기·호출·방향 변경에서 분리. 명령/구조체 필드를 합쳐 실행하지 않음 |

모든 범위는 `[offset, offset + size)`의 바이트 범위입니다. 원본 객체 ID와 접근 당시 생성/소멸 사건을 검사하며 주소 숫자가 같다고 연결하지 않습니다. 함수·변수·필드 이름의 의미, C 원문 재파싱, 최종 값의 유사성은 판정 근거가 아닙니다. 멤버 이름은 컴파일러가 준 경로의 표시 정보로만 남습니다.

접근 델타·개별 복사는 즉시 조회할 수 있지만 최종 호출 범위·전체 복사 열은 필요한 마지막 사건 이전에 표시하지 않습니다. `copy-sequence`는 관측된 열이며 전체 알고리즘 단계의 완료나 정상 레코드 복사를 뜻하지 않습니다. 서로 다른 원소에서 가져온 두 필드도 각각 원본 범위를 유지합니다. 원소를 전혀 읽지 않은 재귀 종료 호출은 포인터 인자 참조만 남고 사용 구간은 미확정입니다.

현재 복사 생산자 연결은 직접 읽기·같은 폭 cast·명시적 메모리 복사까지입니다. 임의의 선택식/반환 전달을 거친 복사, 알고리즘 단계의 자동 구분, 원소 정체성의 전역 역사 색인, 깊은 재귀·대규모 기록의 자원 예산은 후속 항목입니다. 기존 WRITE의 숫자가 같다는 이유로 이 공백을 메우지 않습니다.

저장된 기록에서 실행하려면 다음을 사용합니다. 원본 plan/trace 대신 `execution-relations.json`만 저장합니다. 미구현 상태라도 파일 작성에 성공하면 CLI 종료 코드는 0이며, 완료된 추론이라는 뜻은 아닙니다.

```sh
node scripts/infer-execution-relations.mjs test-results/c-model
# 선택 입력과 출력 폴더
node scripts/infer-execution-relations.mjs test-results/c-model --structure-inference test-results/c-model/inference.json --out-dir test-results/relations
```

뼈대는 [초기 대응표](../validation/execution-relations-scaffold.md), 실제 판정과 예상/실제 비교는 [호출·구간·복사 검증](../validation/execution-relations-rules.md)에 기록합니다. 아래 R 요구와 W 초안 전체가 구현된 것으로 해석하지 않습니다.

## 상태와 목적

아래 R 조항은 이번 대화에서 확인한 요구와 기존 불변 계약입니다. W 조항은 이를 만족시키기 위한 **설계 초안**이며, API 이름·레이아웃·패턴 종류는 구현 확정값이 아닙니다.

현재 알고리즘 흐름은 관찰 가능하지만, 축소 시 가독성 저하와 멀리 떨어진 참조 대상 때문에 자료구조의 변화를 함께 보기 어렵습니다. 이 문제를 해결하면서 기존의 흐름 관찰과 논리 오류 추적도 유지합니다. ‘합병정렬처럼 보인다’ 하나만으로 성공을 판정하지 않습니다.

## R-01 세 목적의 동시 보존

자료구조의 형태·변화, 주변 연산·호출 흐름, 값·연산 오류의 출처를 같은 재생에서 관찰할 수 있어야 합니다. 구조 전용 보기와 흐름 전용 보기 중 하나만 골라야 하는 해결책으로 마무리하지 않습니다. 자료구조가 인식되지 않아도 기본 실행 시각화는 유지합니다.

## R-02 실행과 표현의 경계

SPACE·READ·CALC·WRITE·FLOW와 기록된 ERROR가 실행의 기준입니다. 추가 분석은 사건을 생성·삭제·정렬하거나 C 식을 다시 실행하지 않습니다. 여러 사건에 걸친 관계를 발견해도 원래 명령의 애니메이션을 하나로 대체하지 않습니다. 레이아웃 이동을 메모리 할당·복사·구조 변경으로 연출하지 않습니다.

## R-03 재생 중 동시 관찰

객체·서랍·부분 보기를 살펴본다는 이유로 자동 일시정지하지 않습니다. 여러 관련 대상의 값과 연산을 재생 중 함께 갱신합니다. 사용자의 명시적 일시정지, 실제 입력 대기, 기록된 치명적 오류·실행 종료 등 기존 재생 경계는 별개입니다. 검사를 위해 애플리케이션이 자동으로 멈추는 제안은 철회된 상태입니다.

## R-04 저장소 정체성과 현재 상태

함수 프레임·객체·할당 세대·원소/멤버 범위의 실제 식별자를 유지합니다. 같은 배열의 부분 보기는 새 배열이 아닙니다. 별칭·공유 저장소·해제 후 주소 재사용을 숫자 주소나 같은 값만으로 합치지 않습니다. 현재 시점보다 나중에 얻은 값·참조·분석 근거를 앞 장면에 표시하지 않습니다.

## R-05 변화가 읽히는 작업 문맥

배열 하나만 고립해서 확대하는 것으로 해결하지 않습니다. 현재 접근 구간, 관련 원소·멤버, 인덱스·매개변수, 연산 도구·전달선, 호출·코드 위치를 함께 확인할 수 있어야 합니다. 전체를 보기 위해 축소했을 때 읽을 수 없는 작은 글자를 그대로 늘어놓는 것도 해결 완료로 보지 않습니다.

## R-06 오류와 불완전한 구조의 보존

자료구조 보기에서도 실제 원소 순서·인덱스·연결·부분 쓰기·미초기화 상태를 유지합니다. 트리 모양을 만들기 위해 순환·공유·빠진 연결을 지우거나 정렬된 배열처럼 보정하지 않습니다. 인식한 패턴의 예상과 다른 실행도 그대로 표시합니다. 패턴 불일치는 사용자 프로그램의 치명적 오류를 자동 생성하는 근거가 아닙니다.

## R-07 일반화와 사용자 선택

변수명·함수명·예제 파일명·특정 상수·정답 일치로 분류하지 않습니다. 관측된 주소/인덱스 관계, 값의 출처, 읽기·쓰기와 호출 관계를 근거로 합니다. 사용자 지정 표현이 자동 추천보다 우선하는 기존 정책을 유지하며, 표현 지정이 실제 데이터의 정체성·순서·수명을 바꾸지는 않습니다.

## W-01 구성과 의존성 초안

| 구성 | 입력과 책임 | 출력 |
| --- | --- | --- |
| 중간언어 생성 모델 | 컴파일러 정보와 실제 실행 관찰 | 원본 plan·trace |
| 자료구조 추론기 | 원본 기록의 저장·참조 관계 | 배열·리스트·트리 등의 후보와 근거 |
| 실행 관계 추론기(가칭) | 같은 기록의 호출·접근 범위·값 전달 관계 | 작업별 참여 대상·구간·역할·근거 |
| 표현·배치 | 현재 시점의 기록과 사용 가능한 부가 결과, 사용자 배치 | 동기화된 보기와 작업 문맥 |

두 추론기는 원본 실행 기록의 독립적인 읽기 전용 소비자로 둡니다. 실행 관계 추론기는 자료구조 결과를 선택적으로 활용하되 그것이 없다고 실패하지 않습니다. 생성 모델에서 두 추론기를 가져오지 않고, 상위 경로가 선택한 분석만 불러옵니다. 분석 실패·시간 초과가 실행 상태나 원본 기록을 변경하지 않습니다. 상위 애니메이션 경로의 기본 연결은 [현재 작업 연결 보기](work-context-view.md)를 따릅니다.

AST·LLVM 정보는 이미 생성 모델이 연결한 plan의 선언·자료형·소스 노드·표현식과 관찰 출처를 재사용합니다. 이 추론기가 컴파일러나 C 원문 분석을 새로 수행하지 않습니다. 필요한 연결이 없으면 부족한 근거를 보고합니다.

## W-02 분석할 관계의 초기 범위

먼저 다음과 같은 범용 관계를 대상으로 조사합니다. 이 목록은 완성된 지원 목록이 아닙니다.

| 관계 | 근거와 표현의 용도 |
| --- | --- |
| 부모·자식 호출 | activation/call 식별자에 따라 호출 공간을 가까이 묶기 |
| 호출과 사용 구간 | 실제 배열 접근, 인자와 주소의 출처로 같은 저장소의 사용 범위 표시 |
| 원소·멤버 묶음 | 컴파일러의 배열/레코드 배치에 따라 회의의 start/end 등을 한 원소 안에 표현 |
| 여러 원본에서 목적지로 전달 | 실제 READ/WRITE의 출처·대상 범위로 병합·복사 관계 표시 |
| 교환·이동·삽입 | 실제 중간값과 쓰기 순서를 유지한 원소 변화 표시 |
| 방문과 탐색 경계 확장 | 관측된 참조·큐/스택 사용·방문 변화의 관계 표시 |
| 후보값·상태표 갱신 | 실제 비교 입력과 이전/새 값, 생산자·소비자의 의존 관계 표시 |
| 선택과 복원 | 실제 저장·복구된 상태와 호출/반복 문맥 연결 |
| 연결 변경 | 포인터/인덱스 역할의 실제 변경과 영향을 받는 대상 표시 |

‘합병정렬’, ‘다익스트라’ 등의 이름 판별은 초기 필수 기능이 아닙니다. ‘두 구간에서 같은 목적지로 값이 전달됐다’는 관계만 확인되면 그 관계를 표현하며, 알고리즘의 의도·정확성을 확정하지 않습니다. 앞서 언급한 대표 알고리즘 30~50개, 공통 패턴 15~25개는 조사 규모의 추정이며 구현 개수·완전성·인식률 보장이 아닙니다.

판정은 다음 경계를 둡니다.

- **구간:** 포인터 인자의 관측된 대상·오프셋, 접근한 원소/멤버와 호출 정체성을 연결합니다. 정수 인자라는 이유로 시작/끝 인덱스로 간주하지 않습니다. 할당 전체 크기, 최소~최대 접근 범위, 실제 접근한 구간 집합을 구별하며 중간의 미접근 영역을 사용한 것처럼 채우지 않습니다.
- **분할:** 같은 저장소의 부모/자식 호출 범위에서 포함·겹침·분리를 기록합니다. 두 자식이 있다고 이분할로 확정하거나 겹친 범위를 강제로 분리하지 않습니다. 직접 접근과 하위 호출을 포함한 접근 범위도 구분합니다.
- **병합·복사:** 원본 READ의 생산자와 목적지 WRITE의 실제 범위가 연결돼야 합니다. 두 구간을 읽었다는 사실만으로 정렬·병합을 확정하지 않습니다. 각 필드가 서로 다른 원소에서 왔다면 하나의 정상 레코드 복사로 미화하지 않습니다.
- **교환·복원:** 임시 저장소를 통한 이전 값의 실제 전달 경로를 확인합니다. 바뀐 뒤 숫자가 같다는 이유만으로 복원이나 교환으로 판정하지 않습니다.
- **후보 갱신·상태표:** 비교에 사용한 값, 선택 경로, 저장한 새 값 사이의 출처를 확인합니다. 작은 값으로 바뀌었다는 사실만으로 최단 경로 알고리즘으로 분류하지 않습니다.
- **탐색·연결 변경:** 실제 방문/참조/작업 목록의 변화만 표시합니다. 호출 순서가 비슷하다는 이유로 DFS/BFS 등의 의도를 확정하지 않습니다.

## W-03 부가 결과 계약 초안

최소한 다음 정보가 필요합니다. 값은 원본 기록에서 조회하며 부가 결과에 별도 실행 상태를 만들지 않습니다.

```js
{
  schemaVersion: 1,
  scope: {programId: "…", runId: "…"},
  status: "partial",
  relations: [{
    id: "r17", kind: "range-combine", status: "supported",
    availableAtExecutionId: "x48",
    activationIds: ["f3"],
    participants: [
      {role: "source", objectId: "o2", offset: 0, size: 16},
      {role: "source", objectId: "o2", offset: 16, size: 16},
      {role: "destination", objectId: "o3", offset: 0, size: 32}
    ],
    supportingExecutionIds: ["x40", "x48"],
    contradictingExecutionIds: []
  }]
}
```

`availableAtExecutionId`는 성립에 필요한 근거를 모두 관찰한 시점입니다. x48의 근거가 필요하면 x40에서 이미 확정된 관계처럼 표시하지 않습니다. 전체 기록을 분석해도 현재 재생 시점에서 쓸 수 있는 관계만 조회합니다. 진행 중인 기록에서는 끝 구간·최종 참여 대상 등을 미확정으로 남깁니다.

확인됨·해석이 여러 개임·근거 부족·관측된 반례를 구분합니다. 검증되지 않은 신뢰도 백분율을 확률처럼 표시하지 않습니다. 값만 같거나 접근 범위가 우연히 같다는 이유로 같은 작업으로 합치지 않습니다. 다른 run의 결과와 수명이 끝난 객체를 현재 장면에 붙이지 않습니다.

반례도 해당 사건 이후에만 반영합니다. 뒤에서 모순이 발견됐다고 앞 장면의 당시 후보·표현을 소급 변경하지 않습니다. 증분 분석은 사건/생산자/호출/저장 범위 색인을 재사용하고 새로 확인한 관계와 영향받은 대상을 갱신하는 방향으로 설계합니다. 확정되지 않은 호출 범위를 완성된 최종 구간으로 취급하지 않습니다. 정확한 색인 구조·예산과 결과 버전 방식은 미정입니다.

## W-04 표현과 배치 초안

- 기준 공간의 함수·실제 저장소·사용자 배치는 안정적으로 유지합니다. 자료구조를 예쁘게 만들기 위해 전역 배치를 매번 뒤집지 않습니다.
- 자료구조 보기는 같은 저장소에 연결된 부분 보기이며 기준 공간과 같은 명령·사건 시계로 갱신합니다. 패턴 분석이 없어도 확인된 자료형·원소·멤버의 보기는 사용할 수 있습니다.
- 재귀 호출은 실제 부모·자식 관계로 가까이 배치합니다. 같은 함수 이름이라는 이유만으로 무관한 호출을 한 묶음으로 만들지 않습니다. 종료된 자리 재사용과 사용자 고정 위치의 우선순위는 세부 설계가 필요합니다.
- 포인터는 주소 숫자만으로 대상 확인을 강요하지 않고, 대상·원소 위치와 연결된 보기를 가까이 보여주는 방향으로 설계합니다. 숫자 주소·바이트 정보는 상세 조회에서 유지합니다. 서랍을 열어도 재생을 멈추지 않습니다.
- 축소 시에는 원소 수·구간·연결 등의 요약을 사용하고, 현재 작업 묶음은 읽을 수 있는 크기로 보여줍니다. 구체적인 글자 크기·최대 동시 구간 수·화면 분할 방식은 미정입니다.
- 컴파일러가 만든 문자열/초기화 템플릿은 독립 상자를 기본 숨김으로 두는 방안을 검토합니다. 실제 참조 대상으로 필요하면 같은 저장소의 보기를 제공합니다. 이름 접두사로 판정하거나 사용자 선언 const/static을 함께 숨기지 않습니다.
- 자료구조 보기의 원소를 선택해도 실제 범위·실행 사건·기준 공간의 대응 대상을 찾을 수 있어야 합니다. 외곽 컨테이너 선택으로 내부 모든 포인터를 강조하지 않는 기존 규칙을 유지합니다.

배치 좌표·확대율·고정 창·표현 수준은 표현 계층의 상태입니다. 추론 결과에 임의의 좌표를 박아 실행 사실처럼 다루지 않습니다. 새로운 보기와 기준 공간에 같은 값을 두 번 표시하더라도 메모리 할당·복사로 세지 않습니다.

## W-05 합병정렬로 확인할 과정

1. 같은 배열의 부모 구간과 자식 구간 관계를 표시합니다. 실제로 분리 할당하지 않았다면 새 배열 생성 애니메이션을 만들지 않습니다.
2. 회의 하나는 start/end를 가진 원소로 표시하고, 코드가 필드를 따로 쓴다면 그 사이의 부분 변경 상태도 유지합니다.
3. 병합 중에는 두 입력 구간·임시 배열·활성 인덱스·비교/저장을 함께 볼 수 있어야 합니다. 어느 한 배열만 확대해서 나머지를 잃는 결과는 실패입니다.
4. 실제 쓰기 순서에 맞춰 임시 배열이 채워지고 원본에 반영됩니다. 관계 추론이 전체 병합 장면 하나로 명령 순서를 대체하지 않습니다.
5. 잘못된 원소 선택이나 복사를 넣어도 그 실행을 그대로 보여줘야 합니다. 정상 정렬 결과로 미리 배열을 재배열하지 않습니다.

## W-06 구현 단계의 검증 계획

구현할 때 사례별 예상 관계·원소 정체성·순서·성립 시점·미확정 상태를 먼저 적고, 이후 분석 결과와 비교합니다. 실제 결과에 맞춰 기대값을 고치지 않습니다.

| 검사군 | 확인할 실패 |
| --- | --- |
| 원본 불변 | 분석 전후 사건·객체·프레임·참조·반환 연결이 달라짐 |
| 시간 경계 | 뒤에서 확인한 관계/값이 앞 장면에 나타남, 재할당/주소 재사용 연결 오류 |
| 표현 다양성 | 이름 변경, 별칭, 다른 구조체 필드 배치, 부분 포인터, 반복/재귀 구현에서 특정 예제만 통과 |
| 반례·불완전성 | 비슷한 복사 작업을 정렬로 확정, 틀린 연결/순서 보정, 근거 부족을 실패나 정상으로 단정 |
| 실패 격리 | 추론 모듈 미설치·오류·시간 초과가 중간언어 생성이나 기본 재생을 막음 |
| 실제 화면 | 재생 중 관련 배열·연산·호출·코드 동시 가시성, 축소 가독성, 원본 대응, 선택해도 재생 유지 |

API 검사만으로 마지막 화면 항목을 통과시키지 않습니다. 동일한 입력·화면 크기·배율·속도에서 대표 장면을 기록해 판단합니다. 정확한 가독성 수치와 성능 예산은 구현 전 구체화할 미정 사항입니다. 검사 항목은 설계이며 현재 테스트가 구현·통과했다는 의미가 아닙니다.

## W-07 다음에 확정할 항목

자료구조 추론 결과를 실제 화면에 적용한 뒤, 기존 메타데이터로 가능한 범위와 새 추론이 필요한 범위를 구분하는 단계 원칙을 유지합니다. 2026-11-12 사용자 요청에 따라 입력/출력·범용 규칙의 설계는 [확장 초안](execution-relations-extension.md)으로 선행 정리했습니다. 자원 예산 수치와 배치/고정/요약 정책·시각적 합격 수치는 여전히 구현 전 확정 항목입니다. 알고리즘별 전용 애니메이션 목록이나 만능 인식기를 구현하지 않습니다.

구현 대응표는 [설계 대응 템플릿](../validation/design-implementation-template.md)을 사용합니다. 이 초안의 문서 작성 완료와 기능 구현 완료를 구분합니다.
