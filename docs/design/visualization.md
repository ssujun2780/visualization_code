## 공간과 대상 — 구현

확대·축소·화면 이동이 가능한 무한 공간을 사용합니다. 전역·정적 저장소, 호출별 스택 공간, 힙 저장소를 구별하고, 도구 작업대·입력·출력 돗자리는 처음부터 존재합니다. 실제 객체와 호출 정체성은 유지하고 화면 배치는 실행 상태와 별도로 관리합니다.

- 변수는 이름·C 자료형·값·바이트 크기를 가진 상자입니다. unsigned는 u 배지를 사용합니다.
- 배열은 원소 상자, 구조체는 멤버 상자를 포함합니다. 포함 관계와 실제 포인터 참조는 구분합니다.
- 함수 돗자리는 호출별 매개변수·지역변수·반환구를 모읍니다. 반복·재귀 호출은 별도의 활성화이며 이름이 같아도 같은 공간이 아닙니다.
- 관찰되지 않은 값은 미확정·미초기화로 표시합니다. 최종 객체 장부의 값·포인터·수명을 과거 장면으로 가져오지 않습니다. 쓰레기 아이콘은 초기화 상태의 표현이며 임의의 정상값을 뜻하지 않습니다.
- 값이 0인 바이트, 문자 '\0', 포인터 NULL, 미초기화 상태는 구분합니다. 문자열 미리보기는 해당 시점에 관찰된 바이트와 종결 문자만 사용합니다.

새 상자·커진 배열·함수 공간이 나타날 때 주변 돗자리 겹침을 조정합니다. 안정된 기존 위치와 수동 배치를 우선 보존하고, 드래그 중에는 미리보기 뒤 놓는 시점에 조정합니다. 종료된 공간을 활성 장애물로 유지하지 않습니다.

알루 작업대는 현재 계산 입력의 실제 원소/반환구 가까이에 배치합니다. 알고리즘 이름을 추론하거나 앞으로 실행될 WRITE 주소로 위치를 정하지 않습니다. 기존 입력·출력·사용자 데이터 필드와 겹치지 않는 후보 중 입력까지의 거리와 기존 위치 보존을 고려합니다. 자동 작업대가 데이터 필드에 자리를 양보하며, 사용자가 작업대를 직접 드래그하면 고정합니다.

2026-11-11: 기본 상자는 128×88, 일반 필드의 최소 크기는 400×240으로 줄입니다. 배열·구조체는 원소 수가 적으면 빈 가로 공간을 줄이며 배선 통로 간격은 보존합니다. 입력·출력 필드는 각각 440×360이고 전체 입력 이력·출력을 필드 안의 스크롤 영역에 둡니다. 입출력 글자는 확대율에 따라 제한적으로 크기를 보정합니다. 출력의 화면 높이를 넘었다는 이유로 기존 줄을 버리거나 마지막 몇 줄로 대체하지 않습니다.

컴파일러가 생성한 상수 보조 저장소는 원본 선언과 연결되지 않은 경우 독립 상자로 표시하지 않습니다. `.str`·초기화용 `__const` 등의 이름 패턴만으로 판정하지 않으며, 사용자 선언의 const·static 변수는 유지합니다. 실제 상태·중간언어에서 저장소를 삭제하지 않습니다. 현재 살아 있는 사용자 포인터가 참조하면 연결 대상은 ‘문자열 리터럴’ 또는 ‘상수 데이터’로 표시하고 현재 관찰한 내용과 연결을 유지합니다. 숨긴 보조 저장소의 값 전달선은 가상의 출발 상자를 만들지 않고 생략합니다. 근거가 부족한 과거 기록은 임의로 숨기지 않습니다.

거대한 배열은 전부 펼치지 않고 일부 원소와 관찰·참조된 범위를 표시합니다. 현재 시제품의 표시 상한과 가상화 한계, 정확한 연결점·배치·국소 이동 규칙은 [포인터 배선](pointer-wiring.md)을 따릅니다.

## 두 종류의 연결선 — 구현

자료구조 변화와 주변 연산은 [준비 후 같은 공간 재생](prepared-scene.md)의 PS-01~04로 연결합니다. 과거 [별도 작업 연결 보기](work-context-view.md)는 기본 화면에서 제외했습니다. 원본 소속·값·접근 범위와 기존 명령 시간선을 유지하며, 살펴보기 때문에 자동 일시정지하지 않습니다. [실행 관계](execution-relations.md)의 R-01~R-07은 유지합니다. 모든 규모의 자동 최적 배치·모든 자료구조의 전용 연출은 미구현입니다.

| 연결 | 의미와 기본 표현 |
| --- | --- |
| 값 전달선 | 한 명령어의 데이터 흐름. 주황색·직선 위주이며 선을 분리하고 현재 사건을 더 밝고 굵게 강조합니다. 돗자리의 빈 공간을 통과할 수 있습니다. |
| 포인터 참조선 | 값이 유지되는 동안 존재하는 참조. 상자와 돗자리를 피하는 직교 배선·평행 다발을 사용하고 바뀐 부분을 우선 갱신합니다. |

색·간격·내용 보호·배치 실패의 정확한 정책은 [값 전달 화살표](value-transfer-arrows.md)와 [지속 포인터 배선](pointer-wiring.md)에 각각 둡니다. 두 선의 수명과 강조 상태를 섞지 않습니다.

2026-11-11 수정: 상자·원소·선을 선택하거나 그 위에 커서를 두면 실제 포인터선을 따라 연결된 전체 성분을 강조합니다. 선택/호버가 없으면 현재 READ·WRITE·CALC가 다루는 대상의 연결 성분을 강조합니다. 간선 방향에 상관없이 별칭과 다중 포인터도 따라가며 순환은 한 번만 방문합니다. 포함 관계를 포인터선으로 간주하지 않으므로 바깥 배열·구조체 선택만으로 내부 포인터 전체를 선택하지 않습니다. 접힌/가려진 컨테이너의 선은 보이는 연결점을 사용하되 원래 원소·멤버의 정체성을 유지합니다.

배열·힙·구조체 서랍은 기본 크기를 유지하며 우하단 모서리를 드래그해 표시 폭·높이를 바꿉니다. 크기를 지정한 서랍은 내부에 들어갈 칸만 표시하고 나머지는 대표 연결점에 연결합니다. 확대 시 현재 기록의 바이트와 자료형으로 추가 칸을 표시하며, 미관측·미초기화 칸에 최종 값이나 임의의 값을 넣지 않습니다. 이 설정은 실제 배열 길이나 할당 크기를 바꾸지 않습니다. 세부 경계와 한도는 [서랍 표시 영역](drawer-windows.md)을 따릅니다.

## 설계도와 실행 공간 — 설계 확정·미구현

- 실행 준비에서 함수 설계도를 미리 등록하되 기본은 접힌 목록입니다. 펼치면 매개변수·반환형·내부 선언 등을 확인합니다.
- 설계도는 정적인 정의이며, 펼쳤다고 런타임 상자·호출 프레임·실제 값이 생성되지 않습니다. 실제 함수 돗자리는 기록된 호출의 공간 생성 시점에 나타납니다.
- 하나의 함수 설계도를 여러 호출·재귀의 실행 돗자리가 공유합니다. 정의가 파일에 적힌 순서와 함수 본문의 실행 순서를 혼동하지 않게 합니다.
- 구조체 등의 자료형 정의도 저장소가 아닌 설계도입니다. 접힌 함수 설계도 목록과 작성 연출은 현재 구현된 호출 돗자리와 별개입니다.

## 오류의 표현 — 설계 확정·미구현

오류 처리의 대분류는 컴파일 오류·링크 오류·런타임 오류 세 가지입니다. 대상은 빌드를 실패시켜 실행을 시작할 수 없는 경우와, 실제 실행이 치명적인 오류로 강제 중단된 경우입니다. 이는 C의 표준 Exception 클래스 계층이 아니라 화면의 분류입니다. 경고·정상 실패 반환·논리 오류를 이 오류 연출 대상으로 넣지 않습니다.

| 단계 | 오류 연출의 진입 조건 | 표시 시점 |
| --- | --- | --- |
| 컴파일 | 컴파일러가 소스 분석·컴파일을 실패로 종료함 | 실행 전 즉시 안내. 설계도 작성·검사 설명을 추가할 수 있음 |
| 링크 | 정의 연결·실행 모듈의 사용자 정의 연결이 실패함 | 실행 전 즉시 안내. 설계도 참조 연결 설명을 추가할 수 있음 |
| 런타임 | 실행환경·계측기의 치명적 진단과 실제 실행 중단이 확인됨 | 확보한 실행 구간을 보여준 뒤 중단 지점에서 안내 |

진단의 문구나 비정상처럼 보이는 값만으로 분류하지 않습니다. 실제 단계·실패/중단 결과·진단 근거를 함께 사용합니다. 종료 코드가 0이 아니라는 사실만으로도 강제종료 오류를 확정하지 않습니다. 도구·API 자체의 실패와 기록 제한은 별도 운영 안내입니다.

### 컴파일 오류: 설계도 작성·검사

아래는 실제로 컴파일이 실패했을 때의 표현 분류입니다. 관련 코드 위치가 제공되면 강조하고 원인 메시지를 표시하며, 구조·관계를 확정할 수 있는 항목에는 설계도를 추가합니다. 경고만 발생하고 컴파일이 성공했다면 이 오류 연출을 실행하지 않습니다.

| 세부 문제 | 시각화할 내용 |
| --- | --- |
| 이름 중복·미선언·스코프 위반 | 같은 블록의 중복된 변수 이름표, 스코프 경계, 찾을 선언이 없는 자리 |
| 자료형 호환으로 컴파일 실패 | 구조체 값을 int에 넣는 등 거부된 사용에서 받는 쪽과 주는 쪽의 자료형 비교 |
| 대입·수정 권한 | const 변수 수정 등 거부된 사용에서 잠금과 저장 대상의 유무 표시 |
| 배열·초기화로 컴파일 실패 | `int a[-3]` 같은 음수 고정 크기 등 거부된 설계. 경고만 발생한 초과 초기값은 제외 |
| 구조체·공용체 | 존재하지 않는 멤버 접근 등 거부된 사용에서 멤버 설계도와 요청한 멤버 비교 |
| 포인터·간접 접근으로 컴파일 실패 | int 값의 역참조 등 거부된 사용에서 주소 요구와 실제 자료형 비교. 단순 호환성 경고는 제외 |
| 함수·반환 | 원형과 다른 인자 수 등 거부된 사용에서 인자 자리·자료형·반환구와 실제 사용 비교 |
| 배치 제약 | 허용 비트필드 폭·정렬과 요청한 배치 비교 |

| 메시지 중심으로 처리할 문제 | 기본 표시 |
| --- | --- |
| 전처리 | 헤더·매크로·조건부 지시문·명시적 #error의 위치와 원인 |
| 어휘 | 닫히지 않은 문자열·주석, 잘못된 리터럴 |
| 문법 | 세미콜론 누락·괄호 불일치·잘못된 문장 형태 |
| 선언 형식 | 양립하지 않는 자료형·저장 지정자 |
| 제어문 사용 위치 | continue/break/case의 잘못된 위치, goto 대상 누락 |
| 상수식·제약 조건 | 중복 case, 상수식 요구, 실패한 _Static_assert |

현재 번들 Clang에서 `int a[2]={1,2,3};`와 `double x; int *p=&x;`는 경고만으로 컴파일을 통과했습니다. 현재 설정에서는 오류 연출 대상에서 제외합니다. 다른 설정이 실제로 빌드를 거부한 경우에는 그 결과를 따릅니다. 경고 자체의 에디터 안내는 별도이며 오류 연출로 승격하지 않습니다. [실제 분류 확인](../validation/error-scope-review-2026-11-10.md)을 참고합니다.

컴파일러의 심각도와 위치를 보존합니다. 구조·대상 정보가 부족하면 코드 강조·메시지만 표시하고, 설명을 위해 불완전한 코드를 자체 해석하거나 실제 저장소를 생성하지 않습니다.

### 링크 오류: 설계도 참조 연결

실제 연결 단계가 실패해 프로그램을 시작할 수 없는 경우만 대상으로 합니다. 컴파일 단계에서 이미 거부된 선언·인자·자료형 문제를 이 단계로 옮기지 않습니다.

설계도 참조 연결로 시각화할 항목은 다음과 같습니다. 메시지도 함께 표시합니다.

| 문제 | 표현 |
| --- | --- |
| 선언한 함수의 정의 없음 | 호출 지점에서 연결할 함수 본문을 찾지 못함 |
| 외부 변수의 정의 없음 | 이름을 따라가지만 저장소 정의를 찾지 못함 |
| 시작 함수 main의 정의 없음 | 프로그램 시작 연결점에서 main 설계도를 찾지 못함 |
| 여러 오브젝트·라이브러리의 정의 중복 | 실제로 복수 입력을 연결하다 거부된 경우에만 같은 이름의 정의 충돌 표시 |

다음은 원인 메시지를 기본으로 하고, 직접 관련된 코드 위치가 있으면 함께 강조합니다.

| 문제 | 메시지 중심 처리 이유 |
| --- | --- |
| 필요한 라이브러리·오브젝트 파일을 찾을 수 없어 링크 실패 | 파일·경로 안내가 핵심이며 별도의 공간 연출이 불필요함 |
| 오브젝트 형식·대상 아키텍처 불일치로 링크 실패 | 실행 형식과 대상의 진단을 표시하면 됨 |
| 지원하지 않는 연결 설정·재배치·실행파일 배치 제약으로 링크 실패 | 링커 진단을 보존하고 원인을 설명. 실행 중 공간 생성으로 연출하지 않음 |

현재 단일 C 파일 입력에서 확인한 주요 사례는 정의되지 않은 함수·외부 변수·main의 연결 실패입니다. 복수 오브젝트·외부 라이브러리 관련 항목을 현재 입력 경로의 지원 완료로 해석하지 않습니다. 두 표는 링커가 실제 실패한 경우의 표현 분류입니다.

이 선은 실행 중 포인터 참조선과 구별되는 설계도 참조선입니다. 같은 소스 안의 재정의 등 컴파일러가 이미 진단한 오류를 링크 오류로 바꾸지 않습니다. 컴파일·링크 실패 시 실제 C 실행 공간은 시작하지 않습니다.

### 런타임 오류

여기서 오류 연출 대상으로 다루는 것은 실행환경·계측기가 치명적인 오류로 보고하고 실제 프로그램 실행을 강제 중단한 경우입니다. 위험한 코드나 정의되지 않은 동작이라는 이유만으로 화면이 강제종료를 만들어내지 않습니다. signed 오버플로·잘못된 시프트·미초기화 값 사용 등도 실제 실행 중단이 확인되지 않으면 이 연출 대상으로 자동 분류하지 않습니다. 계측기의 치명적 검사가 실행을 중단한 경우에는 그 근거를 유지하고, 운영체제나 WASM이 자체 발생시킨 트랩과 구별합니다. 검출·중단 여부는 실행환경에 따라 달라질 수 있습니다.

런타임 문제는 현재까지의 실제 객체·값·수명과 실패한 접근 시도를 이용해 표시합니다. NULL 포인터 생성 자체나 malloc의 정상적인 실패 반환을 자동으로 잘못된 포인터 생성으로 취급하지 않습니다.

경고·확인된 오류·미관측 상태를 구별합니다. 사용자 코드의 명시적인 검사나 assert가 실제로 실패하여 중단 진단을 제공하면 해당 실행 진단으로 표시하며, 별도의 논리 오류 종류를 만들지 않습니다.

#### 자원·실행환경 문제

자원 부족이나 실행환경의 치명적 장애 때문에 실제 프로그램이 강제 중단된 경우만 대상으로 합니다.

| 대상 | 표시 |
| --- | --- |
| 스택 오버플로우로 확인된 중단 | 기존 호출 돗자리·관련 지역 저장 범위를 강조하고 원인 메시지 표시 |
| 메모리 소진 등이 원인으로 확인된 비정상 종료 | 확보한 장면을 유지하고 원인 메시지 표시. 메모리가 가득 차는 전용 연출은 만들지 않음 |
| 실행환경의 치명적 장애로 인한 중단 | 제공받은 진단을 표시. 위치가 없으면 코드 위치나 원인을 추정하지 않음 |

정상적인 실패 반환은 위 표의 대상이 아닙니다. malloc의 NULL, 파일 열기 실패, EOF, 실패를 알리는 errno만으로 강제종료 오류를 만들지 않습니다. 기존 호출·반환값·후속 처리를 그대로 보여줍니다. 이후 NULL 역참조 등으로 실제 중단됐다면 그 중단된 작업의 분류로 다룹니다.

실행 도구·API의 장애, 기록 한도·시간 제한, 사용자의 중지는 사용자 C의 강제종료 오류와 별도 안내로 구분합니다. 원인이 확인되지 않은 worker 종료를 메모리 부족으로 단정하지 않습니다. 스택 깊이·사용량·한도도 실제 근거가 있는 범위에서만 표시합니다.

## 논리 오류의 관찰

논리 오류는 사용자가 실행 순서·값·자료구조 변화를 눈으로 보며 찾아내는 대상입니다. 이것은 시각화의 주요 목적이며, 오류 분류에서 제외한다고 관찰 기능을 제외하는 것은 아닙니다. 정답 판정·틀린 값 자동 표시·논리 오류 전용 ERROR나 애니메이션은 이번 오류 처리 범위에 포함하지 않습니다.

## 후속 표현

- 포인터 상자를 서랍처럼 열어 현재 연결된 값을 가까이 확인하는 표현
- 선택한 여러 상자의 바이트 크기 합계
- 포인터 거리의 원소 단위/바이트 단위 표시 선택
- 종료된 함수 공간의 선택적인 점선 흔적
- 자료구조별 세부 속성·전용 연출과 임의 관계 편집 UI. 기본 모양·추천/수동 표현 선택은 [초기 연결](structure-visualization.md) 범위에서 구현

이 항목은 구현 완료가 아닙니다. 자동 추론·표현 선택 API는 [자료구조 표현 정책](structure-presentation-policy.md)의 별도 책임이며 이 문서 정리를 위해 수정하지 않습니다. 실제 값·참조를 추천 모양에 맞춰 고치지 않습니다.
