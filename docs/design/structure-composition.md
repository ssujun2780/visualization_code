# 기본 관계와 조건의 조합

2026-11-11. 이번 문서의 RC 조항은 승인된 구현 계약입니다. 전체 자료구조 자동 판별이 구현됐다는 의미는 아닙니다.

## RC-01 저장 사실, 관계, 조건의 분리

1. 생성 모델이 확보한 객체·자료형·값·참조·수명은 원본 사실입니다.
2. 추론의 기본 관계는 저장소에 대응하는 논리적 구성원과 연결 역할입니다.
3. 자료구조 조건은 그 관계와 확인한 속성에 적용하는 별도 검사입니다.

조건을 만족했다고 작성 의도를 확정하지 않습니다. 한 관계에 여러 조건을 적용할 수 있고, 한 저장 객체가 여러 논리적 관계에 참여할 수 있습니다. 현재 코드가 만드는 구조를 보기 좋게 고치거나 누락 노드를 만들어 넣지 않습니다.

## RC-02 관계의 공통 표현

2026-11-12 후속: 힙·대표 관계·구간 집계·큐·배열 관리·연관 조회의 전용 상태는 `semantic-relations.mjs`로 같은 조회 API에 연결합니다. 상태에 없는 노드를 만들어 일반 트리처럼 보이게 하지 않습니다. 전용 조건은 현재 관측 상태를 소비하고, 조건 근거가 없는 표현은 `not-checkable`로 남깁니다. 트라이의 라벨·종료 조건도 현재 문자열 경로 상태를 사용합니다.

`structure-relations.mjs`가 포인터 연결(`linked-structure`), 정수 인덱스 연결(`rooted-index-structure`), 확인된 부모 역방향·첫 자식/형제·개수 기반 보기(`pointer-tree-projection`)를 같은 표현으로 연결합니다.

공통 항목은 다음과 같습니다.

- `sourceStructureId`, `sourceKind`: 원래 저장 관계 후보.
- `roleIds`: 이 보기에 사용한 연결 역할. 부모 링크까지 포함한 원본 그래프와 자식 링크 보기는 별개입니다.
- `nodes`: 원래 식별자, 저장 범위, 논리 인덱스 및 분리 저장소 구성 정보.
- `edges`: 실제 근거가 있는 논리적 방향과 `storedEdgeIds`.
- `terminals`, `terminalNodeIds`: 종료 관계와 실제 종료 객체. 개념적인 NULL 잎을 메모리 객체로 생성하지 않습니다.
- `afterExecutionId`, `complete`, `roleComplete`, `historyGap`, `alive`: 근거 시점·불완전성·수명.

`queryStructureRelations(trace, {target, candidateId, roleIds, afterExecutionId})`로 조회합니다. 대상은 기존 객체/범위/구조 후보 선택을 사용합니다. 반환한 관계를 수정해도 원본 저장 관계는 바뀌지 않습니다.

AST에서 이미 확인한 배열 크기 등을 다시 추측하지 않습니다. 저장 방식 어댑터는 조건을 검사하지 않고, 조건 검사기는 포인터/분리 배열의 원래 문법을 해석하지 않습니다.

## RC-03 조건과 의존성

`structure-conditions.mjs`의 조건 정의는 필요한 조건(`requires`)과 순수 검사 함수로 구성됩니다. `evaluateStructureConditions`는 공통 선행 조건을 한 번만 검사하고 결과를 각각 유지합니다.

| 조건 | 조합과 의미 |
| --- | --- |
| `graph` | 현재 관계 관측 범위 |
| `dag` | 확인한 연결의 비순환성 |
| `forest` | 비순환·단일 부모. 여러 루트 허용 |
| `tree` | forest + 하나의 루트와 일치하는 구성원 관계 |
| `chain` | forest + 하나의 루트 + 최대 하나의 다음 연결. 비순환 사슬 조건이며 원형 리스트를 뜻하지 않음 |
| `binary-tree` | tree + 노드당 최대 두 자식 |
| `bst-order` | binary-tree + 관측 비교 역할과 모든 조상 경계의 키 순서 |
| `avl-balance` | binary-tree + 실제 좌우 높이 차이. 키 순서까지 주장하지 않음 |
| `avl` | bst-order + avl-balance |
| `red-black-rules` | binary-tree + 색 영역·검은 루트/종료·빨강 연속 금지·검은 높이 |
| `red-black` | bst-order + red-black-rules |

빈 구조의 위상 조건은 허용하지만, 키/색 역할 근거가 없으면 그 세부 조건은 미확인입니다. 레드-블랙 조건에 AVL의 높이 차이 조건을 넣지 않습니다. 선택적인 저장 높이 검사는 `storedHeightCheck`로 분리하며, 캐시가 틀려도 실제 균형 여부는 그대로 남깁니다. 캐시 위반은 별도 경고에 포함합니다.

현재 BST 생성 경로도 `projectStructureRelation`과 `checkBSTOrder`를 사용합니다. 기존 조상 경계·중복 허용·복합 키·큰 정수의 조건은 유지합니다. `ordered-tree-candidate.composition`과 각 상태의 `relation`은 조건이 어떤 원본 관계·역할·시점에 연결됐는지 기록합니다. 독립 검증기가 이 연결을 검사합니다.

## RC-04 속성의 근거와 명시적 지정

수동 저장 역할은 `key`, `terminal`도 허용합니다. `key`는 실제 범위의 키를 부모 우선순위 검사에 연결할 수 있습니다. 역할 지정 자체는 BST의 왼쪽/오른쪽 비교 계약이나 임의 사용자 규칙을 생성하지 않습니다. `terminal`은 트라이의 종료 역할을 명시하며 해당 범위의 관측된 값을 요구합니다. 바이트가 없으면 자동 종료 역할로 대체하지 않고 불완전으로 남깁니다.

BST 키·비교 방향은 기존 실행 근거 추론을 사용합니다. 색과 저장 높이는 명시적으로 지정할 수 있습니다. 2026-11-12의 [EXT-03](structure-extensions.md)에서는 실제 연산을 근거로 높이·rank·크기·색 후보를 추가합니다. 높이는 역할이 하나로 확인되면 자동 연결하지만 명시적 지정이 우선합니다. 색 후보의 빨강/검정 의미는 여전히 명시적으로 지정해야 합니다. 필드 이름이나 두 가지 값의 존재만으로 색 역할을 생성하지 않습니다.

```js
queryStructureConditions(trace, {
  target, candidateId, afterExecutionId,
  expected: 'red-black',
  bindings: {
    color: {
      kind: 'record', offset: 0, size: 4,
      mask: '1', redValue: '1', blackValue: '0'
    }
  }
});
```

`offset`·`size`는 실제 필드 배치에 맞춰 지정합니다. 예시의 0/4가 고정 규칙은 아닙니다. 분리 배열은 `{kind:'array', arrayId, redValue, blackValue}`로 같은 논리 인덱스의 속성을 연결합니다. 숫자 인덱스가 같다는 이유로 자동 결합하는 기능이 아닙니다.

비트 필드는 `mask`와 선택적인 `shift`를 지원합니다. 표현값은 마스크/이동을 적용한 값 기준입니다. 정수 표현은 BigInt로 비교합니다. 높이 역할은 `height`에 같은 저장소 지정을 사용하고, `leafHeight:0|1`로 기준을 명시할 수 있습니다. 부호가 필요한 경우 `signed:true`를 지정합니다.

속성 값은 해당 시점까지 기록된 바이트로 복원합니다. 일부 바이트만 쓰거나 미초기화 상태이면 이전 정상값을 그대로 재사용하지 않습니다. 관측되지 않은 값, 수명이 끝난 저장소, 대응되지 않는 필드는 `null`입니다. C 표현식을 다시 실행하지 않습니다. 실제 NIL 객체의 색이 미관측이면 검정이라고 채우지 않습니다.

## RC-05 판정과 의도

검사별 `status`는 `satisfied-observed`, `violated`, `incomplete`, `not-checkable`, `ended`입니다. 공개 결과의 `assessment`는 위반을 `contradicted`로 표현합니다. 여러 대안의 결과가 다르면 종합 결과는 `ambiguous`이며 각 후보 결과와 경고는 유지합니다.

지원하지 않는 기대 조건도 이유가 있는 `not-checkable`을 반환합니다. 선행 조건이 불충분하면 `blockedBy`에 그 조건을 남깁니다. 부분 관계의 루트 개수만 보고 구조 위반으로 단정하지 않습니다. 실제 확인된 순환·공유 자식 등과 미관측 부분은 구분합니다.

회전·재색칠 도중 조건이 깨진 시점도 기록된 상태 그대로 검사합니다. 이를 자동으로 C 런타임 오류로 만들거나, 무조건 알고리즘 구현 오류 또는 정상 복구 중이라고 단정하지 않습니다. 알고리즘 작업의 시작/완료 경계 추론은 이번 범위가 아닙니다.

## RC-06 추천 및 사용자 지정

자동 추천의 조건 검사는 **선택한 후보 ID와 역할**에 고정합니다. 다른 키/구성원 해석 후보의 위반을 선택한 후보의 위반으로 섞지 않습니다. 수동 지정에 여러 관계 해석이 남으면 대안을 유지합니다. BST를 검사할 때 키 순서 근거가 있는 후보가 있으면, 키 역할 자체가 없는 부분 연결을 경쟁 BST 후보로 넣지 않습니다.

`setStructurePresentation`의 `conditionBindings`로 위 속성 연결을 저장할 수 있습니다. `resolveStructurePresentation`은 공통 조건 조회를 사용합니다. 사용자 지정이 자동 추천보다 우선하며, 지정한 종류가 조건을 만족한다고 보증하지 않습니다. 일반 `tree` 지정에는 BST·색·균형 조건을 상속하지 않습니다.

기본 상위 5개 추천 정책은 유지합니다. 색 역할이 확인되지 않은 상태에서 모양만 보고 AVL·레드-블랙 추천을 추가하지 않습니다. 화면·우클릭 메뉴는 구현하지 않았습니다.

## RC-07 실행 기록과 시간 경계

중간언어 생성 모델은 변경하지 않습니다. 관계/조건 조회는 별도 추론 결과를 읽고, SPACE·READ·CALC·WRITE·FLOW 및 값·참조·수명을 수정하지 않습니다. 미래 근거로 이전 시점의 역할을 확정하지 않으며, 이력 한도 뒤의 오래된 성공 판정을 현재 결과로 재사용하지 않습니다.

2026-11-12: 상태형 후보의 제한된 이력은 `state-history.mjs`를 공유합니다. 앞부분과 최신 상태를 보관하고, 덮어쓴 최초 상태의 사건을 `coverage.historyGapFromExecutionId`, 생략 수를 `omittedStates`로 기록합니다. 생략 구간은 **최초 생략 사건 이상, 최신 보관 상태 사건 미만**입니다. 보관된 앞부분과 실제로 다시 관측한 최신 상태에 생략 표시를 소급하지 않습니다. `firstStateExecutionId`로 최초 관측을 보존하며 한도 1에서도 후보의 발견 시점을 최신 시점으로 바꾸지 않습니다.

그 구간의 조회는 `historyGap:true`이며, 이전 보관 상태가 있으면 원래 `afterExecutionId`를 유지한 채 `status:'incomplete'`로 반환합니다. 그 내용은 이전 참고 상태이지 현재 값의 확정이 아닙니다. 한도가 1이라 이전 상태도 없으면 `state:null, historyGap:true`입니다. 발견 전 조회는 기존처럼 null입니다. 공통 관계·조건 조회도 불완전성을 전달하고, 자동 추천은 이 상태를 사용하지 않습니다. 사용자 지정은 유지됩니다. 최신 보관 상태 자체에 다른 근거 누락이 있으면 그 불완전성은 그대로 유지합니다.

정확한 생략 구간이 없는 기존 결과의 보수적 처리는 유지합니다. 트리·인덱스/그래프·대표 관계·구간·우선순위·공유·지연 갱신의 제한된 생성기를 이관했고, 나머지 상태형 어댑터에도 공통 출력 보관 한도를 적용합니다. 상태를 읽는 공통 조회는 객체 수명을 확인하며, 보관 상태 뒤에 구성원 수명이 끝났으면 현재 정상 상태로 재사용하지 않습니다.

표시 상태의 보관 한도는 후속 판정의 입력을 미리 잘라내는 옵션이 아닙니다. 판정 후 보관할 상태를 줄입니다. 판정 검증에 필요한 과거 구간 체크포인트는 별도 `proofStates`에 두며, 이 정보로 생략된 현재 상태를 채우지 않습니다. 근거 노드도 별도 한도를 검사하고, 확보하지 못한 근거에 의존하는 후보는 한도 진단과 함께 제외합니다. 실제 출처 사건으로 직접 검사할 수 있는 값·자식 관계는 과거 표시 상태에 의존하지 않습니다.

조회 결과의 `historyGap`, `lifetimeGap`, `evidenceGap`과 추론 결과의 `structure-inference-limit` 진단은 C 실행 오류가 아닙니다. 불완전한 현재 상태는 자동 추천의 정상 근거로 쓰지 않으며, 사용자 지정은 유지합니다. [공통 한도·통합 검증](../validation/inference-limits-integration-2026-11-12.md)을 참고하십시오.

분리 배열의 공동 인덱스 관계는 같은 출처의 실제 접근 중 두 저장소 이상과 READ를 처음 함께 입증한 시점부터 제공합니다. 이후 반복 접근은 발견 시점을 늦추지 않습니다. 나중에 추가된 저장소는 그때부터 더 큰 관계 후보에 포함하며, 이전 후보에 소급해서 넣지 않습니다. 여러 자식 역할의 결합도 같은 순회 함수가 실제 사용한 역할의 접두 집합별로 기록하고, 여러 함수가 같은 조합을 입증하면 가장 이른 완성 근거를 사용합니다.

공유 종료 객체의 필드를 읽었다는 사실만으로 그 객체를 데이터 구성원으로 되돌리지 않습니다. 순회 커서가 당시 가리킨 객체 식별자와 원소 오프셋이 읽은 레코드와 일치하는지 확인합니다. 이웃 연결을 따라 읽은 관리 정보는 커서의 직접 방문과 구분합니다. 실제 커서 위치의 데이터 소비, 원형 리스트의 시작 원소, 종료 객체의 데이터를 반환하는 경우는 보존합니다. 물리 저장 그래프와 원래 READ는 삭제하지 않습니다.

## RC-08 확장 범위와 남은 작업

2026-11-12: [힙·대표 관계·구간 집계](priority-partition-range-inference.md)에 인덱스 힙 산식·사용 구간, 대표 확인과 병합, 집계 출처 구간과 Fenwick 이동의 조합을 추가했습니다. 공통 추론 API의 별도 후보이며 기존 조건 API 전체를 이관한 것은 아닙니다. 세부 지원 한계는 해당 문서에 명시합니다.

이번에 공통 관계에 연결한 대상은 위 세 저장 표현과 그래프·사슬·트리·BST·AVL/RB 조건입니다. 기존 배열 컨테이너·큐·힙 등의 전용 추론은 유지합니다. 앞서 정한 12계열 모두를 새 조건 API에 옮겼거나 모든 세부 종류를 자동 인식하도록 구현한 것은 아닙니다.

새 계열을 추가할 때는 저장 방식의 관계 어댑터, 속성의 관측 근거, 순수 조건 정의를 각각 추가합니다. 전체 IR 생성 경로에 예제 전용 분기를 넣지 않습니다. 스택/큐의 순서 조건, 해시/구간/소속 조건 등은 별도의 동작 근거와 검사기를 갖추어 확장합니다.

이전 AVL/RB 점검의 분리 배열 발견 시점 지연과 공유 종료 노드의 관리 정보 읽기 오인식은 2026-11-11에 공통 관계 추론에서 수정했습니다. [수정 검증 기록](../validation/relation-boundary-fixes-2026-11-11.md)에 최초 근거, 실제 구성원·간선, 종료 경계와 반례를 남겼습니다. 조건 검사기가 불완전한 관계를 임의로 완전한 트리로 보정하는 방식은 사용하지 않습니다. 추천과 검사 후보의 범위 불일치는 앞선 연결에서 수정했습니다.

검증과 실제 적용 범위는 [구현 검증 기록](../validation/relation-condition-composition-2026-11-11.md)에 있습니다.

트라이는 [문자열 경로 계약](sequence-lookup-inference.md)에 따라 관계 어댑터와 입력 소비·종료 표지 근거를 결합합니다. `sequence-conditions.mjs`는 저장 방식에 독립적으로 트리 모양, 간선 라벨의 접두어 충돌, 종료 역할을 검사합니다. 트리 모양만으로 트라이를 확정하지 않습니다.
