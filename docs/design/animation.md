# 애니메이션 설계

2026-11-13: 실행·분석과 표현 이력을 준비한 후 재생합니다. 자료구조와 연산은 기존 공간에서 같은 명령 시간선으로 보이며, 표현을 매 명령 다시 고르지 않습니다. [PS-01~04](prepared-scene.md)를 따릅니다.

2026-11-10. [문서 안내](presentation.md)의 애니메이션 담당 문서입니다. 공간·표현은 [시각화](visualization.md), 조작은 [UI](ui.md)를 따릅니다.

## 기본 원칙

[현재 작업 연결 보기](work-context-view.md)에도 같은 피연산자 도착·계산·WRITE 반영·전달선 강조 시간선을 투영합니다. 연결 보기를 위해 명령·사건을 추가하거나 원본 순서를 바꾸지 않습니다.

- 캐릭터 없이도 모든 값 변화와 실행 과정이 이해되어야 합니다. 캐릭터는 같은 작업에 부가되는 연출입니다.
- 중간언어 명령 하나에 대응하는 애니메이션을 만들고, 그 내부에서 전달·도착·계산 등의 사건을 나눕니다. 사건 때문에 명령을 추가·분할·재정렬하지 않습니다.
- 소스의 작업 경계와 실제 관찰 순서를 따릅니다. 한 순수 계산 묶음은 CALC 하나이며 하드웨어의 보조 명령을 독립 장면으로 펼치지 않습니다.
- 값·자료형·대상·선택 경로는 기록에서 얻습니다. 결과를 맞추기 위해 C 식을 JavaScript로 다시 평가하지 않습니다. 실제 평가 정책은 [모델 문서](evaluation-order.md)의 책임입니다.
- 명령어 클릭은 미리보기이고 실행이 아닙니다. 재생 상태는 명령어 경계에서 반영하며, 중간의 값 표시 시점은 공통 시간선에 맞춥니다.
- 자료구조 보기·작업 관계 분석은 같은 명령·사건 시계에 연결합니다. 그룹을 발견해도 원래 명령의 연출을 대체하지 않습니다. 살펴보기 때문에 자동 정지하지 않는 요구와 후속 설계는 [실행 관계 추론](execution-relations.md)의 R-01~R-07을 따릅니다. 추가 동기화 보기는 설계 초안입니다.

## 다섯 명령의 기본 연출

| 명령 | 기본 연출 |
| --- | --- |
| SPACE | 대상 상자·함수 돗자리의 현장 생성·정리 |
| READ | 실제 읽은 상자·원소·멤버와 범위를 강조 |
| CALC | 알루에 입력을 모아 식·부분 결과·최종 결과와 판정을 표시 |
| WRITE | 실제 출처에서 목적지로 전달하고 도착·반영 시점에 값을 갱신 |
| FLOW | 호출·반환·선택된 분기·반복 이동을 해당 코드와 공간에 연결 |

오류 표시는 기존 ERROR 정보에 연결합니다. 오류 세부 정보를 표현하기 위해 새 C 작업을 만들지 않습니다. 현재는 확보한 실행 구간을 재생하고 ERROR에서 메시지·코드 강조와 함께 정지합니다. 오류 종류별 별도 애니메이션은 후속 구현입니다.

## 값 전달과 사건별 속도 — 구현

명령어를 선택하면 전체 경로를 표시합니다. 재생 중에는 전체 경로를 유지하면서 한 사건씩 강조하고, 명령 끝에 함께 사라지게 합니다.

1. 출발점과 화살표 강조
2. 값 이동
3. 도착한 값 확인
4. 다음 입력에 같은 과정 적용
5. 모인 입력 확인 → 계산 → 결과 확인
6. 별도 저장 명령에서 결과 전달 → 도착 확인 → 목적지 숫자 갱신

도착한 입력은 알루에 남습니다. 계산의 입력 전달을 결과 WRITE나 FLOW에서 반복하지 않습니다. 상수에는 가상의 출발 상자·운반 명령을 만들지 않습니다.

사건이 늘면 명령어 시간도 늘리고, 기존 사건 시간을 압축하지 않습니다. 0.25×~10×는 명령 간 간격뿐 아니라 강조·이동·도착·계산·반영·정리까지 함께 조절합니다. 수동 한 명령어/한 줄 이동은 사건 연출을 기다리지 않고 원본 기록을 해당 경계까지 적용한 뒤 정지합니다. 정확한 시간과 준비·반영 경계는 [사건별 시간선](animation-incidents.md), 미리보기·재생·정지의 구분은 [전달 화살표](value-transfer-arrows.md)를 따릅니다.

## 함수·조건·메모리·입출력 — 구현

- 함수 돗자리가 펼쳐질 때 매개변수 자리도 함께 표시하고 실제 WRITE에서 값을 채웁니다. 지역변수는 해당 생성 명령 때 나타납니다.
- 호출 인자는 원래 READ·CALC·다른 반환값에서 매개변수로 전달합니다. 반환은 기록된 수신 작업으로 전달한 뒤 함수 공간을 정리합니다. 순서는 모델의 [반환 계약](return-sequence.md)이 정합니다.
- 조건은 참/거짓을 초록/빨강과 문자로 함께 표시합니다. switch는 선택된 case/default를 표시합니다. 단락 평가로 생략한 식은 회색·미실행 안내로 표시하며 결과나 부수효과를 만들지 않습니다.
- `FLOW/assert.check`는 기록된 검증 결과를 통과/실패로 표시합니다. 앞선 CALC의 입력 전달·조건 계산을 반복하지 않으며, 실패 뒤의 호출·출력·종료도 실제 기록을 따릅니다. 검증 사건 자체를 삭제하거나 별도 ERROR를 만들어 넣지 않습니다. [지원 누락 수정·검증](../validation/assert-playback-2026-11-13.md).
- 생성·복사·채우기·재할당·해제는 기록된 저장소와 범위에만 적용합니다. free 뒤 포인터의 자동 NULL 대입이나 미관측 꼬리 값은 만들지 않습니다.
- 입력이 필요하면 현재 구간 재생 끝에서 입력 돗자리를 강조하고 정지합니다. 사용자가 전송하면 같은 실행이 이어집니다. 출력은 관찰된 채널·바이트의 전달에 맞추어 표시합니다. [입력 세션](interactive-input.md), [메모리·입출력 검증](../validation/memory-io.md)을 참고합니다.

## 도구·캐릭터·간결 표시

구현된 비캐릭터 연출에서는 계산할 때 작업대에 알루가 나타나고 결과가 소비될 때까지 유지됩니다. 공간 생성·정리는 현장 효과이며 상수 공급기·값 전달기를 경유하는 독립 단계를 추가하지 않습니다.

2026-11-12: 알루 작업대는 계산 준비 경계에서 현재 입력 데이터 가까이 자동 이동합니다. 동일 CALC의 결과 WRITE·완료 분기에서는 위치를 유지합니다. 이동을 새 명령이나 추가 메모리 읽기로 만들지 않고 기존 값 전달 시간선을 유지합니다. 이번 구현은 위치 변경이며 캐릭터의 운반·걷기와 별도 이동 경로 애니메이션은 포함하지 않습니다. [연산 도구 배치](moving-tools.md)의 현재 상태·충돌 회피·수동 고정을 따릅니다.

캐릭터가 도구를 꺼내고 이동·달리기·순간이동하는 연출은 후속 검토입니다. 계산 외의 전달·생성 도구와 포인터 서랍 연출도 현재 비캐릭터 기능의 구현 완료로 간주하지 않습니다.

기본 기록과 설명은 상세 모드입니다. 간결 모드는 부차적인 이동·대기·설명을 줄일 수 있지만 값 변화·수명·출처·오류·실제 실행 경계를 삭제하지 않습니다. 상세/간결 전환 UI는 후속 구현입니다.

## 오류 정지 — 임시 구현 / 설계도 연출 — 미구현

2026-11-11: 컴파일·링크 실패는 실행 전에 즉시 알립니다. 런타임 오류는 이미 실행을 비정상 중단시킨 ERROR에 도달했을 때 재생을 멈춥니다. 이전 장면과 출력은 유지하고, 기록된 문제 위치를 원본 코드에 강조합니다. 실패·미완료 명령은 정상 결과나 저장 효과를 만들지 않습니다. 기록에 위치가 없는 트랩은 위치 미상으로 안내합니다. 시점 이동·처음부터 재생은 가능하며 오류 뒤 작업은 진행하지 않습니다. 중간언어 생성 모델·추론기는 변경하지 않습니다.

- 컴파일은 설계도를 작성·검사하는 과정, 링크는 설계도의 참조를 실제 정의에 연결하는 과정으로 표현합니다.
- 컴파일·링크 실패 알림은 결과를 받으면 즉시 표시합니다. 설명 연출을 재생하면 진단에 연결된 설계도에서 문제를 보여줍니다. 앞부분의 C가 실제로 실행된 것처럼 값 계산·호출·출력·할당을 만들지 않습니다.
- 실제 빌드가 성공한 경고에는 위 오류 연출을 적용하지 않습니다. 진단 이름만으로 오류 여부를 정하지 않고 컴파일·링크의 실제 실패 결과를 확인합니다.
- 런타임 오류 연출은 실제 프로그램 실행이 치명적인 오류로 강제 중단된 경우만 대상으로 합니다. 확보한 실행 구간을 보여준 뒤 문제 코드·대상·접근 시도를 강조하고 오류 상태에서 멈추는 것을 목표로 합니다. 이미 전달된 ERROR와 중단 진단을 사용하며, 경고·위험한 연산·정의되지 않은 동작만으로 화면에서 오류나 강제종료를 만들지 않습니다.
- 자원·실행환경 오류는 실제 실행의 치명적 중단이 확인된 경우만 대상으로 합니다. 메시지가 기본이며 추가 시각화는 스택 오버플로우의 기존 호출 돗자리·관련 지역 저장 범위 강조로 한정합니다. 정상 실패 반환은 오류 연출 없이 기존 호출·반환·저장 흐름으로 보여줍니다. 이 오류 연출은 아직 구현하지 않았습니다.
- 설계도를 구성할 근거가 부족한 문법 오류는 코드 강조·메시지로 처리합니다. 시각화 대상 분류는 [시각화의 오류 표현](visualization.md#오류의-표현--설계-확정미구현)을 따릅니다.

## 대표 연출 확인 범위

2026-11-14 구조 변화의 공통 연출은 [ST-01~05](structure-transitions.md)의 속성·관계·위치 변경을 사용합니다. 원본 사건의 apply/hold 구간 안에서만 보간하며 실제 화면 검증 여부는 [대응표](../validation/structure-transitions.md)에 별도로 기록합니다.

① 변수·계산, ② 함수, ③ 조건·반복, ④ 포인터, ⑤ 배열·구조체, ⑥ 동적 메모리, ⑦ 입출력·라이브러리는 기초 예제와 공통 처리를 확인했습니다. 임의의 C 프로그램을 모두 지원한다는 의미는 아닙니다.

⑧ 상태·오류의 공통 연출을 마저 확인한 뒤, 8묶음을 함께 사용하는 코드로 동적 실행을 확인합니다. 구조 추론의 정확성과 캐릭터 연출의 완성은 별도 작업입니다. 제거된 상수 분기 등 모델에서 관찰하지 않은 사건을 재생기가 만들어 보충하지 않습니다.
