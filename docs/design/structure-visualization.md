# 자료구조 추론과 화면 연결

2026-11-13 최신: [PS-01~04](prepared-scene.md)에 따라 전체 실행·분석 뒤 표현·배치·관계 이력을 준비하고 기존 공간에서 연산과 함께 재생합니다. 아래 과거 별도 작업 패널·매 경계 비동기 조회의 비용/선택 설명은 대체되었습니다.

2026-11-13. **초기 구현**입니다. 모든 구현 방식의 정확한 인식이나 모든 자료구조의 전용 연출을 보장하지 않습니다. [표현 정책](structure-presentation-policy.md), [RC-01~02](structure-composition.md), [R-01~07](execution-relations.md)을 소비하는 화면 계약입니다.

## SV-01 입력과 책임

`inferStructures(plan, trace)`의 독립 결과에는 프로그램·실행 범위, 후보 `structures`, 저장소 `bindings`, 관측 범위와 진단이 있습니다. 원본 `plan/trace`와 합쳐 수정하지 않습니다. `createInferenceView`가 만드는 별도 조회 입력으로 `resolveStructurePresentation`과 `queryStructureRelations`를 호출합니다.

화면은 추천 표현, 원래 노드 식별자, 저장 바이트 범위, 실제 간선·역할·종료 관계, 관측 시점·수명·불완전성을 받습니다. 저장소 참조 그래프는 별도의 기존 `queryStorageReferences` API도 사용합니다. 유일한 원본 구조체 내부의 필드 포트는 그 구조체 노드 안에 묶어 그리고 간선의 실제 ID를 유지합니다. 수동 전체 보기에서 읽기에 사용되지 않았던 저장된 포인터 역할을 지우지 않습니다. 자동 역할 부분 보기는 제외 역할 수를 알립니다.

노드 값은 추론 결과의 복사본에서 읽지 않고 **현재 재생 장면의 원본 메모리**에서 읽습니다. C 소스를 다시 분석하거나 실행하지 않습니다. 매개변수·관리 변수 카드에서 다른 저장소의 구조를 보여주면 구성 저장소 이름과 영역을 덧붙입니다.

이미 받은 `workAnalysis.structureInference`를 재사용합니다. 없는 기록은 전용 브라우저 Worker에서 한 번 분석합니다. 재생 준비 Worker의 제한은 180초이며 준비 완료 뒤 조작을 활성화합니다. 실패는 준비 오류로 안내합니다. 이는 추론 알고리즘의 성능 최적화가 아닙니다.

## SV-02 시점과 원본 대응

현재 명령의 반영 전에는 직전 사건까지, 반영 후에는 해당 사건까지 조회합니다. 첫 사건 이전에는 구조·추천을 만들어내지 않습니다. 이력 생략 구간은 이전 구조를 현재 상태로 표시하지 않습니다. 수명이 끝난 대상의 값을 되살리지 않습니다.

논리 노드·필드 클릭은 해당 객체·오프셋·크기를 원본 공간에 연결합니다. 함수/지역/전역/힙 정체성은 원본 공간에 남습니다. 표시는 같은 저장소의 다른 보기이며 새 객체·명령·복사를 생성하지 않습니다. 노드의 읽기/쓰기 강조는 기존 사건의 실제 범위를 사용합니다. 선택·지정으로 재생을 자동 정지하지 않습니다.

## SV-03 표현

2026-11-13 후속 구현: 아래 초기 모양은 [SS-01~04](structure-shapes.md)의 원형 큐/리스트, 원형 정점과 가중 간선, Union-Find 부모 트리, 속성 전달로 보완했습니다. 표의 초기 격자 묶음/박스 중심 모양은 구현 이력입니다.

| 입력 관계 | 초기 모양 |
| --- | --- |
| 배열·동적 배열 | 원래 인덱스의 칸, 용량과 논리 구성원 구별 |
| 컴파일러가 확인한 다차원 배열 | 스칼라 칸의 격자, 실제 좌표·바이트 범위 |
| 연결 리스트 | 실제 다음 연결 순서의 칸과 방향선 |
| 트리·이진 트리·BST·힙·트라이·구간 트리 | 루트와 실제 간선으로 계산한 층별 배치 |
| 그래프·DAG | 방향 간선과 노드, 같은 논리 식별자의 기존 위치 재사용 |
| 스택·큐·덱 | 관측된 활성 구성원의 세로/가로 배치, 확인된 front/back/용량 |
| 서로소 집합 | 확인된 대표별 묶음 |
| 해시 테이블 | 확인된 버킷별 항목. 버킷 대응이 없으면 미확인 안내와 키·값 항목 |

순환·공유·자기 참조를 트리에 맞추어 삭제하지 않습니다. NULL은 실제 종료 관계의 표시이며 가상 메모리 객체가 아닙니다. 부분 관계와 부족한 조건 근거는 경고로 구별합니다. 배열 전체 중 일부 저장소만 대응하면 그 오프셋·크기를 표시합니다. 직접 계산해 자료구조를 완성하거나 키 순서를 보정하지 않습니다.

AVL/레드-블랙은 전달된 높이·색 역할을 표시합니다. 2026-11-14부터 실제 연결 변화의 시점별 배치와 기존 사건 구간 내 이동·색 보간은 [ST-01~05](structure-transitions.md)를 사용합니다. 회전/분할/병합의 의미 인식·원인 설명과 임의 역할 편집 UI는 미구현입니다. 3차원 이상 격자는 좌표를 보존하는 평면 나열이며 전용 입체 보기가 아닙니다.

## SV-04 선택과 비용

현재 UI에서는 원본 저장소를 선택한 뒤 자동·원래 상자·자료구조별 모양으로 전환하고 그래프 방향을 지정합니다. 선택은 같은 실행에서 유지합니다. API의 모든 역할 편집을 옮긴 것은 아닙니다. 원본 공간에서 직접 노드·멤버를 선택하며 같은 칸/저장 범위에 대응한 표현 연결점을 연산의 출발지·목적지로 사용합니다.

원소·멤버는 기존 공간의 같은 저장소 안에서 접고 펼칩니다. 도구와 저장소의 직접 조작을 유지합니다. 임의 관계의 역할 편집, 여러 저장소를 합쳐 지정, 파일 저장·재실행 재연결 UI는 후속입니다. API 지원과 화면 구현을 구별합니다.

재생 전 조회로 관계 이력을 준비하며 사건 내부 프레임에는 이력을 읽습니다. 현재 한도는 준비 조회 256노드·저장소 내부 기본 표시 128부분이며 생략을 알립니다. 큰 구조는 기존 무한 공간의 확대·축소·서랍 크기 조절을 사용합니다. 모든 규모의 최적 부분 선택·가독성은 보장하지 않습니다.

현재 검증과 남은 문제는 [통합 재생 대응표](../validation/unified-playback.md), [별도 문제 기록](../../test-results/unified-playback/problems.md)을 따릅니다. [과거 별도 패널 검증](../validation/structure-visualization.md)은 구현 이력입니다.
