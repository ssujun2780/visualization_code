# 실행·분석 후 같은 공간에서 재생

2026-11-13 사용자 승인에 따른 현재 화면 계약입니다. 과거 작업 보기의 별도 패널·명령 경계별 비동기 조회 방식은 이 문서로 대체합니다. 중간언어 생성과 추론 알고리즘은 변경하지 않습니다.

## PS-01 준비 완료 후 재생

기본 흐름은 입력을 미리 받기 → 기존 실행기로 실행 기록 완성 → 기존 추론 결과 확보 → 표현·관계 이력·배치 준비 → 재생입니다. 준비 중에는 재생을 활성화하지 않습니다. 완성된 `workAnalysis.structureInference`가 있으면 재사용하고 없으면 준비 Worker에서 기존 공개 추론기를 호출합니다. 브라우저의 표현 준비 제한은 180초이며 실패는 준비 오류로 알립니다.

2026-11-13: 실행 기록의 정상 종료와 재생 준비 완료는 별도 검증 항목입니다. 기록 크기 한도를 통과해도 준비 Worker가 `ready`를 반환하지 않으면 재생 준비 성공으로 보고하지 않습니다. [No43 준비 시간 검증](../validation/no43-preparation-fix-2026-11-13.md)을 참고합니다.

입력 방식의 기본값은 **미리 입력하고 전체 실행**입니다. UTF-8 16KiB 이내의 표준 입력과 EOF를 같은 실행에 전달합니다. 선택 가능한 **실행 중 입력**은 입력 대기까지 확보한 기록을 먼저 준비하고, 입력 후 같은 실행의 다음 기록 구간을 준비합니다. 입력 때문에 앞부분을 다른 값으로 재실행하지 않습니다.

## PS-02 고정 표현과 현재 사실 분리

전체 기록은 표현 종류와 물리 슬롯의 자리를 선택하는 데 사용합니다. 조회 API의 분류 규칙은 그대로 두고 선택 결과를 준비 어댑터가 고정합니다. 배열·레코드·힙 저장소마다 관계가 바뀐 사건 경계의 결과를 미리 보관합니다. 포인터 기반 계층의 노드 좌표는 그 시점의 실제 연결을 사용한 이력을 준비하고, 색 변경만으로 재배치하지 않습니다. [구조 변화 표시](structure-transitions.md)의 ST-01~05를 따릅니다. 재생은 이 이력을 이진 탐색하며 프레임마다 추론·추천·관계 조회를 실행하지 않습니다.

고정 대상은 이름뿐 아니라 원형 여부·방향·용량/차원에 따른 슬롯 자리와 도형입니다. 초기·빈 상태·관계 미확정·이력 생략을 이유로 원래 상자 표현으로 되돌리거나 다른 종류를 선택하지 않습니다. 같은 모양을 유지하고 확인되지 않은 연결·속성은 표시하지 않습니다. 자동 표현 변경은 새 실행의 준비 또는 사용자의 명시적 보기 변경 때만 허용합니다. 과거 저장 기록도 열 때 한 번 표현을 준비하며 원본 기록을 수정하지 않습니다.

미래에 쓰일 배치 자리가 있다는 이유로 아직 할당되지 않은 객체를 그리지 않습니다. 값은 해당 재생 시점의 원본 메모리, 간선은 해당 시점의 실제 관계에서 읽습니다. 기록 이력이 생략된 구간을 최종 간선으로 채우지 않습니다. 할당·해제·WRITE 도착 시점·생명주기·사건 ID와 순서를 보존합니다.

조회 소비자는 고정된 기록마다 `createStructureQueryTrace`로 별도 검색 세션을 만듭니다. 사건 위치·객체별 접근·루트 범위·현재 시점의 상태를 재사용하며, 저장 그래프의 델타는 앞 방향 조회에서 누적하고 뒤로 이동하면 다시 구성합니다. 새 실행이나 입력 후 늘어난 기록에는 새 세션을 생성합니다. 원본 기록과 분류 결과는 수정하지 않습니다.

전체 저장 참조 그래프를 선택했다면 해당 시점의 저장 그래프를 먼저 조회합니다. 이 결과로 대체될 다른 후보 관계를 미리 계산·복제하지 않습니다. 아직 그 대상의 저장 그래프가 없다면 기존 후보·사용자 지정 관계 조회 경로를 사용합니다. 후보 추천·역할 선택·경고·과거 시점의 관계는 그대로 유지합니다. [후속 최적화 검증](../validation/no43-preparation-optimization-2026-11-13.md)에 전체 준비 결과의 동일성과 시간을 기록합니다.

저장 그래프의 준비 경계는 대상 저장소에서 역사적으로 도달 가능한 저장소의 연결 변경·발견·종료 사건으로 좁힐 수 있습니다. 이 합집합은 **조회할 시점만 고르는 보수적인 색인**입니다. 실제 화면 관계는 각 시점의 공개 조회 결과이며, 미래 연결을 과거에 표시하지 않습니다. 나중에 이어지는 저장소와 연결 해제도 경계에 포함하고, 무관한 저장소의 변경 때문에 같은 그림을 다시 계산하지 않습니다.

## PS-03 기존 공간에 표시

자료구조는 별도 창의 복사본이 아닌 원래 객체의 표현입니다. 함수별 스택, 전역·정적, 힙 소속과 원본 객체·멤버·오프셋·크기·포트 ID를 유지합니다. 구조의 노드 상자는 원본 바이트 범위를 묶는 화면 컨테이너입니다. 내부 상자를 누르거나 접어도 실제 메모리를 바꾸지 않습니다.

노드와 원소의 자리를 미리 정하고 값·참조·강조만 실제 사건에 맞춰 바꿉니다. 이미 놓인 돗자리를 새 호출 때문에 다시 밀지 않습니다. 확장 컨테이너의 배선 장애물은 제목 부분과 실제 내부 칸으로 나누며, 전체 외곽을 막아 내부 포트를 가두지 않습니다. 노드 내부와 노드 사이에는 지속 포인터 배선의 여유 공간을 둡니다.

알루와 값 전달은 기존 명령 시간선을 그대로 사용합니다. 실제 참조 대상 가까이에 도구를 배치하고 화면 비율도 고려합니다. **작업 따라가기**는 관련 원소/작은 구조와 도구를 부드럽게 함께 보여줍니다. 수동 이동·확대·축소는 따라가기를 끄며 재생을 멈추지 않습니다. 자료구조 전용 창을 열어야 연산을 볼 수 있는 구조로 만들지 않습니다.

## PS-04 선택과 한계

선택 저장소는 자동·원래 상자·자료구조별 모양으로 전환할 수 있고 그래프 방향도 지정할 수 있습니다. 모양 지정만으로 빠진 연결/키/색 역할을 생성하지 않습니다. 기존 추론 API의 임의 역할 편집을 모두 UI에 옮긴 것은 아닙니다. 실제 포인터 선과 인덱스 관계 선을 구별하며, 원본에 없는 포인터를 만들지 않습니다. 세부 모양은 [SS-01~04](structure-shapes.md)를 따릅니다.

현재 관계 준비 조회는 최대 256노드, 저장소 내부 기본 표시에는 최대 128부분을 사용하고 생략을 알립니다. 거대한 구조에서 모든 글자를 동시에 읽을 수 있다고 보장하지 않습니다. 드래그·확대·서랍 조절을 유지합니다. 색 의미 편집 UI·회전 이동 보간·모든 자료구조의 세부 속성·여러 저장소를 합친 역할 편집은 후속입니다. 추론 실패를 화면에서 정답으로 보정하지 않습니다.

## PS-06 탐색 경로와 무관한 표시 이력 — 2026-11-13 구현

같은 실행 기록·표현 선택·접기/크기·사용자 고정 좌표·화면 크기에서는 정상 재생, 명령/행/반복 건너뛰기, 이전 이동과 슬라이더 탐색이 같은 시점의 객체·필드·도구 좌표와 지속 포인터 경로를 사용합니다. 카메라 이동/확대, 선택·호버는 별도의 보기 상태입니다.

`PresentationHistory`는 원본 사건 순서로 기존 표시 메모리·배치·도구 배치·증분 라우터를 한 번 진행합니다. 과거로 돌아가도 native 라우터를 그 과거 그래프로 되감지 않습니다. 통로 슬롯·차선·실패 시 주변 이동까지 그 시점의 이력을 읽습니다. 생성되지 않은 객체와 미래 참조를 표시하지 않습니다.

필요한 지점까지 Worker에서 준비하고 준비된 장면만 표시합니다. 앞부분이 아직 준비되지 않은 큰 이동에는 장면 복원 진행을 알립니다. 그 과정에서 C·추론을 다시 실행하거나 중간언어 명령을 추가하지 않습니다. 새 기록/표현 설정/접기·크기/화면 크기 변경은 새 기본 표시 이력을 만듭니다. 배치에 쓰는 화면 크기는 정수 픽셀로 정규화하여 소수 픽셀 측정 흔들림으로 이력을 다시 만들지 않습니다. 카메라 확대·이동은 이력을 무효화하지 않습니다.

수동 좌표 이동은 기본 이력을 초기화하지 않습니다. 객체/돗자리/도구의 고정 좌표를 별도 보기 설정으로 얹고, 요청한 사건 전후의 저장된 배치에서 기존 충돌 회피와 도구 양보 규칙만 적용합니다. 과거부터 현재까지 배치기를 다시 진행하지 않습니다. 포인터 경계 슬롯·끝점 슬롯·부분 경로도 변경 이력으로 보존하여, 변경되지 않은 영역은 native 라우터를 만들지 않고 경로를 그대로 사용합니다. 바뀐 영역은 저장된 예약을 복원하고 이동한 끝점/새 장애물에 막힌 선만 다시 탐색합니다. 복원용 장애물 등록은 선 탐색과 별도로 수행합니다.

수정 장면은 같은 원본 시점의 기본 배치·예약에서 파생하며 직전에 방문한 장면을 시작점으로 삼지 않습니다. 따라서 캐시가 제거되어도 같은 시점/수동 좌표의 결과가 탐색 순서와 무관합니다. 이동을 여러 번 하거나 준비 중 다시 이동해도 오래된 응답이 새 좌표를 덮지 않습니다. 드래그 중에는 즉시 미리보기를 유지하고 놓은 뒤 해당 시점의 국소 수정만 준비합니다. 충돌·새 호출 등으로 필요한 주변 조정은 기존 규칙을 따르며, 사용자가 지정하지 않은 위치를 전 시점에서 하나로 고정한다는 뜻은 아닙니다.

저장은 매 명령의 전체 장면 복사가 아닌 변경된 좌표·경로와 제한된 체크포인트입니다. 128개 표시 버전마다 최대 16개 체크포인트를 유지하며, 오래된 체크포인트가 없어도 원점과 변경 이력으로 복원합니다. 원본 상태 체크포인트와 별개입니다. 대규모 기록의 최악 시간/메모리 한도 보장은 별도 검증 항목입니다.

## PS-05 공유 저장소와 준비 이력 저장 (2026-11-13)

반환용 저장소와 이름 있는 지역 객체의 storageAlias는 서로 다른 이름·수명을 가진 같은 저장 범위입니다. 컴파일러가 기록한 별칭 사슬과 상대 offset으로 현재 관측 바이트를 공유하며, 숫자 주소의 일치로 별칭을 추측하지 않습니다. 지역 객체 종료는 호출자 저장소를 종료하지 않습니다. 이전 체크포인트는 변경하지 않습니다.

준비 결과의 공개 조회는 기존 시점별 객체 형식을 유지합니다. Worker와 파일 저장에는 prepared-shared-v1 참조 표를 사용하며 모든 시점의 값·관계·추천·근거를 손실 없이 복원합니다. 같은 내용은 한 번 보관하되 서로 다른 객체 ID·범위·사건은 합치지 않습니다. 이전의 펼쳐진 준비 파일도 계속 읽습니다.

준비 시 저장소별 가능한 도달 범위의 역사적 합집합으로 조회 대상을 좁힙니다. 합집합은 검색 범위일 뿐 현재 간선이 아닙니다. 실제 연결·역할·발견·종료는 요청한 사건의 기록으로 조회하며, 전체 그래프 선택은 전체 범위를 유지합니다. 컨테이너 범위 색인은 불변 조회 세션에 한정하고 실제 시점에 존재하는 컨테이너만 사용합니다. 사용하지 않는 위상 계산은 생략할 수 있지만 구조 기대 조건 검사는 생략하지 않습니다.

연속 준비 상태의 중복 판정은 큰 JSON 문자열을 매번 만들지 않고, 기존 JSON 비교와 같은 키 순서·배열 순서·누락 값 규칙으로 직접 비교합니다. 준비 이력의 시점과 결과는 동일해야 합니다. 루트별 파생 조회는 최대 64개만 보관하며 제거 후 재계산해도 결과는 같습니다.
