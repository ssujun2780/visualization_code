# 자료구조 표현·배치 검증

2026-11-03에 정한 검증 목표입니다. No20·No21의 과정 검증과 해당 보완까지 적용했습니다. No21~No34는 중간언어 과정과 함께, 입력 코드 및 해당 실행의 구조를 어떤 자료구조 보기로 표현하고 배치할지 검토하는 예제로 사용합니다. 이 문서가 자동 배치나 캐릭터 연출의 구현 완료를 뜻하지는 않습니다.

## 목표

실제 저장 방식과 화면의 논리 구조를 분리해 구성과 알고리즘의 동작을 알아볼 수 있게 합니다. 구조체·배열·여러 배열·인덱스 기반 저장 등에서 관찰한 관계를 근거로 표현과 공간 배치를 선택합니다. 노드의 값·주소·크기·수명과 실제 저장 위치의 대응을 유지합니다.

## 저장 방식과 논리 구조의 대응

논리 노드 하나는 배열 원소 하나, 여러 배열의 같은 인덱스에 있는 값들의 묶음, 행이나 일부 범위 등에 대응할 수 있습니다. 표현 계층은 논리 노드·간선과 실제 objectId·바이트 범위·원소 인덱스의 대응을 관리합니다. 그림 때문에 프로그램에 없는 할당·포인터·READ를 만들지 않습니다.

| 저장 방식 | 가능한 표현과 근거 |
| --- | --- |
| 구조체와 포인터 | 레코드와 실제 포인터 관계를 노드·간선으로 표현 |
| 배열 기반 힙 | 원소를 노드로, 코드의 부모·자식 인덱스 관계를 트리 간선으로 표현 |
| 여러 배열로 나눈 노드 정보 | 같은 인덱스의 값·링크 정보를 논리 노드 하나로 묶고 대응 범위를 유지 |
| 인덱스로 연결한 리스트·트리 | 정수 링크를 읽어 다음 원소·부모·자식에 접근하는 관계로 연결 유도 |
| 인접 행렬 | 행·열과 실제 간선 판정 코드·값으로 그래프 후보 구성 |
| 압축된 인접 정보 | 오프셋 구간과 이웃 인덱스 접근으로 그래프 후보 구성 |
| 비트 집합·격자 | 비트 연산·인덱스 계산·접근을 논리 원소와 관계에 대응 |

변수명이나 타입명만으로 역할을 부여하지 않습니다. 값이 다른 저장 위치의 인덱스로 소비되는지, 어떤 범위를 묶어 접근하는지, 삽입·탐색·연결 변경에서 그 관계가 유지되는지 확인합니다. 행렬의 0을 간선 없음으로 사용하는지도 실제 판정 코드에서 확인합니다. 역할이 모호하면 후보와 미확정 근거를 유지합니다.

배열의 물리 순서와 트리 표현을 함께 볼 수 있습니다. 논리 삭제·빈 슬롯·길이 감소와 실제 메모리 해제도 구분합니다. 재할당·복사로 실제 저장 객체가 바뀌면 관찰된 근거에 따라 대응을 갱신합니다.

## 검증 순서

1. 코드와 입력을 보고 예상 객체·연결·실행 변화 및 적절한 보기 후보를 먼저 기록합니다.
2. 실제 중간언어에서 객체 ID, 멤버 배치, 포인터 대상, 인덱스 관계, 접근·쓰기·호출·수명을 확인합니다.
3. 어떤 관계를 근거로 구조를 추론할 수 있는지, 아직 확인할 수 없는 의미는 무엇인지 구분합니다.
4. 후보별 배치와 배열·상자 보기의 대응을 검토하고 필요한 관찰·연결 정보의 결손을 찾습니다.
5. 삽입·삭제·회전·경로 압축 등 실행 변화에서 연결과 표현이 어떻게 갱신돼야 하는지 확인합니다.

현재는 후보와 배치 기준, 중간언어에 필요한 근거를 검토합니다. 실제 그림·애니메이션이 없으면 시각적인 가독성이나 움직임을 검증했다고 기록하지 않습니다.

## 판단 근거

- AST·LLVM의 타입·멤버 접근·인덱스 식과 실제 관찰된 값·참조·변경을 우선 사용합니다. 코드 원문을 매 사건마다 다시 해석하지 않습니다.
- 변수·함수·구조체 이름, 예제 번호·제목·명세의 정답 분류를 추론 입력으로 사용하지 않습니다. 명세는 결과를 비교할 때만 참고합니다.
- 같은 타입의 객체들이 연결돼 있다는 사실부터 구조 후보를 만듭니다. 부모 포인터·자식 포인터·순회용 링크의 역할을 구분해야 하며, 모든 포인터를 한꺼번에 합친 그래프만으로 트리 여부를 확정하지 않습니다.
- 정수 배열의 부모 인덱스나 이웃 인덱스는 인덱스에서 유도한 간선으로, 실제 포인터는 관찰한 주소 참조로 구분합니다. 계산 의존관계도 별도 근거를 갖습니다.
- 트리 모양, 이진 탐색 트리의 순서 의미, Red-black의 색·균형 의미는 각각 필요한 증거를 확인합니다. 모양만으로 세부 알고리즘을 확정하지 않습니다.
- 실행 중 잠시 구조가 끊기거나 불변식이 깨지는 중간 쓰기도 실제 순서대로 남깁니다. 이전 후보와 근거를 유지하며 변화와 불확실성을 표시할 수 있어야 합니다.

## 보기와 배치

- 동일 객체 ID를 사용해 메모리 상자·구조체 필드 보기와 트리·그래프 등의 구조 보기를 연결합니다. 보기 전환 때문에 프로그램의 객체나 저장 공간을 추가하지 않습니다.
- 하나의 배열을 배열과 트리로 함께 보여주거나 버킷 배열과 연결 리스트를 동시에 보여줄 수 있습니다. 후보 선택은 전체 프로그램에 단일 유형을 강제하지 않습니다.
- 트리는 부모·자식 계층, 리스트는 논리적 순서, 격자는 행·열을 중심으로 배치합니다. 보조 링크와 배열의 실제 저장 순서도 확인할 수 있어야 합니다.
- 변경 시 기존 노드 위치와 사용자가 고정한 위치를 최대한 유지하고 영향을 받은 연결과 주변 배치를 우선 갱신합니다. 표현 후보가 바뀌는 것과 실제 객체가 이동·복사되는 것을 구별합니다.
- 구조체의 여러 필드·함수 프레임·공유 객체·서로 다른 자료구조를 함께 추적할 수 있게 합니다. 관계가 강한 객체의 근접 배치와 선의 가독성도 검토합니다.
- 확대·축소와 큰 데이터의 생략 표현에서도 객체 ID·원소 위치·선택한 연결을 유지합니다. 원소 전체를 한 번에 펼치는 것을 전제로 하지 않습니다.

## 현재 구현과의 관계

scripts/model/structure.mjs는 관찰한 참조 그래프의 순환·부모 수 등을 검사해 directed-graph, tree-or-forest, linked-chain-or-chains 후보를 제안합니다. 현재 이것만으로 링크 역할, 배열 기반 힙·숲, Red-black의 의미나 실제 배치를 모두 판단하지는 못합니다.

No21 보강으로 scripts/model/array-views.mjs가 일반 배열 범위와 필드 기반 동적 배열의 역할 후보·상태 대응을 기록합니다. 복사 목적지의 인덱스/stride 또는 타입이 있는 배열 인덱스 접근을, 사용량·용량 필드 비교와 연결합니다. 실제 쓰기·복사와 할당 범위로 후보를 검증하며 배수 성장이나 memcpy 사용을 필수 규칙으로 고정하지 않습니다. 이름만으로 역할을 결정하지 않으며 모호한 원소형은 후보로 유지합니다.

dynamic-array의 논리 ID·소유 객체는 유지하고, 사건별 상태와 backingHistory로 재할당 객체들을 연결합니다. 주소가 같아도 종료된 할당의 별칭을 새 할당으로 자동 갱신하지 않습니다. 미사용 범위와 중간 불일치·종료 상태를 보존합니다. 배열의 용량만큼 논리 셀·C 객체·READ를 생성하지 않습니다. 초기화용 컴파일러 템플릿은 사용자 구조 후보에서 제외하며, 실제 간선이 없는 레코드 집합만으로 트리·연결 리스트를 추천하지 않습니다.

AST의 인덱스 역할과 실제 WRITE가 연결되면 사용량·용량이 처음부터 불일치하더라도 동적 배열 후보를 보존합니다. 이 경우 검증된 정상 상태가 있다고 주장하지 않으며, latestValidState 없이 관찰된 범위·불일치 상태와 근거를 제공합니다. 단순히 비슷한 필드를 읽는 것만으로 동적 배열 후보를 확정하지 않습니다.

No24 보강으로 embedded-array-views.mjs는 컴파일러의 고정 배열 필드·원소형·용량을 기존 배열 보기의 objectId·offset·size와 연결합니다. array-structure는 같은 저장 범위를 사용하며 새 C 객체나 READ를 만들지 않습니다. 정수 인덱스의 선언·대입 의존관계와 실제 호출별 배열 접근·필드 변경에서 LIFO/FIFO 후보를 얻습니다. 임시 인덱스, 별도 문장의 길이 갱신, 상수 또는 단일 리터럴 대입에서 유래한 나머지 연산도 연결합니다. 나머지 연산의 관측은 circularAccess로 따로 기록하며, 이것만으로 FIFO를 확정하지 않습니다.

operationEvidence에는 실제 접근·갱신 사건과 지지/모순/부분 근거를 남깁니다. 지지하는 삽입·제거 관계가 관측된 뒤 잘못된 접근이 나타나도 역할 후보를 지우지 않습니다. states는 실제 length·head·수명, 갱신 중인 intermediate, 불일치 및 미확정 상태를 유지합니다. 중간 상태나 모순 이후의 논리 순서를 자동으로 복구하지 않습니다. 해석 가능한 상태의 logicalOrder는 논리 인덱스를 물리 인덱스로 대응하는 시작점·길이·나머지 범위이며, inactiveRanges는 비활성 저장 바이트를 가리킵니다. 길이 감소로 원래 배열 값을 지우지 않습니다.

현재 삽입·제거의 결합은 호출 활성화 하나에서 배열 접근 하나와 길이 갱신 하나가 관측되는 경우를 지원합니다. 여러 동작이 한 호출에 섞이거나 근거가 모호하면 물리 배열·접근·필드 상태와 부분 후보를 유지합니다. 이는 모든 스택·큐 구현을 자동 판별한다는 뜻이 아닙니다. tests/ir-array-roles.test.js는 전위/후위 갱신, 임시 변수와 별도 문장, 용량 3의 순환 순서, 비활성 범위, 부분 근거, 음수 길이 및 뒤늦은 모순 접근을 확인합니다.

No22·No23 보강으로 linked-views.mjs는 AST의 필드 정체성과 커서 대입의 재귀적 의존관계에서 후속 링크 후보를 얻습니다. 중간 변수와 삼항 선택을 거친 커서 갱신도 연결합니다. 실제 필드 READ와 참조를 확인하고, 반대 필드의 상호 참조에서 양방향 후보를, 커서와 기준 객체의 비교·실제 복귀에서 센티널·원형 후보를 추가합니다. 필드 이름, 예제 번호, 데이터 값, 특정 메모리 배치를 판정 규칙으로 사용하지 않습니다.

linked-structure는 root, roles, inversePairs, logicalNodes와 사건별 states를 기록합니다. 논리 노드는 objectId·offset·size로 실제 저장 범위에 대응합니다. states는 각 방향의 순서·종료 이유, 실제 간선과 마지막 WRITE, 살아 있는 구성원·분리된 구성원·종료된 구성원, 양쪽 연결의 일시적 불일치를 유지합니다. 연결을 자동으로 보정하지 않으며 후보를 유지한 채 현재의 순환·누락·종료 대상을 표시할 수 있습니다. 모든 포인터를 합쳐 만든 과거 그래프만으로 현재 리스트를 판단하지 않습니다.

구성원은 기준점에서 역할별 연결을 따라 실제로 도달한 노드입니다. 초기화 복합 리터럴이나 외부 별칭처럼 단순히 들어오는 참조만 가진 저장소는 associatedStorage로 구별합니다. 실제로 리스트에 연결된 복합 리터럴은 정상 구성원이 됩니다. 이후 분리된 노드의 참조가 다른 저장소를 가리키면 그 대상의 범위도 보존하되 membershipEvidence로 외부 대상임을 구별합니다. 아직 연결되지 않은 객체는 기존 메모리 상자에도 그대로 존재합니다.

array 보기에서는 관찰된 포인터의 targetOffset과 컴파일러 레코드 필드 범위로 하위 객체의 경계를 제한합니다. 예를 들어 노드 안의 포인터 칸 주소는 노드 전체를 포인터 배열로 만들지 않습니다. 실제 연속 heap 배열의 전체 범위는 유지하며, 부분 범위를 포함하는 같은 타입의 배열 보기가 이미 있으면 중복 후보를 늘리지 않습니다.

포인터 연결 역할은 레코드 범위와 실제 포인터 슬롯으로 추론합니다. 배열 인덱스 산식으로 구현한 트리는 index-relations.mjs의 별도 후보 경로를 사용합니다. 여러 배열의 임의 정수 인덱스로 연결한 일반 그래프까지 자동 추론하는 것은 아직 지원하지 않습니다. 자료구조를 구조체로 구현해야 한다는 제약은 없습니다. 역할 근거가 부족한 저장소는 기존 상자·참조 그래프와 미확정 근거를 유지합니다.

## 사용 길이와 인덱스 트리 보강 (2026-11-04)

내장 배열의 active-prefix 역할은 원소의 제거 순서와 별개입니다. 컴파일러의 필드·인덱스·경계 비교 관계와 실제 count 증감, 기존 끝 위치 쓰기·감소한 끝 위치 읽기를 함께 확인합니다. 여러 READ/WRITE와 포인터 교환 함수가 있어도 해당 저장소의 접근을 연결하며, 관련 함수 종료까지 intermediate 상태를 유지합니다. count 변화 자체가 저장 공간의 생성·해제를 뜻하지 않습니다. 모호한 역할이나 잘못된 끝 위치 접근·범위를 복구하지 않고 미확정·모순 상태로 남깁니다. 기존 LIFO/FIFO 역할 추론은 유지합니다.

index-relations.mjs는 AST의 선언 관계와 degree*x+offset, (x-offset)/degree 형태의 인덱스 산식 및 실제 CALC·배열 접근으로 index-tree 후보를 만듭니다. 구조체 필드뿐 아니라 일반 배열도 대상입니다. 같은 배열에 여러 base/degree 후보가 남으면 하나를 강제하지 않습니다. parent/child 양쪽의 실행 근거와 실제 비교를 별도로 기록하며, 비교 방향은 max/min 후보이지 작성 의도나 힙 정확성의 증명이 아닙니다.

index-tree는 기존 arrayId/objectId/범위/원소 크기를 재사용합니다. 포인터 간선을 만들지 않으며 descriptor로 부모·자식 관계를 표현합니다. 배열의 사용 길이가 확인되면 실제 prefix와 교집합을 활성 노드 범위로 삼습니다. 각 WRITE와 중간 상태에서 max/min 위반·unknown을 보존합니다. 길이 근거가 없으면 물리 범위 후보와 미확정 활성 범위를 남깁니다. 큰 배열은 제한된 관측 간선만 검사하고 생략한 간선을 정상으로 간주하지 않습니다. queryIndexRelations의 제한된 페이지 조회로 특정 시점의 실제 값과 인덱스 관계를 확인할 수 있습니다. 자동 배치·애니메이션은 아직 더미입니다.

중간언어 생성 모델은 SPACE·READ·CALC·WRITE·FLOW와 관찰 근거를 유지합니다. 자료구조 표현·배치에서는 이를 해석해 후보와 배치를 정하고, 필요한 정보가 부족하면 공통 관찰·연결을 보완합니다. 기존 모델을 예제별 그림 생성기로 갈아엎지 않습니다.

## 호출과 별칭을 통과한 연결 구조 루트 (2026-11-04)

루트 후보는 변수명이 아니라 AST 선언과 직접 호출 인자/매개변수의 연결로 찾습니다. 필드 이동이 없는 별칭 경로를 전이적으로 따라가고, 근거 경로를 structureBindings.linkRootOrigins에 보존합니다. 순회 필드를 지나간 포인터나 함수 반환의 의미를 같은 루트의 정적 별칭으로 추측하지 않습니다.

실행 시에는 실제 포인터 슬롯의 객체 ID·offset·수명으로 루트를 구분합니다. 비순회 매개변수도 후보이면 루트가 될 수 있으므로 배열 decay, 내부 원소 주소, 반환 포인터의 직접 전달을 처리합니다. 같은 할당 내부의 두 목록, 같은 함수의 여러 호출, 해제 후 다시 만든 객체가 합쳐지지 않아야 합니다. 서로 다른 루트가 같은 노드를 가리킬 때 노드 저장소를 복제하지 않습니다.

tests/ir-linked-root-aliases.test.js는 여러 단계 wrapper와 지역 별칭, 필드 순서 변경, 같은 할당의 분리된 목록, 호출별 수명, 반환별칭 미추측, 배열·직접 반환값 인자를 검사합니다. 실제 연결과 상태를 근거로 한 후보이며 임의 코드의 자료구조 의미를 완전히 판정한다는 뜻은 아닙니다.

## 배열 작업 관계 보강 (2026-11-04)

scripts/model/array-work.mjs는 기존 배열 위에 `array-work` 관계를 추가합니다. `arrays`는 기존 배열 ID·objectId·바이트 범위를 재사용합니다. `accesses`는 실제 읽기·쓰기·복사 원본 범위, 원소 인덱스, 원소 안의 바이트 위치와 주소 계산에 사용된 커서 READ를 연결합니다. 복사의 원본 범위 표시는 이미 관측된 copy 사건을 가리키며 별도 READ를 생성하지 않습니다.

`transfers`는 관측된 copy 범위 또는 WRITE의 LLVM 데이터 입력과 실제 READ 범위를 연결합니다. 구조체 전체 복사와 필드별 쓰기를 구별하며 같은 값을 다시 쓰는 사건도 유지합니다. `temporaries`는 배열 값이 별도 지역 저장소로 복사된 사건과 수명을 기록합니다. 비교에서 사용된 임시값은 `copied-comparison-operand`로 연결하고 `isReference: false`로 명시합니다. 원본 배열 값이 바뀌어도 복사값을 원본에 대한 참조처럼 갱신하지 않습니다. 복사 목적 범위가 다시 쓰이면 `invalidatedBy`로 이전 관계의 종료 근거를 남깁니다.

`comparisons`는 CALC 내부의 실제 비교 단계와 양쪽 피연산자 READ를 연결합니다. 비교 연산자와 복사·배열 피연산자의 역할만 기록하며 변수명으로 피벗·키를 정하거나 정렬 알고리즘을 확정하지 않습니다. 포인터로 받은 배열 원소를 별도 비교·교환 함수에서 접근해도 관측된 대상 범위를 같은 배열에 연결합니다. 인덱스 AST 근거가 없는 역참조는 부분 근거로 남깁니다.

`activations`는 호출 활성화별 배열 참여, 구간 후보, 전달 사건의 순서를 유지합니다. 구간은 AST의 커서 초기값·인덱스·경계 비교 및 직접 호출의 매개변수 대응에서 얻고, 해당 활성화에서 관측된 선언 값으로 범위를 구성합니다. 인자 위치 자체로 하한·상한을 정하지 않습니다. 단순 선언값과 상수 오프셋의 범위 관계만 지원하며 임의의 C 식을 재실행하지 않습니다. 인접한 구간의 결합과 재귀 래퍼로 전달된 관계를 기록하므로 원본 배열 두 입력 구간·목적 배열 구간·되돌려 쓰는 전달 순서를 같은 저장소 위에 표시할 수 있습니다. `transferRuns` 안에서도 실제 필드 쓰기 사건은 합쳐지지 않습니다.

구간의 `supported`는 컴파일러 관계와 관측된 경계값이 저장 범위에 대응한다는 뜻입니다. 모든 원소를 접근했다거나 해당 정적 호출이 실행됐다는 뜻은 아닙니다. `executedForwarding`, 실제 접근 ID, 경계 상태를 함께 확인합니다. 관측 도중 바뀌거나 없는 경계는 `partial`, 관련 실제 접근이 후보 범위를 벗어나면 `contradicted`로 남깁니다. 재귀 종료 경로에서 실행되지 않은 내부 구간을 잘못된 프로그램 접근으로 처리하지 않습니다. 호출별 구간 때문에 새 배열 저장소를 만들지 않습니다.

선언 자료형이 단일 record임이 확인된 객체는 같은 전체 범위를 원소 1개 배열로 중복 제안하지 않습니다. 실제 배열 선언·heap 배열·레코드 내부 배열의 범위는 유지합니다. tests/ir-array-work.test.js는 이름·필드 배치·인자 순서를 바꾼 레코드 복사와 두 배열의 재귀 전달, 값 복사 비교 기준, 같은 값 교환, 빈 호출 구간, 변하거나 없는 경계와 모순 접근을 검증합니다. 이는 메타데이터 검증이며 실제 배치·애니메이션 가독성을 검증한 것은 아닙니다.
