# UI 설계

2026-11-13 최신: [PS-01~04](prepared-scene.md)에 따라 실행 전 입력과 전체 준비를 기본값으로 합니다. 자료구조는 기존 실행 공간 안에 표시하며 별도 작업 패널은 사용하지 않습니다. 선택 저장소의 자료구조별 모양·그래프 방향과 작업 따라가기를 제공합니다([SS-03](structure-shapes.md)). 아래 과거 작업 보기의 카드·근거 패널 설명은 현재 기본 UI의 기능이 아닙니다.

2026-11-10. [문서 안내](presentation.md)의 조작·상태 안내 담당 문서입니다. 동작 연출은 [애니메이션](animation.md), 공간과 설계도는 [시각화](visualization.md)를 따릅니다.

## 화면과 조작 — 구현

현재 비캐릭터 시제품은 `animation.html`입니다. HTML/CSS로 조작부·코드·중간언어 목록을, Canvas로 실행 공간을 구성합니다. 기존 코드 편집 화면 전체와 모든 실행 제어가 통합 완료된 상태는 아닙니다.

- 실행 공간 옆에서 원본 코드와 중간언어 과정을 함께 확인하고 현재 명령의 행·부분 범위를 강조합니다.
- 재생·일시정지·처음으로·이전 명령어·한 명령어·한 줄·시점 슬라이더를 제공합니다. ‘한 명령어’·‘한 줄’은 해당 경계로 즉시 이동하고 자동 재생을 정지합니다. 한 줄은 같은 소스 행·호출 안의 연속 기록이며 함수 진입/복귀를 넘어 한꺼번에 건너뛰지 않습니다. 선택한 위치의 기록 상태를 복원하며 실제 C를 역방향으로 실행하지 않습니다.
- for·while·do-while은 반복별로 묶어 1번째·2번째…로 표시합니다. 펼치기는 재생을 유지하며, 행에서는 한 반복을, 하단에서는 1·5·10·50·100회·남은 전체를 건너뜁니다. 현재 진행 중인 반복을 포함하고, 남은 횟수 이상이면 해당 반복문 종료 지점까지만 이동합니다. [반복 탐색 계약](loop-navigation.md)의 호출별 구분·입력/오류 경계를 따릅니다.
- 중간언어 행을 선택하면 전체 값 전달 경로를 미리 봅니다. 재생 도중 일시정지는 사건의 진행 위치를 유지합니다.
- 속도는 0.25×~10×, 0.25× 간격의 슬라이더입니다. 기본 1×와 사건별 시간은 [시간선](animation-incidents.md)을 따릅니다.
- Space는 재생·일시정지입니다. 길게 눌러 반복 전환하지 않으며 코드·입력란·선택/체크 컨트롤·IME 조합 중에는 기존 키 동작을 유지합니다. 단축키로 작업 따라가기를 끄지 않습니다.
- 전체 보기·현재 작업·확대·축소·배치 초기화를 제공합니다. 카메라와 수동 배치는 실행 상태에서 분리합니다.
- 전체 출력과 stdout/stderr 선택은 실행 공간의 출력 필드 안에 둡니다. 내부 스크롤로 앞선 출력도 확인하고, 끝에서 보고 있을 때만 새 출력 끝을 따라갑니다. 위로 스크롤해서 살펴보는 동안에는 재생을 멈추거나 위치를 끝으로 당기지 않습니다. 시점·스트림 변경 시에는 해당 내용의 처음을 보여줍니다. 입력·출력 필드 안에서도 Ctrl+휠 확대·축소가 가능합니다.
- 입력란의 안내와 타이핑 중인 글자, ‘아직 도착한 입력이 없습니다’ 같은 빈 상태 문구는 작은 글자로 표시합니다. 전송 후 ‘도착한 입력’에 표시하는 실제 값과 출력의 기존 큰 글자 크기는 유지합니다. 타이핑 시작에 따라 입력란의 글자 크기가 바뀌지 않습니다.
- 예제는 현재 모델을 사용해 실행합니다. 저장된 plan/trace 또는 묶음 JSON을 여는 기능은 해당 실행의 기록 재생입니다. 새 실행과 저장 기록 재생을 구별합니다.
- 자료구조와 연산은 원본 공간의 같은 칸·포트에 연결합니다. 준비된 관계 이력은 시점에 맞춰 선택하며 별도 카드 창을 재구성하지 않습니다. 조회 실패와 준비 실패를 C 런타임 오류로 바꾸지 않습니다.
- 실행 공간의 조작부·상태·조작법은 Canvas 밖에 둡니다. 상단 ‘보기’에서 실행 공간·코드/중간언어를 켜고 끕니다. ‘작업 따라가기’는 관련 데이터와 알루를 함께 보여주며 수동 카메라 조작은 따라가기를 끕니다. 재생은 유지합니다.

## 무한 공간의 직접 조작 — 구현

| 조작 | 동작 |
| --- | --- |
| 휠·트랙패드 | 화면 이동 |
| Shift+휠 | 가로 이동 |
| Ctrl/Cmd+휠, 확대·축소 버튼 | 확대·축소 |
| 빈 공간 드래그·가운데 버튼 | 카메라 이동 |
| 상자 내부 좌클릭 드래그 | 소속 객체 위치 이동. 배열·구조체 멤버를 잡으면 해당 저장소 전체 이동. 짧은 클릭의 멤버 선택과 실제 바이트 범위는 유지 |
| Space | 재생·일시정지 |
| 돗자리 제목 드래그 | 소속 상자와 함께 이동 |
| 알루 작업대 제목 드래그 | 자동 이동을 멈추고 수동 고정. 배치 초기화로 자동 이동 복원 |
| 컨테이너의 접기 표시·제목 더블클릭·선택 후 Enter | 배열·구조체 접기·펼치기 |
| 상자·선 클릭/호버 | 실제 포인터선으로 이어진 연결 성분 전체 강조 |
| 서랍 우하단 모서리 드래그 / 선택 후 Shift+방향키 | 서랍의 표시 폭·높이 조절. 실제 할당 크기는 유지 |
| Esc·빈 공간 클릭 | 선택 해제 |

정확한 선택 범위·중첩 접기·배선 대기·충돌 조정은 [포인터 배선 명세](pointer-wiring.md)를 따릅니다. 드래그·선택·접기 때문에 원래 값·참조·명령 순서를 변경하지 않습니다.

## 입력·출력 — 구현

입력 편집창은 출력처럼 실행 공간 안의 이동 가능한 돗자리에 둡니다. 편집할 내용과 실제 도착한 입력을 구분하고 카메라 이동·배율에 맞춰 배치합니다.

현재 관찰 구간의 입력 요청에 도달하면 입력 돗자리·창을 강조하고 재생을 멈춥니다. ‘입력 전송하고 계속’ 또는 Enter로 대기 중인 같은 실행에 입력을 전달하고, Shift+Enter는 입력창에 줄바꿈을 넣습니다. 기존 Ctrl/Cmd+Enter도 유지합니다. 실제 입력이 더 필요할 때 다시 대기하며, 이미 전달된 버퍼의 재읽기를 새 입력으로 요구하지 않습니다.

기본 ‘줄바꿈 추가’ 모드에서는 끝에 LF가 없을 때만 하나 붙여 전송합니다. 선택을 끄거나 EOF를 선택하면 작성한 내용을 그대로 전달합니다. 빈 줄 전송과 ‘입력 종료(EOF)’는 구분합니다. 전송 중에는 중복 제출을 막고, 성공 후 편집창을 비웁니다. 실제 입력 대기와 일반 일시정지를 상태 문구로 구별합니다.

출력은 현재까지 도착한 내용만 표시하고 전체·stdout·stderr를 선택할 수 있습니다. 입력 세션은 [세부 명세](interactive-input.md)를 따릅니다. 현재 구현은 입력 요청 사이의 실제 실행을 관찰한 뒤 구간을 재생하며, 모든 명령 직전의 실제 실행 정지까지 완성된 것은 아닙니다.

## 오류 UI — 임시 구현 / 설계도 UI — 미구현

2026-11-11: 컴파일·링크 실패 시 메시지와 원본 코드를 즉시 표시하고 재생을 시작하지 않습니다. 런타임은 앞선 기록을 재생한 뒤 ERROR에서 정지하며, 오류 패널·관련 코드 강조·당시 장면을 유지합니다. 오류 앞 시점으로 이동하면 오류 표시를 해제하고 다시 관찰할 수 있습니다. 위치는 진단·실패 명령 연결에서 읽고 추측하지 않습니다. 상세 컴파일 원문은 패널에 보존합니다. 경고·EOF·NULL·자발적 비영 종료는 오류 패널을 만들지 않으며, 도구/기록 실패와 기록 한도는 별도 제목으로 표시합니다. 설계도 작성·연결 연출은 아직 구현하지 않습니다.

- 함수 설계도를 접힌 목록으로 확인하고 실행 돗자리와 구별합니다. 설계도 목록을 펼쳐도 호출하거나 메모리를 만들지 않습니다.
- 컴파일·링크 실패는 결과를 받으면 즉시 안내하고 기본은 관련 코드·정의로 바로 이동합니다. 사용자가 원하면 설계도 작성·연결의 오류 설명 연출을 재생합니다.
- 위 연출은 실제 빌드가 실패한 경우에만 적용합니다. 빌드가 성공한 경고는 기존 에디터 진단으로 남기며 오류 연출·실행 중단 안내를 띄우지 않습니다.
- 확인된 오류에 메시지를 제공하고, 코드 위치가 있으면 강조하며 구조적 설명이 가능한 경우에만 설계도를 추가합니다. 정보가 없으면 메시지로 처리하고 위치·대상을 추정하지 않습니다.
- 컴파일 진단의 경고/오류 구분과 원문을 보존합니다. 한국어 설명을 제공하더라도 진단의 의미·대상·위치를 임의로 바꾸지 않습니다.
- 오류의 원인 위치와 검출 위치가 다르면 각각 구별할 수 있어야 합니다. 이전 유효한 장면은 확인할 수 있게 하고 이후 명령을 정상 완료한 것처럼 진행하지 않습니다.
- 런타임 오류 연출과 중단 안내는 실제 실행이 치명적 오류로 강제 중단된 경우에 한정합니다. 계속 실행되는 경고·정상 실패 반환·위험 동작을 화면에서 강제종료 오류로 승격하지 않습니다.
- 자원·실행환경 오류는 실제 실행의 치명적 중단이 확인된 경우에만 안내하며, 추가 공간 강조 대상은 확인된 스택 오버플로우로 한정합니다. 실행 중 문제는 확보된 구간을 재생한 뒤 안내합니다. 정상 실패 반환·EOF·errno·자발적인 비영 종료 코드만으로 강제종료 오류를 만들지 않습니다. 도구·API 실패와 기록 제한·사용자 중지는 별도 운영 안내입니다.

오류 처리 대상인 컴파일·링크·런타임 오류의 상세 분류는 [오류 표현](visualization.md#오류의-표현--설계-확정미구현)을 따릅니다. 논리 오류는 자동 오류 표시 대상에서 제외하고, 사용자가 실행 과정을 관찰하며 찾습니다. 화면이 자체적으로 C 오류를 새로 판정하거나 입력·출력 순서를 바꾸는 계약은 아닙니다.

## 설정·확장 — 후속 검토

- 상세/간결 표시 전환과 캐릭터 표시 여부
- 객체별 보기·포인터 서랍, 바이트/원소 단위 선택, 여러 상자 크기 합계
- 자동 자료구조 추천과 사용자가 지정한 보기의 선택·유지·해제 UI
- 큰 반복의 구간 탐색과 기록 누락 범위 안내
- 설정의 파일 저장과 다른 실행·변경된 코드로의 재적용

구현 여부는 해당 기능을 확인한 뒤 갱신합니다. 자료구조 사용자 지정의 기존 API가 있다는 사실을 선택 UI·파일 저장까지 완료됐다는 의미로 사용하지 않습니다.
## 직접 작성한 코드의 시각화 — 구현

2026-11-11: 시각화 페이지의 **C 코드 직접 입력**을 펼치면 기존 Monaco 편집기를 같은 페이지에서 사용할 수 있습니다. 코드를 작성·붙여넣고 **컴파일·시각화** 또는 **Ctrl+Enter**로 실행합니다. `animation.html?source=direct`는 편집기를 펼친 상태로 열며, 실행 버튼을 누를 때까지 C를 실행하지 않습니다. 기본 코드는 Hello World입니다. 편집기는 필요할 때만 불러옵니다.

기존 C 작업실 편집기의 **현재 코드 시각화 →** 경로도 유지합니다. 화면의 **직접 작성한 C 코드** 항목과 **코드 다시 실행** 버튼으로 코드를 다시 실행할 수 있습니다. 편집 중인 초안과 현재 재생 기록의 원본은 구별합니다. 컴파일 오류는 실행 코드의 위치 강조와 함께 편집기에도 표시하며, 이후 편집은 현재 기록을 소급 변경하지 않습니다.

소스는 예제 파일로 치환하지 않고 `POST /api/animation/sessions`의 `{source: "..."}`로 보냅니다. 기존 `{example: "..."}` 경로와 동일한 컴파일·실행·중간언어 변환·재생기를 사용합니다. 단일 C 파일과 512KiB 소스 한도를 적용하며, 임의의 서버 파일 경로를 받아 읽지 않습니다. 실행 시점의 원본 코드를 별도로 보존하므로 나중의 편집이 재생 기록을 바꾸지 않습니다.

입력 함수에서는 입력 돗자리에 대기하고 같은 실행을 이어갑니다. 컴파일 실패는 즉시 표시하며, 런타임 ERROR는 앞선 기록을 재생한 뒤 해당 위치에서 정지합니다. 이번 연결은 중간언어 생성 모델·추론기를 변경하지 않습니다.
