# 정규식 동치 판정기 계측과 구조 표현

`regex_equivalence.c`의 원본 동작을 유지하고, 고정한 예측과 실행 기록을 비교합니다. GCC의 함수 진입·복귀 계측과 이 예제용으로 선정한 관찰 지점을 함께 사용합니다. 범용 자동 계측의 완성을 의미하지 않습니다.

## 예측과 실제 결과

예측은 `examples/c/regex-equivalence-predictions.json`에 계측 실행 전에 고정했습니다. 입력별 출력, 노드 수, 포인터 슬롯 쓰기 횟수와 간접 호출 순서를 모두 비교했습니다.

| 입력 쌍 | AST 좌우 | NFA 좌우 | 생성된 DFA 좌우 | 곱 상태 | 비교 |
| --- | --- | --- | --- | --- | --- |
| ab / a(b\|c) | 3 / 5 | 3 / 5 | 4 / 4 | 5 | 예측 일치, 최단 반례 ac |
| a* / a*a* | 2 / 5 | 3 / 5 | 1 / 1 | 1 | 예측 일치, 동치 |
| abcdefghij / 동일 입력 | 19 / 19 | 11 / 11 | 12 / 12 | 12 | 예측 일치, 동치 |
| 바이트 FF / 동일 입력 | 1 / 1 | 2 / 2 | 3 / 3 | 3 | 예측 일치, 64비트 최상위 비트 유지 |
| 닫히지 않은 괄호 / a | 생성 도중 중단 | 생성 전 | 생성 전 | 생성 전 | ERROR 블록 하나 |

숫자는 알고리즘상 노드 수이며 모든 C 임시 객체의 수가 아닙니다. 전체 함수 호출 수와 사건 수는 예측 대상으로 고정하지 않고 실제 기록으로 남겼습니다. 원본과 계측본의 출력 및 프로그램 자체의 통계도 일치합니다. CPU 시간은 계측 비용 때문에 비교에서 제외합니다.

## 기록 연결

`ab`와 `a(b|c)`에서는 다음 흐름을 예상했고, 실제 기록도 이 순서의 의존 관계를 보였습니다. 함수 호출 내부의 세부 사건은 생략한 요약이며, 전체를 하나의 새 명령어로 합친 것은 아닙니다.

```text
SPACE 입력 저장 공간과 함수 프레임 생성
SPACE + WRITE 구문 트리 노드 생성, 자식 참조 연결
READ + FLOW 함수 포인터 읽기, 실제 대상 함수 진입
SPACE + WRITE NFA 상태 생성, 미완성 연결을 포인터 필드에 기록
CALC + WRITE 비트 집합 계산, DFA 상태와 전이 캐시 기록
WRITE + FLOW 상태 쌍 추가, 탐색과 반례 복원
SPACE 아레나 할당 해제, 함수 프레임 종료
```

이 입력에서는 실제 사건 3,947개와 함수 호출 프레임 842개를 기록했습니다. 아래 두 사건은 실제 JSONL에서 주소 표시만 생략한 발췌입니다.

```text
e439 READ  object5.slot → object4.field0의 주소
e440 WRITE object4.field0: NULL → 다음 NFA 상태의 주소
     addressInputs=[e439], pointerToSlotUnchanged=true
```

`*p->slot = target`에서는 목적지가 Patch 자체가 아닙니다. 실제 NfaState의 `out[k]` 필드 주소가 목적지입니다.

```text
READ  p->slot → 실제 포인터 필드의 주소
WRITE 그 주소의 포인터 ← target
```

모든 관측에서 목적지가 등록된 필드 주소로 해석됐고, 이때 p->slot의 주소값 자체는 바뀌지 않았습니다. 기록에는 목적 객체·필드, 전후 참조, 주소의 출처와 호출 번호를 연결합니다. 쓰기 전 대상 값의 추가 관찰은 상태 스냅샷으로 구분합니다.

간접 호출은 함수 포인터 필드를 읽은 위치, C의 동일 함수 포인터 비교로 얻은 대상 식별자, 컴파일러가 기록한 실제 진입을 연결합니다. C11에서 함수 포인터를 임의로 void 포인터로 변환해 값이라고 기록하지 않습니다. 반환된 Fragment는 호출한 쪽에서 실제로 받은 집합 값을 관측하며, 읽지 못한 피호출 함수 내부의 임시 상태를 만들지 않습니다.

벡터 확장 입력에서는 저장 공간을 바꾼 뒤 이전 할당이 여전히 살아 있는 사례가 11번 관측됐습니다. 이 할당들은 아레나 정리에서 모두 해제됐습니다. 논리적인 배열 교체와 실제 메모리 해제를 구분하며, 복사된 배열 원소를 이전 C 객체와 같은 객체로 합치지 않습니다.

## 이름 대신 구조와 접근을 이용한 표현

표현 판정 함수에는 원래 변수명과 자료형 표시명이 필요하지 않습니다. 표시명을 graph, array, grid처럼 서로 바꾸거나 배열 필드 순서를 바꾼 검증에서도 결과가 유지됩니다. 다만 관찰 지점과 타입 경로는 이 실험을 위해 선정했으므로, 임의의 C 코드에서 자동으로 같은 사실을 수집하는 단계는 별도로 남습니다.

| 관측한 근거 | 표현 후보 | 판정의 범위 |
| --- | --- | --- |
| 동일 타입 객체의 참조, 무순환, 부모 수 최대 1 | 트리 또는 숲 | 현재 스냅샷의 위상입니다. 이후 공유나 순환이 생기면 그래프 후보를 유지합니다. |
| 자기 타입 포인터 배열, 실제 공유·순환 참조 | 방향 그래프 | 실제 포인터 필드가 바뀔 때 연결선을 갱신합니다. |
| 자기 타입 next 참조와 다른 객체 필드 주소를 가리키는 슬롯 | 연결 리스트와 필드 서랍 | p->slot이 가리키는 포인터 저장 위치를 별도로 보여줍니다. |
| 일정 복사 폭, 연속 인덱스 쓰기, 증가하는 길이, 할당 크기에 맞는 용량 | 동적 배열 | void 포인터의 이름 대신 실제 접근 폭과 값의 관계로 역할을 제안합니다. |
| 정수 인덱스로 해석된 실제 전이 캐시 쓰기 | 인덱스 기반 그래프 | 아직 계산하지 않은 캐시 항목은 미계산이며 없는 간선으로 확정하지 않습니다. |
| 별도 두 인덱스 영역에서 온 값의 쌍 | 희소 격자 투영 | 곱 상태를 좌표로 보여줍니다. C의 물리적인 이차원 배열은 아닙니다. |
| 처음 발견한 상태에 저장한 부모 인덱스 | 탐색 트리 | 전체 곱 그래프의 모든 간선과 구분합니다. |
| 고정 폭 정수의 shift/or와 비트셋 복사 | 비트셋 | 64비트 비트열은 문자열로 전달하고 복사된 유연한 배열에도 연결합니다. |
| 일정 폭 레코드의 함수 포인터 필드와 실제 간접 호출 | 디스패치 배열 | 실행한 행만 관측됐다고 표시합니다. |
| 버킷에 대한 인덱스 접근만 확인됨 | 일반 배열 | 보기 좋다는 이유로 의미 없는 격자나 그래프를 만들지 않습니다. |

따라서 같은 실행 화면에 트리, 그래프, 배열, 비트셋, 격자를 함께 둘 수 있습니다. 이는 별개의 메모리를 복제하는 것이 아니라 같은 관측 객체에 대한 표현입니다. 원본 메모리 보기와 다른 표현의 대응 관계를 유지합니다.

## 실제 데이터에서 드러난 한계

- NFA에 순환이 생긴 입력에서는 트리 후보가 제외됐습니다. 짧은 입력의 선형 연결에는 체인과 트리 후보도 함께 남습니다. 표현 의도를 항상 하나로 확정하지 않습니다.
- 곱 상태를 격자로 나타낼 근거는 두 인덱스 영역과 실제 저장·탐색의 연결입니다. 임의의 정수 두 개나 int 배열만으로는 격자를 제안하지 않습니다.
- 재해시 내부의 모든 버킷 쓰기를 계측한 것은 아닙니다. 새 테이블에서 관측되지 않은 칸은 미관측으로 남습니다.
- 자료구조 그림은 아레나 정리 직전의 기록을 보여줍니다. 실행 종료 후에도 객체가 살아 있다고 주장하지 않습니다.
- 주요 배치·참조·전이·복사를 관측했지만 모든 스칼라 읽기와 연산을 수집하지 않았습니다. libc 내부 접근 순서도 미관측입니다.
- 오류는 ERROR 하나로 표시하고 이후 실제 정리 사건은 그 오류 블록의 실행 이력에 연결합니다. 실패 후 정상 복귀를 만들어 넣지 않습니다.

## 재현과 결과 파일

`pnpm trace:regex`로 재현합니다. 원본 스냅샷 해시가 달라지거나 선정한 소스 위치가 맞지 않으면 실행 전에 계측을 거부합니다.

- `test-results/regex-equivalence-trace/plan.json`: 선정한 작업과 원본 위치
- `test-results/regex-equivalence-trace/comparison.json`: 예측·관측값과 구조 제안
- 각 입력의 `*.trace.jsonl`: 실제 사건과 호출 프레임
- 각 입력의 `*.structures.json`: 참조, 배열, 격자 좌표와 할당 이력
- `cycles.mmd`: 실제로 기록한 순환 연결에서 생성한 Mermaid 그림
