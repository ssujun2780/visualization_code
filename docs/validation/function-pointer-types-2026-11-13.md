## 원인과 전후 결과

`N* (*pick)(N*,N*,int)`의 LLVM 자료형은 `%struct.N* (%struct.N*, %struct.N*, i32)*`입니다. 이전 파서는 기본형 `%struct.N` 뒤에서 먼저 괄호를 확인하고 마지막에 별표를 소비했습니다. 반환형의 `*`를 만나 함수형 처리를 건너뛰어 `%struct.N*`까지만 읽었습니다. 할당 계측에서 다시 주소용 `*`를 붙여 잘못된 `%struct.N** %pick`을 생성했습니다.

실제 이전 오류:

```text
/main.ll:318:44: error: '%pick' defined with type
'%struct.N* (%struct.N*, %struct.N*, i32)**'
but expected '%struct.N**'
  %cvm_a25a03db_112 = ptrtoint %struct.N** %pick to i32
```

수정 후 같은 원본 C의 계측은 완전한 타입을 사용합니다.

```llvm
ptrtoint %struct.N* (%struct.N*, %struct.N*, i32)** %pick to i32
```

관찰 계획의 할당 타입과 C 포인터 타입도 연결됐습니다. 원래 `indirect-return`은 `engine-error`에서 `completed`로 바뀌었고, 종료 코드 0 및 원래 예상 출력 `9\nA\n9\nB\n`을 만족합니다. 서로 다른 두 목록의 객체 ID·원소 순서·부분 객체 오프셋·NULL 종료까지 기존 추론 검사로 확인했습니다. TODO 표시만 제거했으며 원래 기대값과 검사는 변경하지 않았습니다.

공통 파서는 중첩 함수 포인터 반환도 처리합니다. 함수형 반환 추출에서 기존의 넓은 괄호 제거 정규식도 제거해, 가변 인자 함수가 반환하는 함수 포인터의 내부 매개변수 목록을 보존했습니다.
