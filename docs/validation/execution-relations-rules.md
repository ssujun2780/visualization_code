실제로 읽은 계약: AGENTS.md, presentation.md, execution-relations.md의 R-02/R-04/R-06/R-07 및 W-01/W-02/W-03/W-06, inference-model.md의 읽기 전용 소비자 경계, design-implementation-template.md. 사용자 요청으로 호출·구간·복사 초안의 초기 구현을 승인받았으며 전체 W 설계의 구현 승인이 아닙니다.

## 실행 전 예상과 실제 비교

`examples/c/walkthrough/meeting_selection_fixed.c`에 다음 입력을 고정했습니다. 테스트의 기대값과 결과 폴더의 prediction.json은 추론 전에 작성합니다. 모델 출력에서 정답을 읽어 기대값을 생성하지 않습니다.

```text
4
5 7
1 2
3 5
2 3
```

구간 표기 `[a,b)`는 a 이상 b 미만입니다. 이 실행의 구조체 원소는 8바이트입니다.

| 항목 | 실행 전 예상 | 실제 추론 비교 |
| --- | --- | --- |
| 사용자 함수 호출 | 정렬 7회 + 병합 3회, 부모·자식 연결 10개 | 일치. 함수명은 테스트의 독립 oracle에만 사용하며 판정기는 function/activation/call ID 사용 |
| 루트 사용 범위 | 원본 배열 원소 `[0,4)` | subtree `[0,32)` 바이트. 정렬 함수 자체의 direct 배열 접근은 없음 |
| 두 하위 정렬 | `[0,2)`·`[2,4)` | `[0,16)`·`[16,32)`, 서로 분리됨 |
| 세 병합의 접근 범위 | `[0,2)`·`[2,4)`·`[0,4)` | 각 바이트 범위 일치 |
| 배열 필드 복사 | 임시 배열 16회 + 원본 반영 16회 = 32회 | 각 READ→WRITE의 실제 원본/목적지·start/end 오프셋·사건 순서 일치 |
| 임시 배열로 향하는 복사 열 | 병합별 원소 2·2·4개 | 필드 전달 4·4·8개. 원본으로 돌아오는 필드 전달도 유지 |
| 최종 원소의 최초 입력 정체성 | `1,3,2,0` | 추론된 바이트 복사 간선을 시간순으로 따라가서 일치 |
| 배열을 읽지 않는 재귀 종료 | 4개 호출은 사용 구간 미확정 | 포인터 인자는 연결되지만 사용 구간은 생성하지 않음 |

첫 비교에서는 마지막 병합의 현재 읽기 인덱스 `0,2,3,1`을 최초 입력 정체성과 혼동해 검사에 실패했습니다. 초기 예측 `1,3,2,0`을 실제 출력에 맞춰 바꾸지 않고, 앞선 copy-back으로 변경된 원소 정체성을 복사 간선으로 추적하는 독립 검사를 추가했습니다. 현재 저장 위치와 최초 입력 원소는 별개의 정보입니다. 원소 숫자가 같다는 이유로 출처를 연결하지 않습니다.

## 공통성·반례 검사

- 동일 회의 소스의 사용자 함수·변수·필드·구조체 이름을 바꾸어 같은 관계 계약을 재검사합니다.
- `examples/c/execution-relations/array-relations.c`: 재귀가 아닌 반복 복사, 같은 값이 반복되는 배열, 부분 포인터, 별칭과 임시 스칼라, 겹치는 memmove, 12바이트 구조체의 서로 다른 원소에서 가져온 필드를 검사합니다.
- sparse 읽기는 `[0,4)`·`[8,12)`·`[16,20)`이며 중간의 미접근 영역을 채우지 않습니다. 부분 포인터의 추가 접근은 `[4,8)`·`[12,16)`입니다.
- 값이 같은 상수 대입과 산술 결과를 원본 READ의 복사로 판정하지 않습니다. 구조체 두 필드의 출처가 서로 다르면 각각 0·12바이트 원소 출처를 유지합니다.
- 같은 폭의 signed→unsigned 변환은 비트 보존 복사로 연결하고, 값이 우연히 같아도 narrowing은 연결하지 않습니다. 매개변수가 없는 호출도 저장소 참여 없이 두 프레임 관계를 확인합니다.
- 인자는 받지만 배열에 접근하지 않는 함수의 구간을 만들지 않습니다. 호출 진입까지만 남긴 기록에서 미래 자식 호출·최종 사용 구간을 가져오지 않습니다.
- 실제 복사 WRITE에 다중 값 생산자를 넣은 변형, 같은 주소를 쓰지만 읽기 이후에 생성된 다른 객체 ID의 변형, 복사 순서를 뒤집은 부가 결과를 거부합니다. 사용자 C에 오류를 심어 실행시키는 검사가 아닙니다.
- 기존 뼈대 검사로 원본 JSON 불변·스냅샷 동결·Worker 격리·시간 제한·독립 CLI·의존성 경계를 유지합니다.

## 실행과 결과 위치

```sh
node --test tests/execution-relations-scaffold.test.js tests/execution-relations-rules.test.js
node scripts/infer-execution-relations.mjs test-results/execution-relations/meeting
```

관련 검사만 수행하며 전체 예제 모음을 재실행하지 않습니다. 결과는 `test-results/execution-relations/{meeting,renamed-meeting,array-relations}/`의 prediction·plan·trace·execution-relations·comparison JSON입니다. 테스트는 생성 API로 실제 C를 실행한 다음 별도 추론 API를 호출합니다. 추론기 자체가 컴파일러를 실행하는 것은 아닙니다. 임시 테스트 산출물은 gitignore 대상이며 이 문서·테스트 소스에 재현 계약을 보관합니다.

검증 결과: 위 두 테스트 파일의 12개 검사 통과. 실제 C 세 변형의 실행·추론·예상 관계 비교와 뼈대 회귀 검사를 포함합니다. 최초 원소 정체성 검사는 유지했으며 실제 출력에 맞춰 초기 예상값을 변경하지 않았습니다.

현재 비교는 실제 API와 메타데이터 검증이며 화면 가독성의 검증이 아닙니다. 초기 판정기의 completed는 실행 성공입니다. 알고리즘 이름 인식, 정렬의 정확성 증명, 전체 배열 사용의 사전 예측, 모든 관계 지원을 의미하지 않습니다. 대규모 기록·깊은 재귀의 메모리/시간 예산은 별도 검증이 필요합니다.
