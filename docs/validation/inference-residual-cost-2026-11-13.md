# 남은 추론 비용 집중 점검 — 2026-11-13

## 범위

상태 조립·입력 복제·최종 공유값 정규화의 남은 비용을 확인했습니다. **구현 변경은 없습니다.** 기존 8·16·32노드 실행 기록을 재사용했고, 생산 모듈의 사본에만 타이머/카운터를 넣었습니다. 모델·계측·추론 163개 파일의 시작/종료 해시가 동일합니다. 세 크기 모두 전체 추론 결과 SHA-256이 이전 결과와 같고 원본 입력도 불변입니다. UI/화면 검증은 범위 밖입니다.

이번 결과는 한 차례의 프로파일 측정이며 성능 개선 수치가 아닙니다. 타이머가 포함되고 32노드에는 CPU 샘플링도 사용했습니다. 이전 3회 중앙값과 직접 비교해 빨라졌다고 판단하지 않습니다.

## 측정 결과

| 구간 | 8노드 | 16노드 | 32노드 |
| --- | ---: | ---: | ---: |
| 전체 추론 | 0.502초 | 1.540초 | 8.491초 |
| 연결 후보 처리 | 0.088초 | 0.437초 | 2.055초 |
| 전체 계약 검증 | 0.058초 | 0.148초 | 1.050초 |

32노드의 나머지 주요 구간은 포인터 트리 투영 1.113초, 순서 트리 의미 분석 1.080초, 포인터 우선순위 0.791초, 최종 공유값 정규화 0.394초, 입력 복제 0.159초, 입력 동결 0.101초입니다. 입력 복제/동결은 합쳐 약 3%로 첫 수정 대상이 아닙니다.

연결 상태를 실제 조립한 횟수와 저장한 횟수:

| 노드 | 조립 | 저장 | 조립 후 동일해서 버린 상태 |
| --- | ---: | ---: | ---: |
| 8 | 2,613 | 1,236 | 1,377 |
| 16 | 14,748 | 5,127 | 9,621 |
| 32 | 84,771 | 22,335 | 62,436 |

32노드는 약 74%를 **완성한 뒤** 동일성 비교로 버립니다. 이미 버리는 상태이므로 저장 이력을 더 삭제할 이유는 없습니다. 변경되지 않음을 조립 전에 증명해 동일한 일을 생략하는 것이 목표입니다.

상태 처리 내부 시간은 준비/관계 계산 0.475초, 행 조립 0.120초, 필드 공유값 정규화 1.043초입니다. 마지막 구간 중 `unrelatedStorage`가 0.467초, `associatedStorage`가 0.090초였습니다. `unrelatedStorage`는 해당 루트의 구성원 밖에 있는 같은 자료형의 살아 있는 레코드를 표시하는 정보입니다. 정보 자체를 삭제하는 개선이 아닙니다.

32노드 프로파일의 추론 직후 JS 힙은 279.8MB, GC 후 51.2MB였고 최대 RSS는 426.8MB였습니다. 많은 메모리가 회수 가능함을 보여주지만, 두 힙 값의 차이가 모든 임시 할당의 총량이나 특정 함수의 정확한 할당량을 뜻하지는 않습니다. 프로파일링 오버헤드도 포함합니다.
