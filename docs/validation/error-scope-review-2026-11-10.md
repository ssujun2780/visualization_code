# 오류 연출 범위 재검토 — 2026-11-10

사용자 요청에 따라 컴파일·링크·자원 및 실행환경 오류를 빌드 실패 또는 실제 실행의 치명적 강제 중단 기준으로 다시 정리했습니다. 기준 문서는 [시각화](../design/visualization.md#오류의-표현--설계-확정미구현), 연출·조작은 [애니메이션](../design/animation.md)·[UI](../design/ui.md)입니다. 구현·중간언어 생성 모델·추론기는 변경하지 않았습니다.

## 현재 도구로 확인한 빌드 결과

프로젝트의 기존 Clang 분석과 Clang/WASM 링크를 사용했습니다. 아래 여섯 확인에서 사용자 C 본문은 실행하지 않았으며, 전체 예제 모음도 재실행하지 않았습니다.

| 확인한 코드 형태 | 실제 결과 | 오류 연출 대상 |
| --- | --- | --- |
| `int x = ;` | 컴파일 거부: expected expression | 포함. 코드 강조·메시지 |
| `int a[-3];` | 컴파일 거부: array with a negative size | 포함. 잘못된 배열 설계도와 메시지 |
| 두 인자 함수 원형에 `f(1)` 호출 | 컴파일 거부: too few arguments | 포함. 인자 자리 비교와 메시지 |
| `int a[2]={1,2,3};` | 경고만 발생, 컴파일 통과 | 제외. 에디터 경고로 유지 |
| `double x=1; int *p=&x;` | 호환되지 않는 포인터 경고, 컴파일 통과 | 제외. 에디터 경고로 유지 |
| 선언만 있는 `missing()` 호출 | 링크 거부: undefined symbol | 포함. 연결할 함수 정의가 없는 모습 |

컴파일 확인에는 기존 `analyze`를 사용했습니다. 마지막 확인은 기존 `compileAndRun`의 링크 단계에서 거부되어 사용자 본문이 실행되지 않았습니다. 이는 현재 번들 도구·옵션의 결과이며 다른 버전이나 경고를 오류로 바꾸는 설정에도 같은 결과라고 가정하지 않습니다.

## 컴파일·링크 실패의 추가 분류 확인

같은 기준으로 여덟 컴파일 진단과 두 링크 진단을 추가 확인했습니다. 모두 빌드 단계에서 거부되어 사용자 C 본문은 실행되지 않았습니다. 화면 연출을 구현한 검사가 아니라 분류의 실제 실패 여부를 확인한 것입니다.

| 사례 | 실제 실패 단계 | 기본 표시 |
| --- | --- | --- |
| 같은 블록에서 초기화된 지역변수 이름 재정의 | 컴파일 | 충돌하는 이름표·설계도와 메시지 |
| 선언되지 않은 이름 사용 | 컴파일 | 참조할 선언이 없는 자리와 메시지 |
| const 지역변수에 대입 | 컴파일 | 잠긴 상자 설계도와 메시지 |
| int 값을 역참조 | 컴파일 | 주소 요구와 실제 자료형 비교 |
| 구조체 값을 int로 초기화 | 컴파일 | 초기화하는 쪽·받는 쪽의 자료형 비교 |
| 구조체에 없는 멤버 접근 | 컴파일 | 멤버 설계도와 요청한 멤버 비교 |
| 반복문·switch 밖의 break | 컴파일 | 코드 위치와 사용 조건 메시지 |
| `_Static_assert(0, "failed")` | 컴파일 | 코드 위치와 실패 메시지 |
| 정의 없는 외부 전역변수 참조 | 링크 | 연결할 저장소 정의가 없는 모습 |
| main 정의 없음 | 링크 | 프로그램 시작 연결점과 누락된 main 표시 |

컴파일·링크 단계에는 사용자 프로그램이 아직 시작되지 않았으므로 실행 중 강제종료라는 표현을 적용하지 않습니다. 이 두 단계의 대상은 실제 빌드 실패로 실행을 시작할 수 없는 경우입니다. 런타임의 치명적 강제 중단과 구별합니다.

## 자원·실행환경의 경계

- 확인된 스택 오버플로우로 실행이 강제 중단되면 기존 공간 강조와 메시지를 사용합니다.
- 확인된 치명적 메모리 소진·실행환경 장애는 메시지 중심으로 안내합니다. 자원 소진을 실제로 유발하는 실험은 하지 않았습니다.
- malloc의 NULL, 파일 열기 실패, EOF, errno, 자발적인 비영 종료 코드만으로 강제종료 오류를 만들지 않습니다.
- 이후 실패 반환값을 잘못 사용하다 실제 중단되면, 그 중단된 작업의 분류로 다룹니다.
- 도구·API 자체 실패와 기록 제한·사용자 중지는 사용자 C의 강제종료 오류와 구별합니다. 원인 없는 프로세스 종료에 추정 원인을 붙이지 않습니다.
