## 공통 완료 기준

1. 원본 plan/trace의 값·사건·순서·수명이 불변이어야 합니다.
2. 저장 위치, 구성원 식별자, 연결 순서, 종료와 관측 시점의 예상은 코드에서 정합니다.
3. 긍정 사례뿐 아니라 근거 변조·불충분·무관한 동일 값도 확인합니다. 실패에 맞추어 기대값을 완화하지 않습니다.
4. 전용 판정과 공통 조회/수동 지정이 같은 현재 근거를 사용해야 합니다. 의미를 알 수 없는 사용자 규칙은 이유를 남깁니다.
5. 전체 자료구조의 의도 추론, 임의 비교 함수를 실행하는 기능, 영속성 증명, 알고리즘 완료 색칠은 자동으로 구현됐다고 주장하지 않습니다.

## 세부 경계

- 정확한 정수 payload와 안전 정수 좌표는 분리합니다. NaN은 순서 불명으로 남습니다. 일반 사용자 비교자의 모든 연산을 추측하지 않습니다.
- 문자열 키 관계는 실제 외부 `strcmp` 결과·인자 출처·관측 버킷 의존성이 함께 있어야 합니다. 같은 이름의 사용자 정의 함수나 문자열 선형 검색만으로 해시를 만들지 않습니다.
- 상수 잎의 좌표는 실제 저장 배열의 원소 위치입니다. 존재하지 않는 원본 입력 배열이나 0부터의 논리 좌표를 만들지 않습니다.
- 태그만 쓰는 호출은 `aggregateEffect: not-written`입니다. 같은 위치의 관측된 결합 근거와 호출 종료를 확보한 시점 이후에만 제공하고, 가상의 집계 WRITE는 만들지 않습니다.
- 저장소 교환 정보는 해당 후보의 구성원 관측 구간입니다. 공유 노드는 후보별 대응을 유지하고, 이탈·재진입·해제를 별도 구간으로 기록합니다. 소비자 구현은 수정하지 않습니다.
- 수동 key는 부모 우선순위와 실제 트리 조건을, terminal은 현재 트라이 종료 역할의 관측 여부를 검사합니다. 바이트가 없으면 자동 역할을 몰래 대신 사용하지 않습니다. 모든 사용자 정의 규칙을 자동 검사하는 기능이나 UI를 뜻하지 않습니다.

## 검사 결과

관련 검사 **69개 통과**입니다. 한 번의 전체 실행 숫자가 아니라 아래 파일/이름 필터로 확인한 서로 다른 테스트 수입니다. 처음 실패한 기준을 유지한 채 공통 코드와 시간/식별자 계약을 보완했습니다.

- `ir-inference-completion.test.js`: 18개. 기존 감사의 고정 실행 기록과 새 반환 순회·포인터 DSU·마스크 큐·선형 문자열 반례·크기 변형·넓은 정수/실수 키를 사용합니다.
- `ir-array-containers.test.js`: 10개.
- `inference-separation`, `ir-associative-lookups`, `ir-inference-history-gap`, `ir-sequence-label-binding`, `ir-structure-composition`, `ir-structure-extensions`: 38개. 이후 우선순위 경로 변경 뒤 관련 4개를 다시 확인했습니다.
- `ir-priority-partition-range.test.js`: record fields, zero-based bit, heap storage의 3개만 실행했습니다. 전체 과거 예제를 재실행하지 않았습니다.

검사 중 추가로 고친 원인은 다음과 같습니다.

1. 반환 호출의 AST 위치에 원래 호출과 보조 호출이 함께 있었는데, callee가 없는 보조 정의가 원래 정의를 덮었습니다. 의미가 있는 호출 정의로 연결했습니다.
2. 문자열 키의 문자 읽기를 버킷 접근으로 먼저 선택했습니다. 실제 숫자 변환을 거친 주소 의존성까지 요구하도록 고쳤습니다. 선형 검색은 여전히 제외합니다.
3. XOR의 첫 전파 뒤에 결합 위치 근거가 확인됐습니다. `occurredAtExecutionId`/`completedAtExecutionId`와 발견 시점 `afterExecutionId`를 분리합니다. 첫 전파는 실제 x207, 그 근거가 사용 가능한 시점은 x252입니다. x207 시점 조회에 미래 근거를 넣지 않습니다. 두 자식이 같은 발견 시점을 가질 수 있으므로 시점과 자식 식별자를 함께 검사합니다.
4. 첫 자식/형제 표현의 형제 선까지 부모 우선순위로 검사했습니다. `new.sibling = owner.child; owner.child = new`의 실제 전달 근거에서 별도 `priorityEdges`를 구성합니다. 저장 간선은 그대로 두고, 투영 간선에도 원래 간선 식별자를 남깁니다. 같은 값의 다른 노드를 합치지 않습니다.

중간언어 생성·계측 **52개 파일의 시작/종료 해시가 동일**합니다. 각 사례의 원본 JSON 불변과 읽기 전용 분리 검사도 통과했습니다. 증거는 `test-results/inference-common-completion-2026-11-12/verification.json`, 각 `.inference.json`, `.metrics.json`, `growth.json`입니다.

8/16/32원소 반환 순회의 사건 수는 335/647/1271개입니다. 추론 시간은 해당 실행의 `growth.json`에 기록했습니다. 작은 입력 세 점의 측정으로 대규모 복잡도나 성능 상한을 보증하지 않습니다.
