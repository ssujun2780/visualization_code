# 자동 추론 역할의 재연결 검증

## 작업 범위와 적용 계약

- 요청: 자동 추론에서 선택한 역할을 필드 선언·저장 배열 근거로 복원하고 관계·조건을 함께 연결합니다. 구현을 마친 뒤 관련 변형·반례·통합 경로를 확인합니다.
- 읽은 계약: presentation.md 모델·추론 경계, inference-model.md 읽기 전용 경계, structure-presentation-policy.md 사용자 선택·역할 범위, user-structure-relations.md UR-09~11, tree-inference-projections.md 공동 인덱스·현재 관측 규칙. 새 공통 역할 규칙은 UR-12로 명시했습니다.
- 생성 모델·계측·UI를 수정하지 않았습니다. 전체 예제 재실행이나 Git 커밋·푸시도 하지 않았습니다.

## 소스에서 고정한 예상

포인터 구조체, 분리 배열, 구조체 인덱스, 2차원 표 네 구현은 모두 루트 0에서 원소 1·2로 이어집니다. 값은 10, 5, 15이며 합계는 30입니다. 각 프로그램을 입력 0/1로 실행하며 입력 1에서는 무관한 추가 할당이 먼저 발생합니다.

- A: 노드 3개, 간선 2개, 서로 다른 자식 1·2, 명시한 BST 조건 만족.
- B: realloc 후 용량은 5가 되어도 연결된 원소는 같은 3개. 합계 30, 조건 만족.
- C: 왼쪽 값만 50으로 변경. 합계 75, 동일 연결과 조건 위반.
- 다시 A: 원래 객체·역할·값을 사용해 조건 만족.

각 `.expected.json`과 C 파일을 첫 실행 전에 저장했습니다. 검사에서 실제 원소 식별자·바이트 위치·자식 오프셋·방향·조건 결과를 확인합니다. 0번 자식/1번 자식을 바꾸어 연결하면 BST 조건 검사도 실패합니다. 동일 출력만 확인한 검사가 아닙니다.

결과 경로는 `test-results/inferred-role-reconnect-2026-11-12/`입니다. 네 구현별 `*-0.json`, `*-1.json`에는 실제 plan/trace/inference/stdout, `.comparison.json`에는 조건 결과와 역할 대응을 보관했습니다. 포인터 배열 슬롯은 별도 실제 C 실행과 `pointer-member-slots-evidence.json`으로 확인했습니다.

## 발견한 공통 결함과 수정

분리 배열은 같은 인덱스 값의 실제 출처를 재사용하므로 이전 할당과 새 할당 접근이 같은 출처 목록에 들어올 수 있습니다. 기존 그룹 수집은 이 목록에서 먼저 본 배열을 영구히 유지했습니다. 세 배열을 realloc한 뒤에도 종료된 세 배열이 새 그룹에 남아 `storageAlive:false`가 되어, 새 역할 두 개를 가진 완전한 후보가 만들어지지 않았습니다.

각 접근에서 종료된 배열과 그 읽기 근거를 제거하고 살아 있는 배열의 공동 인덱스 근거만 유지하도록 수정했습니다. realloc 함수명·예제 이름·특정 객체 ID에 대한 분기는 없습니다. 일반 free 후 새 저장소를 사용하는 합성 반례에서도 동일하게 검사했습니다. 이미 종료된 READ를 새 그룹의 읽기 증거로 재사용하지 않는지, 서로 다른 인덱스 출처를 같은 숫자라는 이유로 합치지 않는지도 확인했습니다.

저장소 그래프 조회에는 재연결 실패 뒤 빈 역할 필터 결과를 정상적인 빈 트리로 판정할 가능성이 있었습니다. 역할 복원 실패 시 관계를 반환하지 않고 `relationAvailable:false`, `topology:null`, `assessment:incomplete`로 구분했습니다.

## 검사 구성 정정과 실행 결과

처음 작성한 검사에는 API 인자 `roleIds`를 `roles`로 전달한 오류와, 서로 다른 추론 어댑터의 topology 상태 문자열을 모두 `tree`로 가정한 오류가 있었습니다. 인자명을 고치고 노드 3개·간선 2개·단일 루트·비순환이라는 동일한 구조 조건으로 후보를 찾도록 정정했습니다. 이후 공통 조건의 완전성·자료구조 조건 검사는 그대로 유지했습니다.

포인터 배열 검사에서는 초기화 중 레코드 소유자가 아직 확인되지 않은 임시 저장 보기를 자동 역할과 함께 세고 있었습니다. 실제 사용자 선택 대상인 `roleProjections`에서 고르도록 수정했습니다. 기대 슬롯 2개, 상대 오프셋 4/8, 구성원 3개, 간선 2개는 변경하지 않았습니다. 범용 추론 결과를 맞추려고 기대 연결·값·조건을 바꾸지는 않았습니다.

- 최초 네 C 프로그램의 입력 2개씩은 실제로 컴파일·실행했습니다.
- 추론 수정 후에는 `ROLE_RECONNECT_SAVED=1`로 같은 소스의 저장된 실제 plan/trace를 사용하고 **현재 추론기를 다시 실행**했습니다. 저장 소스와 현재 테스트 소스의 일치를 검사하며 과거 inference 결과는 재사용하지 않습니다. 생성 모델은 작업 전후 불변입니다.
- 관련 7개 검사 파일에서 61종 중 60종 통과(`focused-tests.txt`). 마지막 슬롯 선택 검사 구성 정정 뒤 해당 1종을 다시 실행해 통과했습니다(`slots-recheck.txt`). **서로 다른 관련 검사 61종을 확인한 결과**이며 마지막에 61종 전체를 다시 실행했다는 의미는 아닙니다.
- 기존 재연결·표현·공동 인덱스 발견 시점·추천 범위·분리 경계를 함께 확인했습니다. 전체 과거 예제 목록은 실행하지 않았습니다.
- `model-before.json`, `model-boundary.json`: 생성·계측 52개 파일의 개수·SHA 동일, 추가 파일 없음. `git diff --check`도 통과했습니다.

## 남은 지원 경계

소스·컴파일러 배치 변경, 미관측 역할, 유일하지 않은 필드/배열/후보 대응은 재연결 필요로 남습니다. 새 사용자 의도를 자동 추정하지 않습니다. 현재 앵커가 표현하지 못하는 새로운 역할 스키마도 임의 문자열 치환으로 연결하지 않습니다. UI·영속 저장·대규모 성능 상한 검증은 이번 작업의 완료 범위가 아닙니다.
