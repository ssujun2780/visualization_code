# while·do-while 반복 탐색 검증

2026-11-11. 기존 for 탐색에 두 종류를 공통 적용했습니다. 중간언어 생성 모델·추론기는 변경하지 않았습니다.

## 계약과 변경 경로

`presentation.md`, `animation.md`, `visualization.md`, `ui.md`, [반복 탐색 계약](../design/loop-navigation.md) L-01~L-06을 확인했습니다. 기존 L-01~L-05를 while·do-while에 확장하되 사건 순서·상태 복원·재생 유지 규칙은 그대로 적용했습니다.

예상 조건을 실행 전에 정했습니다. 혼합 중첩 예제의 반복 수는 for 2회 + 바깥 while 4회 + do-while 12회 + 재귀 while 6회 = 24회이며 출력은 `466\n`입니다. 별도 화면 예제는 while 3회 출력 `1\n3\n6\n`, 이후 do-while 2회 뒤 `sum=26`, `n=1`입니다. while의 마지막 거짓 조건은 반복 밖, do-while의 마지막 거짓 조건은 마지막 반복 안에 있어야 합니다.

## 검사 결과

- 새 while·do-while 검사 8개와 기존 반복·재생·입력·사건 시간 검사: 32개 통과.
- 최초 API 검사 한 개는 샌드박스의 localhost 연결 `EACCES`로 실패했습니다. 해당 검사만 로컬 연결 가능한 실행에서 재검사하여 통과했습니다.
- 수정한 예제 worker의 HTTP API 검사 3개 통과. 관련 검사 합계 35개이며 기존 예제 전체는 재실행하지 않았습니다.
- Vite 프로덕션 빌드 통과. 기존 Monaco 번들 크기 경고는 그대로 남습니다.
- 검사 작성 중 총 반복 수 합산 오기와 존재하지 않는 반환 상태 필드 참조를 정정했습니다. 개별 반복 수·출력·실제 상태 비교는 유지했습니다.

## 범위와 제한

AST 탐색 정보는 원문을 의미 분석하지 않습니다. 기존 위치 변환기로 AST 끝 토큰 길이만 보충합니다. 실행을 다시 돌리거나 조건의 값을 추측하지 않습니다. 과거 plan/trace만으로는 제거된 do-while(0)의 전체 범위가 없을 수 있으며, 그러한 구간은 평면 목록을 유지합니다. 새 애니메이션 API 기록은 탐색 정보를 함께 전달합니다. 기록되지 않은 미래 반복·빈 실행 사건을 만들지 않으며, 초대형 기록의 모든 규모에 대한 성능 보장을 추가하지 않았습니다.
