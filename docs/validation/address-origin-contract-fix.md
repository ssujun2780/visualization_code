# 주소 출처·복귀·매개변수 전달 계약 보완

2026-11-12.

## 범위와 적용 계약

- 사용자 승인: 주소 출처 인계, 복귀의 잘못된 경고, 매개변수 전달 화살표를 공통 보완. 불필요한 독립 주소 명령 추가 금지. 관련 경로만 검사.
- 읽은 문서: presentation 모델/추론 경계, c-model 상세 기록·주소 계산 연결, execution-visualization 중간 표현, inference-model 분리 경계, return-sequence 범용 연결, 실행 관계 E-06c·E-07 및 v2, animation 기본 원칙, visualization 공간과 대상, ui 화면과 조작, value-transfer-arrows 시간선.
- 필수 조건: 실제 관측값·객체/오프셋·생명주기·C 평가 순서 유지. 소스 재평가·이름/숫자 일치로 출처 복원 금지. 자료구조 추론기 변경 제외.
- 문제: administrative 주소를 생략한 뒤 남은 원시 관찰 ID를 소비자가 연결하지 못함. 복귀의 보관용 호출 인자를 반환 피연산자로 오분류. 렌더러는 공개 생산 사건만으로 화살표 출발점을 찾음.
- 검증 전 기대: 주소 전달은 배열 원소 내용 READ/복사가 아님. 동적 첨자·구조체/격자·전역 상수 주소·힙·포인터/다중 포인터·반환 경유에서도 대상 정체성·오프셋 보존. void 및 상수 반환은 호출 인자와 구별. 원래 재귀 예제는 1,166개 공개 사건과 출력 `1 2 3 5 6 7 ` 유지.

## 집중 검사

새 C 코드 두 개는 다음을 확인합니다.

- 지역/전역 배열, 동적 인덱스, 구조체 내부 배열, 포인터 기저, 이중 포인터, 함수 포인터 호출, 포인터 배열, 힙, 중첩 포인터 반환, 미사용 반환, void와 상수 반환. 기대 출력 `4 11 3 14 9 10 19 24 7 17 12`.
- 2차원 배열, 구조체 필드, 반복 호출, 전역 배열의 onePast. 기대 출력 `31 31 31`, onePast는 첫 배열 소속·12바이트 오프셋·역참조 불가.
- 원래 재귀·구간 복사 예제는 1,166개 사건 유지. 기존 네 사건의 `unresolved-value-operand`/`unresolved-callee-operand`가 해소되고 두 주소 인자 WRITE에 실제 경로가 생김.
- 모델 검사·분석·렌더링 뒤 원본 지문 불변, 주소 인계 제거 반례, 미래 사건 주입·출처 노드 변조 반례, 값 도착 전후, 원본 배열 READ 오인 방지.

관련 테스트 38개 통과(반복 실행·중복 3개를 더하지 않은 수):

1. 주소 계약·호출 주소·비공개 값 출처·반환 순서·호출 ABI·함수 참조·기존 전달: 21개.
2. v2의 출처/스냅샷/인자·반환 등 선택한 공통 경로: 5개.
3. 주소 계약 3개를 다시 포함한 작업 안내·화살표 사건·상수 저장소 표시: 15개.

전체 번호 예제 모음은 다시 실행하지 않았습니다. 프로덕션 빌드는 통과했고 기존 큰 번들 경고는 유지됩니다.

## 화면 확인

현재 API로 새 work-merge 기록을 생성해 `&data[0] → a`, `&temporary[0] → buffer` 경로와 한 명령어 재생을 확인했습니다. 주소 전달 전후 배열의 원소 값은 유지됩니다. 1086/1166에서 복귀 이후의 정렬된 원본 배열과 잘못된 출처 경고가 없음을 확인했고, 출력 명령의 보조 경로에 숨긴 `.str`가 다시 등장하지 않는 것도 확인했습니다. 화면 증거: `address-origin-parameter-arrows.png`, `address-origin-resume.png`.

## 범위와 남은 항목

이 보완은 기존 주소 인계·복귀 분류·주소 전달 표시 경로입니다. 모든 외부 라이브러리의 내부 생산 과정이나 기존의 다른 캡처 입력 출처까지 완전하다고 선언하지 않습니다. 알 수 없는 주소/부족한 근거의 경고를 전부 지우지 않았습니다. 새 계약이 없는 저장된 과거 JSON은 재실행해야 새 메타데이터를 얻습니다.
