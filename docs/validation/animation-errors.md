# 실행 오류 표시 검증

2026-11-11. 화면과 실행 세션 어댑터만 변경했습니다. 중간언어 생성 모델·계측·자료구조 추론기는 변경하지 않았습니다.

- 컴파일 실패: 실행 기록 없이 컴파일 진단·원본 코드·행/열을 전달하고 즉시 표시합니다.
- 링크 실패: 실행 전에 안내하며, 위치 근거가 없으면 코드 위치를 추측하지 않습니다.
- 런타임: 이미 비정상 중단된 실행이 남긴 ERROR까지 앞선 명령을 재생하고 정지합니다. 정상 결과·후속 출력·자동 공간 정리를 만들어내지 않습니다.
- 실패·미완료 CALC/READ/WRITE는 관찰 시도로 받아들이되 결과나 저장 효과를 적용하지 않습니다. 없는 계산값을 만들거나 잘못된 주소를 정상 접근으로 표시하지 않습니다.
- ERROR의 실패 명령·실행 ID 연결과 진단 위치로 원본 코드를 강조합니다. 정확한 위치가 없는 트랩은 위치 미상으로 안내합니다.
- 경고가 있는 성공 빌드, 자발적인 종료 코드 3, 정상 입력 종료 EOF는 런타임 오류로 만들지 않습니다. 기록 한도·엔진 실패는 별도로 구분합니다.
- 실제 입력 대기 이후에도 같은 실행의 기록을 이어서 오류 지점까지 재생합니다. C 라이브러리 출력은 실제 전달된 바이트만 표시하며, 버퍼 내용을 임의로 출력하지 않습니다. 입력 후 출력 검증은 `fflush(stdout)`로 오류 전 전달을 명시했습니다.

범용 검사는 `tests/animation-faults.test.js`의 임의 이름·별도 소스와 합성 실패 기록으로 수행합니다. 합성 기록은 실패 명령의 재생 계약 검사에만 쓰고 실제 실행 결과로 간주하지 않습니다. 다른 예제 전체를 다시 실행하지 않습니다. 화면 예제 선택기에 컴파일 오류와 런타임 오류 예제를 추가했습니다.

검사 결과: 오류 관련 9개와 기존 재생·입력·사건 시간·전달 단계 관련 24개, 총 33개 통과. Vite 빌드 통과. 브라우저에서 런타임 예제의 초기 0/16에는 오류 패널이 없고, 16/16에서 정지하며 7행 강조와 `before: 12` 출력을 유지하는 것을 확인했습니다. 컴파일 예제는 0/0, 실행 목록 없음, 재생 비활성 상태에서 진단과 5행 강조를 즉시 표시했습니다.
