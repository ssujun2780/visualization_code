# 명령 완료 경계에서의 재생 정지 수정

2026-11-10. 대규모 포인터 연결망의 19/3245, 39/3245, 78/3245, 87/3245, 116/3245 등 여러 위치에서 멈춘다는 보고를 조사했습니다. 특정 C 대입문이나 포인터 배선만의 문제가 아니라 공통 재생기의 시간 환산 오차를 재현했습니다.

## 원인

화면은 한 명령을 넘지 않도록 `(1-progress) * duration / speed`로 남은 벽시계 시간을 제한하고, Playback.advance는 그 시간에 speed를 곱합니다. 두 계산 사이의 소수점 오차 때문에 남은 시간이 필요한 시간보다 극소량 작아질 수 있었습니다.

기존 코드는 이 경우 부분 진행으로 돌아갔지만, 더한 progress는 반올림되어 정확히 1이 되기도 했습니다. 명령 완료 처리는 수행되지 않았습니다. 다음 프레임은 남은 시간을 0으로 계산하고 advance(0)는 즉시 반환하므로 같은 명령에서 영구 정지했습니다. 원본 포인터 기록을 가변 프레임 시간으로 재생했을 때 3×에서 cursor 19, 1.1×에서 cursor 46 등으로 재현됐습니다.

## 수정 범위

- `src/animation/playback.js`: 부동소수점 정밀도 범위의 차이는 완료 경계로 처리하고 잔여 시간을 0 이상으로 제한합니다.
- 이미 progress가 1인 경계는 재생 중이라면 0ms에서도 정확히 한 번 완료할 수 있게 합니다. 일반 일시정지와 아직 남은 실제 연출 시간은 유지합니다.
- 속도·사건 시간·명령 순서·배선 준비 조건은 바꾸지 않습니다. C 코드·중간언어 생성 모델·자료구조 추론기는 수정하지 않습니다.

## 확인

- 새 경계 검사 4개 중 수정 전 3개 실패를 확인한 뒤 수정 후 모두 통과했습니다.
- 경계·기존 재생·사건 시간선·전달 단계 관련 검사 20개와 빌드가 통과했습니다.
- 기존 실제 포인터 실행 기록에서 0.1×~4×의 40개 속도로 보고된 위치를 포함한 처음 150개 명령을 통과했습니다.
- 같은 기록의 3× 재생은 3,245개 명령을 완료하고 기존 출력 `3339\n`을 유지했습니다. 이 확인을 위해 C 예제나 모델을 다시 실행하지 않았습니다.
- 현재 모델로 생성한 브라우저 예제에서도 3×로 19→20, 39→40, 78→79, 87→88, 116→117의 다섯 경계를 한 명령어 재생으로 통과했습니다. 배선 대기 상태는 해제된 상태였습니다.

이 수정은 명령 완료 경계의 영구 정지에 대한 것입니다. 별도로 관찰한 대규모 값 전달선 배치의 지연을 모두 해결했다고 의미하지 않습니다. Firefox의 직접 화면 읽기는 도구 정책 제한으로 사용할 수 없어, 브라우저 화면 확인은 지원되는 별도 재현 탭에서 진행했습니다.
