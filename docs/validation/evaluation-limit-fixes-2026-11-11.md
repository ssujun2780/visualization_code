# 평가 순서 LLVM 변환과 중단 WRITE 검사 보완

대상은 모델 분리 과정에서 발견한 두 실패입니다. 추론 규칙·UI·중간언어 사건 생성 로직은 변경하지 않았습니다.

## LLVM 오류의 원인과 공통 수정

`regex_equivalence.c`의 `nfa_compile`에서 Clang은 `assert` 실패 경로의 `unreachable` 뒤에 이름 없는 기본 블록을 출력했습니다. 해당 블록은 LLVM의 번호 공간에서 68번을 차지하지만 레이블 텍스트는 생략되어 있었습니다.

```llvm
  unreachable
  ; 이름 없는 블록: 원래 번호 68
  br label %lor.end
lor.end:
  %69 = phi i1 [ true, %while.end ], [ false, %68 ]
```

기존 평가 순서 변환은 `%68` 참조를 `%__cvm_evaluation_68`로 바꾸면서 블록 정의를 명시하지 않았습니다. 그래서 유효했던 원래 LLVM이 변환 뒤에는 정의되지 않은 블록을 참조했습니다. 실패한 조건이나 C 원본의 오류는 아니었습니다.

`scripts/model/evaluation-order.mjs`에서 이름 없는 인자·블록·값의 원래 번호를 재배치 전에 추적하고, 생략된 기본 블록의 레이블을 명시했습니다. 이후 정의와 참조를 함께 이름형으로 변경합니다. 기존 피연산자 의존성·단락 평가·조건 선택 규칙은 유지합니다. 문자열·인용된 이름·주석은 바꾸지 않고, 재배치하지 않은 함수는 원문 LLVM을 유지합니다. 특정 예제 이름·함수 이름·번호 68에 대한 분기는 없습니다.

`tests/ir-evaluation-blocks.test.js`는 번들 컴파일러로 원래 LLVM과 변환된 LLVM을 모두 검증합니다. 번호형 인자·암묵적 진입 블록·이름 있는 블록·도달 불가능한 PHI 선행 블록을 혼합했습니다. 별도 C 사례에서는 `assert`와 직접 `abort` 표현식, 좌→우·우→좌 실행의 값과 실제 호출 순서를 검사합니다.

## WRITE 검사 수정의 근거

기존 바이트 한도 검사는 모든 WRITE에 `value.decimal`이 있다고 가정했습니다. 실제로는 마지막 WRITE의 attempt만 기록되고 commit이 한도에 걸릴 수 있습니다. 공개 기록은 이 경우 `phase: incomplete`, 완료값 없음, 계산된 대입 입력 보존이라는 기존 계약을 따르고 있었습니다.

생성 모델을 바꾸지 않고 `tests/ir-partial-limits.test.js`의 검사를 보완했습니다.

- 완료 WRITE의 값은 여전히 필수입니다. 예제의 `n=0; n=(n+1)%7`에서 직접 얻은 값 순서와 원시 commit 기록을 각각 비교합니다.
- 미완료 WRITE는 완료값이 없어야 하며, 원시 attempt·계산된 다음 입력·값 생산자의 선행 관계를 확인합니다.
- 공개 객체와 원시 객체의 writer가 각각 마지막 완료 사건을 가리키는지 확인합니다. 미완료 입력을 확정 저장값으로 사용하지 않습니다.
- 같은 유한 반복 코드를 쓰기 시도 직후와 완료 관측 직후에 각각 중단합니다. 전자는 입력 1과 마지막 관측값 0, 후자는 완료값 1을 기대합니다. 사건 ID를 고정하지 않고 원시 기록의 대상·단계로 절단 지점을 찾습니다.

저장 뒤의 관측 콜백에서 한도에 걸릴 수 있으므로, 미완료 기록만 보고 실제 저장 명령이 실행되지 않았다고 주장하지 않습니다. 확인하는 것은 기록된 실행의 범위와 마지막으로 관측된 저장 상태입니다.

## 검증 결과와 예산

- 평가 순서 기존 검사 17개, 블록 변형 3개, 기록 한도·복구·저장 검사 4개, 모델 분리 검사 6개: **30개 모두 통과**.
- 원래 정규식 소스·입력 `ab\na(b|c)\n` 유지: 실행 완료, 종료 코드 0, 공개 사건 **30,672개**, 원시 관찰 **61,344개**, IR gap·미해명 관찰·진단 모두 없음.
- 원래 예상 출력 유지: `NOT EQUIVALENT`, `WITNESS "ac"`, `LENGTH 2`, `ACCEPTED_BY 2`.
- 선택적 추론도 완료: 후보 554개, 간선이 있는 과거 레코드 관계 5개, 추론 진단 없음. 기존 관계 조건을 제거하지 않았습니다.

큰 정규식 사례의 원시 기록은 34,784,031바이트여서 기본 16MiB 예산으로는 완료되지 않습니다. 이 회귀 검사에만 64MiB 기록 예산과 별도 추론 120초 예산을 지정했습니다. 기본 API 제한·사용자 C·예상 출력·관계 조건은 유지했습니다. 최종 생성+추론 확인은 약 57초였으며, 25초 추론 예산으로 실행한 앞선 검사는 마지막 관계 조건에 도달하지 못했습니다.

전체 예제 집합은 실행하지 않았습니다. 근거는 `test-results/evaluation-limit-fixes-2026-11-11/`의 `compiler.ll`, `ordered-before.ll`, `compile-before.txt`, `limit-before.json`, `focused.txt`, `regex-after.json`입니다. `regex.txt`는 예산을 늘리기 전 시도의 실패 로그이며 최종 결과는 `regex-after.json`에 있습니다.
