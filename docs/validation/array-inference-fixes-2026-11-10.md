# 배열 추론의 네 가지 공통 보완

2026-11-10. [직전 점검](array-inference-audit-2026-11-10.md)의 네 가지 보완점을 적용했습니다. 변경 범위는 공통 추론기와 관련 검사입니다. 중간언어 생성·계측 코드와 UI는 수정하지 않았습니다.

## 적용한 규칙

1. **별도 관리 변수와 실제 배열 보기 연결**
   - `separate-array-structure`와 `dynamic-array`의 저장소 ID·바이트 오프셋·관리 변수 슬롯을 배열 보기와 연결합니다.
   - 길이 숫자만으로 앞부분을 사용 중이라고 판단하지 않습니다. 기존 길이를 읽어 계산한 목적지에 실제 쓰기가 있었고, 그 범위가 늘어난 길이와 일치해야 접두 사용 범위를 확정합니다.
   - 재할당은 기록된 `copiedFrom` 범위로만 기존 사용 범위를 계승합니다. 다른 저장소로 포인터를 바꾸면 이전 사용 범위를 계승하지 않습니다.
2. **묶음 쓰기와 여러 원소 수 변경**
   - AST의 `used + n <= cap`, `n <= cap - used` 같은 덧셈·뺄셈 관계로 관리 역할 후보를 찾습니다. 실제 관찰로 역할과 범위를 검증합니다.
   - `base + used`의 자료형·원소 크기, 실제 주소 계산 의존성, WRITE 범위, 동일 관리 변수의 전후 값을 연결합니다. `memcpy`라는 이름을 기준으로 분기하지 않습니다.
   - 증가분 전체가 쓰였는지 확인하며, 이미 입증된 접두 범위를 줄일 때는 버리는 값을 읽지 않아도 됩니다. 값과 길이 갱신 사이에는 중간 상태를 남깁니다.
3. **저장소 수명과 관리 역할 수명 분리**
   - 잠재적 관리 변수였던 반복 인덱스가 죽어도 배열 보기 자체는 살아 있습니다.
   - 선택한 관리 역할이 죽으면 범위·순서에 그 값을 계속 사용하지 않습니다. 점유 배열에서도 개수 변수 소멸을 반영하면서 실제 저장소와 살아 있는 점유 표시를 보존합니다.
4. **희소 배열의 점유 집합**
   - 동일 인덱스의 표시 값을 검사한 뒤 데이터를 읽는 관계, 표시의 추가·제거 변화, 같은 분기에서 증감한 개수 슬롯을 연결합니다.
   - 두 배열이 같은 인덱스를 쓰거나 표시 값이 0/1이라는 사실만으로 점유 배열이라고 확정하지 않습니다. 반대 의미의 표시나 다른 정수 값도 실제 조건으로 판별합니다.
   - `activeIndices`와 비활성 범위를 제공하지만 `logicalOrder`는 미확정으로 둡니다. 원소 수 2를 앞의 두 칸으로 바꾸지 않습니다.
   - 필요한 관찰이 모이기 전 상태로 근거를 소급하지 않습니다. 표시와 개수가 불일치하면 `intermediate`, 개수 역할이 소멸하면 `partial`로 남깁니다.

구현: `scripts/model/array-views.mjs`, `embedded-array-views.mjs`, `structure-inference.mjs`, 새 `array-membership.mjs`, `array-occupancy.mjs`.

- 별도 배열과 반전된 비불리언 표시(`9`: 비점유, `-2`: 점유)에서도 점유 집합을 확인했습니다.

- 점유 근거를 이전 시점에 소급하지 않는지, 개수 불일치와 개수 변수 수명 종료를 구별하는지 확인했습니다.

재사용 검사에는 원래 예측과 수정 전 실행 기록의 해시를 `example/c/codex_code/array-inference-audit-2026-11-10/expected.json`으로 옮겼습니다. 수정 후 추론에 맞춰 기대값을 바꾸지 않았으며, 큰 임시 결과 파일 없이도 같은 기준으로 검사할 수 있습니다.

### 남겨 둔 No8 고정 사건 수 불일치

`tests/ir-array-metadata.test.js`의 기존 No8 검사는 사건 수 610을 기대하지만 현재 생성 결과는 641입니다. CALC도 기대 124, 실제 125입니다. 원래 검사는 첫 사건 수 비교에서 실패하므로 이후 단언까지 통과했다고 보고하지 않습니다.

저장된 실제 관찰 기록을 `recordObservedTrace(..., {inference:false})`로 변환해도 641개입니다. 추론을 켠 결과와 끈 결과의 전체 사건 JSON 해시가 동일합니다. 따라서 이번 추론 보완으로 늘어난 사건은 아닙니다. 고정 수 검사를 수정하거나 중간언어 생성 모델을 고치지 않았으며, 이 기존 검사와 현재 생성 결과의 불일치는 별도 확인 대상으로 남겼습니다.

## 지원 범위와 미확정 처리

이 규칙은 관찰된 실행에서 사용 범위를 뒷받침하는 관계를 찾습니다. 임의의 모든 컨테이너 구현이나 개발 의도를 증명하지 않습니다. 접두 범위의 열거 순서는 LIFO/FIFO 제거 정책과 별개입니다.

점유 규칙은 현재 동일 인덱스 접근과 단순 참거짓·부정·등호·부등호 조건, 개수 증감의 양방향 근거를 요구합니다. 삭제가 전혀 관찰되지 않았거나 후보가 여러 개면 확정을 보류합니다. 비트로 압축한 표시, 복합 점유 조건은 이 새 규칙의 확인 범위 밖입니다. 점유 추론의 현재 분석 한도는 표시 원소 4,096개, 원소 폭 8바이트입니다. 이를 넘는 경우 물리 배열 정보는 유지하고 점유 추론을 생략합니다.
