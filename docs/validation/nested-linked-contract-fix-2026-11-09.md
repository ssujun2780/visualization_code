# 중첩 목록: 검사 복원과 공통 추론기 보완

## 이전 판단의 정정

`linked-structure` 누락은 실제 추론기 문제였습니다. 존재 조건을 원시 레코드 개수 검사로 교체했던 것은 동등한 정정이 아니었습니다. 이번에는 원래 조건을 복원하고 C 코드로 정한 기대 관계를 강화한 뒤 추론기를 수정했습니다. 기존 실패 로그와 교체 후 통과 로그는 삭제하지 않았습니다.

## 독립적인 검사 기준

원래 C 예제의 기대 관계는 다음과 같습니다. 이 순서는 추론 결과에서 가져오지 않습니다.

```text
b[0] -> b[1] -> NULL
b[0].items -> a[0] -> a[1] -> NULL
b[1].items -> a[2] -> a[3] -> NULL
```

`tests/helpers/nested-link-contract.mjs`는 C에서 지정한 배열 이름·원소 번호·필드 이름을 받습니다. 실행 객체와 컴파일러 자료형에서 객체 ID와 ABI 바이트 위치만 구하고 다음을 대조합니다.

- 각 원시 간선의 출발 객체·필드 위치·대상 객체·원소 오프셋.
- 외부 구성원 ID와 각 내부 목록의 구성원 ID 전체 및 정확한 순서.
- 진입 간선 ID, 순서대로 나열한 연결 간선 ID, 마지막 NULL 간선과 관측 사건.
- 바깥 목록과 각 내부 목록에 독립적으로 사용할 수 있는 `linked-structure` 및 그 연결 순서·종료 상태.
- 빈 목록은 실제 소유자의 머리 포인터 위치에서 NULL로 남고, 임시 순회 변수의 소멸로 함께 사라지지 않는지.

단순 `[2, 2]` 길이 비교나 원시 노드 개수만으로 통과할 수 없습니다. 검사 자체의 음성 대조로 구성원 교환·순서 뒤집기·NULL을 cycle로 변경·필수 목록 후보 삭제를 각각 주입했습니다. 네 가지 모두 검사가 거부합니다. 코드·값·길이는 맞더라도 관계가 틀리면 실패합니다.

## 공통 원인과 수정

생산 코드 변경은 `scripts/model/linked-views.mjs`와 `scripts/model/composed-container-views.mjs` 두 파일입니다.

1. **순회 시작점 누락**: AST에는 `p = p->link`, `q = q->link`가 있었지만, 실행 추론은 별도 머리 변수·호출 인자·인덱스 포인터 모음 위주로 루트를 등록했습니다. 직접 배열 주소와 이종 구조체의 머리 필드는 빠졌습니다. 컴파일러의 순회 관계와 실제 cursor WRITE 값의 출처를 연결해 실제 시작 객체 또는 포인터 슬롯을 등록합니다. 같은 활성 호출·순회 역할군에서 값을 가져오는 이동은 새 루트로 만들지 않습니다.
2. **임시 별칭 수명**: 머리 필드를 별칭에 담은 뒤 순회하면 임시 변수만 루트가 되어 종료 후 목록을 놓쳤습니다. 실제 READ 출처를 따라 가장 가까운 구조체 필드·배열 슬롯을 사용합니다. 이름이나 값의 유사성으로 연결하지 않습니다.
3. **합성 정보 부족**: 구성원 배열에 더해 `entryEdgeId`, `linkEdgeIds`, `termination`을 기록합니다. 실제 cycle·unknown·종료된 대상은 NULL로 바꾸지 않습니다. 배타적 소유권을 주장하지 않습니다.
4. **센티널 관측 이력**: 종료 조건 확인 후 늦게 등록한 루트도 앞서 관측한 필드 역할을 이어받습니다. 센티널의 방향 필드와 순회 진행 별칭으로 불필요한 루트를 만들지 않습니다. 기존 양방향 센티널 검사는 그대로 유지했습니다.
5. **빈 목록의 역할 확정**: 연결 자체가 관측되지 않은 필드는 `candidateRoles`에 보존합니다. `roles`는 관측된 연결 또는 필드 읽기가 있는 역할이며 `traversalRoles`는 읽기로 확인한 역할입니다. 기존 빈 목록의 `roles.length === 0` 검사를 유지하고 후보 정보 보존도 추가 검사했습니다. 내부 상태의 미관측 연결은 계속 unknown으로 남습니다.

## 변형 및 검사 결과

원래 예제 외에 필드 순서·이름·물리 원소 위치를 바꾼 변형을 추가했습니다. 모든 payload가 9여도 다음 관계를 구별합니다.

```text
y[2] -> y[0] -> y[1] -> NULL
y[2].first -> x[5] -> x[1] -> x[4] -> NULL
y[0].first -> x[2] -> x[0] -> NULL
y[1].first -> NULL
```

이 변형은 수정 전 실제로 루트를 놓쳤습니다. 기대 관계를 변경하지 않고 별칭 출처 추적을 고쳤습니다. 별도 코드에서는 실행 중 NULL 연결을 cycle로 바꾼 다음 복구하고 머리를 NULL로 바꾸는 세 시점을 확인했습니다. 순회는 횟수로 제한하므로 정상 종료합니다. 포인터 저장만 있고 순회 근거가 없는 반례는 연결 목록을 임의로 만들지 않습니다.

관련 **26개 고유 검사 통과**입니다. 전체 예제는 재실행하지 않았습니다.

- 연결 루트·별칭·역할·투영·루트 모음과 새 진입 계약: 23개 (`final-linked.log`).
- 원래 중첩 목록과 이종 간선 합성: 3개. 빈 목록의 추가 단언도 재확인 (`final-composed.log`, 4개 중 1개는 앞선 묶음과 중복).
- 구성원·순서·종료·후보 삭제의 검사 음성 대조 4개는 새 진입 계약 검사 안에 포함됩니다.

중간언어 생성·계측 파일은 작업 시작 해시와 동일합니다. 원래 예제의 수정 전후 `events`, `objects`, `frames`, `resultDeliveries`도 각각 SHA-256이 동일합니다. 추론 전후 입력 plan/trace가 바뀌지 않는 검사도 유지했습니다. UI·애니메이션은 변경하지 않았습니다.

실행 자료는 `test-results/codex_code-results/nested-link-contract-fix-2026-11-09/`에 있습니다. `before.log`, `variants-before-alias-fix.log`, `final-linked.log`, `final-composed.log`, `model-boundary-and-ir.json`, `variants/`를 함께 보시면 수정 전 실패와 수정 후 결과를 구별할 수 있습니다. 각 변형의 `inference-final.json`은 최종 추론 코드로 보존된 plan/trace를 읽기 전용 재계산한 결과입니다. 원래 예제의 연결 목록 후보는 0개에서 3개로 복원되었습니다.
