# 통합 감사 19건 원인과 수정

2026-11-14. [원래 감사 목록](integration-2026-11-14-audit.md)의 19건을 대상으로 수정했습니다. 전체 1,231건을 다시 실행한 결과가 아닙니다.

## 범위와 계약

- 실제 읽은 계약: `presentation.md`, `c-model.md`, `evaluation-order.md`, `inference-model.md`, `structure-presentation-policy.md`, `execution-relations.md`, `graph-worklist-relations.md`, `structure-common-fixes-2026-11-09.md`의 관련 절.
- 적용하는 필수 조건: C의 필수 순서와 실제 값/수명 보존, 생성과 추론의 읽기 전용 경계, 시점별 관계 근거, 관측 부족과 한도 구분, 선택 범위/사용자 지정 우선.
- 모델 변경은 복합 리터럴의 LLVM 평가 순서 오류에 한정합니다. 추론기가 중간언어를 바꾸도록 연결하지 않았습니다. UI·애니메이션은 변경하거나 화면 검증하지 않았습니다.
- 예제 파일명·변수명·정답에 따른 분기를 넣지 않았습니다. 테스트의 값·원소 식별자·연결 순서·NULL 종료·분기/수명 조건은 유지했습니다. 계약이 바뀐 검사 전제의 수정은 아래에 별도로 공개합니다.

## 검사 전제 수정의 범위

결과에 맞춰 값이나 정답을 교체한 것이 아닙니다. 아래 변경은 현재 문서/공개 API 계약과 대조했습니다.

1. 생성/추론 분리 이후 추론을 요구하는 검사는 명시적으로 추론 헬퍼를 호출합니다. 원시 생성기 안에 추론을 다시 넣지 않습니다.
2. 이력 한도 검사는 생략 구간과 최신 보관 상태를 각각 검사합니다. 한도나 incomplete 검사를 제거하지 않습니다.
3. No6는 READ 배열의 첫 원소라는 위치 가정 대신 실제 CALC 입력 연결로 피연산자를 찾습니다.
4. 행렬 검사는 기존 operand-pair와 현재 gated-access 근거를 모두 허용하되, 정확한 간선 수/속성과 간선별 복수 근거를 추가 검사합니다.
5. 루트 추천은 내부 후보 종류가 반드시 linked-view라는 가정 대신 공개 추천의 실제 구성원 ID와 원본 배열 범위를 검사합니다. 양쪽 루트마다 원래 기대한 인덱스 세 개를 정확히 비교합니다.
6. 대형 예제는 실행 완료와 추론 완료를 구분합니다. 기본 `maxStates=2048`, 포인터 루트 한도 256을 변경하지 않았으므로 추론은 `partial`입니다. 허용하는 진단을 `structure-inference-limit`의 세 자원으로 한정하고, 생략 수·후보 ID·보관 수·공백 끝/최신 상태 일치를 검사합니다. 시간 초과·내부 예외는 통과하지 못합니다. JSON 검사는 문서화된 `encodeInference` 공유 직렬화를 사용합니다.

## 시간과 결과 보존

동일하게 저장한 30,652개 공개 사건의 정규식 실행 기록을 사용한 단계별 측정입니다. 컴파일 시간과 Worker 전송은 제외합니다. 단일 측정이므로 장비 공통 성능 보장은 아닙니다.

- 최종 컴파일·실행·Worker 추론·검사를 포함한 해당 테스트는 약 39.9초였습니다.
- 성능 전용 세 변경은 저장된 11개 실행의 33개 단계 결과를 이전 구현과 전체 JSON SHA-256으로 비교했습니다. 전부 일치했고, 13개 결과는 비어 있지 않았습니다. 의도한 버그 수정까지 이전 출력과 같다고 주장하지 않습니다.
- 기록을 삭제하거나 한도를 늘려 시간을 줄이지 않았습니다. 과거/미래 근거, 객체 수명, 공유 저장소와 같은 역할의 최초 간선 선택을 보존합니다.
- 프로파일러 실행의 최대 RSS는 약 1.93GiB였습니다. 이번 결과로 저메모리 환경의 적합성을 보장하지 않습니다. 메모리 상한과 기본 25초 Worker 예산 안의 처리 완료도 별도 과제입니다.
