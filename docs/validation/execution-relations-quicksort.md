## 코드와 사전 예상

이 코드는 원소 6개 `{5,2,5,1,4,2}`를 하나의 배열에서 정렬합니다. 함수 포인터로 비교 함수를 호출하고, 세 대입으로 교환합니다. 반열린 구간 `[left,right)`의 마지막 원소를 피벗으로 사용하며 작은 원소만 왼쪽으로 옮깁니다. 변수·함수 이름은 난수화되어 있습니다.

| 코드 작업 | 예상 관계 | 실제 결과 |
| --- | --- | --- |
| 정렬 호출 | 7회, 부모·자식 호출로 분리 | 일치 |
| 분할 호출 | 3회, subtree 배열 구간 `[0,6)`·`[2,6)`·`[3,6)` | 바이트 `[0,24)`·`[8,24)`·`[12,24)`로 일치 |
| 함수 포인터 비교 | 10회, 각 실제 비교 함수의 activation 연결 | 일치. 비교 반환 `1,0,1,-1,1,1,1,1,0,-1` |
| 교환 호출 | 5회, 인덱스 `(0,3),(1,5),(2,5),(3,4),(4,5)` | 실제 인자 참조가 같은 배열의 해당 오프셋을 가리킴 |
| 교환 내부 | `temp=*a; *a=*b; *b=temp;`의 READ→WRITE 세 단계 | 15개 복사 관계, 그중 배열 쓰기는 10개. 임시 변수 복사를 제거하지 않음 |
| 첫 교환의 접근 | 원소 0·3만 접근 | `[0,4)`·`[12,16)`. 중간의 미접근 영역을 채우지 않음 |
| 재귀 종료 | 4개 호출은 원소를 읽지 않음 | 전달된 배열 참조만 연결하며 구간을 정수 인자로 추측하지 않음 |
| 최종 출력/원소 정체성 | 값 `1 2 2 4 5 5`, 최초 입력 인덱스 `3,5,1,4,2,0` | 값·정체성 모두 일치 |

예상값·소스 해시·검증 계약을 API 실행 전에 prediction.json에 저장합니다. 최종 정체성은 추론된 바이트 복사 간선을 시간순으로 추적해 검사합니다. 같은 값 2 또는 5의 원소를 같다고 합치지 않습니다. 기대값을 실제 결과에 맞춰 바꾸지 않았습니다.

## 현재 작업 문맥

첫 비교에서는 main→정렬→분할→비교 호출 경로와 실제 배열 원소, 분할 함수의 피벗 상자, 비교식의 원본 source가 함께 조회됩니다. 피벗은 부모의 실제 지역변수이며 새 배열이 아닙니다.

교환 도중에는 해당 호출의 임시 변수와 두 배열 위치를 유지합니다. 정리 사건 이후에는 교환 지역변수를 현재 프레임에서 제외하고 완료된 호출을 history로 분리합니다. 모두 기존 query의 동일 규칙으로 확인했으며 화면 동시 가시성 검사는 아닙니다.
