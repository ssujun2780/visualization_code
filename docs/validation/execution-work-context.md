# 현재 사건의 작업 문맥 조회 검증

2026-11-11. 사용자 승인 범위는 현재 실행 위치에서 관련 배열·주변 연산·호출·코드 위치를 묶는 조회 기능입니다. 화면·배치·중간언어 생성·자료구조 추론기는 변경하지 않았습니다.

실제로 읽은 계약은 AGENTS.md, presentation.md, execution-relations.md의 R-02/R-04/R-05/R-06/R-07 및 W-01/W-03/W-04/W-05/W-06, inference-model.md의 읽기 전용 경계, design-implementation-template.md입니다. 이번에 승인된 작업 문맥 조회만 구현하며 화면 표현 초안 전체를 구현 승인으로 취급하지 않습니다.

## 예상과 실제

예상은 테스트 코드에 API 조회 전에 고정했습니다. 회의 입력은 기존과 같은 `(5,7), (1,2), (3,5), (2,3)`입니다. 검증에는 앞서 생성한 같은 소스의 plan/trace를 재사용했습니다. 깨끗한 체크아웃에서 저장 기록이 없으면 해당 사례 하나만 생성하도록 테스트를 구성했습니다.

| 시점 | 미리 정한 기대 | 검사 결과 |
| --- | --- | --- |
| 첫 병합의 첫 비교 | end[0]=7과 end[1]=2, 바이트 읽기 `[4,8)`·`[12,16)`, i=0/j=1/k=0 | 관찰 사건 ID로 값·범위 일치. current 호출 경로 main→정렬→정렬→병합과 정확한 source 위치 일치 |
| 첫 목적지 필드 복사 직후 | 원본의 관측된 읽기 `[4,16)`, 임시 배열의 쓰기 `[0,4)` | 실제 prefix와 focus 범위 일치. 이후 end 필드 쓰기나 최종 함수 구간은 노출하지 않음 |
| 첫 병합 frame.end 직후 | 병합 호출·그 지역변수는 현재 대상에서 제외, 부모 프레임이 current | 완료 호출·종료 저장소는 history, 공유 배열은 계속 live |
| 마지막 병합 도중 | 앞선 두 정렬은 종료된 관련 호출, 마지막 병합만 current | 완료된 두 하위 구간은 history 관계로 조회하며 현재 지역변수는 마지막 activation ID만 사용 |
| 원본 배열 free 직후 | 원본 객체를 현재 storage에서 제외하고 기존 포인터는 종료된 대상을 참조 | dangling 대상 수명은 ended, 이전 객체와 다른 주소 재사용 세대는 연결하지 않음 |

API는 값 실행기가 아닙니다. i/j/k의 숫자는 `latestObservation.executionId`로 원본 사건에서 검증합니다. 출력은 메모리 전체 값·이전값 복원 상태를 만들지 않으며 일부 필드의 WRITE를 정상 구조체 전체 복사로 바꾸지 않습니다.

## 관련 회귀와 반례

- 임의 시점 앞뒤 이동, 조회 반환값 변경, 입력 JSON 불변과 호출자 비동결.
- 원본 객체의 최종 lifecycle/initializationRanges 및 프레임의 최종 block/ended를 바꿔도 앞 시점의 결과 불변.
- 같은 시점에서 전체 기록과 prefix 기록의 조회 결과 일치. 미래 생산자를 입력 간선에 넣어도 unavailable이며 미래 값이 나타나지 않음.
- 모든 객체/함수 표시 이름을 동일하게 바꾸고 source.expression 텍스트를 제거해도 ID·구간·의존 관계 묶음은 동일.
- 포인터 재대입 후 새 참조 사용, 참조 없는 덮어쓰기 후 과거 인자 연결 무효화, one-past를 역참조로 표시하지 않음.
- 반환 후 지역변수 소멸, 같은 숫자 주소의 새 객체 생성, 미완료 WRITE 시도와 ERROR/fault에서 완결된 쓰기·자동 정리를 발명하지 않음.
- 호출자에게 반환값을 저장하는 사건이 피호출자 정리 전에 기록된 변형에서도 사건 소유 프레임과 resident-callee 공간을 함께 보존. 기존/다른 반환 순서로 재정렬하지 않음.
- 분석 실패 결과에서도 원본 사건 조회는 가능하고 analysisStatus로 실패를 구별. 다른 실행의 결과는 거부.
- 기존 뼈대 회귀로 Worker·CLI·의존성 경계 유지. 조회기는 컴파일러·자료구조 추론·재생기를 호출하지 않음.
