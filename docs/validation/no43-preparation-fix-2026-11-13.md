# No43 재생 준비 시간 초과

## 범위와 계약

실제 신고 문구는 “자료구조 재생 준비 시간이 초과되었습니다”입니다. 이는 `prepare-playback.js`의 **180초 Worker 제한**이며, 실행 기록기의 16MiB 관찰 예산과 다릅니다. CLI 실행 완료만 확인해서는 이 오류 해결을 증명할 수 없습니다.

읽은 계약: `presentation.md`의 책임 경계, `prepared-scene.md` PS-01~04, `execution-storage.md` EF-01~04, `inference-model.md`의 읽기 전용 소비자, `structure-composition.md` RC-01~03 및 `bst-inference.md`의 저장 관계·조건 분리. 관련 실행 기록·수명 및 애니메이션 준비 계약도 확인했습니다.

이번 작업은 공통 추론기와 조회·준비 어댑터를 수정합니다. 중간언어 생성 모델, 예제 C 코드, 기록 예산, 준비 제한 시간은 변경하지 않습니다. 전체 예제 모음은 실행하지 않았습니다.

## 측정

현재 No43 기본 CLI 실행은 completed/exit 0, 공개 사건 **29,474개**, 객체 **3,158개**입니다. 공개 `definitions.json`·`plan.json`·`trace.json` 합계는 **21,741,063바이트**입니다. 이 크기는 이번 준비 최적화에서 줄였다는 수치가 아니라 현재 기록 형식의 측정값입니다.

1. 수정 전 추론은 **143.0초**였습니다. 추론 후 준비만 따로 측정해도 **90초 내 완료되지 않았습니다**. 기존 추론은 두 예외 때문에 일부 단계를 제외한 411개 후보를 반환했습니다.
2. 첫 성능 수정 후 동일한 411개 결과는 전체가 같았으며, 추론 **34.6초**, 준비 **3.28초**였습니다. 이 수치에는 예외 때문에 빠진 단계가 있으므로 최종 완료 수치로 사용하지 않습니다.
3. 두 예외를 고치고 새로 수행되는 공통 경로도 최적화했습니다. 추론은 **35.76초**, 후보는 499개입니다. **기존 411개 후보의 모든 내용은 그대로**이며, 이전에 예외로 누락된 저장 그래프·종속 관계·트리 조건 등 88개가 추가되었습니다.
4. 제품의 `prepared-worker.js`를 그대로 실행하여 **128.55초에 `ready`**를 받았습니다. 입력은 기본 CLI의 완성된 공개 기록, 출력은 **31개 저장소 트랙, 5,671,680바이트**입니다. 제한은 180초 그대로입니다. 이 측정은 Node Worker 실행이며 Firefox의 실측값은 아닙니다.
5. 웹과 같은 요청과 Accept 헤더를 실제 세션 API 미들웨어에 전달했습니다. 실행과 API 직렬화는 **16.45초**, 응답은 **21,623,423바이트**(`execution-definitions-v2`, HTTP 상태값 200)였습니다. 실제 JSON을 파싱·복원한 뒤 제품 준비 Worker에 전달하여 **144.72초에 `ready`**를 받았습니다. 사건 29,474개·객체 3,158개·준비 트랙 31개·준비 JSON 5,671,680바이트를 확인했습니다. 실행/응답 시간은 준비 Worker의 180초 제한에 포함되지 않습니다.

## 관련 검사

- 배열 하위 객체·BST 단일/복합 키·포인터 트리 공통 회귀: **29개 통과**.
- 검색 세션·경계 축소·기존 재생 준비·추론 연결: 최종 수정 후 **17개 통과**.
- 객체 수명과 이력 보존: **2개 통과**. 원래 18개 묶음 중 위와 중복되는 16개는 이중 집계하지 않습니다.
- Vite 제품 빌드 통과. 기존 큰 청크 경고는 남습니다.

## 남은 한계와 근거

- 예외 두 건은 없어졌지만, 새로 실행되는 추론 경로에서 **후보 루트 256개 / 후보별 상태 이력 한도** 경고가 남습니다. 이는 중간언어 실행 중단이나 180초 준비 실패가 아닙니다. 이력 생략 구간은 미확인으로 유지합니다. 모든 추론 시점을 무제한 보관한다고 주장하지 않습니다.
- 브라우저 화면의 가독성·버튼 조작·Firefox 실제 소요 시간은 이번 검사로 확인하지 않았습니다.
- 로컬 HTTP 소켓 검사 시 `connect EACCES 127.0.0.1`이 발생하여, 실제 세션 API 미들웨어에 같은 요청/Accept 헤더를 전달하고 실제 JSON 직렬화·복원 뒤 제품 Worker로 연결하는 검증을 사용합니다. 네트워크 접속 자체를 검증했다고 주장하지 않습니다.
- 근거: `test-results/no43-preparation-fix/`의 `infer-report.json`, `prepare-report.json`, `semantic-comparison.json`, `worker-report.json`, `api-worker-report.json`, `diagnosis.json`, 프로파일과 재현 스크립트. 결과 파일은 작업 산출물이며 저장소에 강제로 추가하지 않습니다.
