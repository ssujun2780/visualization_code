# 입력 안내 크기와 컴파일러 보조 저장소 표시

2026-11-11. 사용자 지적에 따라 누락된 보조 저장소 숨김을 적용하고, 입력 안내만 실제 값보다 작게 표시했습니다.

적용 계약은 `visualization.md` 공간·대상, `ui.md` 입출력, `animation.md`의 기록 보존과 실행/표현 분리입니다. 생성 모델과 추론기는 수정하지 않습니다. 기존 선언·초기화·복사·출력 명령을 삭제하지 않고 화면 투영만 바꿉니다.

| 계약/요구 | 공통 변경 위치 | 검증 근거 | 결과·제한 |
| --- | --- | --- | --- |
| 작은 안내, 큰 실제 값 | `style.css`, `input-field.js`, `main.js`: placeholder 및 입력 빈 상태만 작은 글자로 구분 | 실제 화면의 입력 대기에서 안내 폰트가 실제 값 폰트보다 작고, `10 20` 입력 후 빈 상태 클래스 해제 확인 | 실제 값·출력 폰트 유지 |
| 보조 상자 숨김 | `source-storage.js`, `playback.js`: 상수 정적 저장소의 실제 생성 사건과 원본 선언 연결로 분류, 표시 객체에서 제외 | 초기화 보조 상수·포맷 문자열이 배치에서 빠지고 사용자 전역/static/const/배열과 출력 `10 AB 2 2`는 유지. 원본 plan/trace 직렬화 불변 | 이름 패턴 사용 안 함. 분류 근거 부족 시 보존 |
| 연결과 실제 상태 보존 | 현재 살아 있는 사용자 포인터에서 도달하는 보조 저장소는 일반 이름으로 표시 | `p="Hello"` 전후 시점에서 대상 표시 여부·문자열 내용·연결 확인. `p=NULL` 뒤 화면에서 숨겨도 실제 저장소는 살아 있음 | 미래 포인터 상태로 미리 노출하지 않음 |
| 숨긴 출발점 처리 | `canvas.js`: 숨긴 내부 저장소에 해당하는 전달선만 표시 경로에서 제외 | 보조 복사 출발점 판정 검사와 기존 계산·함수 반환·선택·포인터 배선 회귀 검사 | 가상 출발 상자나 추가 실행 사건 생성 없음 |

관련 검사 20개 및 프로덕션 빌드 통과. 전체 예제는 재실행하지 않았습니다. 기존 Monaco 번들 크기 경고는 남습니다. 화면 검증은 입력 `10 20`, 전역 `n`·정적 `count`, 지역 배열 초기화와 printf를 함께 사용하는 코드로 수행했습니다. 화면 자료: `input-hints-source-storage-verified.png`.

후속 정정: 입력란의 placeholder만 작고 타이핑 글자는 커지는 문제를 수정했습니다. `ui.md`의 입력 표시 규칙에 따라 textarea 본문도 안내와 같은 작은 크기로 맞췄습니다. 실제 브라우저에서 빈 입력·안내·타이핑 후 글자가 모두 16.9865px이고, 도착한 입력·출력은 기존 22.0825px임을 확인했습니다(확대율에 따라 수치는 달라짐). 실행·모델 변경이나 새 테스트 추가 없이 CSS·설명만 수정했고 빌드가 통과했습니다. 검증 입력 초안은 복원했습니다. 화면 자료: `input-draft-font-verified.png`.
