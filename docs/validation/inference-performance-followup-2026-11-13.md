## 기존 2건의 원인과 수정

기존 코드는 관측된 반환 READ의 표현식을 **함수 ID별**로 모은 후 `origins(CallExpr)`에서 모든 호출의 인자를 대입했습니다. 한 호출에서 특정 포인터를 반환했다는 관측을 함수 전체의 정적 반환 별칭 증명처럼 사용한 것이 문제였습니다. `identity(seed)`의 반환을 받은 변수가 실제 루트가 될 수 있다는 사실과, `seed`까지 정적 선언 경로로 추정할 수 있다는 주장은 구분해야 합니다.

정적 출처 탐색은 선언 대입과 직접 호출의 인자→매개변수 경로를 유지하고 호출 결과에서 멈춥니다. 수신 변수/매개변수의 실제 주소·부분 객체·수명은 그대로 사용합니다. 같은 값의 서로 다른 두 목록, 같은 함수의 분기별 다른 반환, 배열 내부 주소 반환도 확인했습니다.

단순히 모든 반환 경로를 끊으면 기존 `p = advance(p)` 순회가 사라지는 회귀가 발생했습니다. 이를 발견한 뒤 함수 단위 추측을 복구하지 않고, 실제 `resultDeliveries`와 값 출처로 다음 관계를 확인하도록 보완했습니다.

```c
N* advance(N* p, int yes) {
    N* selected = yes ? p->next : p;
    return selected;
}
N* wrap(N* p, int yes) {
    N* copy = advance(p, yes);
    return copy;
}
/* 실제 next 반환인 호출만 순회 근거가 됩니다. */
cur = wrap(cur, 0);
for (; cur; cur = wrap(cur, 1)) sum += cur->value;
```

원래 커서 읽기→그 커서가 가리킨 객체의 링크 필드 읽기→해당 호출들의 반환 전달→같은 커서 슬롯 대입이 연결되어야 합니다. `returnWitnesses`에 각 사건·호출 식별자와 완료 시점을 보관합니다. 반환 전달을 제거하거나 호출 활성화 식별자를 바꾼 반례에서는 순회를 만들어내지 않습니다. 첫 호출의 전달만 제거하면 이후 호출의 근거로 첫 호출을 채우지 않습니다. 후보와 시점별 추천은 구분하며 실제 역할 읽기 이전의 `observedRoleIds`는 비어 있습니다.

기존 frozen `returned-list`의 이력 한도와 실행 관계 연동 검사도 통과했습니다. 기존 실패 2건을 포함한 기존 검사 기대값은 변경하지 않았습니다.

## 갱신 범위와 임시 메모리

- 도달 노드, 종료된 대상, 경계, 미확인 링크의 시작 노드에 대한 역방향 의존성을 보관합니다. 링크 쓰기와 수명 변화가 해당 연결도에 영향을 줄 때만 다시 계산합니다. 새 합류·분리도 이전에 읽었던 시작 링크를 통해 무효화됩니다.
- 같은 할당 안의 다른 레코드를 구분합니다. 다만 루트 배열의 다른 슬롯 쓰기에도 역관계 근거 시점이 갱신되는 기존 경계는 유지합니다. 상태 이력 삭제와 연결도 재사용을 혼동하지 않습니다.
- 같은 그래프 버전의 연결 성분·역관계 후보·역할별 순서·임시 저장소 목록을 재사용합니다.
- 긴 문자열 서명과 중복 포장 객체를 줄이고 속성 키 스키마를 공유합니다. 해시는 후보 검색에만 사용하며 정확한 값 비교가 동등성을 결정합니다. 객체·범위·사건 ID를 지우지 않습니다.

8노드의 연결도 계산 호출은 **1,000회 → 154회**입니다. 호출 수 계측은 별도 검사본에서 수행했으며 생산 코드에 카운터를 넣지 않았습니다. 해당 두 결과의 확장 JSON 전체 해시는 동일합니다.

## 최종 검증과 남은 항목

- 관련 집중 검사 **55건 통과**, 추가 사례 **1건 미해결(TODO)**. 기존 예제 전체를 반복 실행하지 않았습니다.
- 추가 `indirect-return`은 함수 포인터를 호출하는 정상 C 코드이나 계측 LLVM이 함수 포인터 슬롯을 `%struct.N**`로 처리하여 컴파일에 실패합니다. 추론 전 단계이며 이번 범위 밖입니다. `completed` 기대값/검사는 그대로 두고 TODO로 명시했으며 통과에 포함하지 않았습니다. 원본 코드·예상·실제 실패 기록을 보존했습니다.
- 32노드는 기존과 동일하게 `partial`입니다. 포인터 루트 한도 256의 최초 시점 `x4364`/12회 진단, 공유 관계 이력 604개 생략/최초 `x7259`를 유지했습니다. 생략한 결과를 복원하거나 한도를 바꾸지 않았습니다.
- UI·애니메이션과 화면 가독성은 변경·검증하지 않았습니다.
