## 동일 입력 비교

입력은 이전에 저장한 `test-results/inference-semantic-extensions-2026-11-13/scale-{8,16,32}.execution.json`입니다. C 코드를 다시 컴파일하여 성능 입력을 바꾸지 않았습니다. 변경 전 추론기 전체와 공통 유틸리티를 작업 시작 시 별도 복사해 보관했습니다.

후보 55/106/225개, 연결 이력 1,236/5,127/22,335개를 모두 유지했습니다. 복원한 **전체 JSON의 바이트 해시가 변경 전과 동일**합니다. 이는 상태 사건, 포인터 재쓰기 출처, 관계/조건, 외부 참조 요약, 한도 진단까지 포함합니다. 예제별 후보 수에 맞추는 분기나 느슨한 비교 기준을 사용하지 않았습니다.

최초 구현에서 비활성 루트의 상태를 생략하면 외부 참조 요약까지 달라지는 것을 발견했습니다. 해당 생략은 제거했습니다. 빈 연결도는 공유하지만, 생성 전·종료 후 저장소 변화도 기존대로 보관합니다. CLI 기본 JSON 형식도 유지하고 공유 저장은 `--shared` 옵션으로 제공합니다.

## 시간·메모리·결과 크기

동일 실행 기록을 읽은 독립 Node 프로세스에서 추론 직전 GC 후 측정했습니다. 시간은 동기 추론 호출만 포함하며 파일 읽기·결과 직렬화는 제외합니다. MB는 1,000,000바이트입니다. 아래 값은 최종 코드의 개별 측정이며 통계적 성능 보장은 아닙니다. 최종 정리 전 32노드 측정에서는 14.87초도 관측되어 실행 환경에 따른 변동이 있습니다.

| 노드 | 실행 사건 | 추론 시간: 전 → 후 | 추론까지의 최대 RSS: 전 → 후 | GC 후 유지 JS 힙: 전 → 후 | 기본 JSON → 공유 JSON |
| --- | ---: | ---: | ---: | ---: | ---: |
| 8 | 2,085 | 1.00 → 0.65초 | 178.9 → 176.1MB | 27.8 → 22.3MB | 7.42 → 1.28MB |
| 16 | 4,142 | 4.29 → 2.28초 | 307.2 → 283.2MB | 54.1 → 28.9MB | 34.56 → 4.00MB |
| 32 | 9,455 | 29.06 → 11.59초 | 526.6 → 443.6MB | 178.9 → 49.2MB | 189.66 → 15.64MB |

RSS는 프로세스 전체, 유지 힙은 원본 기록·추론 결과 등을 포함한 GC 후 JS 힙입니다. 결과 파일 크기와 RAM 사용량을 혼동하지 않습니다. 최대 RSS는 출력 분석/직렬화 **이전**에 수집했습니다. 최초 읽기까지의 프로세스 최대값도 포함됩니다.

32노드에서 최종 시간 약 60%, 유지 힙 약 73%, 공유 저장 크기 약 92% 감소입니다. 최대 RSS 감소는 약 16%에 그칩니다. 공유 형식을 복원한 기본 JSON 크기는 189.66MB 그대로입니다. 내용 삭제로 크기를 줄인 것이 아닙니다. 32노드 공유 인코딩+JSON 직렬화는 약 146ms, 기존 확장 JSON 직렬화는 약 421ms였습니다.

기본 CLI 출력은 기존 소비자와 호환되도록 확장 JSON입니다. 작은 공유 파일이 필요하면 다음처럼 저장합니다.

```powershell
node scripts/infer-structures.mjs test-results/c-model --out-dir test-results/inference-shared --shared
```

읽을 때는 `decodeInference(json)` 또는 `createInferenceView(execution, json)`을 사용합니다. Worker 전송에는 공유 형식을 적용하며, 공개 비동기 API는 복원된 일반 객체를 반환합니다.

## 관련 검증과 기존 실패 구분

- `ir-inference-sharing.test.js` + `inference-separation.test.js`: 최종 10개 통과. JSON/Worker/CLI 호환, 겹친 필드, 역순 이력 조회, 입력 불변, 변조 거부 포함.
- 이력 한도 및 연결 우선순위 검사를 포함한 집중 실행: 41개 통과. 같은 키의 서로 다른 객체, 문자열 비교, 반환/복사 출처, 연결 분리·복귀, 수명과 과거 시점 판정을 확인했습니다.
- `ir-structure-extensions.test.js`의 공유·포인터 힙·복합 비교·변형 구현 관련 4개 통과.
- 최초 연결 관계 회귀 55개 중 52개 통과. CLI 형식 실패는 기본 형식 보존으로 수정하고 위 최종 검사에서 확인했습니다. 반환 포인터의 **정적 루트 경로가 없어야 한다**고 기대하는 2개는 변경 전 추론기에서도 동일하게 실패합니다. 같은 실제 실행 기록에서 변경 전후 `bindings` 전체가 동일합니다. 이 두 검사의 기준이나 해당 의미 추론은 이번 작업에서 수정하지 않았습니다.
- 8·16·32노드: 변경 전 저장 결과와 신규 공유 결과의 복원 JSON 전체가 바이트 단위 동일. 입력 실행 기록 불변. 생성/계측 파일 52개 불변.

기존 2개 실패의 재현과 실제 바인딩은 `old-failures.json`에 기록했습니다. 현재 AST 의존성 바인딩에 반환 호출의 인자 경로가 포함되어 있어 검사 기대와 충돌합니다. 이번 성능 수정으로 발생한 회귀는 아니며, 반환 별칭에 대한 기존 의미 계약과 별도로 판단해야 합니다.

## 남은 항목

- 32노드는 변경 전후 모두 기존 한도에 걸린 `partial`입니다: 포인터 루트 한도 256, 공유 관계 이력 604개 생략 진단. 진단 내용·최초 시점·생략 수를 그대로 유지했습니다. 한도 해제나 미관측 결과 복원은 하지 않았습니다.
- 약 12초·최대 444MB는 실시간 추론에 충분히 가볍다고 볼 수 없습니다. 동일 관계군의 많은 후보에 상태를 조립하는 비용과 임시 객체/원본 복제 메모리 등이 남습니다. 이번 결과는 네 공통 경로 개선의 측정값이며 성능 문제 전체가 해결되었다는 뜻은 아닙니다.
- UI·애니메이션·화면 가독성은 이번 범위가 아니며 검증하지 않았습니다.
