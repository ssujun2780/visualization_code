## 검사 범위와 결과

- 기존 C 예제 18개의 **저장된** plan·trace에 현재 추론기만 다시 적용했습니다. 27개 관찰 지점에서 기존 예상의 추천, 금지 추천, 사용 길이, 원소 순서와 값이 맞았습니다. 기존 코드와 사전 예측은 수정하지 않았습니다.
- 같은 값이 반복되는 두 스택 합성 큐는 원소의 삽입 사건 식별자로 검증했습니다. 최종 `[9,8]`의 원소 출처와 실제 순서가 유지됩니다.
- 관련 검사 **54개 통과**: 기존 관련 검사 44개, 새 검사 10개입니다. 새 검사는 C 프로그램 12개를 실제 실행합니다. 전체 예제나 전체 테스트를 재실행하지 않았습니다.
- 새 사례는 자료형 크기·용량·필드 순서·초기 좌표 변경, 내부를 가리키는 포인터와 별칭, 인라인 전위/후위 변경, 양방향 범위 복사, `%`형 원형 큐, full 표지 반례, 미실행 pop, 조회 뒤 별도 호출의 커서 변경을 포함합니다.
- 기존 관찰 기록에서 커서 WRITE 하나를 뺀 검사는 여전히 미완료입니다. 이를 peek로 바꾸어 통과시키지 않았습니다.
- 기존 검사 파일 120개의 해시가 그대로입니다. 기존 판정 기준을 결과에 맞춰 바꾸지 않았습니다.

추가 검사를 만드는 과정에서 초기 커서 2만으로 빈 시작점을 2라고 단정한 입력의 모호성도 확인했습니다. 이를 하나로 강제 선택하지 않고, **경계 비교가 없는 경우 두 해석을 보류하는 검사**와 **실제 경계 비교가 있을 때 예상 순서를 선택하는 검사**로 구분했습니다. 경계를 제공한 공유 배열 검사의 예상 순서는 왼쪽 `[2]`, 오른쪽 `[10]`입니다.

## 변경 경계

기존 변경 파일은 `embedded-array-views.mjs`, `queue-views.mjs`, `structure-presentation.mjs`, `structure-storage.mjs`, `ir-schema.mjs`입니다. 시간별 후보 선택은 새 추론 모듈 `array-container-history.mjs`로 분리했습니다.

`ir-schema.mjs`의 변경은 `validateStructureTrace` 안의 자료구조 검사뿐입니다. 역방향 논리 순서, 후보별 범위, 미래 사건을 현재 근거로 사용하지 않는 조건을 검사합니다. 그 앞의 중간언어 검사와 생성 코드는 원본 해시·내용 비교로 변경 없음을 확인했습니다. UI·애니메이션은 수정하지 않았습니다.

저장된 3,220개 사건의 값·순서·수명은 바뀌지 않았습니다. 추론 호출 전후 plan·trace 직렬화가 같다는 검사도 통과했습니다. 원본 실행과 예측 자료는 `test-results/array-containers-audit-2026-11-10/`에 그대로 두었습니다.
