# 수동 관계의 저장 표현·조건·실행 관계 연결

## 범위와 적용 계약

직전 제안의 세 단계인 수동 관계→실행 관계 연결, 저장 표현 확대, 선언형 조건 확장을 구현했습니다. 핵심 코드·문서·새 검사 코드를 작성한 뒤 검증했고, 실패와 경계 문제는 관련 공통 경로에서 보완했습니다. 중간언어 생성·계측, UI·애니메이션은 변경하지 않았습니다.

읽은 문서: `presentation.md` 모델 경계, `inference-model.md`, 표현 정책 1~6, RC-01~07, `execution-relations.md`의 실제 구현 및 W-03/W-06 계약, 사용자 관계 UR-01~05. 이번 확장 명세는 UR-06~08에 추가했습니다.

| --- | --- | --- | --- |

공통 경로에 파일명·변수명·예상 정답을 검사하는 분기는 추가하지 않았습니다. 테스트에서 필드를 이름으로 선택하는 부분은 사용자가 지정할 오프셋을 얻는 검사 설정이며 자동 판정 규칙이 아닙니다.

## 실제 C 예제와 사전 기준

새 소스·원본 실행 JSON은 `test-results/user-relations-extension-2026-11-12/`에 있습니다. 배열 인덱스와 구성원·연결 기대값을 검사 코드에 먼저 작성했습니다.

- `csr-work.c`: 0→1·2, 1→3. 실제 계산은 8+13+21=42입니다. 숫자 출력과 별도로 실제 구성원, 분리 저장소 접근, 구조 접근 대응을 확인합니다.
- `indirect-spans.c`: 첫 노드의 인접 배열이 `[1,2]`에서 realloc 후 `[1,2,1]`로 바뀝니다. 평행 간선을 유지하고 해제·길이 0 뒤에는 간선이 없습니다. 과거 조회는 원래 두 간선입니다.
- `linked-adjacency.c`: 보조 간선 레코드 두 개로 0→1·2를 나타냅니다. 보조 next를 NULL로 바꾸면 0→1만 남습니다. 보조 레코드를 그래프 데이터 노드로 합치지 않습니다.
- `manual-mixed-keys.c`: 실수 키가 같을 때 문자열로 비교합니다. alpha→zeta 포인터 재대입 뒤 왼쪽 조상 경계 위반을 확인하고 과거 시점은 정상으로 유지합니다.

합성 관측 검사에는 다른 종료값·기준 인덱스, 부분/미관측 입력, 목록 자체의 순환과 그래프 순환, 중복 연결, 노드 한도 경계, 다중 선행 조건, 임의 조건 이름 거부, 이력·조회 한도를 포함했습니다. 실제 C 실행 검사와 합성 기록 검사를 구분합니다.

## 검증에서 보완한 공통 원인

1. 새 사용자 규칙이 `comparePayload`의 결과 객체를 부호 숫자처럼 사용했습니다. `.sign`을 사용하도록 수정했습니다. 알려지지 않은 순서와 NaN을 위반이나 성공으로 바꾸지 않습니다.
2. 기존 실행 관계 소비부는 한 넓은 접근이 같은 논리 구성원의 여러 저장 범위와 겹칠 때 동일한 관계 ID를 만들었습니다. 실제 전체 접근은 유지하고 `matchedRange` 교집합으로 대응을 구분했습니다. 동일한 대응만 중복 제거하고 교집합 변조 검사도 추가했습니다. 사용자 대응의 `mappingOrigin`도 끝까지 보존합니다.
3. 레코드를 배열 타입과 개별 포인터에서 중복 발견하면 실제 구성원 수가 정확히 한도와 같아도 초과로 표시했습니다. 객체·오프셋 식별자로 중복을 제거한 뒤 새로운 노드에만 한도를 적용합니다.
4. 키·역할 계약이 명시된 빈 BST는 빈 구조로 검사하도록 보완했습니다. 이때 기존 최소 입력 형태의 공통 BST 호출에 `relation.nodes`가 없을 수 있다는 회귀를 발견하여 해당 선택 항목의 존재도 확인합니다. 기존 NaN 단일 키 검사는 그대로 유지했습니다.
5. 가변 목록의 미확정 포인터 참조가 잘못된 포인터 경고가 되지 않도록 직접 연결과 같은 incomplete 규칙을 적용했습니다. 실제 범위 위반·종료된 대상과 구분합니다.
6. 긴 인접 목록의 경로 근거를 간선마다 전체 복제하지 않도록 필요한 제어·현재 항목 근거를 보존하고, 저장 범위 중복 확인은 Set을 사용합니다. 기록 색인을 조회 사이에 재사용하며, 한도에 도달하면 명시적으로 미확정 구간을 닫습니다.

검사 설정 오류 1건도 분리했습니다. 복합 키의 보조 배열을 만든 뒤 **생성 이전 시점 C**를 조회하면서 정상 판정을 기대했습니다. C의 기대를 `incomplete`로 명시하고, 배열 생성 후 별도 시점의 원래 정상 기대를 추가했습니다. 키 값·배치·비교 규칙을 실제 결과에 맞춰 바꾸지 않았습니다.

## 검사 기록

관련 검사 **102개(중복 제외)**를 확인했습니다. 전체 예제 모음은 실행하지 않았습니다.

- `first-tests.log`: 초기 34개 중 31개 통과, 비교기/소비부 구현 실패 2건과 검사 시점 설정 오류 1건.
- `second-tests.log`: 초기 실패 수정 후 관련 검사 통과.
- `boundary-tests.log`: 노드 한도 경계 실패 재현. 혼합 실수/문자열 C 검사는 통과.
- `final-tests.log`: 관련 101개 중 100개 통과. 기존 최소 BST 입력 형식 회귀 1건 발견.
- `final-condition-recheck.log`: 해당 공통 경로 수정 후 키 자료형·사용자 조건·조합 **33개 통과**.
- `final-extension-recheck.log`: 미확정 포인터 반례 추가 후 확장 검사 **11개 통과**.
- `final-exchange-recheck.log`: 사용자 출처 전달까지 반영한 뒤 확장·실행 관계 v2·기존 한도/통합 경로 재검사 통과.

생성·계측 52개 파일의 SHA-256은 `model-before.json`과 `model-boundary.json`에서 동일합니다. 중간언어를 고쳐 예제 결과를 맞추지 않았습니다. 검증 중간의 실패 로그도 보존했습니다.

## 남은 항목

이번 세 단계의 API와 관련 검증을 완료했습니다. 사용자 지정이 객체의 직접 ID에 묶인 경우 재할당/새 실행 후 선언을 찾아 자동 재연결하는 기능, UI 입력·저장·배치, 모든 구현 조합과 대규모 성능 보증은 남아 있습니다. 다만 노드별 간접 인접 배열은 현재 관측 포인터를 읽으므로 이번 realloc 예제처럼 대상이 바뀌는 경우를 처리합니다. 모든 포인터 인코딩·임의 사용자 프로그램 의미를 추론한다고 주장하지 않습니다.
