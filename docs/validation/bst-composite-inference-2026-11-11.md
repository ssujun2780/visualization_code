# 복합 키 BST 추론 검증

2026-11-11. 공통 추론기와 추론 추천 범위만 수정했습니다. 중간언어 생성·계측·UI는 수정하지 않았습니다.

## 기존 예상 유지

`test-results/bst-semantics-audit-2026-11-10/`의 원본 소스·예상·plan·trace·inference를 변경하지 않고 다시 추론했습니다. 6개 관련 사례의 15개 시점/대상이 원래 예상과 일치합니다. 전체 예제 모음을 재실행하지 않았습니다.

이전에 미충족이었던 복합 키 3개는 다음과 같습니다.

| 시점 | 실제 결과 |
|---|---|
| P0 | `(major, minor)` 사전식 BST. 원래 4개 구성원·3개 간선 유지 |
| P1 | `cache` 변경은 비교 키에 포함되지 않음. BST 유지 |
| P2 | `(2, 6)`이 조상 `(2, 5)`의 왼쪽 경계 위반. 결정 성분은 `minor`, 경로 길이는 3 |

원본 예상은 변경하지 않았습니다. 구성원 식별자, 간선 방향/역할, 조상 경로, 위반 값도 별도로 검사했습니다. 정상 부분 트리가 잘못된 전체 루트의 BST 추천을 대신하던 추천 범위 문제도 함께 수정했습니다. 일반 트리 사용자 지정에는 BST 조건을 강제하지 않습니다.

## 추가 검사

`tests/ir-bst-composite.test.js`에 예상과 검사를 먼저 작성한 뒤 실행했습니다.

- 성분 선언 순서와 비교 순서가 다른 3성분 키: 첫째 오름차순, 둘째 내림차순, 셋째 오름차순.
- 같은 의미의 조기 반환, 중첩 if, 중첩 삼항식, 단락 논리식/보조 함수 구현.
- 캐시 변경 무시, 조상 경계 위반, 값 복구, 위반을 결정한 성분의 정확성.
- 분리 배열 저장소, 0이 아닌 루트, 음수 NULL 인덱스.
- 정수 인덱스 구조체의 복합 키 삽입. 앞 성분만 같음과 전체 키 동등을 구분.
- 조상에서 같은 키를 만난 뒤 아래에 삽입하는 흐름. 직접 필드 비교와 별도 함수의 스칼라 인자로 복사하는 형태 모두 확인.
- unsigned long long과 signed int 성분을 섞고, Number 정밀도 밖의 값과 음수를 정확히 비교.
- 반례: 성분별 단순 AND 비교를 사전식 비교로 오인하지 않음.
- 근거 부족: 같은 앞 성분끼리만 비교한 기록에서 앞 성분 방향을 임의로 만들지 않음.
- 기호 비교 단위 검사: 20개 성분을 고정된 2/3성분 제한 없이 처리. 위반 성분을 변조한 부가 결과는 독립 검증기가 거부.

총 10개 추가 C 코드와 기호 비교 단위 검사를 포함합니다. 기존 BST·추천·선택 범위 검사와 함께 **31개 관련 검사 통과**입니다. `focused-tests.txt`에 30개, 추가 인자 전달 검사 1개는 `argument-tests.txt`에 있습니다. 전체 예제는 재실행하지 않았습니다.

추론 전후 plan/trace의 직렬화 내용이 같음을 확인했습니다. 작업 시작 시의 파일 해시와도 비교하여 기존 생성 모델·계측 파일이 바뀌지 않았음을 확인했습니다. 다른 세션에서 변경된 `docs/design/ui.md`는 별도 관측 항목으로 기록했고 수정하지 않았습니다.

## 결과 위치와 한계

결과는 `test-results/bst-composite-inference-2026-11-11/`에 저장했습니다.

- `verification.json`: 원본 15개 예상 비교와 변경 범위/입력 불변성.
- `06_composite_key-comparison.json`: 원본 복합 키의 세 시점과 추천·경고 근거.
- `cases/`: 추가 코드의 소스, 예상 stdout, 실제 plan/trace/inference.
- `replay.mjs`: 원본 기록을 읽기만 하는 재검사 도구.

검사는 관측된 정수 비교와 저장소·자식 이동 관계에 대한 것입니다. 임의의 사용자 비교자, 문자열/부동소수점 키, 모든 입력에 대한 정확성을 보장하지 않습니다. 우선순위가 모호하거나 기록·분석 한도에 도달하면 판정 불가로 남깁니다.
