- 요청: realloc → 같은 코드 재실행 → 모호한 경우 처리. 관계·조건을 함께 연결하며 중간언어 생성 모델을 수정하지 않습니다.
- 읽은 계약: presentation.md의 모델·추론 경계, inference-model.md의 읽기 전용 경계, structure-presentation-policy.md의 사용자 우선/실행 범위, user-structure-relations.md UR-03~04·06~08. 이번 승인 내용을 UR-09~11로 추가했습니다.

- 구현을 마친 뒤 관련 API만 검사했습니다. 전체 예제 일괄 실행, UI 변경, Git 커밋·푸시는 하지 않았습니다.

## 예상과 실제

독립 예상: 노드 3개의 연결은 `0→1→2`, -1로 종료합니다. A 시점의 조건 배열은 `[4,5,6]`이므로 모든 값이 양수입니다. realloc으로 노드 저장 용량이 늘어나도 지정한 3개 원소만 유지합니다. B 시점에는 조건 배열만 `[4,-5,6]`으로 바뀌어 위반으로 나와야 하며 연결은 그대로여야 합니다. 입력 1은 관계와 무관한 추가 할당을 먼저 실행합니다.

실제 C 결과는 `test-results/presentation-reconnect-2026-11-12/comparison.json`에 저장했습니다. 연결과 A/B 조건 결과가 예상과 일치합니다. 재실행에서 노드/연결/조건 저장소는 각각 `o10→o11`, `o13→o14`, `o16→o17`로 대응했습니다. 이 숫자는 검사 결과이며 구현의 분기 조건이 아닙니다.

## 검사 이력

- 첫 관련 검사: 41개 중 40개 통과. 실패는 검사 예상 객체에서 정규화 기본값 `offset: 0`을 생략한 문제였습니다. 원래 정규화 조건의 모든 속성을 보존한 채 예상 objectId만 바꾸도록 검사 구성을 수정했습니다. 연결·값·순서·조건 판단의 기대는 변경하지 않았습니다.
- 복합키와 후보 대응 추가 후: 4개 관련 파일 **43/43 통과** (`tests.txt`).
- 현재 재할당 대상의 reset/replacement 경로 보완 후: 영향을 받는 재연결/표현 2개 파일 **23/23 통과** (`presentation-recheck.txt`). 서로 다른 관련 검사 총 44개를 확인했습니다. 44개 전체를 마지막에 다시 돌렸다는 뜻은 아닙니다.
- 실제 실행 2개의 plan/trace/stdout과 C 소스를 같은 결과 폴더에 보관했습니다. 원본 파일명·변수명·특정 값에 따른 구현 분기는 없습니다.

## 동시 변경과 남은 범위

`model-before.json`과 `model-boundary.json`을 비교하면 공유 작업 도중 `scripts/model/ir-record.mjs`, `recorder.mjs`, `return-sequence.mjs` 세 파일의 해시가 변경되었습니다. 이 작업의 편집 대상에는 포함되지 않았고 수정·복원하지 않았습니다. 따라서 작업 공간 전체에서 생성 모델이 불변이었다고 주장하지 않습니다. 검사는 해당 실행 당시 공유 작업 공간의 코드로 통과했습니다.

코드가 변경된 실행의 자동 이식, 근거가 없는 후보/역할의 임의 재연결, 반복 호출 객체를 실행 순번으로 짝짓기, UI 메뉴·영속 저장 연결은 하지 않습니다. 재연결 필요 상태와 원래 설정을 반환하므로 사용자 선택을 붙일 수 있습니다. 명시된 관계/조건 범위는 보존하며 realloc 성장 용량을 자동으로 논리 원소에 추가하지 않습니다.
