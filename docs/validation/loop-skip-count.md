# 반복 건너뛰기 횟수 확장

2026-11-13. 사용자가 요청한 단위는 초가 아닌 기존 반복·명령·행 탐색입니다. 하단 반복 건너뛰기를 1·5·10·50·100회·남은 전체로 확장했습니다. 중간언어 생성 모델과 두 추론기, 기존 명령/한 줄 탐색은 변경하지 않았습니다.

읽은 계약: `presentation.md`, `animation.md` 기본 원칙/재생 조작, `visualization.md` 원본 정체성/수명/화면 배치 경계, `ui.md`, `loop-navigation.md` L-01·04·05·06. 최신 사용자 합의에 따라 L-04와 UI 문서를 갱신했습니다.

| 설계 조항 | 변경 위치 | 검증 근거 | 남은 항목 |
| --- | --- | --- | --- |
| L-01·03 현재 반복문 실행 구분 | `src/animation/loop-skip.js` | 기존 반복 색인의 가장 안쪽 실행을 사용. 동일 반복문을 호출한 다른 활성화와 중첩 바깥 반복을 넘지 않음 | 새 반복 인식 규칙/소스 파싱 없음 |
| L-04 횟수와 상한 | 같은 파일, `main.js`, `animation.html`, `style.css` | 1·5·10·50·100·all 목적지 계산. 현재 진행 중인 반복 포함, 초기 준비/0회/마지막 거짓 조건 확인. 남은 수 이상은 해당 loop.end로 제한 | 개별 반복 행의 기존 한 번 이동은 유지 |
| L-05 실행 효과와 중단 | 기존 `Playback.skipTo`/`seek`/`applyEvent` 재사용 | 정상 애니메이션과 상태 깊은 비교, 출력 누적, 진행 중/정지 유지, 되돌아가 재탐색. 100·전체로 ERROR/입력 대기를 넘지 않는 검사 | 임의 시점의 배치·배선 이력까지 동일하게 복원하는 별도 표시 시간선은 이번 변경 범위 아님 |
| L-06 실제 UI | 실제 C 실행에서 저장한 1,048개 사건 기록 | 네이티브 브라우저에서 여섯 버튼 모두 클릭. 49회 반복에서 50/100/전체 모두 803/1048, 출력의 마지막 합 1225. 5회 뒤 10회 연속 이동은 254/1048, 합 120·남은 34회. 100회 추가는 803/1048, 합 1225로 제한 | 화면은 이 관련 사례로 검사. 전체 예제 재실행 아님 |

현재 반복이 아닌 위치와 오류/입력 대기에서는 버튼을 비활성화합니다. 부분 실행에서는 미래 반복을 만들지 않고 관측된 끝까지 이동합니다. 최종 반복까지 건너뛸 때 마지막 거짓 조건과 정리도 반영하므로 반복문 밖의 첫 명령 위치가 선택됩니다. 반복문 밖에서 계속 명령을 건너뛰거나 다음 함수 호출의 같은 루프로 이동하지 않습니다.

## 근거

- `tests/animation-loop-skip-count.test.js`, `tests/animation-loop-groups.test.js`: **11개 통과**, 실패/건너뜀 0. 기존 상태 기대값을 유지했고, 새 49회 사례의 누적 출력은 소스의 삼각수 합으로 독립 계산했습니다.
- `test-results/loop-skip-count/tests.log`, `build.log`: 관련 검사와 빌드 성공. 기존 편집기 청크 크기 경고는 유지됩니다.
- 같은 폴더의 `recording.json`, `expectations.json`, `native-checks.json`: 실제 실행 기록, 목적지/예상 출력, 여섯 UI 버튼의 실제 위치·출력.
- 화면: `loop-skip-count-controls.png`, `loop-skip-count-capped.png`. 전자는 남은 34회와 여섯 버튼, 후자는 49회 종료 후 합 1225와 반복문 밖 상태입니다.

모든 기록·원래 명령 순서·객체 수명을 그대로 두며, C 재실행이나 임의 계산 결과 대입으로 스킵을 구현하지 않았습니다.
