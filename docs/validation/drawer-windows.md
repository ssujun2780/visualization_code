# 서랍 크기 조절과 연결 성분 강조

2026-11-11. [서랍 표시 영역](../design/drawer-windows.md) D-01~D-06, `visualization.md`·`ui.md`·`pointer-wiring.md`와 실행/표현 분리를 적용했습니다. 생성 모델·자료구조/실행 관계 추론기는 변경하지 않았습니다.

| 조항 | 공통 구현 | 검증 근거 | 결과·제한 |
| --- | --- | --- | --- |
| D-01~02 | `world.js`, `object-view.js`, `canvas.js`: 별도 표시 크기 설정, 모서리 드래그·Shift+방향키, 현재 크기·칸 수 안내 | 기본 기하 불변, 확대/축소에 따른 가시 칸 수, 중첩·접기 복원, 재생 중 크기 변경 후 재생 유지 | 통과. 기본 배치는 바꾸지 않고 사용자 조절 때만 표시 창 적용 |
| D-02 | 가려진 원소를 서랍 대표점에 연결하고 원래 논리 ID 유지 | 먼 원소가 숨겨졌다가 확대 후 정확한 원소 끝점으로 복원. 실제 libavoid에서 네 가지 크기 상태 모두 미배선·상자 관통 0 | 통과 |
| D-03~04 | `memory.js`: 현재 바이트·자료형으로 한정된 추가 미리보기 생성 | calloc의 현재 0과 이후 WRITE의 20을 구분. 미초기화 칸은 null 유지. 1억 원소 크기의 메타데이터도 표시 한도 내에서만 생성 | 통과. 임의 구간 스크롤은 후속 범위 |
| D-05 | `connectionFocus`, `focusForTargets`: 포인터 그래프의 양방향 연결 성분, 선택·호버·현재 연산 대상에 적용 | 이중 포인터·별칭·순환 전체 선택과 포함 관계 경계 검사. 실제 화면에서 동일 원소/이중 포인터 4개 연결 강조 | 통과. 컨테이너 포함·같은 대표점만으로 연결 합치지 않음 |
| D-06 | 기존 재생 상태·원본 IR 불변, 현재 값으로만 렌더링 | 상태·JSON 불변 및 기존 반환·선택·배치·배선 회귀 검사 | 관련 검사 합계 35개 통과. 전체 예제 재실행 안 함 |

중첩 서랍 검사에서 기존 화면 자료형 해석기가 구조체 안 다차원 배열의 컴파일러 dimensions를 평탄화하는 문제를 발견했습니다. 화면의 `typeResolver`가 해당 차원으로 중첩 배열을 구성하도록 보완했고, 실제 `.grid[0]` 행 서랍 검사를 유지하여 통과했습니다. 생성 모델의 자료형·중간언어는 변경하지 않았습니다.

기존 ‘선 하나만 강조’ 검사 두 개는 최신 사용자 요구에 따라 실제 공유 별칭까지 포함하는 명시적인 간선 ID 집합 검사로 바꿨습니다. 무관한 형제 포인터를 포함하지 않는 경계 검사는 유지했습니다. 값 노출 검사는 표시용 값 포맷으로 비교하되 기대값 0/20은 유지합니다.

프로덕션 빌드 통과. 기존 Monaco 번들 크기 경고는 남습니다. 화면 자료는 `drawer-resize-expanded.png`, `drawer-resize-small.png`, `drawer-connected-focus.png`에 저장합니다. 모서리 잡기 영역은 축소 중에도 최소 약 12px을 확보하고 키보드 조절을 함께 제공합니다. 초대형 장면의 모든 성능·배선 품질을 보장하는 검증은 아닙니다.

실제 화면: 456×384의 기본 13칸에서 키보드로 636×564/30칸, 모서리 드래그로 약 893×630/42칸까지 확대했습니다. 축소 후 약 413×270/6칸, 복원 후 42칸을 확인했습니다. 조절 중 재생이 유지됐으며, 원소 선택에서는 연결 4개 강조가 표시됐습니다. 선택을 해제하고 READ 작업으로 이동해도 연결망 강조가 나타났습니다(`drawer-operation-focus.png`). 시점을 앞뒤로 옮겨도 서랍 크기는 유지됐고 아직 실행하지 않은 두 WRITE의 값은 0으로 남았습니다.
