## 기존 공통 추론의 문제 3가지

### 1. 분리 배열의 발견 시점이 미래 접근까지 밀립니다

02의 핵심은 다음과 같습니다.

```c
int keys[8], aa[8], bb[8];
if (k < keys[p]) aa[p] = put(aa[p], k);
else bb[p] = put(bb[p], k);
```

P0 `x765` 시점에 이미 세 배열의 동일 인덱스 사용과 좌우 탐색 증거가 있습니다. 하지만 공동 레코드의 `discoveredAtExecutionId`는 `x1891`입니다. 따라서 초기에는 두 자식 역할을 묶은 BST가 조회되지 않습니다.

원인은 `scripts/inference/coindexed-record-views.mjs:32`의 `firstProof` 계산입니다. 각 provenance 그룹에서 **전체 실행에 걸친 마지막 접근**을 고른 뒤 가장 이른 것을 발견 시점으로 사용합니다. 실제 세 증거 그룹은 P0 이전에 각각 15·20·9개의 READ를 이미 포함하지만, 마지막 접근은 `x2010`, `x1918`, `x1891`입니다.

개선안: 사건 순서대로 동일 인덱스 출처·배열별 접근·READ 조건을 누적하고, 해당 그룹을 증명하는 최소 접두 구간이 완성된 시점을 기록합니다. 나중에 새 배열이 추가되는 경우 이전 두 배열 관계와 이후 확장 관계를 구분해야 합니다. 단순히 모든 발견 시점을 첫 접근으로 앞당기면 미래 정보를 과거에 적용하게 됩니다.

### 2. 종료 노드의 관리 정보 읽기를 데이터 소비로 취급합니다

04는 공유된 검은 NIL 노드를 사용합니다.

```c
enum { DARK = 7, LIGHT = 11 };
nil.t = DARK;
nil.a = nil.b = nil.p = &nil;
int walk(N *p) { return p == &nil ? 0 : 1 + walk(p->a) + walk(p->b); }
/* 균형 검사에서는 자식이 NIL이어도 색을 읽습니다. */
if (p->t == LIGHT && (p->a->t == LIGHT || p->b->t == LIGHT)) return -1;
```

실제 P0 `x641`의 데이터 구성원은 `nodes[0..2]`여야 합니다. 추론에는 별도 저장소 `nil`도 들어갑니다. 자식 역할만 골라도 NIL의 자기 연결과 공유 연결 때문에 트리로 확인하지 못합니다. 부모 포인터만 제외하면 해결되는 문제가 아닙니다.

`linked-views.mjs:410–419`는 커서에서 도달한 비포인터 멤버 READ를 모두 `payloadReads`로 기록하고 기존 종료 표식을 제거합니다. `:304`도 이 노드를 종료 노드로 등록하지 않습니다. 따라서 NIL의 색 같은 관리 정보를 읽는 구현을 처리하지 못합니다. 종료 비교를 나타내는 소스 정보는 이미 있습니다.

05에서도 `tag[aa[p]]` 같은 색 읽기가 0번 종료 슬롯을 포함하는 다른 논리적 레코드 후보를 만듭니다.

개선안: 특정 순회·연결 역할의 종료 증거와 노드의 관리 정보/데이터 역할을 구분해야 합니다. 종료 노드의 메타데이터를 읽었다는 이유만으로 전체 종료 증거를 지우면 안 됩니다. 물리적인 NIL 상자·읽기·연결은 그대로 두고, 논리적 트리 구성원에서만 역할별로 제외합니다. 자기 연결, 이름, 숫자 0만으로 종료 노드라고 단정해서도 안 됩니다.

### 3. 추천한 후보와 조건을 검사하는 후보 범위가 다릅니다

05의 P0 `x355`에는 다음 후보가 함께 존재합니다.

- 구성원 `[1,2,3]`: 예상 간선·키와 일치, `satisfied-observed`.
- 구성원 `[0,1,2,3]`: 종료 슬롯이 섞임, `incomplete`.

따라서 BST 추천 자체가 틀렸다는 뜻은 아닙니다. 정확한 후보를 추천하면서 종합 질의는 다른 불완전 후보까지 합쳐 `incomplete`를 돌려주는 것이 문제입니다. `structure-presentation.mjs:298`의 검사 연결도 선택된 자동 추천 후보 ID로 범위를 한정하지 않습니다.

개선안: 추천·선택·조건 검사가 같은 후보 ID, 키·연결 역할, 논리적 구성원 범위를 사용하도록 연결해야 합니다. 서로 다른 해석의 후보는 별도로 보존하되 그 경고를 선택된 후보의 오류처럼 표시하지 않습니다. 2번의 종료 노드 문제를 먼저 고쳐도, 다른 중첩·복합 자료구조에서 생길 후보 범위 문제는 따로 해결해야 합니다.

## 아직 구현되지 않은 기능 3가지

### 4. AVL의 실제 균형과 저장 높이 검사

현재 BST 판별은 키 순서를 확인하며 AVL 조건은 확인하지 않습니다. 03에서 세 상태 모두 BST라는 판정은 맞지만, 다음 차이를 설명하지 못합니다.

```c
/* P0: 10 → 20 → 30, BST이지만 편향 */
seed = turn_a(seed);
/* P1: 루트 20, 자식 10·30. 모양은 균형이지만 nodes[0].h는 여전히 3 */
refresh(seed);
/* P2: nodes[0].h도 실제 높이 1로 갱신 */
```

개선안: 확인된 자식 관계로 실제 서브트리 높이와 좌우 차이를 계산합니다. 저장된 높이/균형도 필드는 갱신식·읽기 용도에서 역할 근거가 있을 때 별도로 대조합니다. 02처럼 높이를 매번 재귀 계산하는 구현에는 캐시 필드가 필수가 아닙니다. 회전 도중 일시적 상태와 완료된 상태를 구분하고, 관찰된 균형 만족과 AVL 유지 알고리즘이라는 추정을 분리해야 합니다.

### 5. Red-black의 색 역할과 불변식 검사

04의 색은 7/11이며 05의 색은 다음처럼 일부 비트에만 저장됩니다.

```c
unsigned tag[8] = {0, 0x10, 0x21, 0x31, 0x41};
if (tag[p] & 1) { /* 이 비트만 색입니다. */ }
tag[2] &= ~1U;
```

현재 색 역할·마스크와 빨간 루트, 빨강-빨강 연결, 경로별 검은 높이를 판정하는 기능이 없습니다. 개선 시 AST 연산과 관찰된 검사·갱신 관계에서 역할을 추출해야 합니다. 필드명 `red`, 값 0/1, 우연히 균형 잡힌 모양만으로 단정하면 안 됩니다. 색 의미가 모호하면 후보와 부족한 근거를 남기고, 사용자 지정으로 보완해야 합니다. 검사는 확인된 BST·자식·종료 관계를 기반으로 실행합니다.

### 6. 사용자 지정 종류와 해당 조건 검사 연결

18개 시점에서 `avl/avl-balance`, `red-black/red-black-rules`를 수동 지정해 확인했습니다. 일반 사용자 지정 경로가 view·expected를 보존하기는 하지만 `expectationCheck`는 생성하지 않습니다. 결과의 `no-checker`는 점검 스크립트가 붙인 표기이며 모델의 공식 판정값이 아닙니다.

개선안: 종류별 조건 검사기를 등록하고, 미구현 검사에는 명시적인 `not-checkable`과 이유를 반환해야 합니다. 사용자 지정이 추천보다 우선하되, 사용자가 AVL이라고 지정했다고 조건이 만족된 것으로 바꾸지는 않습니다. 지정된 의도와 실제 관찰 결과를 나란히 보존합니다. UI 구현은 이번 범위가 아닙니다.

1. 발견 시점과 종료/구성원 관계를 먼저 수정합니다(1·2).

모든 작업은 공통 추론층의 부가 정보에 한정해야 합니다. 트리 조건 위반을 C 런타임 오류로 바꾸거나, 추론을 위해 WRITE·CALC·수명 사건을 수정해서는 안 됩니다. 이번 예제의 배열명·색 상수·노드 수를 구현 규칙으로 사용해서도 안 됩니다.
