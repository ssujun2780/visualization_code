# 공통 추론기의 중복 상태 조립·문자열 검색 개선

## 범위와 고정 기준

사용자 승인: 직전 비용 분석의 1~3을 구현하되 기존 결과를 유지합니다. 중간언어 생성 모델과 UI는 변경하지 않습니다. 전체 예제 재실행 없이 해당 공통 경로만 검사합니다.

읽은 계약: `presentation.md`, `inference-model.md` 실행 분리·공유 이력, `structure-composition.md` RC-07, `structure-presentation-policy.md` 추천/사용자 의도 분리, `linked-container-inference.md` 구성원·역할·NULL·이력, `bst-inference.md` 독립 근거 검증. 기존 필수 조건의 비용 개선이며 추론 범위나 한도 확대는 아닙니다.

수정 전 `scripts/inference`와 `scripts/shared`를 `test-results/inference-state-cache-2026-11-13/baseline/`에 고정했습니다. 동일 원본 실행 기록으로 수정 전/후 전체 추론 객체를 깊은 비교하고 JSON SHA-256을 비교했습니다. 예측 검사·기존 기대값은 수정하지 않았습니다. 생성/계측 파일 52개의 작업 전후 SHA-256도 일치합니다.

## 결과 보존과 작업량

- 관련 자동 검사: **48개 통과**, 실패·건너뜀·TODO 0. 기존 검사 기준 변경 없음.
- 전체 객체/JSON 비교: 반환·연결·저장소·문자열·영속 트리 **17개 기록 일치**. 이와 별도로 크기별 **3개 실행 기록**의 3회 전후 측정에서 전체/공유 JSON 해시, 크기, 상태 수, 진단이 일치합니다.
- 32노드 연결 상태 처리 호출: **86,891 → 86,891회**. 사건을 건너뛴 것이 아닙니다.
- 상태 조립: **84,771 → 22,497회**(73.5% 감소). 실제 보존 상태: **22,335 → 22,335개**. 의존성은 바뀌었지만 출력은 같은 162회는 기존 최종 중복 판정이 처리합니다.
- 원래 32노드의 `partial`, 포인터 루트 256개 한도, 공유 하위구조 이력 생략 진단도 동일합니다. 이 한도를 늘려 정상 완료처럼 처리하지 않았습니다.

## 성능

Node.js v24.22.1, 각 측정을 새 `node --expose-gc` 프로세스로 3회 수행한 중앙값입니다. 추론 시간은 출력 직렬화를 제외합니다. 최대 RSS는 추론 반환 직후까지의 프로세스 최대 메모리로 런타임·입력을 포함하며 순수 캐시 크기가 아닙니다. 성능 측정과 테스트/작업량 계측은 동시에 실행하지 않았습니다.

| 노드 | 수정 전 시간 | 수정 후 시간 | 최대 RSS 전 → 후 | GC 후 heap 전 → 후 |
| --- | ---: | ---: | ---: | ---: |
| 8 | 0.527초 | 0.509초 | 167.18 → 172.48 MiB | 21.22 → 21.22 MiB |
| 16 | 1.629초 | 1.447초 | 276.52 → 282.77 MiB | 27.57 → 27.55 MiB |
| 32 | 6.616초 | 5.511초 | 405.67 → 379.73 MiB | 46.76 → 46.73 MiB |

시간 중앙값은 약 3.4% / 11.2% / 16.7% 감소했습니다. 8·16노드 최대 RSS는 각각 약 5.3 / 6.2 MiB 증가했습니다. 캐시·색인의 비용과 GC 시점 영향이 있으며, 모든 크기에서 메모리가 감소했다고 주장하지 않습니다. 32노드 최대 RSS의 수정 후 개별 값도 378~411 MiB로 변동했습니다.

| 노드 | 기존 JSON 바이트(전후 동일) | 공유 JSON 바이트(전후 동일) |
| --- | ---: | ---: |
| 8 | 7,422,892 | 1,283,506 |
| 16 | 34,560,842 | 4,004,036 |
| 32 | 189,662,263 | 15,641,419 |

## 재현 자료와 남은 범위

`test-results/inference-state-cache-2026-11-13/`에 다음을 보관합니다.

- `baseline/`, `model-before.json`: 수정 전 코드와 생성 모델 해시.
- `preservation.mjs`, `preservation.json`: 17개 기록 전체 비교와 입력/결과 해시.
- `benchmark.mjs`, `before-*.json`, `after-*.json`, `summary.json`: 반복 측정과 동일성 판정. 예: `node --expose-gc test-results/inference-state-cache-2026-11-13/benchmark.mjs after 32 1`.
- `count-work.mjs`, `before-work.json`, `after-work.json`: 사본에만 카운터를 넣은 작업량 측정. 생산 코드에 계측 표지를 추가하지 않았습니다.
- `tests.tap`: 색인/연결 수명/공유/루트 컬렉션/역할/경계/문자열 키/우선순위 관련 48개 검사.

관계군의 dirty 후보 선정, 필요한 연결도·역관계 계산, 포인터 트리 투영, 순서 추론 및 계약 검증은 유지합니다. 남은 분석 비용 전체를 제거한 것은 아닙니다. 출력 크기와 기존 기록 한도도 이번 최적화 대상이 아닙니다. 시각화/UI 변경이나 화면 가독성 검사는 하지 않았습니다.
