## 원래의 화면 개발 기록

2026-11-08부터 비캐릭터 재생 시제품을 `animation.html`에 구현했습니다. HTML/CSS는 조작부와 코드·사건 목록을, Canvas 2D는 돗자리·상자·값 카드·알루·연결선을 그립니다. `src/animation/playback.js`가 스키마 3의 명령 정의와 실행 사건을 연결하고, `canvas.js`가 같은 사건의 진행률에 따라 그립니다. 캐릭터 없이 상태 변경과 재생이 완결됩니다. 2026-11-10부터 예제 화면의 입력은 [실행 세션의 입력 대기](../design/interactive-input.md)를 사용합니다. 실제 입력 요청에서 같은 실행을 대기시키고, 재생도 해당 지점에서 입력 돗자리를 강조하며 정지합니다. 입력을 받으면 재실행 없이 이어갑니다. 기존 일괄 생성 API는 별도 호환 경로로 유지합니다.

현재 시제품은 스칼라·포인터와 배열·구조체의 생성·읽기·계산·저장·종료, 동적 메모리, 라이브러리 범위 효과와 입출력 및 기본 FLOW를 재생합니다. 관찰하지 않은 값이나 지원하지 않는 사건을 임의로 만들어 표시하지 않습니다. 기본 예제는 `examples/c/animation/scalar.c`·`add.c`를 현재 공통 중간언어 생성 모델로 실행한 결과입니다. Vite의 `/api/animation/examples/:id`가 요청마다 새 Node 프로세스에서 현재 모델과 예제 소스를 읽어 plan·trace를 생성하며, 고정 JSON을 예제 실행에 사용하지 않습니다. 예제 선택·페이지 열기·‘예제 다시 실행’에서 갱신하고, 개발 중 모델·계측·예제 C 파일 변경도 재생 페이지에 알려 자동 재생성합니다. 요청·응답 캐시는 사용하지 않고 실패하면 오류와 재시도를 표시합니다. 오래된 JSON으로 조용히 대체하지 않습니다. `public/animation-demo.json`·`animation-functions.json`은 이전 저장 기록의 호환성 검사 자료로 남아 있습니다.

실행 기록 열기에서는 plan.json과 trace.json을 함께 선택하거나 `{plan, trace}` 결과 파일 하나를 선택할 수 있습니다. 재생·일시정지·한 명령어·한 줄 진행·명령어 경계 시점 이동과 카메라 이동·확대/축소를 제공합니다. 시점 복원은 사건의 앞부분을 순서대로 적용하며, 마지막 객체 장부의 최종 값·수명을 과거 상태로 가져오지 않습니다. 현재 API의 반복 요청이 다른 실행 ID를 생성하는지, 최신 반환 계약대로 대입 뒤 정리되는지, 입력 C와 화면의 소스가 같은지, 모델 변경 알림·잘못된 예제 요청을 검사합니다. 새 기록은 재생기 정리 지연 없이 중간언어 순서대로 처리합니다.

동적 공간의 좌표는 `src/animation/world.js`에서 실행 상태와 독립적으로 관리합니다. 함수 돗자리는 상자의 실제 배치 범위를 감싸며 새 함수의 기본 위치는 기존 필드 크기를 고려합니다. 상자는 드래그로 옮기고, 돗자리 제목을 드래그하면 소속 상자들이 함께 이동합니다. 상자의 소속·메모리 참조는 원래 객체 ID를 유지합니다. 변경한 배치는 재생과 시점 이동 중 유지하고, 새 기록을 열거나 배치 초기화를 누르면 초기 배치를 구성합니다.

돗자리 배치는 생성·이동·범위 확장 시 모든 활성 돗자리 사이에 24 단위의 간격을 확보합니다. 안정된 기존 위치를 우선 보존하고, 이동하거나 크기가 바뀐 돗자리는 가로·세로 방향 중 이동량이 작은 빈자리로 조정합니다. 같은 방향의 장애물 구간을 합쳐 연쇄 겹침도 피합니다. 수동 배치한 도구와 새 함수, 지역 상자로 확장된 프레임, 피연산자 카드로 확장된 알루도 같은 규칙을 적용합니다. 드래그 중에는 미리보기 위치를 보여주고 놓는 시점에 조정합니다. 종료된 돗자리는 장애물에서 제외합니다. 관련 재생·공간 검사 17개가 통과했습니다.

도구 작업대·입력·출력은 첫 화면부터 존재하는 이동 가능한 돗자리입니다. 캐릭터가 없는 현재 재생에서는 계산할 때 알루를 소환하고 그 결과를 저장할 때까지 유지합니다. 상수 공급기·값 전달기·공간 조립기는 캐릭터의 부가 연출로 남겨둡니다. READ는 대상 상자를 강조하고, WRITE는 해당 사건이 시작되면 대상 상자·매개변수·반환구에 실제 기록값을 바로 표시합니다. 운반 카드와 중간 전달기 경유는 없지만 데이터 흐름 화살표는 표시합니다. 계산의 상수와 입력값은 알루 안에 바로 표시합니다. SPACE는 대상 상자·돗자리의 현장 생성·정리 효과를 사용합니다.

알루 위치는 작업대 좌표를 따라 움직입니다. 내부 값 출처 토큰은 화면 크기·카메라 범위·돗자리 배치에 영향을 주지 않습니다. 입력 돗자리는 관찰된 입력 도착만 누적하고 버퍼 재읽기를 중복 입력으로 추가하지 않습니다. 출력 돗자리는 해당 시점까지의 출력으로 갱신합니다. 휠·트랙패드는 공간을 스크롤하고 Shift+휠은 가로 이동, Ctrl/Cmd+휠과 확대/축소 버튼은 배율을 조절합니다. 빈 공간 드래그·가운데 버튼·Space+드래그로 카메라를 이동할 수 있습니다. 전체 보기는 음수 위치와 멀리 옮긴 돗자리를 포함한 현재 내용 범위에 맞추고, 현재 작업은 실행 대상에 초점을 맞춥니다. 화면 밖 상자는 그리기를 생략하고 격자 간격은 배율에 맞춰 조절합니다.

2026-11-09 함수 호출·반환 재생: 상단 예제 선택에서 변수·계산과 함수 호출·반환 기록을 전환합니다. `examples/c/animation/add.c`를 실제 API로 실행한 27개 사건은 `public/animation-functions.json`에 보존했습니다. 호출 전 `c` 상자를 생성하고, FLOW/call에서는 인자 카드를 보존하며, SPACE/frame.begin에서만 호출된 함수의 돗자리를 생성합니다. WRITE/argument는 원래 READ·CALC·다른 호출의 결과 카드 또는 기록된 상수에서 매개변수 상자로 전달합니다. 주소 인자는 기록된 저장 객체를 출발점으로 사용합니다. 함수 이름·변수 이름·숫자의 일치로 관계를 추측하지 않습니다.

반환값은 WRITE/return.value에서 반환구에 기록합니다. 공통 중간언어 생성 모델이 FLOW/return에 실제 수신 위치를 명시하고, 반환값 대입 WRITE 다음에 SPACE/frame.end를 생성합니다. 따라서 순차 재생만으로 ‘반환값 대입 → 함수 필드 정리’가 됩니다. 원시 실행과 실제 메모리 수명은 보존하되, 공개 공간 정리 순서는 [반환 전달 계약](../design/return-sequence.md)을 따릅니다. `void`·사용하지 않은 반환값에는 가상의 수신 작업을 만들지 않습니다. 반복 호출과 재귀는 실제 프레임 ID로 구분합니다. 구체적인 연출 시간과 화면 구현은 별도 시각화 작업입니다.

`src/animation/transfers.js`는 READ·WRITE의 대상과 기록값을 현장 효과에 연결합니다. Canvas는 상수·변수·계산 결과·함수 인자에 같은 대상 강조를 적용합니다. 읽기는 300ms, 쓰기는 350ms이며 별도 운반 명령이나 도구 소환 대기 사건을 추가하지 않습니다. 실제 출처가 있는 쓰기는 해당 전달이 도착한 뒤 값을 표시하고, 상수 대입은 현장에서 즉시 표시합니다. 내부 피연산자·주소 토큰의 수명과 호출 문맥은 유지하므로 시점 이동과 값 출처 추적은 그대로 동작합니다. 실제 add 기록, 이름이 다른 중첩·반복 호출, 재귀, void·포인터 인자, 사용하지 않은 반환값, 돗자리 이동 및 실제 Canvas 그리기 경로를 검사했습니다. 자료구조 추론과 캐릭터 연출은 이 변경에 포함하지 않습니다.

데이터 흐름 화살표는 `inputs.executionId`와 명시적인 호출·반환 관계로 연결합니다. 변수 대입·인자 전달은 원본 상자에서 대상 상자로, 계산은 입력 상자에서 알루로, 계산 결과 저장은 알루에서 목적지로 표시합니다. 한 번에 값 전달선 하나만 나타났다가 사라집니다. CALC의 입력은 기록된 입력 순서대로 전달하고, 도착한 값은 선이 사라져도 알루에 남깁니다. 모든 입력 도착 이후 계산 결과를 표시합니다. 결과 WRITE에는 알루 → 목적지 선만 표시하며 이전 입력선을 다시 그리지 않습니다. 이미 계산한 값을 소비하는 FLOW에서도 입력 전달을 반복하지 않습니다. 상수는 별도 전달선 없이 표시하며 가상의 원본 상자를 만들지 않습니다.

순차 전달은 하나의 기존 중간언어 명령 안에서 나누는 화면 단계입니다. 명령 추가·순서 변경·추가 READ나 C 표현식 재평가는 없습니다. 현재 사건과 진행률만으로 활성 선·도착한 값·판정 준비 상태를 결정하므로 일시정지·시점 이동·재생에서 동일하게 복원합니다. 비교·논리·산술·복사·인자·반환에 같은 전달 규칙을 적용합니다. 반환 출처인 함수 필드는 실제 소비 작업까지 보존합니다.

`src/animation/routing.js`는 현재 상자 좌표를 장애물로 삼아 수평·수직 선분의 경로를 찾습니다. 값 전달선은 다른 상자와 자료형 라벨, 출발지·도착지를 포함하지 않는 다른 돗자리를 우회합니다. 선 중앙의 값 라벨은 표시하지 않아 다른 상자 값을 가리지 않습니다. 배치별 경로를 재사용하고 드래그로 배치가 바뀌면 새 좌표로 계산합니다. 막힌 경로를 상자 관통 직선으로 대체하지 않습니다. 이는 일시적인 값 전달선의 배선이며 지속되는 포인터 참조선의 다발 배치는 별도입니다.

2026-11-09 생성 모델의 반환 순서 보완: `FLOW/return.delivery`와 `SPACE/frame.end.cleanupAfterExecutionId`를 연결하고 공개 사건 목록을 수신 완료 → 공간 정리 순서로 정규화합니다. 실제 읽기·계산·쓰기 순서는 유지하며 공간 정리만 뒤로 배치합니다. 직접 대입의 API 결과는 `return(x21) → resume(x22) → WRITE(x23) → frame.end(x24)`입니다. 관련 모델 검사 31개가 통과했습니다. 이전의 화면 보존 방식은 이 생성 모델 계약을 대신하지 않습니다.

함수 돗자리를 펼칠 때 매개변수 자리도 함께 표시합니다. `frame.begin.parameters`·컴파일러 함수 선언·`ParmVarDecl`과 실제 인자 WRITE의 parameterIndex/대상 ID를 연결합니다. `displayScene`이 화면용 빈 자리를 만들며 실제 실행 상태의 객체 생성·값·수명은 앞당기지 않습니다. 매개변수는 별도 행과 배지, ‘인자 대기’로 표시합니다. 이후 SPACE/object.begin은 그 자리에 실제 저장소를 연결하고 두 번째 생성 연출을 하지 않습니다. WRITE/argument에서 실제 값을 채우며, 일반 지역변수는 원래 선언 시점에 나타납니다. 재귀·반복 호출도 프레임 ID별로 구분합니다. 화살표 연결, 매개변수 동시 표시, 저장소 연결 시 위치 유지, 실제 Canvas 경로 등을 포함한 관련 검사 32개가 통과했습니다.

조건 판정은 `src/animation/conditions.js`가 AST 작업·기록된 CALC 결과·FLOW의 condition/selectedOutcome·논리식 평가 정보를 읽어 표시합니다. C 피연산자를 JavaScript로 다시 비교하거나 형 변환하지 않습니다. `< <= > >= == !=`, 논리 `! && ||`, 수치·실수·_Bool·포인터의 직접 조건, 삼항식과 반복 조건을 공통 처리합니다. 참은 초록과 ‘참 · True’, 거짓은 빨강과 ‘거짓 · False’로 함께 표시하며 색만으로 구별하지 않습니다. 결과가 0/1인 일반 산술식을 부울식으로 오인하지 않고, 산술식 내부의 비교는 부분 판정으로 구별합니다. 산술 조건의 진릿값은 FLOW에 기록된 실제 변환 결과를 사용합니다.

논리식은 실행한 하위 판정과 피연산자를 표시하고, 단락 평가로 실행되지 않은 피연산자는 회색·‘평가 생략’·도움말로 표시합니다. 미실행 피연산자의 참거짓을 만들거나 호출·증가·메모리 읽기를 수행하지 않습니다. NOT으로 감싼 논리식도 하위 노드의 실제 결과와 최종 결과를 구별합니다. switch는 부울 판정으로 바꾸지 않고 선택된 case/default를 표시합니다. 각 연출은 현재 중간언어 사건에 종속되며 명령을 추가하지 않습니다. 분기와 반복의 실제 break/continue/goto/loop.next도 공개 FLOW 동작으로 재생합니다.

조건 예제 세 종류는 `comparisons.c`(6종 비교·signed/unsigned·실수·NaN·_Bool·NULL), `logic.c`(복합 논리·부정·단락 평가·부작용 보존), `branches.c`(if/else·삼항·switch·while/do/for 조건)이며 기존 예제 API로 현재 모델을 실행합니다. 조건 패널과 알루·코드 강조에 같은 기록 결과를 사용하고 시점 이동에서도 복원합니다.

확인된 중간언어 누락: `if (1)`·`if (0)`처럼 컴파일러가 조건 분기 자체를 제거하면 현재 모델은 해당 판정의 실행 사건을 만들지 않습니다. 이 경우의 신호를 렌더러가 임의로 만들지 않습니다. 상수 논리식의 결과를 저장하는 `result = 0 && ++calls` 등은 기존 기록으로 표시되지만, 제거된 제어 조건까지 모두 지원한다고 간주하면 안 됩니다. 해당 계열은 실행 경로에 연결된 공통 모델의 관찰·명령 보강이 필요합니다.

기초 확인은 ① 변수·계산, ② 함수, ③ 조건·반복, ④ 포인터, ⑤ 배열·구조체, ⑥ 동적 메모리, ⑦ 입출력·라이브러리, ⑧ 상태·오류의 8묶음으로 진행합니다. 현재 ①~⑤의 기초에 이어 ⑥·⑦의 실제 모델 예제를 연결했습니다. 동적 할당·재할당·해제, 복사·채우기·입력 저장·버퍼 쓰기와 출력 채널의 규칙은 [동적 메모리·입출력 확인](memory-io.md)에 정리했습니다. ⑧은 후속 확인 대상이며, 최종 단계에서 8묶음을 함께 사용하는 실행으로 검증합니다.

기존 컴파일·실행 화면과 trace API의 실행 중 정지·재개 연결은 후속 단계입니다. `scripts/animation/stub.mjs`는 기존의 예약 입구이며, 현재 페이지는 저장된 공개 명령·사건을 직접 재생합니다.


## 상세 표시와 간결 표시

중간언어 생성은 항상 비간결 기준입니다. 간결 모드는 기록을 그대로 두고 이동·값 운반·알루 내부 단계·반복 전환·부차적 상세의 연출만 줄입니다. 코드 위치, 값·참조 변경, 생성·해제, 오류는 알아볼 수 있어야 합니다. 현재 plan.presentation에 규칙을 기록하며 실제 모드 전환 UI와 애니메이션은 구현하지 않습니다.

- 자료형 정의는 설계도입니다. 작성 연출은 후보이며, 정의를 읽었다고 함수 공간이나 객체를 미리 생성하지 않습니다. plan.typeBlueprints는 정적 정보입니다.
- 대입은 상자로 이동 → 값 읽기 → 계산 → 대입을 기본으로 합니다. 관찰된 대상 주소와 C 평가 순서를 우선합니다.
- `+=`, `-=` 등 오른쪽이 단일 값인 복합 대입은 대상 상자에서 바로 갱신할 수 있습니다. READ/CALC/WRITE 기록은 유지합니다.
- 초기화는 상자 생성 → 호출·계산 → 반환값을 바로 대입합니다. 반환과 대입 사이에 가상의 임시 상자를 만들지 않습니다. 반환값의 실제 다음 소비자가 계산·다른 호출·반환구이면 그 작업으로 전달합니다.
- 논리식은 기본적으로 양쪽을 설명하되 생략된 쪽은 미실행으로 명시합니다. 설명 때문에 프로그램을 추가 실행하지 않습니다. 간결 모드에서는 생략된 쪽의 설명을 숨깁니다. 안전한 상태 기반 미리보기 계산은 후속 구현입니다.
- `free(p)`는 대상 할당의 수명을 끝냅니다. 포인터 변수 p를 없애거나 NULL을 자동 대입하지 않습니다.

반환 수신 작업과 함수 공간 정리의 순서는 생성 모델이 확정합니다. 공개 중간언어에서는 실제 수신 WRITE 뒤에 SPACE/frame.end가 오며, C 원시 실행의 종료 시점은 별도로 보존합니다. 렌더러에서 임의로 작업 순서를 다시 추론하지 않습니다.
