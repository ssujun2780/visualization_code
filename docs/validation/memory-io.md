# ⑥ 동적 메모리와 ⑦ 입출력·라이브러리

이 문서는 각 검증 당시의 이력입니다. 이후 입력 재실행 방식은 같은 실행을 유지하는 [입력 대기](../design/interactive-input.md)로 변경됐습니다. 현재 화면 정책은 [애니메이션](../design/animation.md)·[시각화](../design/visualization.md)·[UI](../design/ui.md)를 따릅니다. 이전 시점의 미구현 설명과 현재 상태를 구분합니다.

2026-11-09. 기존 실행 사건·순서·수명은 유지하고 공통 재생·표시 계층을 보완했다. 캐릭터 없이 기존 생성·정리, 범위 강조, 전달 화살표를 사용한다. 자료구조 추론은 변경하지 않았다.

## 동적 메모리

`dynamic-memory.c`는 malloc과 calloc, 확장·축소 realloc, free와 NULL 대입을 사용한다. 예상 stdout은 `7 11 11\n`이며, 실제 모델 실행으로 확인한다.

- SPACE/object.begin에만 저장소를 생성한다. malloc은 미초기화, calloc은 기록된 0 바이트를 표시한다. 포인터 대입 후 관찰된 C 자료형으로 원소를 표시한다.
- 재할당은 기록된 copiedFrom의 범위만 보존한다. 이전에 관찰된 자료형·원소는 보존 범위 안에서 이어받고, 새 꼬리에는 값을 만들지 않는다. 주소는 문자열 표기가 아닌 실제 숫자로 비교한다.
- 이전 저장소 종료 → 새 저장소 생성이라는 사건 순서는 유지한다. 새 저장소 생성 사건의 copiedFrom을 전달선으로 표시하고, 이미 종료된 이전 저장소는 점선 참고 모습으로만 보여준다. 실제 수명을 되살리거나 포인터를 자동으로 새 저장소에 연결하지 않는다.
- free는 저장소를 정리하고, 남은 포인터는 기존 수명 종료 표시를 사용한다. NULL 대입은 뒤에 기록된 WRITE에서만 반영한다.

## 입출력과 메모리 효과

`io-library.c`의 기본 입력은 `3 abc\nhello\n`이다. 예상 stdout은 `abc!:3\n!!!\nhello\n`, stderr는 `len=6\n`이다.

- 표준 입력 편집 후 예제 다시 실행으로 현재 모델을 새로 실행한다. 입력은 POST JSON과 프로세스 간 메시지로 전달하며, 비어 있는 입력도 그대로 전달한다. 기본 GET 실행은 유지한다. 입력은 UTF-8 16KB까지다.
- READ/input 도착과 buffer-read를 구분한다. 버퍼 재읽기를 새 입력으로 누적하지 않는다. WRITE/input 및 WRITE/write.range의 관찰된 범위를 저장하고 표시한다.
- 복사는 sourceObjectId·offset·size에 따라 범위끼리 연결한다. memmove의 겹침도 동일한 규칙이다. memset은 기록된 byte와 범위를 표시한다.
- snprintf 등 버퍼에 쓰는 외부 함수는 범위 저장으로 표시하며 터미널 출력에 추가하지 않는다. 출력은 함수 이름과 무관하게 WRITE/output의 스트림 기록을 사용한다. readRegions가 있으면 실제 읽은 버퍼에서 전달선을 표시한다.
- stdout과 stderr를 각각 누적하고 전체는 기존 사건 순서대로 유지한다. 선택기로 두 스트림을 따로 볼 수 있다. 재생 중 해당 출력의 전달이 끝나면 화면에 도착하지만, 중간언어 클릭만으로 미래 출력을 반영하지 않는다.
- 외부 함수의 내부 프레임을 꾸미지 않는다. 호출·반환은 기존 작업대에 함수 이름·효과·기록된 결과를 표시하고, 결과를 소비하는 WRITE는 작업대에서 목적지로 연결한다. getchar처럼 입력 사건에 직접 연결된 결과는 입력 돗자리에서 전달한다.
- 알려진 문자 배열의 NUL까지 읽을 수 있으면 문자열 미리보기를 표시한다. 문자 원소는 문자와 `\\0`으로 표시한다. 미초기화 바이트를 문자열로 추측하지 않는다.

## 검사 범위

새 두 예제의 실제 중간언어를 재생해 값·범위·해제·주소 변화·채널·입력 중복 방지·시점 복원을 검사한다. 기록과 이전 상태가 표시 때문에 변하지 않는지도 확인한다. 같은 렌더러로 생성·복사·입력 저장·출력·반환을 검사하고, 실제 HTTP API에서 다른 입력과 빈 입력, 잘못된 요청을 검사한다.

관련 기존 애니메이션 검사와 빌드만 실행한다. 과거 전체 C 예제 모음과 자료구조 추론 검사는 다시 실행하지 않는다. 아직 파일 스트림 편집, 대화식 실행 도중 입력 추가, 모든 외부 라이브러리 계약, ⑧ 상태·오류 연출의 완성은 포함하지 않는다. 알 수 없는 외부 효과는 현재 모델이 실제로 관찰한 범위까지만 표시한다.

최종 관련 회귀 검사 73개와 Vite 빌드가 통과했다. 2바이트 원소의 재할당, 0으로 초기화된 보존 영역과 미초기화 꼬리, snprintf 잘림, fwrite·fputc, 이미 값이 있는 스칼라에 대한 입력·채우기·일부 바이트 복사도 확인했다. 범위 쓰기는 기존 스칼라 표시값을 무효화하고 관찰된 바이트로 갱신하며, 바이트 별칭이 선언된 스칼라를 임의로 배열로 바꾸지 않는다.

브라우저에서는 12→20 B 재할당 후 7·11 보존 및 새 원소 미초기화, snprintf 후 문자열 상자와 아직 비어 있는 출력, 사용자 입력 변경 후 stdout/stderr 분리를 확인했다. `4 xy\nworld\n`로 다시 실행한 결과 stdout은 `xy!:4\n!!!\nworld\n`, stderr는 `len=5\n`이었다.

## 입력 필드와 속도 조정

입력 편집창은 실행 공간의 기존 입력 돗자리 안에 둔다. DOM 편집기는 월드 좌표·카메라 배율을 따라 이동하며, 화면 밖에서는 숨긴다. 제목 드래그는 기존 캔버스가 처리하고 편집·선택·스크롤은 실제 textarea가 처리한다. 편집 중인 다음 실행 입력과 현재 실행에서 도착한 입력을 구분한다. ‘이 입력으로 다시 실행’은 현재 모델에 입력을 전달해 새 기록을 만든다. 입력·출력 사건의 ‘현재 작업’은 해당 돗자리에 초점을 맞춘다.

초기에는 전체 시간을 두 배로 늘렸지만, 2026-11-10부터 [사건별 시간선](../design/animation-incidents.md)으로 바꿨다. 강조·이동·도착·계산·반영·결과 확인 시간을 합산하며 사건이 많아져도 개별 시간을 압축하지 않는다. 0.1×~4× 슬라이더는 0.1× 간격으로 이 시간선을 조절한다. 중간언어 순서와 명령어 경계에서의 실제 상태 반영은 유지한다.

관련 검사 32개가 통과했다. 카메라 이동·배율·돗자리 이동·초기화·화면 밖 숨김, 같은 실제 진행률에서 0.1/0.5/1/2/4×의 상태 일치와 쓰기 경계를 검사했다. 브라우저에서 슬라이더 양 끝과 1× 복귀, 필드 안의 입력 `5 zz\nfield\n`로 재실행 후 결과와 도착 입력을 확인했다.
