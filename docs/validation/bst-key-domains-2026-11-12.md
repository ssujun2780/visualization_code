## 먼저 작성한 기대와 실제 결과

입력과 기대는 `tests/fixtures/bst-key-domains.mjs`, 검사는 `tests/ir-bst-key-domains.test.js`에 있습니다. 추론기는 이를 가져오지 않으며 파일명·변수명·특정 키 값으로 분기하지 않습니다.

| 입력 변형 | 기대와 실제 결과 |
|---|---|
| double 구조체, 부모는 맞지만 조상 경계를 넘는 변경 | 정상 → 위반 → 복구 → NaN으로 불완전 |
| float 값과 자식 인덱스의 분리 배열, 종료까지 순회 | 정상 → 키 변경 위반 |
| char* 키, 문자 한 개 변경 | 정상 → 위반 → 복구 |
| 레코드 내 char 배열, 재귀·strcmp 역순 인자 | 정상 → strcpy 이후 위반 |
| 별도 객체에 있는 내장 char 배열 | 정상 → 위반 → 복구; 같은 할당 안에 있다는 가정 없음 |
| 문자열 포인터 재대입 | 정상 → 새 대상 위반 → 복구 |
| double + int 복합 키 | 정상 → 두 번째 성분 위반 → 복구 |
| 문자열 + int 복합 키 | 정상 → 두 번째 성분 위반 → 복구 |
| 문자열 + int 복합 키 삽입, 동등 키의 연속 이동 | 중복 허용 관측 → 엄격 조상 경계 위반 |
| int32→double 비교 | 정상 |
| double→int 키 변환 | 판정 불가 유지 |
| strcmp 반환값과 0이 아닌 상수 비교 | 현재 지원 범위 밖으로 판정 불가 유지 |

초기 `floating-split` 예측은 현재 숫자가 정렬됐다는 사실만으로 정상 BST 추론까지 기대했습니다. 실제 기록에서는 음수 종료 인덱스를 방문하지 않아 원본 인덱스 관계가 불완전했습니다. **원래 코드·예측·실제 결과를 보존**하고, 별도 `floating-split-complete` 입력에 실제 종료까지의 순회를 추가했습니다. 새 입력은 실행 전에 `A 5\nB\n`, 정상→위반을 기대하도록 작성했습니다. 추론기의 관계 완성 조건이나 기존 검사를 약하게 바꾸지 않았습니다.

관측 자료형 확장 중 발견한 공통 누락도 함께 수정했습니다. 형변환 단계는 `operator:null`이어도 기존 `conversion` 메타데이터로 인식하고, 접힌 상수 반환은 실제 기록 값과 제어 분기를 보존합니다. 문자열 비교의 참거짓과 반환 경로도 복합 비교의 앞 성분 조건으로 연결합니다.

## 남은 항목과 한계

기존 `ir-structure-composition.test.js`의 한 검사는 `omittedStates=1`로 바꾸고 상태를 잘라내지만 `historyGapFromExecutionId:null`을 유지합니다. 현재 이력 계약의 생략 구간과 맞지 않는 입력에서 AVL 조회가 `satisfied-observed`를 반환하여, 검사의 `incomplete` 기대와 다릅니다. 수정 전 HEAD 추론기에서도 동일합니다. 이 입력을 검증기가 거부할지, 조회가 불완전으로 처리할지 및 옛 검사 형식의 호환 범위는 별도 보완 대상이며 **이번에는 검사 기준·이력 모델을 변경하지 않았습니다**.

후속 작업에서 이 항목과 추가로 확인한 생략 구간의 종료 오판·BST 관계 근거 소실을 수정했습니다. 위 문단은 키 자료형 작업 당시의 결과이며, 현재 결과는 [이력·근거 수정 검증](inference-tree-history-fix-2026-11-12.md)에 있습니다.

관측되지 않은 종료·링크·키의 의미, 임의 로캘/문자열 비교, 임의 키 산술, 순서 변경 형변환까지 지원한다고 주장하지 않습니다. 문자열에 키 관측 한도를 적용하며, 근거가 부족하면 미확인 상태를 유지합니다. 사용자 의도를 지정하는 UI 및 누락된 관계를 사용자가 새로 정의하는 일반 API는 이번 범위가 아닙니다. 화면 가독성·애니메이션 검증은 수행하지 않았습니다.
