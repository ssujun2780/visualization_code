# 일반 실행의 간선 목록 그래프와 A*·LWA* 예제

2026-11-14. 수동 역할 기록을 별도 페이지에서 보여 준 이전 결과는 일반 예제 실행의 해결이
아니었습니다. 해당 페이지와 지정 스크립트를 제거하고 기존 메뉴의 실행·추론·표현 경로를 고쳤습니다.

적용 계약은 `presentation.md`, `inference-model.md`의 분리 경계와 그래프 저장 역할,
`graph-worklist-relations.md`, `structure-presentation-policy.md`, PS-01·02, SS-01~04,
`ui.md`의 현재 작업·작업 따라가기입니다. 생성 모델의 실제 READ·인덱스 출처가 충분해
생성기나 원본 실행 사건을 바꾸지 않았습니다.

검사 전에 고정한 조건은 다음과 같습니다.

- 기본 입력 3: 8정점·12방향 간선, 가중치 300/305/325/375/500/780이 두 번씩.
- GRAPH_READY가 SEARCH_BEGIN보다 먼저이며 그 전에 OPEN·POP·CHECK·EXPAND가 없음.
- 그래프는 충돌 검사 전의 잠재 연결이며 차단 결과를 미리 반영하지 않음.
- 경로 0→3→7, 비용 650, A* 검사 6회·LWA* 검사 3회.
- 이름 변경에 불변, 미사용 용량 제외, 평행 간선 보존, 변환 인덱스 제외,
  단순 복사를 덧셈 가중치로 오인하지 않음, 끝점 수정 후 기존 연결은 미확정.

| 설계 조항 | 변경 위치 | 검증 근거 | 범위와 남은 항목 |
|---|---|---|---|
| 생성·추론 분리 | `edge-list-proofs.mjs`, `traversal-graph-views.mjs` | 실제 비교·분기·동적 커서·정점 접근·덧셈 출처만 결합 | 직접 정수 인덱스의 레코드 배열, 관측된 분기 내부 관계 지원 |
| 시점·저장 범위 보존 | `structure-overlay-contract.mjs` 및 신규 근거 검증기 | 좌표/분기/끝점 변조 거부, 실제 값 대조, WRITE 무효화, 복사·산술 변환 반례 | 작성 의도·방문 완료·정답 경로 색을 자동 확정하지 않음 |
| 그래프 완성 후 연산 | 두 C 파일의 `build_graph`, `initialize_search`, `search` | 256회 독립 정답 검사와 순서 단언; 기존 API에서 SEARCH_BEGIN 이전 8/12/12 | 구성 O(VE)는 공통 전처리이며 탐색 시간과 별도 |
| SS-02·03 | `structure-layout.js`, `structured-memory.js`, `canvas.js` | 같은 층 가로 배치, 모든 원본 필드/대표 포트 보존, 현재 작업 전체 그래프 확대 검사 | 전체 공간 자동 최적화나 모든 화면 크기의 보장은 아님 |
| 실제 일반 화면 | 기존 `animation.html` 예제 메뉴 | 화면 검사 결과는 아래 기록 | 수동 JSON·수동 역할·별도 페이지 사용 금지 |

관련 검사:

- `tests/ir-edge-list-graph.test.js`: 6개 통과. 곱셈으로 변형한 비용을 원래 저장 가중치로 표시하지 않는 반례 포함.
- 그래프·저장 관계·레코드 인덱스 회귀: 19개 통과.
- 공통 모양·고정 표현·저장 기록·축소 그래프: 48개 통과.
- `python examples/c/pathfinding/verify.py`: 엄격 C11 4빌드, 정상 256회,
  잘못된 입력 12회, EOF 기본값 4회. 독립 정수 기하 판정과 Floyd–Warshall 비교.

화면 검사는 기존 메뉴 선택과 기존 현재 작업 버튼으로 수행합니다. 테스트의 관찰자는
렌더러 인스턴스만 읽으며 그래프 역할·배치·카메라 값을 주입하지 않습니다.
기존 메뉴에서 A*와 LWA*를 각각 새로 컴파일·실행했습니다. 1680×1050 화면에서
구성 완료 직전의 마지막 정점 관리 WRITE, 검색 초기화의 마지막 WRITE,
목적지 비용·부모 갱신 시점을 검사했습니다. 6개 화면 모두 8정점·12간선을 유지하고
정점 전체가 Canvas 안에 있으며 원의 화면 지름은 약 59px였습니다. 가중치와 실제
g값(목적지 650)이 함께 읽히는 것을 캡처로 확인했습니다. '전체 보기'로 모든 함수 공간을
축소한 사진을 그래프 가독성 근거로 사용하지 않았습니다.

목적지 갱신 부근의 짧은 1배속 재생 구간은 A* 5505→5507, LWA* 5173→5175로
진행했습니다. 수천 개 사건 전체를 1배속으로 완주한 검사는 아닙니다.
`test-results/pathfinding-comparison/*.ordinary-{ready,search,end,1x}.png`에 근거를 보관했습니다.
원형 노드의 숫자 변화는 실제 첫 필드 g이며 방문 완료/최적 경로를 별도 로그로 색칠하지 않습니다.

`node node_modules/vite/bin/vite.js build`가 성공했습니다. 기존 코드 편집기 번들의 큰 청크
경고는 남아 있으며 이 작업에서 번들 구성을 변경하지 않았습니다.

가중치의 보존 전달 조건을 마지막으로 강화한 뒤, C를 재실행하지 않고 앞서 일반 메뉴/API에서
얻은 두 원본 실행을 다시 추론했습니다. 양쪽 모두 탐색 전 8정점·12간선·12가중치가 유지됐습니다.
`latest-reinference-summary.json`에 결과를 보관했습니다.
