BST 의미 판별과 `bst-order` 검사기는 기존에 명시된 미구현 범위입니다. 이번 조사에서 이미 구현된 BST 기능이 고장 난 것으로 세지 않습니다. 새로 확인한 기존 기능의 문제는 아래 A1·A2입니다.

| 사례 | 소스로 예상한 관계/의미 | 실제 결과 |
|---|---|---|
| 01 포인터 트리, 키 변경·복구 | 구성원 `{0,1,3,4}`. 검색 전은 일반 트리; 검색 후 BST 근거. 7→12는 조상 경계 위반, 12→7은 복구 | 모든 시점에 정확한 4노드 이진 트리. BST 추천 없음, 명시한 `bst-order`는 `not-checkable` |
| 02 값·좌·우 분리 배열 | 01과 같은 4노드 관계·키 조건 | 정확한 4노드 후보는 있음. 추천의 대표 트리는 2노드 부분 경로로 잘못 선택됨 |
| 03 역순 비교 보조 함수 | 큰 값은 x, 작은 값은 y. 역순 BST; 12→8은 조상 경계 위반 | 정확한 4노드 이진 트리. 역순 BST·범위 판별 없음. 별도로 0노드 리스트 추천 |
| 04 중복 오른쪽/왼쪽 삽입 | `<`와 `<=` 분기 및 실제 동등 키 삽입으로 서로 다른 중복 규칙 | 두 대상 모두 정확한 4노드 이진 트리. 중복 정책 의미 판별 없음 |
| 05 정렬 모양의 일반 트리·정렬 배열 | 키가 우연히 정렬되어도 BST 의도 미확정. 미실행 검색 함수는 실행 근거가 아님 | 트리는 3노드 이진 트리, 배열은 배열. BST/heap 오추천 없음 |
| 06 복합 키·부모 링크·캐시 | `(major,minor)` 사전식 비교. cache 변경은 무관; `(2,1)`→`(2,6)`은 루트 `(2,5)`의 경계 위반 | 보조 부모 링크와 구별되는 정확한 4노드 자식 트리. 복합 키·조건 판별 없음 |

05는 현재의 보수적인 결과를 확인한 반례입니다. BST 판별기가 아직 없으므로, 미래 판별기의 오인식 방지가 검증된 것은 아닙니다.

## A1. 겹치는 분리 배열 후보 사이의 범위 계산 누락

02의 핵심은 다음과 같습니다.

```c
int val[6]={7,5,99,10,15,100};
int west[6]={-9,-9,-9,1,-9,-9};
int east[6]={-9,0,-9,4,-9,-9};
// root=3: west 3→1, east 3→4 및 1→0
int find(int i,int k) {
    while(i>=0) {
        if(val[i]==k)return 1;
        i=k<val[i]?west[i]:east[i];
    }
    return 0;
}
```

실제 추천에서는 다음 두 후보가 공존합니다.

| 후보 | 구성원 수 | familyNodeCount | omittedNodeCount | 선택 |
|---|---:|---:|---:|---|
| val+east의 부분 경로 | 2 | 2 | 0 | 대표 tree; linked-list도 추천 1위 |
| west+east의 전체 관계 | 4 | 4 | 0 | tree의 alternatives에 남음 |

두 후보 모두 같은 root를 정확히 가리킵니다. 전체 관계는 소스 예상의 구성원·간선과 일치하므로 연결 자체를 잃은 문제가 아닙니다.

원인은 `structure-presentation.mjs`의 rooted-index 후보 `related()`입니다. 동일 relation 또는 **coindexed 후보와 단일 배열 후보**의 직접 연결은 확인하지만, **서로 겹치는 coindexed 후보끼리**의 관계를 연결하지 않습니다. 그 결과 val+east 부분 경로가 west+east 전체 관계와 같은 범위를 비교하지 못합니다. 이후 정렬은 이미 잘못 계산된 누락 수 0을 사용합니다.

공통 보완 방향:

1. 실제 공동 인덱스·역할 결합 근거를 이용해 같은 루트/논리 영역의 후보 관계를 연결합니다. 이름·배열 길이·키 숫자로 결합하지 않습니다.
2. 관계군 구성원은 같은 논리 영역임이 입증된 식별자로 합집합을 구합니다. 서로 다른 영역의 인덱스 0을 동일 노드로 취급하지 않습니다.
3. 부분 후보의 표시 수 2는 유지하고 가족 수 4·생략 수 2로 비교합니다. 부분 경로는 대안으로 남기고 전체 관계가 대표 추천에 반영되게 합니다.
4. 근거 시점·루트 변경·분리된 무관한 트리를 함께 확인해야 합니다. 단순히 노드가 많은 후보를 무조건 우선하면 안 됩니다.

## A2. 전체 루트 조회에 자식 NULL 슬롯의 빈 리스트가 섞임

03에서 `root`의 이진 트리/일반 트리/그래프는 4노드로 맞습니다. 그러나 같은 추천 목록에 `linked-list`, 구성원 0, `exactRoot:false`인 후보가 들어옵니다. 해당 후보의 루트는 main의 root가 아니라 배열 안의 NULL 자식 포인터 슬롯입니다.

실제 조회 대조:

- `{objectId: root의 객체}` 조회: 0노드 연결 리스트가 포함됩니다.
- 정확한 4노드 트리의 `{structureId: ...}` 조회: 그 빈 리스트가 사라집니다.

원인은 두 규칙의 조합입니다.

- `structure-storage.mjs:selectedStorageRanges()`는 포인터 대상을 `대상 오프셋부터 할당 끝까지` 넓힙니다. 같은 할당 안의 자식 포인터 슬롯들도 조회 범위에 들어갑니다.
- `structure-presentation.mjs`는 살아 있는 루트 슬롯의 empty 상태를 빈 연결 리스트로 제안합니다. 이 후보의 가족 크기는 0이므로 전체 트리 대비 생략된 노드도 계산되지 않습니다.

빈 컨테이너를 표현하는 기능 자체는 필요합니다. 따라서 `nodeCount===0`을 일괄 삭제하는 수정은 부적절합니다.

공통 보완 방향: **선택한 시작점**, **실제 도달 구성원**, **동일 할당 안의 인접/내부 슬롯**을 구분합니다. 전체 루트를 조회할 때 다른 자식 슬롯의 빈 상태를 전체 자료구조 추천처럼 올리지 않습니다. 사용자가 해당 NULL 슬롯을 직접 선택하거나, 확인된 컨테이너가 삭제 후 비었을 때는 빈 상태를 유지합니다. 포인터가 배열 전체를 가리키는 보기 기능도 별도 관계 근거와 함께 보존해야 합니다.

## S1. BST 의미 판별을 추가할 때 필요한 공통 계층

이번에 원하는 BST 후보 8개 시점에서는 모두 BST가 제안되지 않았습니다. 조상 경계 위반 4개 시점에서도 정확한 트리 형태만 유지합니다. 이는 기존 미구현 범위를 실제 코드로 확인한 결과입니다.

01에서는 다음과 같이 **부모만 비교하면 놓치는 변화**가 있습니다.

```text
       10                 10
      /  \               /  \
     5   15             5   15
      \                  \
       7                 12
```

12는 바로 위 부모 5보다 크지만, 조상 10의 왼쪽에 있어야 한다는 상한을 위반합니다. 포인터·노드 수·트리 형태는 전혀 바뀌지 않습니다. 정상 C 실행이므로 실행 ERROR를 생성하면 안 됩니다.

보완은 저장 방식과 독립적인 다음 순서가 적절합니다.

1. **관계와 비교 근거 연결:** 기존 노드 식별자·좌/우 역할에 실제 READ→CALC→분기→다음 노드 선택을 연결합니다. 검색 함수 이름이나 현재 키의 정렬 모양만으로 BST를 판정하지 않습니다. 키 비교가 실행되기 전에는 미래의 근거를 사용하지 않습니다.
2. **키·규칙 기술:** 포인터/정수 인덱스/분리 배열에 공통으로 적용할 키 출처, 비교 방향, 중복 허용 방향을 부가 정보로 남깁니다. helper의 매개변수·반환 출처도 연결합니다. 04의 실제 동등 키 삽입은 중복 방향 근거가 되지만, 동등 키를 찾아 반환했다는 사실만으로 삽입 정책을 정하지 않습니다.
3. **독립 조건 검사:** 모든 조상에게서 받은 상한·하한을 전파합니다. `<`와 `<=`에 따른 열린/닫힌 경계, 03의 역순, 06의 복합 키를 구별합니다. 지원할 수 없는 비교자는 `not-checkable`, 관측이 부족하면 `incomplete`로 둡니다. 임의의 사용자 함수를 다시 실행해 검사하지 않습니다.
4. **시점별 갱신:** 키/연결 쓰기로 현재 검사를 무효화·갱신하고, 01처럼 복구된 상태도 다시 평가합니다. 캐시는 실제 키 의존성이 없으면 키 검사에 포함하지 않습니다. 위반 근거는 변경 WRITE와 경계 조상을 가리켜야 합니다.
5. **표현 정책 분리:** 자동 추천·사용자 지정·현재 조건 결과를 구별합니다. 사용자가 일반 트리를 지정하면 BST 제약을 강제하지 않습니다. BST를 지정했다면 위반이 나와도 표현 지정은 유지하고 부가 경고를 제공합니다.

공통 추론 단계에 비교 의미를 해석하는 별도 모듈을 두고, 기존 tree/index/pointer 후보를 입력으로 받는 방향입니다. 생성 모델의 READ·WRITE·CALC·FLOW·SPACE나 실행 순서는 바꾸지 않습니다. 현재 사용자 tree 지정 우선 정책은 모든 조회에서 유지됐습니다.
