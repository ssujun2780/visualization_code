# 다음 자료구조: 트라이 계열 감사

아래는 수정 전 감사 기록입니다. 이후 네 항목의 구현과 재검사 결과는 [트라이 보완 검증](trie-structures-fixes-2026-11-11.md)에 기록했습니다.

예제는 `example/c/codex_code/trie_structures_20261111/`, 고정 예상·중간언어·추론·메모리 비교는 `test-results/trie-structures-audit-2026-11-11/`에 있습니다. 이 감사에서는 추론기/생성 모델을 수정하지 않았습니다.

실행 전에 예상 노드·문자 간선·단어 종료·질의 결과를 `expectations.json`으로 저장했습니다. 일반 실행과 계측 실행 모두 **5/5 정상**, **2,221사건**, `irGaps=[]`입니다. 기록된 바이트를 별도로 읽어 실제 간선/종료 표지가 예상과 일치하는지 검사했습니다. 추론 결과를 예상의 정답으로 사용하지 않았습니다. 입력과 모델·추론 구현 파일의 해시도 유지했습니다.

## 예상과 실제

앞 세 구현은 `a`, `ab`, `ba`를 저장합니다. 루트를 포함해 노드 5개, 간선은 `0-a→1`, `1-b→2`, `0-b→3`, `3-a→4`, 단어 종료는 노드 1·2·4입니다. `b`는 경로가 있지만 저장된 단어는 아닙니다. `ab,b,ba,bb` 조회 결과는 `1,0,1,0`입니다.

| 구현 | 실제 추론 | 부족한 점 |
| --- | --- | --- |
| 01 포인터 자식 배열 | 저장 그래프에 노드 5개와 포인터 관계 존재. 추천 `array, graph` | 자식 수 변수가 없는 희소 포인터 배열을 논리 트리로 묶지 못함 |
| 02 정수 인덱스 격자 + 종료 배열 | 행 관계 후보에 노드 5개, 간선 4개. 추천 `binary-tree, grid, tree, array, graph` | 트리 모양은 찾았지만 열 0/1과 문자 a/b의 대응, `done`의 단어 종료 역할을 결합하지 못함. 일부 미조회 -1 슬롯은 `unknown`으로 남음 |
| 03 자식/형제 연결 목록 | 물리 두 필드를 합하면 노드 5개와 연결 보존. 기본 루트의 단일 down 역할은 `[0,3,4]`만 포함. 추천 `array, graph, linked-list, binary-tree, tree` | 형제는 같은 부모의 다른 자식이라는 논리 투영이 없음. 추천 일부는 2개 노드의 부분 목록/트리이며 전체 트라이가 아님 |
| 04 압축 트라이 | `ca`, `r`, `t`, `dog` 간선과 대상 포인터가 저장 사실에 있음. 조회 `car,ca,dog,cab → 1,0,1,0`. 추천 `array, graph` | 부모 안 Edge 배열·문자열 라벨·다음 Node를 논리 간선으로 결합하지 못함 |
| 05 순환 자동자 반례 | 행 관계의 순환 관측. 추천 `grid, array, graph`, 트리 추천 없음 | 트라이로 오인하지 않음. 미조회 전이 한 개는 미확정이므로 자동자 전체를 복원했다고 주장하지 않음 |

`binary-tree`는 두 문자 예제의 관측된 최대 자식 수에 따른 모양 후보입니다. BST나 트라이 의미를 알아냈다는 뜻이 아닙니다.

## 공통 보완 방향 — 아직 미구현

1. **희소 자식 배열 투영.** `p = p->child[c]`의 실제 포인터 읽기→역참조와 반복 진행을 연결하고, NULL 슬롯과 실제 대상 노드를 분리합니다. 현재 `pointer-tree-views.mjs`의 배열 투영은 `recordPrefixMembership`에서 자식 수 근거가 있는 경우 중심이라, 개수 변수 없이 문자 슬롯을 선택하는 표현이 빠집니다. 배열 크기 전체를 자식 수로 간주하면 안 됩니다.
2. **문자 선택과 단어 종료 의미.** `c=*s-'a'`, `next[p][c]`, 입력 끝의 `return done[p]`를 실제 값 전달과 조건으로 연결합니다. 경로 존재와 단어 종료를 구별하고, 보조 debug 값이나 방문 표지를 terminal로 단정하지 않아야 합니다. 문자 집합/변환을 이름이나 `'a'` 상수에 고정하지 않습니다.
3. **반복문 자식/형제 투영.** 현재 first-child/next-sibling 발견은 연속 재귀 호출 근거 중심입니다. `q=p->down; while(q && q->token!=*s) q=q->side; p=q` 같은 반복 조회도 부모 고정·형제 탐색·선택된 자식으로 하강의 실제 출처로 다뤄야 합니다. 물리 `3→1` 형제선을 논리 `0→1` 자식 관계로 별도 투영하되 원래 포인터는 보존합니다.
4. **압축된 라벨과 간선 소유권.** 부모의 Edge 배열 원소가 가진 문자열 비교, 입력 커서 길이 이동, 대상 Node 전달을 한 관계로 결합해야 합니다. 문자열 포인터를 자식 노드로 착각하거나 접두어 `ca`를 저장된 단어 `car`와 동일 취급하면 안 됩니다. 일반 라벨 그래프/순환 자동자와 구별할 구조·소비 조건이 필요합니다.

위 네 항목은 RC-01~03의 기본 관계 + 의미 조건 조합으로 보완할 계획입니다. 사용자 강제 지정·상위 5개 추천 정책은 유지합니다. 실제 화면 배치나 애니메이션은 이번 범위가 아닙니다.
