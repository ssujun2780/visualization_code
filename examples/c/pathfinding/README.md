# A* / LWA* C 실행 예제

기존 예제 메뉴에서 현재 C 코드를 컴파일·실행하고, 공통 자료구조 추론으로 그래프를 표시합니다.
수동 역할 지정 파일과 별도 그래프 페이지는 제거했습니다. 출력 로그를 해석해 그래프를 만들지 않습니다.

## 그래프 완성 후 탐색

두 파일 모두 `build_graph → initialize_search → search` 순서입니다.
정점·간선·장애물을 저장하고 모든 인접 연결과 진입 개수·진출 비용 합을 구성한 뒤
`GRAPH_READY`를 출력합니다. 이후 검색 상태를 초기화하고 `SEARCH_BEGIN` 뒤 OPEN을 사용합니다.
그래프 구성은 충돌 검사를 미리 수행하지 않습니다. 잠재 간선 12개를 구성한 뒤
A*와 LWA*가 각자의 시점에 사용 가능성을 검사합니다.

공통 인접 목록 구성은 O(VE) 전처리입니다. 탐색 자체는 완성된 인접 목록을 사용합니다.
전처리·출력·시각화 비용과 탐색 알고리즘 분석을 구분해야 합니다.
OPEN 용량 8은 이 분기형 입력의 최대 동시 후보 6개를 수용합니다.

추론은 실제 출발점 비교와 목적지 인덱스 전달, 같은 동적 간선 행·정점 영역을 연결합니다.
유일한 간선 속성이 정점 갱신의 덧셈 피연산자로 관측되면 가중치 범위를 연결합니다.
이름·출력·예상 경로는 근거가 아닙니다. 그래프의 원형 레코드는 첫 스칼라 값을 표시하며
나머지 원본 필드와 포트도 보존합니다. 상세 값은 원본 상자 보기에서 확인할 수 있습니다.

## 기존 시각화에서 실행

1. 기존 **예제** 목록에서 **A* · 충돌 검사 경로 탐색 (8개 정점)** 또는
   **LWA* · 지연 충돌 검사 경로 탐색 (8개 정점)**을 선택합니다.
2. 두 예제의 기본 **실행 전 입력**은 동일하게 `3`입니다. 필요하면 0~63으로 바꾸고 다시 실행합니다.
3. 직접 입력하려면 `astar.c` 또는 `lwa_star.c` 전체를 **C 코드 직접 입력**에 붙여 넣고
   기존 **컴파일·시각화**로 실행할 수도 있습니다.
4. `vertices`, `edges`, `open_heap`, `open_size`, `collision_checks`와 현재 후보의
   `g/f/verified`를 확인합니다. OPEN 배열은 최소 힙 순서이며, 앞의 `open_size`개만 활성입니다.

입력이 EOF인 경우 기본값은 3입니다. 터미널에서는 숫자를 입력하거나 입력 파일을 전달하세요.

정점 접근 중 **현재 작업**을 누르면 그래프 전체를 확대합니다.
**전체 보기**는 함수 공간·보조 배열까지 모두 포함하므로 크게 축소될 수 있습니다.
과거 수동 지정 JSON을 다시 열지 말고 현재 예제를 새로 실행하세요.

## 같은 입력과 그래프

정점은 8개입니다: 0=S, 1~6=우회 후보, 7=G.
각 후보 i에 대해 `S -> i -> G` 연결만 존재하는 방향 그래프입니다.

| 후보 정점 | 좌표 | 입구/출구 각각의 비용 | 전체 경로 비용 |
|---|---|---:|---:|
| 1 | (300, 0) | 300 | 600 |
| 2 | (300, 55) | 305 | 610 |
| 3 | (300, 125) | 325 | 650 |
| 4 | (300, 225) | 375 | 750 |
| 5 | (300, 400) | 500 | 1000 |
| 6 | (300, 720) | 780 | 1560 |

S=(0,0), G=(600,0)이며, 정수 비용은 실제 선분의 유클리드 길이입니다.
휴리스틱은 각 후보에서 G까지의 직선거리, S에서는 600, G에서는 0입니다.
가중치 1이며 같은 비교 순서 `(f,g,vertex,parent)`를 사용합니다.

입력 숫자의 하위 6비트가 **입구 차단 여부**입니다. 비트 0은 정점 1,
비트 5는 정점 6에 대응하며, 1이면 해당 입구를 막는 작은 사각형을 배치합니다.
두 검색은 비트를 직접 보고 경로를 선택하지 않고 실제 선분-사각형 교차 검사를 호출합니다.
사각형은 모두 x=59~61에 있으므로, x=300~600에 있는 출구 연결은 사전에 검증된 공통 입력입니다.
경계만 닿는 경우는 차단으로 보지 않습니다.

| 입력 | 의미 | 경로/비용 | A* 입구 검사 | LWA* 입구 검사 |
|---:|---|---|---:|---:|
| 0 | 모두 통과 | 0 -> 1 -> 7 / 600 | 6 | 1 |
| 3 | 앞의 두 입구 차단 | 0 -> 3 -> 7 / 650 | 6 | 3 |
| 31 | 마지막 입구만 통과 | 0 -> 6 -> 7 / 1560 | 6 | 6 |
| 63 | 모두 차단 | 경로 없음 | 6 | 6 |

0~63을 균등하게 뽑으면 각 입구의 차단 여부가 독립적인 확률 1/2인 분포가 됩니다.
이 예제는 앞서 논의한 분기형 모형의 비용을 실제 정수 길이로 바꾼 것입니다.

## 비교할 동작

- A*: 연결을 검사한 뒤 g·부모를 갱신하고 검증된 후보를 OPEN에 등록합니다.
- LWA*: 낙관적 비용으로 미검증 후보를 등록하고, 선택될 때 검사합니다.
  통과하면 검증된 후보로 재등록하고, 다시 선택될 때 확장합니다.
- 두 파일 모두 이진 최소 힙을 사용합니다. OPEN이 비었을 때 생성한 후보는
  모아서 heapify하므로 초기 힙 구성이 선형 시간입니다.
- A*는 정점별 힙 위치를 기록하여 후보를 갱신합니다.
  LWA*는 서로 다른 부모의 후보를 허용하며 정점별 최소 검증 비용으로 지배되는 후보를 거릅니다.
- `CHECK`는 새로 수행한 간선 검사, `OBSTACLE_TESTS`는 실제 사각형 검사 횟수입니다.
  이미 검증된 출구 연결과 캐시 재사용은 CHECKS에 더하지 않습니다.
- `EXPAND`는 이웃을 조사하는 동작입니다. 단순 추출, 검증, 목적지 선택은 확장 수에 포함하지 않습니다.
- 시간 복잡도 분석을 흉내 내기 위한 대기나 반복 계산은 넣지 않았습니다.
  출력 로그가 있으므로 이 프로그램의 실행 시간으로 성능 우열을 주장하지 않습니다.

참고: [Lazy Weighted A* 원논문](https://www.roboticsproceedings.org/rss10/p33.pdf).

`python examples/c/pathfinding/verify.py`로 이 두 예제만 검증합니다.

12개 잘못된 입력, 4개 EOF 기본값을 확인했습니다. 별도의 정수 기하 판정과
Floyd–Warshall 결과를 기준으로 경로·최단비용·검사 횟수를 검사합니다.
